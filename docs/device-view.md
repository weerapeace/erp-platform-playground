# Device View — ดูหน้า dashboard แบบจอคอม / แท็บเล็ต / มือถือ + QR เปิดบนเครื่องจริง

ของกลาง: `components/device-view` (+ รูป QR ของกลาง `components/qr-code.tsx`)

## ใช้ทำอะไร

ให้หน้า dashboard/บอร์ดหนึ่งหน้า "เลือกดูได้ 3 แบบ" โดยไม่ต้องทำหน้าแยก:

| โหมด | เกิดขึ้นเมื่อ | หน้าตา |
|---|---|---|
| อัตโนมัติ (ค่าเริ่มต้น) | ไม่ได้เลือกอะไร | ดูจากความกว้างจอจริง: มือถือ ≤ 639px · แท็บเล็ต ≤ 1023px · ที่เหลือ = จอคอม |
| เลือกเอง 🖥️ / 📟 / 📱 | กดปุ่มที่หัวหน้า | URL ได้ `?device=phone` ฯลฯ → refresh/แชร์ลิงก์แล้วยังเป็นโหมดเดิม |
| พรีวิว + QR | เลือกโหมดที่ **แคบกว่าจอจริง** (เช่น อยู่จอคอมแล้วกด 📱) | เนื้อหาถูกครอบในกรอบเครื่อง (มือถือ 400px / แท็บเล็ต 834px) + แผง QR ข้าง ๆ 2 แท็บ: **เปิดหน้านี้** (สแกนแล้วเปิดหน้านี้บนเครื่องจริงในโหมดเดียวกัน) / **📲 ติดตั้งเป็นแอป** (สแกน → `/app/<key>?go=<หน้านี้>` → ปุ่ม 📲 ติดตั้งแอปที่หัวแอปเดี่ยว · เลือกแอปได้ถ้าหน้านี้อยู่หลายแอป · แอปมาจาก /api/menu ที่แคชร่วมกับเชลล์) + ปุ่มคัดลอกลิงก์ + ปุ่ม "กลับมุมมองจอคอม" (prop `onExitPreview`) |

เชลล์แอปเดี่ยว `/app/[appKey]` รับ `?go=/path` = เปิดเมนูที่ตรงกับ path นั้นทันที (ล้างออกจาก URL หลังใช้)

เปิดบนมือถือจริงในโหมดมือถือ = ไม่มีกรอบ ไม่มี QR (เรนเดอร์ตรง ๆ)

## วิธีใช้ในหน้าใหม่

```tsx
import { useViewportLayout, useDeviceMode, DeviceModeToggle, DevicePreviewFrame } from "@/components/device-view";

const viewport = useViewportLayout();                       // จอจริง
const { mode, setMode, layout } = useDeviceMode(viewport);  // โหมดที่เลือก + layout ที่ต้องเรนเดอร์
const isDesktop = layout === "desktop";

// ปุ่มสลับ วางที่หัวหน้า
<DeviceModeToggle mode={mode} viewport={viewport} onChange={setMode} compact={!isDesktop} />

// เนื้อหาหน้า ห่อด้วยกรอบ (ถ้าไม่ต้องพรีวิว จะคืน children ตรง ๆ)
<DevicePreviewFrame layout={layout} viewport={viewport}>{body}</DevicePreviewFrame>
```

**กฎสำคัญ:** ส่วนที่อยากให้ "พรีวิวตรงกับเครื่องจริง" ต้องตัดสินด้วย `layout` (เช่น `isPhone ? "grid-cols-2" : "grid-cols-4"`)
ห้ามใช้ `sm:`/`lg:` ของ Tailwind สำหรับส่วนนั้น เพราะ breakpoint ดูจอจริง ไม่ดูกรอบพรีวิว

## รูป QR ของกลาง

```tsx
import { QrCode, useQrDataUrl } from "@/components/qr-code";
<QrCode text={url} size={168} />
```
โหลดไลบรารี `qrcode` แบบ dynamic เฉพาะตอนใช้ · ห้าม `import("qrcode")` เองในหน้าอื่น

## ใช้แล้วที่ไหน

- Design Dashboard (`components/design-dashboard`)
  - **แท็บเล็ต:** บอร์ดสถานะเป็นแถวเลื่อนซ้าย-ขวา (snap ทีละคอลัมน์ 300px) + ชิปสถานะกดเลื่อนไปคอลัมน์ · แกลเลอรีไม่เกิน 4 ต่อแถว
  - **มือถือ (ออกแบบเป็นแอปมือถือ):** หัวสั้น (ชื่อหน้า + สรุป) · ปุ่มรองทั้งหมดยุบเข้าเมนู ⋯ (รายการงาน/กลับ/รีเฟรช/ปรับธีม/จัดการสถานะ/ส่งขึ้นกระดาน/ตั้งค่าแบรนด์) · แบรนด์เป็นชิปเลื่อนแนวนอน · สถิติ 4 ช่องแถวเดียว · ค้นหาเต็มแถว + ตัวกรองเป็นชิป · บอร์ด = **แท็บสถานะ** (เลือกทีละสถานะ → การ์ด 2 ต่อแถว ใช้การ์ดเดียวกับแกลเลอรี) · ปุ่ม ＋ เพิ่มงานลอยมุมล่างขวา
  - ปิดลากการ์ดบนทัช (ทัชลากไม่ได้ → เปลี่ยนสถานะในหน้ารายละเอียด)
  - **แตะการ์ดบนแท็บเล็ต/มือถือ = เปิดหน้าเต็ม** `/master/design-dashboard/sheet/[id]` (ของกลาง `components/design-sheet-mobile`) ไม่ใช่ป๊อปอัป: รูปปัดดู + นับ 1/N + แตะดูเต็มจอ · สถานะแตะเปลี่ยน (แผ่นเลือกจากล่าง) · กำหนดส่งแตะเปลี่ยน · โน้ตแก้ทันที · รายละเอียดงานย่อ/กาง · ความคืบหน้า ตีราคา/เสนอราคา/SKU (แตะ = ป๊อปอัปเต็ม) · Comment ลูกค้าไทม์ไลน์ + พิมพ์เพิ่ม · **ตีราคา** กางดูรายการวัสดุ/ค่าแรง/ต้นทุนรวม แยกแท็บ Parent (อ่านอย่างเดียว แก้ในหน้าเต็ม) · **เสนอราคา** ไทม์ไลน์รอบ + เพิ่มรอบใหม่จากมือถือได้ · **SKU ที่เชื่อม** การ์ดรูป 2 ต่อแถว แตะเปิด drawer กลาง (skus-v2 / parent-skus-v2) · แถบล่าง [เปลี่ยนสถานะ] [แก้ไขเต็ม] · แท็บเล็ต = รูปซ้าย เนื้อหาขวา · ใช้ API เดิมทั้งหมด
- Dashboard ผลิต (`app/master/production-dashboard`) — รวมถึงตอนฝังในหน้า **ปฏิทินรวม** (`/calendar`) และแท็บปฏิทินใน `/dashboard`
  - **แท็บเล็ต:** ตัวกรองกลุ่มงาน (งานทั้งหมด/ยังไม่จ่าย/…) เป็นชิปเลื่อนแนวนอนแทนแถบซ้าย · ปฏิทินอยู่บน กล่อง "ยังไม่ลงวันที่ส่ง" อยู่ล่าง (การ์ด 2 ต่อแถว)
  - **มือถือ:** หัวสั้น + ปุ่ม รายการ/ปฏิทิน เต็มแถว · ตัวเลขสรุป 4 ช่องแถวเดียว · ช่องวันในปฏิทินเป็น **จุดสี + จำนวนงาน** → แตะวัน = เห็นการ์ดงานของวันนั้น · กล่อง "ยังไม่ลงวันที่ส่ง" พับไว้ก่อน แตะเพื่อกาง (โชว์ทีละ 30 ใบ)
  - **ตั้งวันบนจอสัมผัส:** ลากวางไม่ได้ → ใต้การ์ดมีช่อง 📅 ลงวัน/เปลี่ยนวัน + ปุ่ม "เอาวันออก" (บันทึกผ่าน API เดิม `/api/mo/set-due-date`)

- Dashboard หน้าแรก (`app/dashboard`) — ปุ่ม 🖥️📟📱 อยู่ที่หัวหน้า ข้างปุ่มรีเฟรช
  - **แท็บแรก "👔 ภาพรวม" (แอดมิน)** = รวม "ผู้บริหาร" + "การ์ดระบบ" เดิมเป็นหน้าเดียว: ตัวเลขธุรกิจ → **แท็บแผนก** (`app/dashboard/dept-tabs.tsx`) → การเงิน → คลัง/ผลิต/จัดซื้อ → ระบบอื่นที่มีงานค้าง (คนที่ไม่ใช่แอดมินยังเห็น "🗂️ การ์ดระบบ" แบบเดิม)
  - **แท็บแผนก:** บนแท็บโชว์ตัวเลขที่ต้องระวังที่สุดของแผนก (แดง → เหลือง → ตัวแรกที่ไม่เป็นศูนย์) + จำนวนงานค้าง · กดแท็บ = ตัวเลข 4 ช่อง + งานค้าง (แจ้งเตือน) ของแผนกนั้น (แถวเดียวกับการ์ดระบบ `SystemItemRow`)
  - **แท็บเล็ต:** แท็บแผนก 6 ใบแถวเดียว (ชื่อสั้น) · การ์ดตัวเลข 4 ต่อแถว · ปุ่ม "เปิดแดชบอร์ด →" พาไปหน้าเต็มของแผนก (ไม่เปิดหน้าต่างซ้อน)
  - **มือถือ:** หัวสั้น + ปุ่มรีเฟรชเป็นไอคอน · แถบมุมมองเต็มแถว (ของฉัน/ทีม ลงแถวถัดไป) · การ์ดตัวเลข 2 ต่อแถว · แท็บแผนก 3 ต่อแถว (เห็นครบ 6 แผนกไม่ต้องเลื่อน)
  - หน้าต่างเด้ง (ตั้งค่าการ์ด / เปิดลิงก์แจ้งเตือน) อยู่นอกกรอบพรีวิว → เต็มจอจริงเสมอ
  - ยังไม่ได้ปรับตาม `layout`: มุมมอง แผนงาน / รายการ / widget เสริม (ยังใช้ `sm:`/`lg:` = ถูกต้องบนเครื่องจริง แต่ในกรอบพรีวิวบนจอคอมอาจแน่นกว่าของจริง)

## ปฏิทินกลาง ScheduleBoard รองรับ layout

`components/schedule-board` รับ prop `layout` (`desktop` / `tablet` / `phone`) จาก device-view ได้เลย:

```tsx
<ScheduleBoard layout={layout} getDotColor={(j) => j.brand_color} ... />
```

ไม่ส่ง `layout` = ทำงานแบบเดิม (ดูความกว้างจอจริง · ลากวางได้) — ปฏิทินจัดซื้อยังใช้แบบนี้อยู่

## ข้อจำกัด

- ป๊อปอัปเต็ม (design-sheet-detail) ที่เปิดจากปุ่ม "แก้ไขเต็ม" ยังเป็นหน้าตาจอคอม — ใช้เฉพาะงานหนัก (ตีราคา/เสนอราคา/Parent SKU)
- กรอบพรีวิวจำลอง "ความกว้าง" เท่านั้น ไม่จำลองทัช/ความเร็วเครื่อง
