# หน้าดีไซน์เว็บร้าน (แท็บ 🎨 ดีไซน์ ใน /website/<ร้าน>)

เจ้าของขอ 2026-10-28: "อยากได้หน้าดีไซน์แบบย่อย ๆ ดูง่ายกว่านี้" → เลือกแบบ A (เมนูซ้ายจัดหมวด) + การ์ดพับได้ + ค้นหา + ภาพรวม

## หน้าตา

```
[แถบสถานะ: ร่าง/เผยแพร่ · "แก้เว็บจริง" บรรทัดเดียว · 🌐 EN x/y · ↶ ↷]
┌ เมนูซ้าย ─────┬ ตั้งค่า (การ์ดพับได้) ─────────┬ พรีวิวเว็บสด ┐
│ ค้นหา        │ หมวด › ชื่อหน้า   [กาง/พับทั้งหมด] │             │
│ ภาพรวม       │ TH | EN                         │             │
│ ทั้งเว็บ  ●   │ ▸ การ์ด 1  (สรุปค่าตอนพับ)       │             │
│ หัว-ท้ายเว็บ │ ▾ การ์ด 2                        │             │
│ สินค้า ซื้อขาย│    …ช่องตั้งค่า…                │             │
└──────────────┴─────────────────────────────────┴─────────────┘
[แถบล่าง: แก้ N หัวข้อ (กดชื่อไปหน้านั้น) · ละทิ้ง · บันทึกร่าง · ⏰ · เผยแพร่]
```

- จอ ≥ 1280px: เมนู | ตั้งค่า | พรีวิว · 1024–1279: พรีวิวอยู่ใต้การตั้งค่า · มือถือ: เมนูเป็นช่องเลือก + ช่องค้นหา
- `?d=<หน้า>` ในลิงก์ = เปิดหน้านั้นตรง ๆ (เช่น `/website/louismontini?tab=design&d=menu`)

## เพิ่มของใหม่ในหน้าดีไซน์

1. **ช่อง/การ์ดใหม่ในหน้าเดิม** → แก้ไฟล์แท็บนั้น ใช้ `<DesignCard title="…" summary={…}>` (summary = สรุปค่าตอนพับ บรรทัดเดียว)
   แล้วเพิ่ม `{ title, keywords }` ใน `cards` ของหน้านั้นใน `lib/website-design-nav.ts` (ค้นหาจะเจอ)
2. **ค่าใหม่ในธีม** → ใส่ path ใน `paths` ของหน้าที่แก้ค่านั้น (เทสต์ `lib/__tests__/website-design-nav.test.ts` ฟ้องถ้าลืม — จุดส้มจะไม่ขึ้น)
   + ถ้าเป็นข้อความ → เพิ่มใน `THEME_TEXT_KEYS` ด้วย (กฎเดิม 2 ภาษา)
3. **หน้าใหม่** → เพิ่มคีย์ใน `DesignPageKey` + `DESIGN_PAGES` + หมวดใน `DESIGN_GROUPS` → render ใน `website-theme-panel.tsx` (`{tab === "x" && <XTab />}`) + สรุปใน `overview.tsx pageSummary`
4. ค่าที่แท็บต้องใช้แต่ยังไม่มีใน `useDesign()` → เพิ่มใน `DesignCtxValue` (context.tsx) + `designCtx` ในเชลล์

## การ์ดพับได้ (DesignCard)

- จำพับ/กางต่อคน: `user_ui_prefs` คีย์ `website_design_cards` (`<หน้า>:<ชื่อการ์ดตัดอีโมจิ>` → true/false)
- ยังไม่เคยกด = ใบแรกของหน้ากาง ที่เหลือพับ (หรือ `defaultOpen`)
- นอก `DesignCardsProvider` = การ์ดธรรมดา กางตลอด
- `Card` ของ `website-cart-settings` (ตะกร้า · ชำระเงิน · แนะนำสินค้า) กลายเป็น DesignCard อัตโนมัติเมื่ออยู่ในหน้าดีไซน์
- ค้นหาเจอการ์ด → เชลล์ยิง event `website-design-focus` (ชื่อการ์ด) → การ์ดนั้นกางเอง แล้วเลื่อนไปหา + กะพริบกรอบ

## 🎯 คลิกเลือกส่วนในพรีวิว + พรีวิวเลื่อนไปส่วนที่แก้

- ปุ่ม "🎯 คลิกเลือกส่วน" บนแถบพรีวิว (เปิด/ปิด) → ชี้ชิ้นในพรีวิว = กรอบประ + ป้าย "แก้: <ชื่อ>" · คลิก = เมนูซ้ายไปหน้านั้น + กางการ์ด (พรีวิวอยู่หน้าเดิม)
- เปิดหน้าตั้งค่าเอง → พรีวิวเลื่อนไปส่วนนั้น + กะพริบกรอบ (ท้ายเว็บ = ลงล่าง · หัวเว็บ = ขึ้นบน · การ์ด = การ์ดแรก)
- แผนที่ "ชิ้น → หน้า/การ์ด" = `PREVIEW_PART_RULES` ใน `lib/website-design-nav.ts` (อิงป้าย `data-part` ของชุดปรับหน้าตาชิ้นส่วน hd.* ft.* pc.* pd.* cart.* co.* …) · กฎเจาะจงต้องมาก่อนกฎกว้าง (เทสต์ตรวจ)
- เว็บร้าน: `src/components/layout/DesignAreaBridge.tsx` (ข้อความ storefront-area-pick / -picked / -focus) · ส่วนใหม่ในเว็บร้านที่อยากให้คลิกได้ = ติด `data-part` + เพิ่มกฎ
- ปุ่ม ↻ โหลดพรีวิวใหม่ = ตั้ง src ซ้ำ (เว็บร้านคนละโดเมน contentWindow.location.reload() ถูกบล็อก)

## ↔ ความกว้างพรีวิว + 🔍 ซูมเฉพาะพรีวิว

- เส้นแบ่งระหว่างตั้งค่ากับพรีวิว (จอ ≥ 1280px) ลากปรับได้ · จำต่อคน (`website-design-preview`) · ดับเบิลคลิก = ค่าเริ่ม 40% · ปุ่ม ⇔ = กว้างสุด/คืนค่า
  - ของกลาง `components/split-handle.tsx` (`useSplitWidth` + `SplitHandle`) — หน้าใหญ่แก้ Section (`website-section-studio`) ใช้ตัวเดียวกัน
- ซูม: ปุ่ม − / + (ทีละ 10%) · ช่องเลือก พอดีจอ/50/75/100% · Ctrl+หมุนลูกกลิ้ง/บีบนิ้วบนพรีวิว (ทีละ 5% · 25–150%) · ดับเบิลคลิกตัวเลข % = พอดีจอ
  - Ctrl+ลูกกลิ้งบนตัวเว็บ เบราว์เซอร์ส่งให้หน้าในกรอบ → `DesignAreaBridge` ของเว็บร้านกันซูมทั้งหน้าแล้วส่ง `storefront-preview-zoom` กลับมา · บนขอบรอบกรอบ ERP จับเอง
- ✋ มือจับ: กดปุ่มลูกกลิ้งค้างแล้วลาก = เลื่อนดูทุกทิศ (ซ้าย-ขวาได้เมื่อซูมเกินพอดีจอ) · เคอร์เซอร์เป็นมือกำ · ปิดโหมดเลื่อนอัตโนมัติ (วงกลมลูกศร) + ปุ่มกลางเปิดลิงก์แท็บใหม่ เฉพาะในพรีวิว
  - บนตัวเว็บ: เว็บร้านส่ง `storefront-preview-pan {dx, dy}` (px บนจอ) → ERP `panBy` เลื่อนกรอบนอกก่อน ส่วนขึ้น-ลงที่เหลือส่งกลับ `storefront-preview-scroll {dy}` ให้หน้าเว็บเลื่อน · พื้นเทารอบพรีวิว ERP จับเอง
- ท่าทางซูม/ลากของเว็บร้านเปิดเฉพาะเมื่อ ERP ส่ง `storefront-preview-gestures {on:true}` (แท็บดีไซน์ส่งทุกครั้งที่พรีวิวพร้อม) — หน้าแก้อื่นที่ใช้พรีวิว (จัดหน้าแรก · Section) ลูกกลิ้งทำงานแบบเดิม

## 👷 พนักงานแก้บางหัวข้อ

- ตั้งที่ /website/access (ดู docs/website-access.md) · โหมดอ่านจาก `designAccess` (lib/website-access) ใน website-theme-panel → `DesignModeCtx` (components/website-design/mode.tsx: limited · simple)
- การ์ดใหม่ที่ใช้ API สิทธิ์เต็ม / เปลี่ยนหลายหัวข้อพร้อมกัน → ใส่ `level: "full"` · การตั้งค่าเชิงลึก → `level: "advanced"` ใน cards ของ lib/website-design-nav (DesignCard ซ่อนให้เอง)
- หน้าดีไซน์ใหม่ → เพิ่มใน `DESIGN_TOPICS` ของ lib/website-access ด้วย (เทสต์ฟ้องถ้าไม่ตรง)

## ข้อจำกัด / ทีหลัง

- ส่วนที่ไม่มีป้าย data-part (Section ของหน้าแรก · ปุ่มแชท · แถบเมนูล่างมือถือ) ยังคลิกไม่ได้ — Section หน้าแรกแก้ที่แท็บ 🧱 จัดหน้าแรก
- หน้าสินค้ายังเป็นการ์ดใหญ่ใบเดียว (ข้างในมี ⚙ ต่อส่วนอยู่แล้ว)
