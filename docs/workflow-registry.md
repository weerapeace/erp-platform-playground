# ทะเบียน workflow กลาง + ตัวเช็ก "ใครใช้บ้าง"

> เจ้าของสั่ง 2026-11-02: "เวลาแก้อะไร workflow อยากให้เช็คด้วยว่ามีระบบไหนใช้อยู่บ้าง (ทำเป็นของกลาง)"

## ใช้ทำอะไร

| ชิ้น | ไฟล์ | หน้าที่ |
|---|---|---|
| ทะเบียน workflow | `lib/workflow-registry.ts` | บอกว่ามีเส้นทางงานอะไรบ้าง · กติกาอยู่ไฟล์ไหน · ประตูเปลี่ยนสถานะ (API) · ตาราง · จุดที่ยังไม่เป็นของกลาง |
| ตัวเช็กใครใช้บ้าง | `scripts/where-used.mjs` | ไล่จากโค้ดจริงว่า หน้าไหน / API ไหน ใช้กติกานั้น (ทั้งตรงและต่อทอด) + ใครแตะข้อมูลเองโดยไม่ผ่านกติกา |
| เทสต์ | `lib/__tests__/workflow-registry.test.ts` | ไฟล์ที่ทะเบียนอ้างต้องมีจริง · ตัวเช็กต้องเจอหน้าขอซื้อเมื่อถามกติกาจ่ายงาน |

ทะเบียนจดเฉพาะของที่คนต้องบอก ส่วน "ใครใช้" **ห้ามจดมือ** ให้สคริปต์ไล่หาทุกครั้ง จะได้ไม่ล้าสมัย

คู่กับ **ทะเบียนกติกาธุรกิจภาษาคน** (หน้า `/master/logic` · ตาราง `erp_logic_registry`) ผ่านช่อง `logicIds`

## ใช้เมื่อไหร่

**ทุกครั้งก่อนแก้กติกา workflow / สถานะ / ของกลาง** เช่น เปลี่ยนนิยาม "จ่ายงานแล้ว", "ส่งงานครบ", สถานะ PR/PO, เส้นทางออเดอร์เว็บ

```bash
npm run where-used                       # สรุปทุก workflow
npm run where-used -- mo-production      # workflow เดียว (key)
npm run where-used -- mo-dispatch        # หาจากชื่อไฟล์กติกา
npm run where-used -- lib/po-total.ts    # ไฟล์ไหนก็ได้ (ไม่ต้องอยู่ในทะเบียน)
npm run where-used -- purchasing --all   # โชว์ทุกรายการ (ปกติตัดที่ 15)
npm run where-used -- purchasing --json  # ผลแบบเครื่องอ่าน
```

แล้วเอาข้อ ① "หน้าจอที่กระทบ" ไปเขียนเป็นภาษาคนในแผนให้เจ้าของดูก่อนแก้

## อ่านผลยังไง

- **① หน้าจอที่กระทบ** — หน้าที่ใช้กติกาตรง ๆ หรือเรียก API ที่ใช้กติกา (บอกว่าผ่าน API ไหน)
  - "ขึ้นผ่านของกลางที่ใช้ทั่วระบบ (~N หน้า)" = กติกาไปอยู่ในของกลางที่เกือบทุกหน้าใช้ (เช่น ตารางกลาง master-crud) → รวบเป็นบรรทัดเดียว ไม่ลิสต์ทุกหน้า
- **② API** ที่ใช้กติกานี้ · **③ component** ที่ใช้ต่อ · **④ ประตูเปลี่ยนสถานะ**
- **⑤ แตะข้อมูลเองโดยไม่เรียกไฟล์กติกา** — ไฟล์ที่อ่านตาราง/คอลัมน์ของ workflow นี้ตรง ๆ → ตรวจว่าคิดกติกาเองไหม (ไม่ใช่บั๊กทุกตัว แต่เป็นจุดเสี่ยงกติกาเพี้ยน)
- **⑥ ยังไม่เป็นของกลาง** · **⑦ รหัสกติกาธุรกิจ** · **⑧ workflow ที่รับผลต่อ**

## เพิ่ม / แก้ทะเบียน

- workflow ใหม่ หรือย้ายกติกาไปไฟล์ใหม่ → แก้ `WORKFLOWS` ใน `lib/workflow-registry.ts` ที่เดียว แล้วรัน `npx vitest run lib/__tests__/workflow-registry.test.ts`
- `signals` = ชื่อคอลัมน์ที่ถ้าไฟล์อื่นอ่านเอง แปลว่าอาจคิดกติกาเอง (เช่น `received_qty`)
- ไฟล์ทะเบียนต้อง pure (ไม่ import อะไร) — สคริปต์ Node อ่านตรงได้ และหน้าเว็บนำไปใช้ต่อได้

## ข้อจำกัด

- หา URL API ที่ต่อสตริงแบบ `"/api/x/" + id` ไม่เจอ (เจอ `"..."` และ `` `...${id}...` ``)
- ชื่อหน้าภาษาไทยมาจากแถบเมนู (`components/playground-shell.tsx`) หรือ `<h1>` ในหน้า — เมนูที่ตั้งใน DB อย่างเดียวจะโชว์แค่ URL
- ต้องใช้ Node 22.18 ขึ้นไป (อ่านไฟล์ `.ts` ได้เอง)
- ไม่แตะฐานข้อมูล ไม่มีผลกับเว็บจริง (เป็นเครื่องมือตอนพัฒนา)
