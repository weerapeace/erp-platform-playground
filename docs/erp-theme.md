# ธีมกลาง ERP (`lib/erp-theme`)

> เจ้าของเลือก 2026-11-24: คลังธีม + เลือกธีมต่อโมดูล (แนวทาง B) · ทำเป็น 8 เฟส · ไฟล์นี้อัปเดตทุกเฟส

## ใช้ทำอะไร

ให้สีหลักของระบบ "เปลี่ยนได้" โดยไม่ต้องไล่แก้คลาสในหน้า — คลาส Tailwind อ่านสีจากตัวแปร CSS แทนสีตายตัว

| คลาส | บทบาท | ตัวแปร | ค่าเริ่ม |
|---|---|---|---|
| `blue-*` · `brand-*` | สีหลัก (ปุ่ม ลิงก์ แท็บ) | `--tm-primary-50..950` | ส้มเดิม (`orange` ของ Tailwind) |
| `violet-*` | สีเน้นรอง (Creative ใช้เยอะ) | `--tm-accent-50..950` | ม่วงเดิม (`violet` ของ Tailwind) |
| `status-blue-*` · `status-violet-*` | สีสถานะ — **ล็อก ไม่ตามธีม** | – (สีตายตัว) | เท่าป้ายเดิม |

- ค่าตัวแปรเก็บแบบ `"R G B"` → คลาสโปร่งใส เช่น `bg-blue-500/20` ยังใช้ได้
- ค่าเริ่มวางที่ `:root` โดย plugin ใน `tailwind.config.ts` (แหล่งเดียว = `DEFAULT_THEME_SCALES`)
- `ring` เปล่า (วงโฟกัส) ตั้ง `ringColor.DEFAULT` เองให้ตามสีหลัก
- `indigo-*` / `purple-*` ยังเป็นสีตายตัว (ใช้ปนกับสถานะหลายที่ — ยังไม่ผูกธีม)

## ใช้เมื่อไหร่

- หน้าใหม่: ใช้ `blue-*` (สีหลัก) / `violet-*` (สีเน้น) ตามปกติ = ตามธีมเองอัตโนมัติ
- เปลี่ยนสีทั้งก้อน: เอา `themeVars({ primary: scaleFromHex("#0e7490") })` ไปใส่ `style` ของกล่องครอบ → ทุกอย่างข้างในเปลี่ยนสี
- ป้ายสถานะ / สีที่มีความหมายตายตัว: ใช้ `status-blue-*` / `status-violet-*` (ทำแล้วที่ `lib/status-config` FAM.blue · `lib/creative-status-colors` blue/violet)

## ห้ามใช้เมื่อไหร่

- ห้ามใช้ `blue-*` / `violet-*` กับป้ายสถานะ (ร่าง/รออนุมัติ/อนุมัติ) — เปลี่ยนธีมแล้วความหมายสีจะเพี้ยน
- เว็บร้าน (storefront) ไม่ใช้ตัวนี้ — มีระบบธีมของตัวเอง (`lib/website-theme`)
- สีที่เขียนเป็นรหัส `#xxxxxx` ใน `style` ยังไม่ตามธีม (ทยอยแก้ในเฟส 6/8)

## ตัวช่วย

| ฟังก์ชัน | ทำอะไร |
|---|---|
| `themeVars(scales?)` | ชุดตัวแปร `--tm-*` ทั้งหมด (บทบาทที่ไม่ส่ง = ค่าเริ่ม) |
| `scaleFromHex(hex)` | สร้าง 11 เฉดจากสีเดียว (สีที่ส่ง = เฉด 500) |
| `hexToChannels(hex)` | `#ea580c` → `234 88 12` |
| `tailwindScaleFor(role)` | ใช้ใน tailwind.config เท่านั้น |

เทสต์: `lib/__tests__/erp-theme.test.ts` (เช็กว่าค่าเริ่ม = สีเดิมทุกเฉด)
