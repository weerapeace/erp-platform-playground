# ธีมกลาง ERP (`lib/erp-theme`)

> เจ้าของเลือก 2026-11-24: คลังธีม + เลือกธีมต่อโมดูล (แนวทาง B) · ทำเป็น 8 เฟส · ไฟล์นี้อัปเดตทุกเฟส

## ใช้ทำอะไร

ให้สีหลักของระบบ "เปลี่ยนได้" โดยไม่ต้องไล่แก้คลาสในหน้า — คลาส Tailwind อ่านสีจากตัวแปร CSS แทนสีตายตัว

| คลาส | บทบาท | ตัวแปร | ค่าเริ่ม |
|---|---|---|---|
| `blue-*` · `brand-*` | สีหลัก (ปุ่ม ลิงก์ แท็บ) | `--tm-primary-50..950` | ส้มเดิม (`orange` ของ Tailwind) |
| `violet-*` | สีเน้นรอง (Creative ใช้เยอะ) | `--tm-accent-50..950` | ม่วงเดิม (`violet` ของ Tailwind) |
| `status-blue-*` · `status-violet-*` | สีสถานะ — **ล็อก ไม่ตามธีม** | – (สีตายตัว) | เท่าป้ายเดิม |

- ค่าตัวแปรเก็บแบบ `"R G B"` → คลาสโปร่งใส เช่น `bg-blue-500/20` ยังใช้ได้
- ค่าเริ่มวางที่ `:root` โดย plugin ใน `tailwind.config.ts` (แหล่งเดียว = `DEFAULT_THEME_SCALES`)
- `ring` เปล่า (วงโฟกัส) ตั้ง `ringColor.DEFAULT` เองให้ตามสีหลัก
- `indigo-*` / `purple-*` ยังเป็นสีตายตัว (ใช้ปนกับสถานะหลายที่ — ยังไม่ผูกธีม)

## ใช้เมื่อไหร่

- หน้าใหม่: ใช้ `blue-*` (สีหลัก) / `violet-*` (สีเน้น) ตามปกติ = ตามธีมเองอัตโนมัติ
- เปลี่ยนสีทั้งก้อน: เอา `themeVars({ primary: scaleFromHex("#0e7490") })` ไปใส่ `style` ของกล่องครอบ → ทุกอย่างข้างในเปลี่ยนสี
- ป้ายสถานะ / สีที่มีความหมายตายตัว: ใช้ `status-blue-*` / `status-violet-*` (ทำแล้วที่ `lib/status-config` FAM.blue · `lib/creative-status-colors` blue/violet)

## ห้ามใช้เมื่อไหร่

- ห้ามใช้ `blue-*` / `violet-*` กับป้ายสถานะ (ร่าง/รออนุมัติ/อนุมัติ) — เปลี่ยนธีมแล้วความหมายสีจะเพี้ยน
- เว็บร้าน (storefront) ไม่ใช้ตัวนี้ — มีระบบธีมของตัวเอง (`lib/website-theme`)
- สีที่เขียนเป็นรหัส `#xxxxxx` ใน `style` ยังไม่ตามธีม (ทยอยแก้ในเฟส 6/8)

## ตัวช่วย

| ฟังก์ชัน | ทำอะไร |
|---|---|
| `themeVars(scales?)` | ชุดตัวแปร `--tm-*` ทั้งหมด (บทบาทที่ไม่ส่ง = ค่าเริ่ม) |
| `scaleFromHex(hex)` | สร้าง 11 เฉดจากสีเดียว (สีที่ส่ง = เฉด 500) |
| `hexToChannels(hex)` | `#ea580c` → `234 88 12` |
| `tailwindScaleFor(role)` | ใช้ใน tailwind.config เท่านั้น |

เทสต์: `lib/__tests__/erp-theme.test.ts` (เช็กว่าค่าเริ่ม = สีเดิมทุกเฉด)

จุดที่ธีมคุมในหน้าจริง:
- พื้นหลังทั้งหน้า (ไล่สีอ่อน 16% หรือรูปที่ "ทั้งหน้า" ชัดไม่เกิน 40%) — ชั้น fixed หลังเนื้อหา (`<main>` เป็น relative)
- แบนเนอร์ = แถบตกแต่งสูง 220px บนสุดของทุกหน้า จางลงด้านล่าง (ไล่สีอ่อน 42% / รูปชัดไม่เกิน 55% ถ้าเปิดกันอ่านยาก) · เนื้อหาอยู่ใน `[data-tm-page]` ที่ลอยทับ
- แถบบน: มือถือ = แถบบนเชลล์ (`header[data-shell-topbar]`) · PC = หัวเมนูข้าง (`[data-shell-sidehead]`) · แอปเดี่ยว = แถบบนของแอป (เฟส 3)
- เมนูข้าง: สว่าง/เข้ม/สีธีม + เมนูที่เลือกไล่สี (`aside[aria-label="เมนูหลัก"]`)
- ข้อ 1: ปุ่มหลัก = ทุกปุ่ม/ลิงก์ที่ใช้คลาส `bg-blue-600` → ไล่สี + แสงวิ่ง (ปุ่มลบสีแดงไม่โดน · ข้ามปุ่ม absolute/fixed/sticky/disabled) · เฉพาะธีมที่ปุ่มแบบ "ทึบ"
- ข้อ 2: แถวตารางกลาง (`[data-erp-table]` ใน DataTable) ชี้แล้วเป็นสีอ่อนของธีม · ตัวนับเลข CountUp หยุดนับเมื่อธีมปิด/ปิดแอนิเมชัน · การ์ดที่ใส่คลาส `tm-card` ยกตัว (ยังไม่มีหน้าไหนใส่)
- เข้าหน้า: จางเข้าอย่างเดียว (ไม่ขยับตำแหน่ง — ป๊อปที่ลอยในหน้าไม่เพี้ยน)
- มาสคอต: fixed ขวาล่าง 64px กดทะลุได้ · ไม่พิมพ์ออกกระดาษ
- มือถือ (< 768px) = โหมดเบา: ไม่มีแสงวิ่ง/ไล่สีขยับ/มาสคอต · รูปจาง ไม่เบลอ
- แอปเดี่ยว: หน้าในกรอบวาดพื้นหลัง/แบนเนอร์/มาสคอตเอง · ตัวแอปเดี่ยวไม่วาดซ้ำ (decor={false})
- พรีวิว "หน้าจริง" ในตัวแก้/ดูตัวอย่าง: ส่งตัวแปร + เอฟเฟกต์ (ปุ่ม/แถบบน/เมนูข้าง) ผ่าน `themePreviewMessage` · พื้นหลัง/แบนเนอร์/มาสคอตยังไม่มาในพรีวิว
- ค่าเริ่ม animation.countUp = เปิด (ตรงกับแดชบอร์ดเดิมที่นับอยู่แล้ว)

## เอฟเฟกต์เพิ่ม — รอบ 2: สี ปุ่ม และการกดในหน้าจริง

- `themeEffects` (lib/erp-theme-effects) เพิ่ม: `data-tm-fx-<จุด>` (button/topbar/menu/number/bell — ROUND2_TARGETS) + `--tm-anim-<จุด>` (รายการ animation รวม) + `--tm-ring/spread/blinkmin-<จุด>` + `--tm-flow` `--tm-c1` `--tm-c2` · ชี้/กด: `data-tm-scale / tm-ripple / tm-underline / tm-wiggle`
- CSS: `app/globals.css` หัวข้อ "เอฟเฟกต์ต่อจุด รอบ 2" — ปุ่มหลัก = `bg-blue-600` · แถบบน = `header[data-shell-topbar]` + `[data-shell-sidehead]` · เมนูที่เลือก = `.bg-blue-50.text-blue-700` ในเมนูข้าง · ตัวเลข = `[data-tm-number]` (CountUp) · กระดิ่ง = `[data-tm-bell-btn]` / `[data-tm-bell]` + `data-tm-new` (เล่นเฉพาะมีแจ้งเตือนใหม่ · components/notification-bell)
- คลื่นน้ำ: ThemeApplier ฟัง pointerdown แล้วใส่ `.tm-ripple-dot` ในปุ่มหลัก · ขีดเส้นใต้: ลิงก์ `text-blue-600/700` (ไม่มีพื้น) + แท็บ `border-b-2 border-blue-600` · ไอคอนขยับ: svg ตัวแรกในปุ่ม/ลิงก์
- ⚠️ ห้ามใส่ `!important` ที่ `background` / `background-position` / `background-color` ของจุดที่มีแอนิเมชัน — แอนิเมชันทับค่า !important ไม่ได้ (เจอแล้วตอนรอบนี้: แถบบนเปลี่ยนสี/ไล่สีวิ่งไม่ขยับ · แก้กฎแถบบนเฟส 4 แล้ว)
- ปิดแอนิเมชัน = เหลือเฉพาะเอฟเฟกต์นิ่ง (แถบเน้น) · มือถือ = ตัดเอฟเฟกต์วนตลอด (เหลือสั่น/แถบเน้น)

## เอฟเฟกต์เพิ่ม — รอบ 3: การ์ด ขอบ เงา ในหน้าจริง

- **"การ์ด"** = `CARD_SELECTOR` (lib/erp-theme-effects) = กล่อง `bg-white` + `border` + `rounded-lg/xl/2xl` ในเนื้อหาของหน้า (`[data-tm-page]`) · นับเฉพาะชั้นนอก (กล่องซ้อนในการ์ดไม่โดน) · ป๊อปอัป/ลิ้นชัก (อยู่นอก [data-tm-page]) ไม่โดน
- **กันกล่องไม่ให้โดน:** ใส่ `data-tm-skip` ที่กล่องนั้น (หรือกล่องแม่ = กันทั้งโซน)
- CSS ใน `app/globals.css` หัวข้อ "การ์ด รอบ 3" ต้องใช้ตัวเลือกเดียวกับ CARD_SELECTOR — เทสต์เช็กให้ (แก้ที่หนึ่งต้องแก้อีกที่)
- ค่าเริ่ม (ขอบเทา 1px ทึบ · เงาบางสีเทา) = ไม่ตั้ง attr → การ์ดหน้าตาเดิม · เปลี่ยนเมื่อไหร่ถึงทา (`data-tm-card-border` / `-run` / `-bar` / `-shadow` / `-hglow` · `data-tm-inset` · `data-tm-stagger` · `data-tm-fx-card`)
- ยกตัว/เรืองแสง ไม่ทำกับการ์ดที่มีตาราง (`:has(table)`) — ตารางใหญ่ขยับแล้วเวียนหัว · ขอบ/เงายังทาปกติ
- เรือง + ขอบวิ่ง พร้อมกัน = รวมเป็น animation รายการเดียว (กฎแยกท้ายหัวข้อ)
- การ์ดโผล่ทีละใบ: ThemeApplier ไล่ใส่ `.tm-stagger-in` ให้การ์ดที่เห็นบนจอ (สูงสุด 30 ใบ · เช็ก 3 รอบ 0.04/0.4/1 วิ หลังเปลี่ยนหน้า เผื่อข้อมูลมาช้า)
- เงาในช่องกรอก: input/textarea/select ในเนื้อหาของหน้า
