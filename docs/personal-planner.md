# แผนงานส่วนตัว (Personal Planner)

มุมมอง **"🗒️ แผนงาน"** บนหน้า `/dashboard` + ของกลางให้โมดูลอื่นสั่ง "ใส่แผนงานของฉัน" ได้

---

## ใช้ทำอะไร

หน้าแดชบอร์ดเดิมตอบได้ว่า *"มีอะไรค้าง"* (การ์ดระบบ / ปฏิทิน / รายการแจ้งเตือน) แต่ยังไม่มีที่ให้ผู้ใช้
*"ตัดสินใจว่าจะทำอะไรวันไหน"* — การ์ด "โฟกัสวันนี้" ระบบจัดอันดับให้เอง ผู้ใช้เลือก/เรียงเองไม่ได้ และไม่จำข้ามวัน

แผนงานส่วนตัวเติมช่องว่างนี้: ลากงานจากกล่องงานเข้ามาวางว่าจะทำ **วันนี้ / พรุ่งนี้ / สัปดาห์นี้ / รอไว้ก่อน**
ติ๊กเสร็จได้ และงานที่ค้างจะตกมาช่อง "วันนี้" ให้เองในวันถัดไป

## ใช้เมื่อไหร่ / ห้ามใช้เมื่อไหร่

| ใช้ | ไม่ใช้ |
| --- | --- |
| งานที่ "ฉันจะทำเอง" และอยากจัดคิวรายวัน | มอบหมายงานให้คนอื่น → ใช้ Task Manager (`erp_creative_tasks`) |
| งานส่วนตัวที่ไม่มีในระบบ (โทรหาซัพ, เคลียร์บิล) | งานที่ต้องมีสถานะ/อนุมัติ/ประวัติ → ใช้โมดูลของงานนั้น |
| ปักงานจากโมดูลอื่นมาเตือนตัวเอง | รายงานภาระงานของทีม → ใช้แท็บ "ภาพรวมทีม" (notifications.view_team) |

**แผนนี้ส่วนตัวล้วน** — ไม่มีใคร (รวมแอดมิน) เห็นแผนของคนอื่นผ่าน UI นี้ และ RLS บล็อกที่ชั้นฐานข้อมูล

## โครงสร้าง

```txt
ตาราง erp_plan_items ── RLS: user_id = auth.uid() (ALL)
lib/planner.ts        ── types + logic ล้วน (import ได้ทั้ง API route และ component)
lib/planner-client.ts ── ฟังก์ชันยิง API ฝั่งหน้าเว็บ (addToPlan / movePlanItems / closeDay …)
app/api/plan/route.ts + close-day/route.ts
app/dashboard/planner-view.tsx  ── กล่องงานเข้า + กระดาน 4 ช่อง (@dnd-kit)
app/dashboard/widgets.tsx       ── PlanWidget ("แผนวันนี้") เปิด/ปิดต่อตำแหน่งที่ /admin/role-board
```

### ฟิลด์สำคัญ

| ฟิลด์ | ความหมาย |
| --- | --- |
| `bucket` | ช่องที่ผู้ใช้เลือกตอนวาง (`today` / `tomorrow` / `week` / `later`) |
| `plan_date` | วันที่ตั้งใจทำ (เวลาไทย) — มีเฉพาะ today/tomorrow · **ช่องที่แสดงจริงคิดจากฟิลด์นี้** |
| `source_type` + `source_id` | งานมาจากไหน (`manual` / `notification` / `task` / `subtask` / `calendar`) · unique ต่อคน = ลากซ้ำไม่ได้ |
| `link` | กด ↗ แล้วเปิดหน้างานต้นทาง (เปิดเป็น popup ผ่าน EmbedModal) |
| `done_at` / `archived_at` | ติ๊กเสร็จ / เก็บออกจากบอร์ดหลังกด "ปิดวัน" (ไม่ลบ ยังย้อนดูได้) |

### ทำไมต้องมี `plan_date` ไม่ใช้แค่ `bucket`

ถ้าเก็บแค่ "วันนี้" พอข้ามวันจริง งานเมื่อวานจะยังโชว์ว่าเป็น "วันนี้" ทั้งที่เลยมาแล้ว
`displayBucket()` จึงคิดช่องจากวันที่: `plan_date <= วันนี้` → ช่องวันนี้ · `= พรุ่งนี้` → ช่องพรุ่งนี้
→ งานค้างเลื่อนมาเองโดยผู้ใช้ไม่ต้องกดอะไร และแผน "พรุ่งนี้" กลายเป็น "วันนี้" อัตโนมัติเมื่อถึงวัน

วันที่ทั้งหมดคำนวณด้วย `bangkokDate()` (Intl + `Asia/Bangkok`) — ห้ามใช้ `toISOString().slice(0,10)` เพราะเวลาไทยจะร่นไป 1 วัน

## กล่องงานเข้า (Inbox) มาจากไหน

| แหล่ง | ดึงจาก | หมายเหตุ |
| --- | --- | --- |
| แจ้งเตือนของฉัน | `items` ที่หน้า /dashboard โหลดอยู่แล้ว | ไม่เพิ่ม request · เอาเฉพาะที่ยังไม่อ่านและไม่ถูก snooze |
| งานย่อยที่ฉันรับผิดชอบ | `/api/creative-tasks/my-subtasks` | ไม่มีสิทธิ์ `tasks.view` = ข้ามแหล่งนี้เงียบ ๆ ไม่ทำให้หน้าพัง |
| เดดไลน์ทุกแผนก | `/api/calendar/events` (14 วันข้างหน้า) | ผลิต / ของเข้า / QC / ใบวางบิล / ขาย / Design / งาน |
| พิมพ์เอง | ช่องกรอกในกล่องงานเข้า | `source_type = manual` |

งานที่ปักเข้าแผนแล้วจะหายจากกล่องงานเข้าอัตโนมัติ (เทียบด้วย `plannedKeys()`)

## ตัวอย่างใช้ของกลางจากโมดูลอื่น

ปุ่ม "➕ ใส่แผนงานฉัน" ที่ไหนก็ได้ — ไม่ต้องรู้เรื่องตารางหรือ API:

```ts
import { addToPlan } from "@/lib/planner-client";

await addToPlan({
  title: `อนุมัติ ${pr.doc_no}`,
  bucket: "today",
  source_type: "notification",   // manual | notification | task | subtask | calendar
  source_id: pr.id,
  link: `/purchasing/pr/${pr.id}`,
  module: "purchasing",          // ใช้เลือกสีป้ายระบบ (lib/dashboard-systems)
  due_at: pr.due_at,
});
```

ปักซ้ำใบเดิมไม่พัง — API กรองให้ และมี unique index กันอีกชั้น

## สิทธิ์ / audit

- **ไม่ผูกกับ permission ของโมดูลไหน** — แค่ล็อกอินก็ใช้ได้ (เป็นข้อมูลของตัวเอง)
- API ใช้ token ของผู้ใช้ (`supabaseFromRequest`) ให้ RLS กรอง — **ไม่ใช้ service-role** ที่ bypass RLS
- **ไม่เขียน audit log**: แผนส่วนตัวไม่ใช่ข้อมูลบริษัท ไม่มีคนอื่นเห็นหรือแก้ได้ การล็อกทุกครั้งที่ลากการ์ดจะทำให้ `audit_logs` รก
- widget "แผนวันนี้" โชว์เฉพาะ scope "ของฉัน" และซ่อนตัวเองเมื่ออยู่ในมุมมองแผนงาน (ไม่ซ้ำกับบอร์ด)

## ข้อจำกัดที่รู้อยู่ (เฟส 1)

- ยังไม่มีมุมมองสัปดาห์ 7 วัน และช่องเวลารายชั่วโมง (time block)
- ติ๊กเสร็จในแผน **ไม่** ไปปิดงานจริงในระบบต้นทาง (ตั้งใจ — กันเปลี่ยนสถานะเอกสารจริงโดยไม่ตั้งใจ)
- ปุ่ม "ใส่แผนงานฉัน" ยังไม่ได้ไปแปะในโมดูลอื่น (ของกลางพร้อมแล้ว รอเลือกจุดที่จะแปะ)
- แผนของทีม (หัวหน้าเห็นของลูกทีม) ยังไม่ทำ — โครงตารางรองรับได้ แต่ต้องเพิ่ม policy + permission ใหม่
