# ไลน์บริษัท (LINE OA ตัวเดียว · พนักงาน + ลูกค้า)

> เจ้าของเลือก 2026-11-21: บัญชีเดียว เมนูล่างจอต่างกันตามคน · ตัวเงินไม่พิมพ์ในแชต · HR มีปุ่มเปิดให้ดูสลิป · ลูกค้าผูกด้วยลิงก์เชิญรายร้าน (ร้านเดียวหลายคน) · แชทที่บอทตอบไม่ได้ → ห้องแชทรวม /chat · ไม่ส่งแจ้งเตือนอัตโนมัติ (ตอบเมื่อถาม = ฟรี) · ลูกค้าไม่เห็นราคา

## ใช้ทำอะไร
คนทักไลน์บริษัทแบบตัวต่อตัว → ระบบรู้เองว่าเป็น **แอดมิน / พนักงาน / ลูกค้า / ยังไม่ผูก** → เห็นเมนูล่างจอคนละชุด → กดปุ่มแล้วบอทตอบทันที (ตอบกลับ = ไม่กินโควตา)

## ใครเห็นอะไร
- **พนักงาน** — บอทตอบเอง · ข้อความไม่เข้าห้องแชทรวม · ลาออก/ระงับ = เมนูกลาง ไม่ตอบ
- **ลูกค้า / ไม่รู้จัก** — ข้อความเข้าห้องแชทรวมให้คนตอบ (บอทไม่แย่งโทเคนตอบกลับฟรี) · กดปุ่มได้คำตอบจากบอท
- กดปุ่มจากเมนูเก่าที่ค้างในเครื่อง (เช่น เพิ่งถูกถอนผูก) → ตรวจสิทธิ์ใหม่ทุกครั้ง ไม่ให้ข้อมูล

## พนักงานลาออก / ปิดใช้งาน (ความปลอดภัย)
- **ฐานข้อมูลปลดผูกไลน์ให้ทันที** ทุกทางที่เปลี่ยนสถานะ (ฟอร์มพนักงาน · สัญญาหมด · ปิดช่างจากบอร์ด · แก้ตรง) — trigger `employees_left_unlink_line` (migration 202612220200): `line_memberships` → unlinked (เก็บแถว) · ล้าง `employees.line_*` · ลง audit `unlink_line_on_resign`
- โค้ดสลับเมนูล่างจอเป็นเมนูกลางต่อ (`syncCompanyMenuForEmployees` — เรียกใน `syncUserAccountOnEmploymentChange`, `lib/payroll-contract-lifecycle`, ปิดช่างใน `/api/mo/assignees`)
- ตัวแยกคนยังเช็กสถานะพนักงานทุกครั้งอีกชั้น (ลาออก = ถูกระงับ) แม้ทางใดหลุด
- กลับมาทำงาน = ไม่ผูกคืนเอง → HR พิมพ์บัตร QR ใบใหม่ (บัตรเก่าใช้ไม่ได้)
- เก็บกวาดครั้งแรก 2026-11-21: HR-001 (ลาออกแล้วยังผูกค้าง) ปลดผูกแล้ว
- ตัวเดียวกัน **ปิดบัญชีล็อกอิน ERP** (`user_profiles.active=false` → `erp_can` ปฏิเสธทุกสิทธิ์) ทุกทาง (migration 202612220300) — เดิมปิดเฉพาะตอนแก้ฟอร์มพนักงาน สัญญาหมด/ปิดช่างจากบอร์ดหลุด · ลง audit `deactivate_user_on_resign` · กลับมาทำงานแอดมินเปิดเอง

## ตั้งค่าครั้งแรก (เจ้าของทำ)
1. สร้าง LINE OA ใน LINE Developers **ใต้ Provider เดียวกับ LINE Login ของระบบ (ISG · 2010621559)** — ต่าง Provider = รหัสคนไม่ตรง ระบบจำพนักงาน/ลูกค้าไม่ได้
2. ศูนย์ LINE → บอท → เพิ่มบอท (โทเคน + Channel secret) → คัดลอก Webhook ไปวางใน LINE Developers + เปิด Use webhook
3. LINE OA Manager → ตั้งค่าการตอบกลับ: ปิดข้อความตอบกลับอัตโนมัติ/ข้อความทักทายของ LINE (ไม่งั้นตอบซ้อนกับบอท) · เปิด Webhook
4. ศูนย์ LINE → ไลน์บริษัท → เลือกบอท → กด "สร้างเมนูล่างจอ"

## ย้อนกลับ / แก้ไข / ลบ
- เลิกใช้: เลือก "ยังไม่ใช้" → ถอดเมนูของไลน์บริษัทออก บอทกลับไปทำงานแบบเดิม (แชทลูกค้าเข้าห้องแชทรวมตามติ๊กในหน้าตั้งค่าแชท)
- ลูกค้า: ถอนผูก (เก็บแถวไว้ · กด "ย้อนกลับ" ได้ 5 วิ) · ระงับ/คืนสิทธิ์ · แก้ชื่อเรียก
- พนักงาน: ปลดผูก/ระงับที่ `/payroll/line-members` (ของเดิม)
- แก้ปุ่มเมนู: ศูนย์ LINE → ไลน์บริษัท → ปุ่มเมนู (ชื่อ/คำอธิบาย/ลาก/ซ่อน/เอาออก/เพิ่ม · ดูรูปจริงก่อนบันทึกได้) → บันทึก → "สร้างเมนูในไลน์ใหม่" · ปุ่มใหม่ที่ยังไม่มีในรายการ = เพิ่มใน `COMPANY_ACTIONS` + `companyReplyText`

## ข้อจำกัดที่รู้
- ปุ่มที่ยังไม่มีงานจริง (สลิป/งานเหมา/ออเดอร์ ฯลฯ) ตอบว่า "เปิดใช้ในรอบถัดไป" จนกว่าจะถึงเฟสนั้น
- ผู้ใช้ ERP ที่ผูกไลน์ผ่าน `/account/line` (user_profiles) ยังไม่นับเป็นพนักงานในไลน์บริษัท — ต้องผูกผ่านบัตร QR พนักงาน
- โควตา: ปุ่ม/ตอบกลับไม่กินโควตา · พนักงานตอบลูกค้าช้าเกิน ~1 นาทีในห้องแชทรวม = push (กินโควตา)

| รายร้าน | ให้ร้านนั้น | เห็นชื่อร้าน → ยืนยัน → ผูกทันที (linked_via shop_qr) |

## หน้าเล็กของพนักงานในไลน์ (รอบ 3)

ปุ่ม **เงินเดือน · ใบเตือน · งานเหมาของฉัน** ในเมนูพนักงาน = เปิดหน้าเล็ก (LIFF `/a?me=payslip|warning|piecework`) ทันที ไม่ต้องรอบอทตอบ
(เมนูเก่าที่ยังเป็นปุ่ม postback → บอทตอบลิงก์หน้าเล็กให้ · ตัวเงินไม่พิมพ์ในแชตเด็ดขาด)

- **ตัวตน:** ตรวจ id_token ของ LINE ใหม่ทุกครั้งที่เปิด → หาไลน์นี้ใน `line_memberships` (ผูกอยู่ + ยังทำงาน) · ไม่รับรหัสพนักงานจากหน้าเว็บ
- **ต้อง HR ยืนยันตัวตนก่อน** (ผูกด้วยรหัส+เบอร์) ทั้ง 3 หน้า · ยังไม่ยืนยัน = เห็นข้อความ "รอฝ่ายบุคคลยืนยันตัวตน"
- **เงินเดือน:** เห็นเฉพาะงวดที่ HR กด "เปิดให้ดูในไลน์" (การ์ด "สลิปในไลน์บริษัท" หน้า `/payroll/line-members` · ช่อง `payroll_periods.line_visible_at`) · ตัวเลขตามกติกาสลิปกระดาษ: ไม่โชว์เงินเดือน, รวมรายได้ = บรรทัดที่เห็น, ยอดสุทธิไทยเข้ารหัส · สลิปที่ยกเลิก (voided) ไม่โชว์
- **ใบเตือน:** `employee_warnings` ของตัวเอง · revoked = โชว์จาง "ยกเลิกแล้ว"
- **งานเหมา:** ใบจ่ายงานที่ยังทำอยู่ + ใบที่สร้างใน 120 วัน ที่ลงชื่อเป็นช่างหลักหรือช่างร่วม (`mo_work_orders.assignee_id` / `assignees`) + ค่าแรงที่ลงแล้วจาก `wo_submissions` (นับรอบที่ลงชื่อตัวเอง · รอบไม่มีชื่อนับเฉพาะใบที่ทำคนเดียว)
- ทุกการเปิดดู ลงประวัติ `line_self_view` · เปิด/ปิดสลิปของ HR ลงประวัติ `payroll_line_payslip_open/close` (ค่าเดิม→ใหม่) · ย้อนกลับได้จากแจ้งผลมุมจอ
- โค้ด: `lib/line-self-view.ts` (กติกา) · `lib/line-self-view-server.ts` · `app/api/employee-line/self` · `app/a/self-view.tsx` · `app/api/payroll/line-payslip-periods`
- **ปุ่มเมนูเปลี่ยนเป็นเปิดหน้าเล็ก** ต้องกด "สร้างเมนูในไลน์" ใหม่ 1 ครั้ง (เมนูที่สร้างก่อนรอบ 3 ยังเป็น postback — ใช้ได้ แต่ต้องกดลิงก์อีกที)

## หน้าเล็กของลูกค้าในไลน์ (รอบ 4)

ปุ่ม **เช็คสถานะงาน · ตารางส่งงาน** ในเมนูลูกค้า = เปิดหน้าเล็ก `/a?me=orders|schedule` (แท็บสลับกันได้) · **ไม่มีราคา/ยอดเงิน/ชื่อช่างเด็ดขาด**

- **ร้าน:** ตรวจ id_token ใหม่ทุกครั้ง → `line_customer_links` (linked + ร้านยังใช้งาน) · รอยืนยัน (pending) = "รอพนักงานยืนยันร้าน" · ไม่รับรหัสร้านจากหน้าเว็บ
- **สถานะงาน:** ใบสั่งขาย `so_orders` ของร้าน (ไม่ยกเลิก · ไม่ถูกรวม · ส่งแล้วย้อนหลัง 90 วัน) · ขั้นต่อรายการใช้กติกาเดียวกับหน้าสถานะใบสั่งขาย (`soLineProgress` + `loadMoDispatch` + `soLineStageMulti`) แต่เรียกชื่อแบบลูกค้า: รับออเดอร์แล้ว → เตรียมผลิต → กำลังผลิต → ผลิตเสร็จ รอส่ง → ส่งแล้ว · มีรูปสินค้า (รูปปก SKU)
- **ตารางส่งงาน:** ปฏิทินกลาง `DocCalendar` + รายการตามวัน · เฉพาะรายการที่ยังส่งไม่ครบ · วันนัดส่ง = รายการ → หัวใบ → ใบสั่งผลิต (ช้าสุด · ติด "~" = ประมาณ) · เลยนัด = แดง · ไม่มีวันนัด = นับแยก

## หน้าจัดการ LINE (/admin/line)

เจ้าของเลือก 2026-11-22: แบบ A (หน้าเต็มมีแท็บ) + ข้อ 1-5 · เมนู "จัดการ LINE" แอปตั้งค่า (⚙️ Settings) เห็นเฉพาะแอดมิน (admin.users)
- แถบตัวเลข: ผูกไลน์แล้ว (พนักงาน/ลูกค้า/แอดมิน) · รอ HR ยืนยัน · รอยืนยันร้าน · โควตาเดือนนี้ (บอทไลน์บริษัท)
- แท็บ ภาพรวม (เช็กลิสต์ตั้งค่าครั้งแรก 4 ขั้น + ทางลัด + ล่าสุด) · ไลน์บริษัท (`LineCompanySection part="setup"`) · บอทและกลุ่มแจ้งเตือน (`LineConsoleBody showCompany={false}`) · คนที่ผูกไลน์ (`part="people"`) · ประวัติ (audit_logs · `lib/line-history`)

- ป๊อปศูนย์ LINE เดิมใช้ชิ้นเดียวกัน (แก้ที่เดียว) + มีลิงก์ "เปิดหน้าเต็ม"
- เช็กลิสต์ขั้น 3 (LINE Developers) ตรวจตรงไม่ได้ → ติ๊กเองเมื่อมีคนสแกน QR ไลน์บริษัทสำเร็จครั้งแรก

## สแกน QR = เพิ่มเพื่อนก่อน แล้วค่อยยืนยัน (2026-11-23)

เจ้าของเลือก: บังคับเพิ่มเพื่อนก่อน · QR แยก 3 ใบ + รายร้าน · ไม่มีข้อความต้อนรับแบบมีปุ่ม
- หน้าสแกน (`app/a/company-qr-view.tsx`) เช็ก `liff.getFriendship()` → ยังไม่เป็นเพื่อน = หน้า "1 เพิ่มเพื่อน → 2 ยืนยัน" (ปุ่มเพิ่มเพื่อน `line.me/R/ti/p/@basic_id` + ปุ่ม "เพิ่มเพื่อนแล้ว ไปต่อ" · กลับมาหน้านี้เช็กใหม่เอง) · เช็กไม่ได้ (LINE Login ยังไม่ผูกกับบัญชีไลน์บริษัท) = ไม่บล็อก
- เหตุ: หน้า "เพิ่มเพื่อน" ของ LIFF (Add friend option) เด้งแค่ครั้งแรกที่คนนั้นอนุญาต LIFF และกดข้ามได้
- ปุ่มเมนูคนที่ยังไม่ผูก "ฉันเป็นพนักงาน / ฉันเป็นลูกค้า" = เปิดหน้ายืนยันทันที (`?cq=menu.staff|menu.customer` · ไม่ผูกเลขรุ่น QR · แอดมิน/รายร้านไม่มีแบบ menu) — ต้องกด "สร้างเมนูในไลน์" ใหม่ 1 ครั้ง

## แต่งเมนูไลน์ + ร้านค้าในไลน์ (2026-11-23 · เจ้าของเลือกข้อ 2.1-2.3 + 3.1-3.4)
