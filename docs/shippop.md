## 1. สรุปสั้น (ภาษาคน)

- **ระบบส่งของผ่าน SHIPPOP สร้างไว้แล้วเกือบครบ** ทั้งเว็บร้าน (ต.ค.) และศูนย์ออเดอร์ (พ.ย. ขั้น 1) — ตอนนี้ทำงานแบบ "จำลอง" ทุกปุ่ม ได้เลข `SIM…` ไม่เสียเงิน
- กุญแจมาเมื่อไหร่ = ใส่ค่าใน Vercel 4 ตัว (หัวข้อ 7) → เว็บร้านใช้ของจริงทันที (โหมดทดลอง sandbox ไม่เสียเงิน) · ศูนย์ออเดอร์ยังล็อกจำลองไว้จนเจ้าของสั่งเปิด
- **ช่องโหว่ที่ต้องแก้ก่อนเปิดจริง** (หัวข้อ 5): สถานะอัตโนมัติจาก SHIPPOP ยังไม่อัปเดตออเดอร์ในศูนย์ออเดอร์ · ขนาดกล่องยังไม่ดึงจากสินค้า · ยังไม่บันทึกค่าส่งลงศูนย์ค่าใช้จ่าย · ใบปะหน้ามีแบบเดียว
- ⚠️ **ความจริงที่ต้องรู้**: ออเดอร์ 60 วันล่าสุด **ทั้งหมดเป็น Shopee / Lazada / TikTok** (7,226 ใบ) ซึ่งต้องใช้ขนส่งของแพลตฟอร์ม → SHIPPOP ใช้ได้กับ **ออเดอร์ที่ร้านขายเอง** เท่านั้น (แชต LINE/FB/IG · LINE SHOPPING · เว็บ · โทร/หน้าร้าน) ซึ่ง **ยังไม่มีใครกรอกเข้าระบบเลย** (ออเดอร์สร้างเอง 0 ใบ · เว็บร้าน 0 ใบใน 60 วัน) → ประโยชน์ของ SHIPPOP ขึ้นกับว่าทีมจะกรอกออเดอร์แชตเข้าระบบหรือไม่

## 3. คู่มือ API (สรุป)

แหล่ง: Postman "SHIPPOP API Documentation" (developers.shippop.com) — ดึงครั้งแรก 2026-10-22 · ตรวจซ้ำ 2026-11-19 (ผลอยู่หัวข้อ 3.9)

### 3.1 การยืนยันตัว + ที่อยู่ระบบ
- ส่ง `api_key` ในตัวข้อความ (POST JSON) ทุกคำขอ · จองต้องมี `email` บัญชี SHIPPOP ด้วย
- ทดลอง (sandbox) `https://mkpservice.shippop.dev` · จริง `https://mkpservice.shippop.com`
- กุญแจขอที่ shippop.com/business (ติ๊ก "รับ API KEY") → ได้กุญแจทดลองทางอีเมลก่อน

### 3.2 ลำดับงาน
1. `/pricelist/` ดูราคาทุกขนส่ง (`showall: 1`) — ที่อยู่ผู้ส่ง/ผู้รับ + พัสดุ (น้ำหนัก **กรัม** · กว้าง/ยาว/สูง **ซม.**)
2. `/booking/` จอง (หลายพัสดุในใบเดียว) → `purchase_id` + `tracking_code` (SP…) + ราคา
3. `/confirm/` ยืนยัน = ส่งข้อมูลให้ขนส่ง → `courier_tracking_code` · **หลังยืนยันแก้ไม่ได้**
4. `/label/` หรือ `/label_tracking_code/` ใบปะหน้า (html/pdf · ขนาดดูหัวข้อ 3.9)
5. `/tracking/` ถามสถานะ · webhook = SHIPPOP ยิงมาหาเรา
6. `/cancel/` ยกเลิก (ด้วย courier_tracking_code) — ได้เฉพาะก่อนขนส่งเข้ารับ

### 3.3 ที่อยู่
`name · address · district (ตำบล/แขวง) · state (อำเภอ/เขต) · province · postcode · tel`

### 3.4 สถานะ
`wait` รอยืนยัน · `booking` ยืนยันแล้วรอเข้ารับ · `invalid` ข้อมูลผิด · `shipping` กำลังส่ง · `package_detail` ขนส่งแจ้งน้ำหนักจริง · `problem` มีปัญหา · `complete` ถึงแล้ว · `return` ตีกลับ · `cancel` ยกเลิก · `pending_transfer` รอโอนเงินปลายทาง · `transferred` โอนเงินปลายทางแล้ว

### 3.5 Webhook
SHIPPOP POST `tracking_code, order_status, courier_tracking_code, data[datetime], data[message]` · **ไม่มีลายเซ็น** → เรากัน 2 ชั้น (รหัสลับใน URL + ถาม `/tracking/` ซ้ำเอง) · ตอบ `{"success":1}` ไม่งั้นส่งซ้ำ

### 3.6 ขนส่ง (รหัสที่ระบบรู้จัก)
EMST (ไปรษณีย์ EMS) · ECP (eCo-post) · FLE (Flash) · FLEB (Flash ของใหญ่) · KRYX (KEX) · JNTP (J&T) · BEST · SPX · DHL · LLM (Lalamove)

### 3.7 เก็บเงินปลายทาง (COD)
ส่ง `cod_amount` ตอนจอง · บัญชี SHIPPOP ต้องยืนยันตัวตน + บัญชีธนาคารก่อน · สถานะเงิน `pending_transfer` → `transferred`

### 3.8 เรียกเข้ารับ / แก้น้ำหนัก
`/calltopickup/` เรียกขนส่งเข้ารับ · `/update/` แก้น้ำหนักหลังจอง (เฉพาะบางเจ้า) — ระบบยังไม่ใช้ทั้งคู่

### 3.9 ผลตรวจซ้ำกับคู่มือ (2026-11-19)
แหล่ง: Postman "SHIPPOP APIs" (เผยแพร่ 2024-02-05) — developers.shippop.com → documenter.getpostman.com/view/10021496/Tzz8qwkE · ไม่มี SDK ทางการ

✅ ตรงกับโค้ดเดิม: ที่อยู่ระบบ 2 ตัว · `api_key` ในตัวข้อความ · จองต้องมี `email` · ช่องที่อยู่/พัสดุ · `/pricelist/` · `/booking/` ส่ง data เป็นรายการ ได้ผลกลับเป็นก้อนเลข "0","1" (โค้ดอ่านถูกแล้ว) · `/confirm/` ผลอยู่ใน `result` (โค้ดอ่านถูกแล้ว · บางใบสำเร็จบางใบพลาดได้) · `/tracking/` ไม่ต้องใช้ api_key · `/cancel/` · `/update/` (Flash เท่านั้น) · webhook ไม่มีลายเซ็น

❗ ต่างจากที่โค้ดคิด / ข้อมูลใหม่:
1. **COD ต้องส่งรายการสินค้า `product[]`** ทุกพัสดุ (คู่มือบอกว่าบังคับ) — โค้ดเดิมไม่ส่ง → จองแบบเก็บปลายทางน่าจะพัง
2. **รหัสขนส่ง**: ตารางทางการ = SHF, EMST, DHL, FLE, FLEB, FLEF, FLEDS, BEST, ARM, KRYX, KRYS, KRYDS, JNTP, JNTD, LZDS, MSE/MSEC/MSEF (Makesend), SPX, LLM, SKT · เจอในตัวอย่าง: THP (ไปรษณีย์ลงทะเบียน), EMSX · **`ECP` ไม่มีในคู่มือ** (โค้ดเดิมมี) → เปลี่ยนเป็น THP · รหัสลงท้าย DS + KRYS = ต้องเอาไปส่งที่จุดเอง
3. **ใบปะหน้า**: ขนาด A4 · A5 · A6 · letter · letter4x6 · sticker (8×8) · sticker4x6 (≈100×150) · ไม่มีชื่อ "100x150" · แบบ html / pdf (base64 ในช่อง `pdf`) / json · ตัวเลือก `showproduct` (เฉพาะ 4×6) `logo` `hide_information`
4. **สถานะ cancel ไม่ใช่จุดจบเสมอ** — หลังยืนยัน ถ้าส่งข้อมูลให้ขนส่งพลาด SHIPPOP ส่ง `cancel` ชั่วคราวแล้วลองใหม่เอง ตามด้วย `booking` → ห้ามปลดล็อกให้จองซ้ำทันทีที่เห็น cancel จาก webhook
5. **Webhook**: ส่งแบบ form-urlencoded (โค้ดรองรับแล้ว) · มี `data[code]` รหัสปัญหา PB01–PB21 · `data[cod_amount]` · น้ำหนักจริง/ค่าส่งเพิ่ม · **ส่งซ้ำ 12 ครั้งเฉพาะเมื่อเราตอบ 5xx** (4xx ไม่ส่งซ้ำ) · **ลงทะเบียน URL ด้วยการทักทีม dev SHIPPOP ทาง LINE** (ไม่มีหน้าตั้งค่าเอง)
6. **สถานะเพิ่ม**: return_shipping · return_problem · return_complete · return_return · return_close · rider_accept · wait = "ยังไม่จ่าย" · booking = "จ่ายแล้ว"
7. **เรียกเข้ารับ**: ขนส่ง **เข้ารับอัตโนมัติทุกเจ้า ยกเว้นไปรษณีย์ EMS (EMST/EMSX)** · `/calltopickup/` ใช้กับ EMS (ต้องระบุเวลา) หรือเรียก Flash ซ้ำ (ภายใน 2 วัน)
8. **การจ่ายเงิน**: ไม่มี API ดูยอดเงินคงเหลือ · บัญชีแบบ **เติมเงินก่อน (PREPAID) การจองจะได้ `payment_url` ให้ไปจ่ายก่อน** · บัญชีธุรกิจ = วางบิลเครดิต → ⚠️ ต้องขอ SHIPPOP เป็นบัญชีแบบวางบิล ไม่งั้นจองผ่าน API ไม่จบในคลิกเดียว
9. **COD**: `cod_amount` จำนวนเต็ม · ค่าธรรมเนียมต่างกันต่อเจ้า (ราคาส่งกลับใน `price_cod` + `price_cod_vat`) · ต้องยืนยันตัวตน + บัญชีธนาคาร (`/member/` ดู `isConfirmedCod`) · ดูเงินโอนได้ทาง `/report-cod/` `/report-cod/summary/` `/report-cod/transfer/date/`
10. ตัวเลือกจองอื่น: `force_confirm` (ยืนยันในขั้นเดียว) · ประกัน `insurance_code` + `declared_value` · `meta.ref_no_1/2` · พัสดุมี `use_box_calculation` · มี API ตั้งกล่องสำเร็จรูป `/box-setting/`
11. ไม่พบในคู่มือ: เพดานคำขอต่อนาที · พฤติกรรม sandbox (เลขพัสดุปลอม/ขนส่งทดสอบ) → ⚠️ ต้องลองกับกุญแจทดลอง · ค่าบริการ API: เปิดบัญชีฟรี ไม่ระบุรายเดือน ราคาส่งต่อรองตามปริมาณ
12. API ที่ยังไม่ใช้แต่มี: รายงานส่งสำเร็จ/ค่าส่ง/บิล · ปัญหาพัสดุ + ตอบกลับ · ข้อมูลขนส่ง (น้ำหนักสูงสุด เวลาเข้ารับ %COD) · Flash drop-off · ส่งต่างประเทศ (Crossborder v2)

| G6 | จองแล้วยืนยันทันที | กดพลาด = เสียเงินเลย ยกเลิกได้แค่ก่อนเข้ารับ | ป๊อปยืนยันบอกยอดรวม + "ยกเลิกได้จนกว่าขนส่งมารับ" |
| G7 | ไม่มีเรียกเข้ารับ / ตารางเงินปลายทาง | ต้องเข้าเว็บ SHIPPOP เอง | เฟส 3 |

| G9 | จอง COD ไม่ส่ง `product[]` | ออเดอร์เก็บปลายทางจองไม่ผ่าน | ส่งรายการสินค้า (ชื่อ/จำนวน/ราคา) จากรายการในออเดอร์ |
| G10 | webhook `cancel` ถูกถือว่าจบ → ปลดให้จองซ้ำได้ | อาจจองซ้ำ = จ่ายค่าส่ง 2 ครั้ง | cancel ที่มาจาก webhook = "รอตรวจ" ไม่ปลดล็อก · ปลดเฉพาะยกเลิกที่เรากดเองและ SHIPPOP ตอบสำเร็จ |
| G11 | รหัส `ECP` ไม่มีในคู่มือ · ขาดสถานะ return_* | เลือก ECP แล้วจองพลาด · สถานะตีกลับขึ้นเป็นรหัสดิบ | เปลี่ยนเป็น THP · เพิ่มป้ายสถานะ · ขนส่งแบบ drop-off บอกว่า "ต้องเอาไปส่งเอง" |
| G12 | webhook ตอบ 200 แม้บันทึกพลาด | สถานะหายเงียบ | ตอบ 5xx เมื่อฐานข้อมูลพลาด (SHIPPOP จะส่งซ้ำให้) |

## 6. แผนทีละขั้น

### เฟส 1 — พร้อมเปิดเมื่อกุญแจทดลองมา ✅ ทำแล้ว 2026-11-19 (เจ้าของ "ทำเฟส 1 เลย")
ทำแล้ว: ชั้นกลาง `lib/shipping/provider.ts` + `shippop.ts` · `lib/shipping/cost.ts` (บันทึกค่าส่ง) · `lib/shipping/order-status-db.ts` (สถานะเข้าศูนย์ออเดอร์) · webhook ดู 2 ตาราง + ตอบ 503 เมื่อพลาด · กล่องจากสินค้า · สวิตช์ `orderCenterShippingForce` · ป๊อปยืนยันก่อนจอง (บอกยอด + ยกเลิกได้ถึงเมื่อไหร่) · ขนส่งตั้งต้น = ของแบรนด์ → ที่ใช้ล่าสุดในเครื่อง → ถูกสุด · COD ส่งรายการสินค้า · ECP→THP · ป้ายสถานะตีกลับ · เลือกขนาดใบปะหน้าในหน้าพิมพ์ (จำต่อเครื่อง) · บัญชีเติมเงินก่อน = แจ้งชัด · เทสต์ `lib/__tests__/shipping-phase1.test.ts`
ยังไม่ทำ: ข้อ 4 (ทดสอบกับกุญแจจริง — รอ SHIPPOP) · สถานีแพ็กพิมพ์ใบปะหน้าต่อทันที (รอ session สถานีแพ็ก) · เว็บร้านยังเรียก `lib/shippop` ตรง (ใช้ ECP→THP/บันทึกค่าส่ง/ขนาดใบปะหน้าแล้ว)
1. ชั้นกลาง `lib/shipping/provider.ts` — แบบฟอร์มกลาง `quote / book / label / track / cancel` + ตัวเสียบ `lib/shipping/shippop.ts` (ห่อ `lib/shippop.ts` เดิม ไม่รื้อ) · ลงทะเบียน `lib/shared-parts-registry.ts`
2. แก้ G1 webhook ดูทั้ง 2 ตาราง · G2 กล่องจากสินค้า · G3 สวิตช์ sandbox/จริง · G4 บันทึกค่าส่ง · G6 ป๊อปยืนยัน · G9 COD ส่งรายการสินค้า · G10 cancel ไม่ปลดล็อก · G11 รหัส/สถานะ · G12 webhook ตอบ 5xx
3. เทสต์: กติกากล่อง/น้ำหนัก · webhook หาออเดอร์ทั้ง 2 ตาราง · สวิตช์ห้ามเรียก prod ถ้ายังไม่เปิด
4. ตรวจกับกุญแจทดลอง: ดูราคา → จอง → ใบปะหน้า → ยกเลิก (sandbox ไม่เสียเงิน) แล้วเติมหัวข้อ 3.9

### เฟส 2 — หน้าจอ (ตามที่เจ้าของเลือกใน widget)
- เทียบราคาต่อขนส่ง (ถูกสุด/เร็วสุด) · จองหลายใบ · พิมพ์ใบปะหน้าทีละชุด · สถานะพัสดุในลิ้นชักออเดอร์ (ไทม์ไลน์)
- ทำทั้ง PC + มือถือ

### เฟส 3 — ต่อยอด
- เรียกเข้ารับ (`/calltopickup/`) · ตารางเงินปลายทาง (ยอดที่ต้องได้ vs ได้แล้ว) · รายงานค่าส่งรายเดือน
- ดึงออเดอร์ LINE SHOPPING เข้าระบบ (ถ้า API เปิดให้) แล้วส่ง SHIPPOP ได้ตรง

### แก้ไข · ย้อนกลับ · ลบ (§46 Step 4.1)
- **แก้**: ที่อยู่ผู้รับ/น้ำหนัก/กล่อง แก้ได้ก่อนจอง · ผู้ส่งต่อแบรนด์แก้ได้ทุกเมื่อ
- **ย้อน**: ยกเลิกการจองได้ **เฉพาะก่อนขนส่งเข้ารับ** (สถานะ `booking`) — หลังรับพัสดุแล้ว **ยกเลิกไม่ได้** (ต้องติดต่อ SHIPPOP/ขนส่งเอง) → ป๊อปยืนยันต้องบอกก่อนกด
- **ลบ**: การจองไม่ลบจริง เก็บประวัติ (`shipping.history`) + audit ทุกครั้ง (จอง/ยกเลิก/สถานะ)

## 7. ใส่กุญแจตรงไหน (เจ้าของทำเอง · ห้ามส่งกุญแจในแชต)

Vercel › โปรเจกต์ ERP › Settings › Environment Variables (Production):

| ชื่อ | ค่า |
|---|---|
| `SHIPPOP_API_KEY` | กุญแจที่ SHIPPOP ส่งมา |
| `SHIPPOP_EMAIL` | อีเมลบัญชี SHIPPOP |
| `SHIPPOP_ENV` | **ไม่ต้องตั้ง** ตอนทดลอง (= sandbox) · ตั้ง `prod` เมื่อได้กุญแจจริง |
| `SHIPPOP_WEBHOOK_SECRET` | ตั้งรหัสสุ่มยาว ๆ เอง (ไม่ต้องส่งให้ใคร) |
| `SHIPPOP_ORDER_CENTER_LIVE` | **ไม่ต้องตั้ง** ตอนทดลอง · ตั้ง `1` เมื่อพร้อมให้ศูนย์ออเดอร์จองจริง (เสียเงิน) หลังได้กุญแจจริง — ไม่ตั้ง = ศูนย์ออเดอร์จำลองต่อแม้ใส่กุญแจจริงแล้ว |

ถาม SHIPPOP ตอนเขาติดต่อกลับ: (1) ขอเป็นบัญชีแบบ **วางบิลเครดิต** (ไม่ใช่เติมเงินก่อน) (2) เปิด COD + ยืนยันตัวตน/บัญชีธนาคาร (3) ขนส่งที่ต้องการใช้ + ราคาตามปริมาณ (4) sandbox ให้เลขพัสดุปลอมไหม

แล้วทักทีม dev SHIPPOP ทาง LINE ให้ตั้ง Webhook URL = `https://erp-platform-playground.vercel.app/api/public/shippop/webhook?k=<SHIPPOP_WEBHOOK_SECRET>`
ใส่ค่าแล้วต้องรอขึ้นเว็บรอบถัดไป (หรือกด "ขึ้นเว็บทันที") ค่าใหม่ถึงมีผล

⚠️ ใส่กุญแจทดลองแล้ว **เว็บร้านและศูนย์ออเดอร์จะเรียกระบบทดลองของ SHIPPOP ทันที** (ไม่เสียเงิน · ป๊อปจองขึ้นแถบฟ้า "ระบบทดลอง") · **ห้ามจองจริงด้วยกุญแจจริงโดยไม่ได้รับคำสั่งเจ้าของทีละครั้ง**

ก่อนใช้งาน: ตั้ง "ผู้ส่ง" ต่อแบรนด์ในศูนย์ออเดอร์ (ปุ่ม ตั้งค่าการส่ง) — ตอนนี้ 0 แบรนด์
