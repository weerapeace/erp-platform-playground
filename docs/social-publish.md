# 📤 ระบบโพสต์โซเชียลอัตโนมัติ (Social Publish)

## ใช้ทำอะไร
ให้ระบบโพสต์คอนเทนต์ขึ้นแพลตฟอร์มให้เอง — กด "โพสต์เลย" หรือ **ตั้งคิวให้ระบบโพสต์ตามเวลา** (ไม่ต้องเปิดเครื่องรอ)

| แพลตฟอร์ม | รูปแบบที่ยิงได้ | ตั้งคิวได้ |
|---|---|---|
| Facebook | โพสต์รูป/อัลบั้ม/ข้อความ · วิดีโอ · **Reels** · Story | ✅ |
| Instagram | รูป/อัลบั้ม · Reels · Story | ✅ (แอป IG เองตั้งเวลาให้ระบบภายนอกไม่ได้ — คิวของเราทำแทน) |
| X | โหมดมือ (เปิดหน้า X เติมข้อความ) — เจ้าของเลือกไม่ใช้ API เพราะคิดเงินต่อโพสต์ | – |
| YouTube / Pinterest / TikTok | ยังไม่ทำ (ก้อน 2–4) | – |

## โครงสร้าง (ของกลาง)
```
ป๊อปโพสต์ / ปุ่ม "ตั้งคิวทุกแพลตฟอร์ม" (drawer คอนเทนต์)
   → POST /api/social-publish/jobs        → lib/social-publish/queue.enqueueJobs  (ตรวจครบก่อน ไม่ผ่าน = ไม่ตั้งเลย)
   → ตาราง social_publish_jobs (1 แถว = คอนเทนต์ × แพลตฟอร์ม)
pg_cron ทุก 5 นาที (เรียกเว็บเฉพาะตอนมีคิวถึงเวลา)
   → /api/cron/social-publish             → queue.runDueJobs → meta.publishMeta (ตัวเดียวกับปุ่ม "โพสต์เลย")
   → ผลเขียนกลับ erp_creative_content.post_status / posted_links (ช่องเดิม)
```
- `lib/social-publish/meta.ts` — ตัวยิง FB/IG (ปุ่มโพสต์เลย + คิว ใช้ร่วมกัน)
- `lib/social-publish/rules.ts` — กติกาเลือกสื่อตามรูปแบบ + แปล error เป็นภาษาคน (มีเทสต์)
- `lib/social-publish/media.ts` — URL ไฟล์ให้แพลตฟอร์มดึง (รูป → `/api/post-image` แปลง JPEG · วิดีโอ → r2-image / drive-video)
- `lib/social-publish/queue.ts` — ตั้งคิว / ยกเลิก / ลองใหม่ / ใช้แคปชั่นล่าสุด / ตัวเดินคิว
- UI: `app/tasks/content/publish-queue.tsx` (กล่องคิวใน drawer · ป๊อปตั้งคิวทุกแพลตฟอร์ม · ป๊อปภาพรวมในปฏิทิน)

## สถานะคิว
`queued` (รอเวลา) → `running` (กำลังโพสต์) → `posted` · `processing` (IG Reels รอ IG ประมวลผล → เช็กรอบถัดไป) · `failed` · `cancelled`
- สถานะโพสต์บนคอนเทนต์: ตั้งคิว = `scheduled` (⏰) · ล้ม = `failed` (⚠ แดงในปฏิทิน) · สำเร็จ = `posted`
- แคปชั่น/รูป = **ค่า ณ ตอนตั้งคิว** — แก้แคปชั่นทีหลัง กล่องคิวจะเตือน + มีปุ่ม "ใช้แคปชั่นล่าสุด"

## กันพลาด
- จองงานด้วย `social_publish_claim()` (FOR UPDATE SKIP LOCKED) → ตัวเดิน 2 รอบไม่หยิบงานเดียวกัน
- 1 คอนเทนต์ × 1 แพลตฟอร์ม มีคิวค้างได้อันเดียว (unique index) — ตั้งใหม่ = แทนอันเก่า
- งานค้าง `running` > 15 นาที = ตัวเดินพังกลางทาง → **ไม่ยิงซ้ำเอง** (อาจโพสต์ไปแล้ว) ตั้งเป็นล้ม + ให้คนเช็กเพจก่อนกดลองใหม่
- ล้ม → แจ้งเตือนกระดิ่ง (high) ถึงคนตั้งคิว · ปุ่มคิวในปฏิทินขึ้นเลขแดง
- drawer ที่เปิดค้างแล้วกดบันทึก จะไม่ทับผลของคิว (โพสต์แล้ว/ล้ม + ลิงก์)

## สิทธิ์ / Audit
- ดูคิว = `tasks.view` · ตั้ง/ยกเลิก/ลองใหม่ = `tasks.edit` (เหมือนปุ่มโพสต์เดิม)
- audit: `social_publish:queue|cancel|retry|caption|failed` + การโพสต์สำเร็จ (`published_to`, `via: manual|queue`)

## รูป/วิดีโอจาก Google Drive
- drawer › ＋ เพิ่ม/จัดการ › รูปภาพ › วางลิงก์ **ไฟล์** (เพิ่มเลย) หรือ **โฟลเดอร์** (ป๊อปติ๊กเลือกรูป)
- เก็บเป็นไฟล์แนบ `kind=image, url=drive:<fileId>` — ไม่ก็อปลง R2 · `r2ImageUrl("drive:<id>")` → `/api/drive/thumb`
- ต้องแชร์ไฟล์/โฟลเดอร์ให้ service account ของระบบก่อน (ระบบเช็กตอนวางลิงก์ บอกทันทีถ้ายังไม่ได้แชร์)

## ปรับรูปให้พอดีแพลตฟอร์ม (`lib/social-publish/fit.ts`)
- ป๊อปโพสต์ › "🖼 ปรับรูปให้พอดี Instagram": **สัดส่วน** อัตโนมัติ (แก้เฉพาะรูปที่หลุด 4:5–1.91:1) / 4:5 ทุกรูป / 1:1 ทุกรูป · **วิธี** เติมขอบ (ไม่ตัดรูป) / ครอปกลาง · **สีขอบ** ขาว / ดำ / เบลอจากรูป / สีเอง
- Story: ติ๊ก "ปรับ" = ทำเป็น 9:16 · Facebook ฟีด = ไม่ปรับ (FB รับทุกสัดส่วน)
- IG ฟีดที่ไม่ได้เลือกเอง (รวม "ตั้งคิวทุกแพลตฟอร์ม") = ตัวยิงใช้ `DEFAULT_IG_FIT` (เติมขอบขาวเฉพาะรูปที่ไม่ผ่าน) → IG ไม่ปฏิเสธเรื่องสัดส่วน
- ทำที่ `/api/post-image?fit=pad|crop&ar=auto|<ตัวเลข>&bg=white|black|blur|rrggbb` ตอนแพลตฟอร์มดึงรูป — **ไฟล์ในระบบไม่ถูกแก้** · ตัวอย่างในป๊อปเรียกเส้นเดียวกัน (`&w=700`) = เห็นรูปที่จะขึ้นจริง
- ค่าที่เลือกล่าสุดจำต่อแพลตฟอร์มในเครื่อง (localStorage `post-fit-v1:<platform>`)

## ต้นฉบับ (ความคมชัด)
- รูปที่อัปในคอนเทนต์: R2 เก็บรูปย่อ ≤1600px (โชว์เร็ว) + ระบบส่งต้นฉบับเต็มขึ้น Drive ให้ (`erp_creative_attachments.drive_file_id`)
- ป๊อปโพสต์ "โพสต์ด้วยไฟล์ต้นฉบับจาก Google Drive" (ค่าเริ่ม = เปิด) → ส่ง `drive:<id>` + `fallback` = รูปย่อ R2 · ต้นฉบับเปิด/แปลงไม่ได้ (เช่น HEIC) → `/api/post-image` ใช้รูปสำรองให้เอง (`&fb=`)
- ป้ายบนรูป: ขนาดจริง (`ต้นฉบับ · 4000×5000` เขียว / `1066×1600 · เล็ก` เหลือง = กว้างไม่ถึง 1080 IG · 1200 FB) — ขนาดต้นฉบับอ่านจาก Drive โดยไม่โหลดไฟล์ (`/api/post-image?meta=1`)
- "＋ ต้นฉบับจาก Google Drive" ในป๊อปโพสต์ = วางลิงก์ไฟล์/โฟลเดอร์ แนบ + เลือกให้เลย
- รูปจากงานส่ง (งานย่อย) ถูกย่อ ≤1500px ตอนส่งงาน ยังไม่มีต้นฉบับใน Drive

## ข้อจำกัดที่รู้
- คิวช้าได้ไม่เกิน ~5 นาที · ทีละ ≤5 งานต่อรอบ
- IG: รูปต้องสัดส่วน 4:5–1.91:1 (Story/Reels 9:16) · วิดีโอ MP4/MOV · ~50–100 โพสต์/วัน/บัญชี
- FB Reels: แนวตั้ง ≥540p 3–90 วิ · ≤30 Reels/วัน/เพจ
- ตัวเชื่อม Meta ใช้ Graph API `v25.0` (เปลี่ยนที่ `lib/meta-graph.ts` ที่เดียว · แต่ละเวอร์ชันใช้ได้ ~2 ปี)
