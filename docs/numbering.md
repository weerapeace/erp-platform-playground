# เลขที่เอกสารกลาง (Numbering) — `erp_next_number` + หน้า `/admin/numbering`

ทุกเอกสาร (ใบขาย/ใบกำกับ, ใบวางบิล, ใบส่งสินค้า, ใบสั่งขาย, PR/PO, MO, ใบเสนอราคา, ใบลดหนี้ …) ขอเลขจากตัวเดียวกัน:

```sql
select erp_next_number('so_tax_ISG');   -- → ISG2569-09-014
```

กฎต่อชุดเลขเก็บใน `erp_numbering_rules` (key · pattern · reset_policy · current_value · …) แก้ได้ที่ **ตั้งค่า → เลขที่เอกสาร**

## Token ใน pattern
| token | ความหมาย | ตัวอย่าง |
|---|---|---|
| `{YYYY}` `{YY}` | ปี ค.ศ. | 2026 / 26 |
| `{BYYYY}` | ปี พ.ศ. | 2569 |
| `{YYYYMM}` `{MM}` `{DD}` | เดือน/วัน | 202609 / 09 / 25 |
| `{BRANCH}` | รหัสสาขา (ส่งมาตอนเรียก) | |
| `{000}` | เลขรัน — จำนวน 0 = ความยาว | 001 |

`reset_policy` = never / yearly / monthly / daily → ตัวนับเริ่ม 1 ใหม่เมื่อขึ้นงวดใหม่

## ♻️ นำเลขของใบที่ยกเลิกกลับมาใช้ (`recycle_cancelled`) — ตั้งแต่ 2026-09-25
เจ้าของสั่ง: *"ยกเลิกบิลหรือ SO แล้ว เลขต้องไม่ข้าม — ยกเลิก 009 สร้างใหม่ต้องได้ 009 ไม่ใช่ 010"*

- เปิดสวิตช์นี้ = **เลขถัดไป = เลขว่างที่เล็กที่สุดในงวดนี้** โดยสแกนจากตารางเอกสารจริง และ**ไม่นับใบที่ `status = 'cancelled'`**
- ไม่มีตาราง "เลขที่คืน" แยก, ไม่ต้องเกาะ hook ตอนยกเลิก → ยกเลิกใบไหน เลขก็ว่างทันที · ตัวนับที่เคยตามหลังของจริงก็หายไปเอง (self-healing)
- ใช้ได้เฉพาะชุดที่ผูก `recycle_table` / `recycle_column` ไว้ (ตั้งจาก migration ไม่ใช่จากหน้าจอ):

| key | ตาราง.คอลัมน์ | เปิดอยู่ |
|---|---|---|
| `so_tax_ISG` `so_tax_LOUIS` `so_tax` `so_cash` | `erp_playground_sales_orders.so_number` | ✅ |
| `bn` | `erp_playground_billing_notes.bill_number` | ✅ |
| `dn` | `erp_playground_delivery_notes.dn_number` | ✅ |
| `so_order_ISG` `so_order_LOUIS` | `so_orders.order_no` | ✅ |

**ข้อจำกัดที่ต้องรู้**
- เลขว่างถูกเติมได้เฉพาะ**งวดเดียวกัน** (เลขมีเดือนฝังอยู่) — ยกเลิกใบเดือน ก.พ. ตอน ก.ย. เลข ก.พ. นั้นก็ยังหาย ถ้าอยากใช้ต้องพิมพ์เลขเองในใบใหม่
- ใบยกเลิกยังถือเลขเดิมอยู่ในตาราง (ไว้ดูประวัติ) → รายงานภาษีขายจะ**ซ่อน**ใบยกเลิกที่เลขถูกใบใหม่ใช้ซ้ำแล้ว (ถือว่าไม่เคยมี) และนับ "ซ้ำ" เฉพาะใบที่ยังไม่ยกเลิก
- ⚠️ ตามหลักสรรพากร ใบกำกับที่ออกให้ลูกค้าแล้วและยกเลิก ควรเก็บเลขไว้และออกใบใหม่เป็นเลขใหม่ — เจ้าของเลือกให้ใช้เลขซ้ำได้ (ทำแบบนี้มาตลอดด้วยการพิมพ์เลขเอง) ถ้าวันหนึ่งอยากเข้มขึ้น ปิดสวิตช์ที่ชุด `so_tax_*` ได้เลย

## กันเลขซ้ำ (ใบขาย)
- `erp_so_number_in_use(number, exclude_id)` — เลขนี้มีใบที่ยังไม่ยกเลิกถืออยู่ไหม → ใช้ตอน**สร้าง/แก้**ที่กรอกเลขเอง: ซ้ำ = error *"เลขที่ … ถูกใช้อยู่แล้วโดยใบ … — ถ้าจะใช้เลขนี้ ให้ยกเลิกใบนั้นก่อน"*
- `erp_so_fresh_number(key)` — ขอเลขอัตโนมัติแล้วเช็กชนซ้ำ วนขอใหม่ได้สูงสุด 50 ครั้ง
- `erp_so_numbering_key(company_id, vat_rate)` — เลือกชุดเลข: มี VAT → `so_tax_<CODE>` · ไม่มี VAT → `so_cash`
- แก้ใบแล้ว**สลับโหมด VAT ↔ ไม่มี VAT** = ได้เลขชุดใหม่ (เลขเดิมว่างให้ใบอื่น) — เดิมแก้บิลไม่มี VAT แล้วโดนออกเลขใบกำกับทับ (บั๊กที่แก้ไปพร้อมกัน)

## ย้อนสถานะใบที่ยกเลิก (ใบวางบิล / ใบส่งสินค้า)
ถ้าเลขเดิมถูกใบอื่นใช้ไปแล้ว → ระบบออกเลขใหม่ให้ตอน revert และคืน `renumbered_from` ในผลลัพธ์ (หน้าจอแจ้ง "เลข X ถูกใบอื่นใช้ไปแล้ว จึงได้เลขใหม่ Y")

## ฟังก์ชันใน DB
| ฟังก์ชัน | หน้าที่ |
|---|---|
| `erp_numbering_template(pattern, branch, now)` | แทน token วันที่ → template ที่เว้นเลขรันเป็น `{#}` + pad |
| `erp_numbering_used(rule, branch)` | เลขที่ใบไม่ยกเลิกใช้อยู่ในงวดนี้ (dynamic SQL ตาม recycle_table) |
| `erp_numbering_next_candidate(rule, branch)` | เลขถัดไป (ยังไม่กิน) — ใช้ร่วมกันโดย `erp_next_number` และ `erp_numbering_preview` |
| `erp_next_number(key, branch)` | กินเลข (ล็อกแถวกฎ กันสองคนได้เลขเดียวกัน) |
| `erp_numbering_preview(key)` / `erp_numbering_gaps(key)` | ดูเลขถัดไป / เลขว่างในงวด (สิทธิ์ `numbering.view`) |
| `erp_numbering_rules_upsert(... p_recycle_cancelled)` | บันทึกกฎจากหน้าตั้งค่า (สิทธิ์ `admin.numbering`) |
