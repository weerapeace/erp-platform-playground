# 📧 ส่งอีเมลรายงาน (Email Reports) — ของกลาง

ระบบส่ง "อีเมลสรุป" อัตโนมัติตามวัน/เวลา เช่น ตารางใบงานออกแบบที่ค้าง (มีรูป) ทุกจันทร์–เสาร์ 08:00 น.
เจ้าของตั้งเองได้ที่ **ตั้งค่า → ส่งอีเมลรายงาน** (`/admin/email-reports`) ไม่ต้องแก้โค้ด

## สถานะ
- **รอบ 1 (เสร็จ):** ตาราง + หน้าจัดการ (เพิ่ม/แก้/ลบ/เปิด-ปิด) + ดูตัวอย่างอีเมลจากข้อมูลจริง
- **รอบ 2 (เสร็จ):** ส่งผ่าน Gmail ได้ (ดู [email-setup.md](email-setup.md)) · ปุ่ม ✉️ ทดสอบ (ถึงอีเมลคนกด) · 📤 ส่งเดี๋ยวนี้ · ส่งตามเวลา (pg_cron)
- **รอบ 3 (เสร็จ 2026-10-23):** เลือกเองได้ว่าอีเมลโชว์อะไร (ตัวเลขสรุป · ข้อมูลของแต่ละงานเรียงตามลำดับ) · จัดกลุ่ม/เรียง · เฉพาะงานที่มีป้ายเตือน · ใกล้กำหนดกี่วัน · หัวเรื่อง/ข้อความเกริ่นตั้งเอง — ดู "ตัวเลือกหน้าตาอีเมล"
- **ต่อไป:** ปรับตามการใช้งานจริง

## ส่งตามเวลา (รอบ 2)
- pg_cron job `email-reports-every-15min` (`*/15 * * * *`) → pg_net POST `/api/cron/email-reports` พร้อม header `x-cron-token`
- โทเคนเก็บเข้ารหัสใน **Supabase Vault** ชื่อ `email_reports_cron` · route ตรวจผ่าน RPC `erp_cron_token_ok` (service_role เท่านั้น) — ไม่ต้องตั้งค่าใน Vercel
- ถึงเวลา = วันตรง + ตั้งแต่เวลาที่ตั้ง ถึง +2 ชม. + วันนี้ยังไม่ส่ง (`isDue` ใน `lib/email-report/send.ts`)
- กันส่งซ้ำ: "จอง" `last_sent_on = วันนี้` ก่อนส่ง (update ... where last_sent_on < today) · ส่งไม่สำเร็จ = ไม่ลองซ้ำวันนั้น (ดูในประวัติ)
- ผู้รับที่เป็นผู้ใช้ = อีเมลล่าสุดจาก `user_profiles` ตอนส่ง · ปิดบัญชี/ไม่มีอีเมล = ข้าม + จดใน `detail.skipped`
- แอดมินเปิด `/api/cron/email-reports` เอง (login) = ดูว่ารายงานไหนถึงเวลา ไม่ส่งจริง (dry run)
- ปิดตัวตั้งเวลา: `select cron.unschedule('email-reports-every-15min');` · หน้าตั้งค่าบอกสถานะผ่าน RPC `erp_email_reports_cron_active`

## ใช้เมื่อไหร่ / ห้ามใช้เมื่อไหร่
- ใช้: สรุปรายวัน/รายสัปดาห์ให้คนกลุ่มหนึ่ง (ฉบับเดียวกันทุกคน)
- ไม่ใช้: แจ้งเตือนทันทีตามเหตุการณ์ (ใช้ Notification Rules / LINE ของกลาง `lib/board-notify`) · อีเมลถึงลูกค้าเรื่องออเดอร์ (`lib/order-notify`)

## เพิ่มรายงานแบบใหม่
1. ประกาศใน `EMAIL_REPORT_SOURCES` (`shared.ts`) — ชื่อ + **เลือกโชว์อะไรได้บ้าง** (`rowFields`/`stats`/`groupBy`/`sortBy`/`subjectTokens` + ค่าเริ่มต้น)
2. เขียนฟังก์ชันใน `sources.ts` รับ `ResolvedReportOptions` (เติมค่าเริ่มต้นแล้ว) คืน `BuiltReport` แล้วใส่ใน `SOURCES` — ทำตามตัวเลือก ห้ามตั้งค่าตายตัวในฟังก์ชัน
3. หน้าตาอีเมล + หน้าจัดการ (ส่วน "ตัวเลือก" / "โชว์อะไรในอีเมล" อ่านจากข้อ 1) + ดูตัวอย่าง ใช้ได้ทันที (ถ้าแหล่งใหม่มีตัวกรองเฉพาะ ค่อยเพิ่มช่องใน report-editor)

## ตัวเลือกหน้าตาอีเมล (`email_reports.options` · jsonb)
เก็บเป็นการตั้งค่าของรายงานแต่ละตัว · ตรวจ/เติมค่าเริ่มต้นด้วย `normalizeReportOptions` ตัวเดียว (ใช้ตอนบันทึก + ตอนประกอบอีเมลจากค่าใน DB)
**รายงานเก่าที่มีแค่ `max_rows`/`stale_days` = ได้หน้าตาเดิมทุกอย่าง** (ทดสอบแล้ว: HTML เหมือนโค้ดเดิม)

| คีย์ | ความหมาย | ค่าเริ่มต้น |
|---|---|---|
| `max_rows` | โชว์ในอีเมลสูงสุด (5–100) | 50 |
| `stale_days` | ไม่ขยับเกินกี่วัน = ส้ม (1–60) | 7 |
| `due_soon_days` | เหลือไม่เกินกี่วัน = "ใกล้กำหนด" (0–30) | 3 |
| `group_by` | จัดกลุ่ม: `status` / `brand` (งานเยอะสุดก่อน) / `none` | status |
| `sort_by` | `urgent` (เกิน/ใกล้กำหนด → ไม่ขยับนาน) / `stale` / `deadline` / `newest` | urgent |
| `only_flagged` | ส่งเฉพาะงานที่มีป้ายแดง/ส้ม (หัวอีเมลเป็น "ที่ต้องตาม") | false |
| `stats` | ตัวเลขสรุปด้านบน `total` `overdue` `due_soon` `stale` `fresh` + `by_status` (แถบนับแยกสถานะ) · `[]` = ไม่มีกล่องตัวเลข | total, overdue, stale |
| `row_fields` | ข้อมูลของแต่ละงาน **เรียงตามลำดับ**: `cover` `code` `brand` `status` `deadline` `order_date` `creator` `waiting_for` (= ข้อที่ยังไม่เสร็จของเช็กลิสต์ ⏳ รออะไรอยู่ · docs/record-tasks.md) `note` `detail` `flag` `open` (ชื่องานโชว์เสมอ) | cover, code, brand, deadline, note, flag, open |
| `subject_template` | หัวเรื่องตั้งเอง ใส่ `{จำนวน}` `{เกินกำหนด}` `{ใกล้กำหนด}` `{ไม่ขยับ}` `{วันที่}` `{ชื่อรายงาน}` · ว่าง = แบบเดิม · ตัดขึ้นบรรทัดทิ้ง (กันแทรกหัวอีเมล) · ≤150 | "" |
| `intro` | ข้อความเกริ่นบนสุด (ขึ้นบรรทัดได้ · ≤500 · escape ทุกตัว) | "" |

- แม่แบบอีเมล (`render.ts`): แถว = `parts` เรียงตามที่เลือก (`meta` ติดกันรวมบรรทัดเดียวคั่น " · " · `note` กล่องเหลือง · `tag` ป้ายฟ้า ⏳ · `small` ตัวเล็กจาง) · `showImages=false` = ไม่มีช่องรูป · หัวกลุ่ม `label` ว่าง = ไม่มีหัวกลุ่ม
- หน้าตั้งค่า: ข้อมูลของแต่ละงานใช้ของกลาง `FieldChipsPicker` (ติ๊กตามลำดับ · `hint` = "มีข้อมูล x/y" จาก `fill` ของ API preview)

## แหล่งข้อมูลแรก: ใบงานออกแบบที่ค้าง (`design_sheets_pending`)
- ค้าง = สถานะที่ไม่ใช่ "ปิดงาน" ใน Workflow กลาง (`is_terminal`) — เปลี่ยนสถานะที่ /admin/workflows หรือปุ่ม "จัดการสถานะ" แล้วรายงานเปลี่ยนตาม
- กรองได้: กลุ่มแบรนด์ (ทุกแบรนด์ / งานลูกค้า / แบรนด์เรา — กฎกลาง `isOwnBrandJob`) · เฉพาะแบรนด์ · เฉพาะสถานะ
- เรียงค่าเริ่มต้น: เกินกำหนด → ใกล้กำหนด (`due_soon_days`) → ไม่ขยับนานสุด (`updated_at`) — เพราะใบงานส่วนใหญ่ไม่มีกำหนดส่ง (ต.ค. 2026: มีกำหนดส่งแค่ 1/54 ใบ)
- "รายละเอียดสั้น" = ตัด HTML ของช่องรายละเอียด (`excerpt` ใน `lib/design-sheet-summary-server`) · หลายใบเป็นย่อหน้าว่าง → นับว่าไม่มีข้อมูล
- "ผู้สร้างใบงาน" = `created_by` → `user_profiles.display_name` (ไม่ใช่ผู้รับผิดชอบ — ใบงานยังไม่มีช่องนั้น)
- รูป: รูปปกจากระบบแนบไฟล์ ผ่าน `/api/r2-image?w=160` (เปิดได้โดยไม่ต้อง login)
- ลิงก์ "เปิดใบงาน" → `/master/design-dashboard?open=<id>`

## สิทธิ์ / ประวัติ
- สิทธิ์: `admin.email_reports` (แอดมินได้อัตโนมัติ · ตำแหน่งอื่นติ๊กที่ Roles & Permissions)

- ลบ = เก็บประวัติ (`is_active=false`) ประวัติการส่งยังอยู่

- Outlook บางเครื่องถามก่อนโหลดรูป (Gmail โชว์ทันที)
