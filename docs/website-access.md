# 🔐 สิทธิ์เว็บไซต์ (ใครทำอะไรได้ · รายร้าน)

ตั้งได้ว่าแต่ละคน **เห็น / ดูได้ / แก้ได้** ส่วนไหนของเว็บไซต์ และ **เข้าร้านไหนได้** — ระบบกันทั้งหน้าจอและตอนบันทึก

## ใช้ทำอะไร

- แยกงานหลังร้าน: กราฟิกแก้หน้าตาเว็บได้แต่ไม่เห็นออเดอร์ · แอดมินตอบออเดอร์ได้แต่แก้ดีไซน์ไม่ได้
- แยกร้าน: คนดูแล Pixiedustie ไม่เห็นหลังร้าน Louis Montini
- เมนู "เว็บไซต์" อยู่ในแอป **จัดการงาน** (และช่องทางขาย/หน้าหลักเหมือนเดิม) — คนที่ไม่เห็นกลุ่มไหนเลย เมนูหายเอง

## ตั้งค่าที่ไหน

- หน้า **/website/access** — ปุ่ม "🔐 ใครทำอะไรได้" ในหน้าเว็บไซต์ หรือ ⚙️ ของแอปจัดการงาน → แท็บ "🔐 สิทธิ์เว็บไซต์"
- แถว **ตามตำแหน่ง** = ค่าเริ่มของทุกคนในตำแหน่ง (แก้ต้องมีสิทธิ์ `admin.roles`)
- แถว **ยกเว้นรายคน** = เฉพาะคน ชนะตำแหน่ง (ต้อง `admin.users`) · "↺ ตามตำแหน่ง" ล้างข้อยกเว้น
- ร่าง → กด 💾 บันทึกทีเดียว · มีผลภายใน ~1 นาที (คนนั้นรีเฟรชหน้า) · ผู้ดูแลระบบได้ทุกอย่างเสมอ

## ชิ้นส่วน (ของกลาง)

| ไฟล์ | หน้าที่ |
| --- | --- |
| `lib/website-access.ts` | กลุ่ม/แท็บ/คีย์สิทธิ์ · route API → กลุ่ม (`websiteApiGroups`) · ระดับ ↔ คีย์ (pure + เทสต์) |
| `lib/website-api-guard.ts` | `guardWebsite(request, "view" \| "edit")` — ใช้แทน guardApi(products.*) ใน `/api/website/*` · เช็กร้านจาก query/body |
| `components/website-access-settings.tsx` | ตาราง "ใครทำอะไรได้" |
| `app/api/website/access` | GET/POST ตั้งค่า (ใช้ RPC `erp_role_permission_toggle` + `erp_user_permissions` เดิม · audit) |

คีย์: `website.access` (เห็นเมนู · ตั้งอัตโนมัติ) · `website.<กลุ่ม>.view|edit` · `website.shop.<slug>` — อยู่ในตารางสิทธิ์กลางหมวด "เว็บไซต์" (เห็นใน Role Board ด้วย)

## 👷 หน้าดีไซน์แบบง่ายสำหรับพนักงาน (แก้ได้บางหัวข้อ)

เจ้าของขอ 2026-10-29: ให้หัวหน้าเลือกได้ว่าพนักงานแก้หัวข้อดีไซน์อะไรได้ (เช่น เมนู · หน้ารายการสินค้า)

- ตั้งที่ /website/access ส่วนล่าง “หน้าดีไซน์แบบง่ายสำหรับพนักงาน” (รายตำแหน่ง/รายคน · ชุดสำเร็จรูป ดูแลเมนู/หัวเว็บ · ดูแลหน้าสินค้า · แคมเปญ/ป๊อปอัป) → ช่อง “หน้าตาเว็บ” ขึ้น “แก้บางหัวข้อ (n)”
- คีย์: `website.design.topic.<หน้า>` (17 หน้าใน lib/website-design-nav ยกเว้น ภาพรวม/ประวัติ) · `website.design.publish` (เผยแพร่เองได้) · `website.design.advanced` (โชว์การตั้งค่าละเอียด) — ต้องมี `website.design.view` ด้วย · สร้างในทะเบียนตอนบันทึกครั้งแรก
- มี `website.design.edit` = แก้ได้ทุกหัวข้อแบบเดิม (เปลี่ยนช่องเป็น “แก้ได้/ไม่เห็น” = ล้างหัวข้อให้เอง)
- ของกลาง `designAccess(has)` (lib/website-access) ใช้ทั้งหน้าจอและ API
- พนักงานเปิดแท็บดีไซน์: เมนูซ้ายเฉพาะหัวข้อ (ไม่มีภาพรวม/ประวัติ/⏰ ตั้งเวลา) · แบบง่ายซ่อนการ์ด `level: "advanced"` + ปรับละเอียดทีละชิ้น (PartStyleFold) · การ์ด `level: "full"` ซ่อนเสมอ (ธีมที่บันทึกไว้ · ธีมทั้งชุด · ตั้งเวลา · ธีมแคมเปญ) — ระดับการ์ดอยู่ใน cards ของ lib/website-design-nav
- บันทึก: `PUT /api/website/theme` ส่ง `pages` (หัวข้อที่แก้) → เซิร์ฟเวอร์ (`guardDesignEdit`) ตรวจสิทธิ์รายหัวข้อแล้ว **คัดเฉพาะค่าของหัวข้อนั้น** (`applyDesignPages`) ทับร่างในระบบ — แก้หัวข้ออื่นมาก็ไม่ถูกบันทึก/ไม่ทับงานคนอื่น · เผยแพร่ (มีสิทธิ์) = เผยแพร่เฉพาะหัวข้อของตัวเอง ร่างหัวข้ออื่นยังค้าง · ละทิ้งร่างทั้งก้อน (DELETE) = ต้องแก้ได้ทุกหัวข้อ
- ไม่มีสิทธิ์เผยแพร่ → ปุ่ม “ส่งให้หัวหน้าตรวจ” → `POST /api/website/theme/review` เด้งกระดิ่ง (erp_notifications · event website_design_review) ถึงคนที่มี `website.design.edit` + เข้าร้านนั้นได้ (`lib/perm-holders` usersWithPerms) · ลิงก์เปิดหน้าดีไซน์หัวข้อแรก · audit `website_design.review_request`
- 🗂 **แท็บอื่น (2026-10-30)** — ติ๊กเพิ่มได้ในคอลัมน์ “แท็บอื่น (นอกหน้าดีไซน์)” + ชุดสำเร็จรูป “ดูแลหน้าแรก/หน้าเว็บ”: คีย์ `website.design.topic.home` (แท็บหน้าแรก) · `.webpages` (หน้าเว็บ) · `.webimages` (รูปบนเว็บ) — `DESIGN_TAB_TOPICS` ใน lib/website-access (แยกจาก DESIGN_TOPICS ที่ต้องตรงกับหน้าดีไซน์)
  - ด่าน API `guardDesignTab(request, tab)` (lib/website-api-guard): แก้ได้ทั้งหมด หรือ ดูได้ + ติ๊กแท็บนั้น · เผยแพร่ใช้ `website.design.publish` ตัวเดียวกับหน้าดีไซน์
  - หน้าแรก (`/api/website/layout`): บันทึกร่างได้ · เผยแพร่ต้องเผยแพร่เองได้ · ละทิ้งร่าง/กู้เวอร์ชัน = แก้ได้ทั้งหมด
  - หน้าเว็บ (`/api/website/pages`): สร้างหน้า (เป็นร่าง) + แก้ร่างได้ · ชื่อหน้า/SEO ไม่มีร่าง (ขึ้นเว็บทันที) → เผยแพร่เองไม่ได้ = เซิร์ฟเวอร์ข้าม (`metaSkipped`) + หน้าจอล็อกช่อง · สลับลำดับ/ลบหน้า = แก้ได้ทั้งหมด · คำขอมีแค่ pageId → เช็กร้านของหน้าเอง
  - รูปบนเว็บ (`/api/website/site-images`): คำอธิบายรูปได้ (ขึ้นเว็บทันที ไม่เปลี่ยนหน้าตา) · เปลี่ยนรูปทุกที่ = ลงร่างเฉพาะหน้าแรก/หน้าเว็บที่ติ๊กหัวข้อไว้ด้วย ไม่แตะร่างดีไซน์ (`noAccess` = จำนวนที่ต้องให้หัวหน้าเปลี่ยน)
  - หน้าจอ: แถบแท็บไม่ขึ้น 👁 (`designTabTopicOf`) · ของกลาง `components/website-tab-review` (`useDesignTabAccess`) — เผยแพร่ไม่ได้ = ปุ่ม “ส่งให้หัวหน้าตรวจ” (บันทึกร่างก่อน → `POST /api/website/theme/review` แบบ `area: home|webpages` ลิงก์ไปแท็บนั้น) · ไม่ใช่แก้ได้ทั้งหมด = ซ่อนละทิ้ง/ประวัติ/ลบ/สลับลำดับ
  - ทุกการบันทึกร่างของพนักงานแท็บ = audit (`by: topic`)
- แปลภาษา = ยังดูได้อย่างเดียวสำหรับพนักงานบางหัวข้อ (บันทึกลงหลายกลุ่มสิทธิ์ รวมชื่อสินค้า)

## กฎสำหรับคนเขียนโค้ด

- route ใหม่ใต้ `/api/website/` → ใช้ `guardWebsite` และเพิ่มใน `API_GROUPS` ของ `lib/website-access.ts` (ไม่ใส่ = ใช้กฎเดิม products.*)
- แท็บใหม่ในหน้าเว็บไซต์ → ใส่ใน `tabs` ของกลุ่มใน `WEBSITE_GROUPS`
- route ที่แอปอื่นใช้ด้วย (tag-categories · product-png · listings/images · video-upload) คงกฎเดิม — ไม่งั้นแอปอื่นพัง

## ข้อจำกัด

- กลุ่มที่ "ดูได้" แท็บยังกดปุ่มบันทึกได้ (มีแถบเตือน 👁) แต่ระบบปฏิเสธตอนบันทึก
- คำขอที่ไม่บอกร้าน (เช่น แก้ออเดอร์ด้วยเลข id อย่างเดียว) เช็กแค่กลุ่ม ไม่เช็กร้าน
- ตอนเปิดใช้ (2026-11-04) ทุกตำแหน่งที่เคยมี products.view/edit ได้สิทธิ์ใหม่ครบ = เหมือนเดิมทุกอย่าง — เจ้าของตัดเอง
