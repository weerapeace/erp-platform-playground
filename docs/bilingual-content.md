# 🌐 เนื้อหา 2 ภาษา (ไทย / อังกฤษ) — ของกลาง

ใช้กับ "ข้อความที่ลูกค้าเห็น" เช่น หัวข้อ/ปุ่ม/ย่อหน้าบนหน้าเว็บร้าน
(ไม่เกี่ยวกับปุ่ม TH/EN ของหน้าจอ ERP — อันนั้นคือภาษาของเมนูพนักงาน `components/i18n.tsx`)

## ใช้ทำอะไร

- ตั้งชื่อ/ข้อความได้ 2 ภาษาในหลังบ้าน
- มีปุ่ม 🌐 ให้ AI ช่วยแปลจากภาษาไทย (GPT → Cloudflare AI → Google ตามที่มี)
- บอกสถานะทุกช่อง: ยังไม่มี EN / AI แปล·รอตรวจ / EN ✓ / ไทยเปลี่ยน·แปลใหม่?

## กฎการเก็บข้อมูล (ทุกที่ใช้กฎเดียว)

| ช่อง | เก็บอะไร |
|---|---|
| `<key>` (ช่องเดิม) | ภาษาไทย — ไม่ย้าย ไม่เปลี่ยนชนิด ข้อมูลเก่า/เว็บรุ่นเก่าไม่พัง |
| `<key>_en` | ภาษาอังกฤษ — **ว่าง = ใช้ไทยแทน** (ลูกค้าไม่เจอช่องว่าง) |
| `_i18n` | สถานะการแปลต่อช่อง `{ [key]: { h, ai? } }` · `h` = ลายนิ้วมือข้อความไทยตอนแปล/ตรวจ (ไทยเปลี่ยนทีหลัง → รู้ว่าคำแปลค้าง) · `ai` = AI แปล ยังไม่มีคนตรวจ |

- ปุ่ม/ลิงก์ (`{ text, href }`) → `<key>_en` เก็บ **ข้อความบนปุ่ม** อย่างเดียว ปลายทางใช้ร่วมกับไทย
- รายการ (`string[]`) → `<key>_en` เป็น `string[]` เรียงตรงกับไทยทีละบรรทัด
- ภาษาที่ 3 ในอนาคต (เช่น จีน) ใช้รูปแบบเดียวกัน `<key>_zh`
- ไม่มีคำแปล = ไม่มีช่อง `_en`/`_i18n` เลย (ข้อมูลร้านที่ไม่ใช้ 2 ภาษาเหมือนเดิมทุกไบต์)

## ไฟล์ของกลาง

| ไฟล์ | หน้าที่ |
|---|---|
| `lib/content-i18n.ts` | กฎกลาง (ไม่ผูก React): `enKey` · `pickText`/`pickList` (เลือกภาษา + fallback ไทย) · `translationStatus` · `translationPatch`/`confirmPatch` · `coverageOf` |
| `lib/content-translate.ts` | ส่งไปแปลที่ `/api/ai/translate` (`kind: "content"`) แบ่งชุดเอง คืนลำดับตรงกับที่ส่ง |

| `lib/website-i18n.ts` | ต่อกฎเข้ากับ Schema ของหน้าเว็บ: ช่องไหนแปลได้ · ทำความสะอาด `_en` ตอน normalize · รวบรวมช่องที่ขาด · ใส่คำแปลทีเดียวหลายช่อง |

## ใช้ยังไง

### ช่องข้อความเดี่ยว (เช่น ชื่อหมวด/ชื่อคอลเลกชัน ในอนาคต)

```tsx
<ContentLangProvider>
  <ContentLangSwitch />
  <BilingualText label="ชื่อหมวด" value={row} fieldKey="name" onPatch={(p) => setRow({ ...row, ...p })} />
</ContentLangProvider>
```

`onPatch` อาจได้หลายช่องพร้อมกัน (`name_en` + `_i18n`) — รวมเข้า object ทั้งก้อน
ถ้าเก็บในตาราง DB ต้องมีคอลัมน์ `<key>_en` (+ `i18n jsonb` ถ้าอยากเก็บสถานะ) และ API ต้องยอมรับช่องนั้น

### การ์ดแก้ "1 รายการ" (เช่น หมวดหมู่ — ทำให้แล้ว) — `RecordLangBar`

แถบเดียวจบ: ปุ่ม 🇹🇭 ไทย | 🇬🇧 EN + "อังกฤษ x/y" + 🌐 แปลที่ยังขาด (นับเฉพาะช่องที่มีอักษรไทย · ช่องที่แปล/แก้เองไม่ถูกทับ)

```tsx
<ContentLangProvider lang={lang} onLangChange={setLang}>
  <RecordLangBar value={row} keys={["label", "blurb"]} onPatch={(p) => patch(row.key, p)} />
  <BilingualText label="ชื่อหมวด" value={row} fieldKey="label" onPatch={(p) => patch(row.key, p)} />
</ContentLangProvider>
```

ใช้จริง: แท็บ 📂 หมวดหมู่ (`components/website-categories-panel.tsx`) — ชื่อ · คำอธิบาย · ชื่อ/คำอธิบายใน Google · ตัวอย่างผลค้นหาโชว์ตามภาษาที่กำลังแก้ (`/en/c/<รหัส>`)

### ช่องในฟอร์ม Section (ทำให้แล้ว)

`SchemaForm` ห่อช่อง text/textarea/link/list ด้วย widget ให้เองเมื่ออยู่ใน `ContentLangProvider`
ช่องที่ "ไม่ใช่ภาษา" ใส่ `i18n: false` ใน `lib/website-schema.ts` (เช่น รหัสกลุ่ม ชื่อบัญชี IG บันทึกช่วยจำ)

### ฟอร์มทะเบียน (MasterCRUD เช่น Parent SKU) — คู่ช่องไทย/อังกฤษ

ตั้งที่ทะเบียนฟิลด์: ช่องไทยใส่ `ui_style.lang_en = "<ชื่อช่องอังกฤษ>"` (เช่น `description` → `english_description`)
- ปุ่มบนสุด 🇹🇭 ไทย / 🇬🇧 EN = สลับ**ทุกช่อง**พร้อมกัน
- ปุ่มเล็ก **TH | EN ข้างหัวข้อ** = สลับ**เฉพาะช่องนั้น** (ช่องอื่นอยู่ภาษาเดิม) · จุดเขียวข้าง EN = มีภาษาอังกฤษแล้ว · จุดเทา = ยังว่าง
- ช่องที่ไม่ได้ตั้งคู่ = ไม่มีปุ่ม (ไม่ต้องมี 2 ภาษา)
- โค้ด: `components/master-crud` (`langField` + `LangPill` + `FieldDef.labelAddon`) — ใช้ได้ทุกโมดูลที่ตั้งคู่ไว้

### ฝั่งแสดงผล (เว็บร้าน)

```ts
pickText(block, "title", lang)   // อังกฤษว่าง → ไทย
pickList(block, "messages", lang)
```

## ห้ามใช้เมื่อไหร่

- ข้อมูลที่ไม่ใช่ภาษา: รหัส, SKU, ลิงก์, อีเมล, เบอร์โทร, ชื่อบัญชีโซเชียล
- ข้อความภายในที่ลูกค้าไม่เห็น (บันทึกช่วยจำ)
- สินค้า (Parent SKU) มีคอลัมน์อังกฤษของตัวเองอยู่แล้ว (`name_en`, `introduction_en`, `english_description`) + ปุ่ม 🌐 ในฟอร์มสินค้า — ไม่ต้องใช้ `_en` ซ้ำ

## สิทธิ์ / ค่าใช้จ่าย / ประวัติ

- ปุ่มแปลเรียก `/api/ai/translate` — ใช้ได้เมื่อมีสิทธิ์ `products.edit` (คนจัดหน้าเว็บ) หรือ `tasks.view`
- แปลเมื่อกดเท่านั้น ไม่แปลเองตอนบันทึก · GPT ≈ 0.02 บาท/ช่องยาว · ไม่มี key → ใช้ Google ฟรี (แปลตรงตัวกว่า)
- สไตล์การแปลตั้งได้ที่ทะเบียน prompt `platform = "translate"` (หน้า /tasks/settings)
- คำแปลอยู่ในโครงหน้าเว็บ → ประวัติ/ย้อนกลับ ใช้ระบบเวอร์ชัน + บันทึกร่าง/เผยแพร่ของหน้าเว็บเดิม

## เว็บร้าน (repo storefront) — หน้า /en

- ไทย = ที่อยู่เดิมทุกหน้า · อังกฤษ = `/en/...` — `src/proxy.ts` ตัด `/en` ออกแล้วส่งหัว `x-sf-lang: en` ให้หน้าเดิมวาด (ไม่มีโฟลเดอร์ซ้ำ)
- ร้านต้องเปิด **🌐 เปิดภาษาอังกฤษบนเว็บ** (`lang_en_enabled` แท็บข้อมูลร้าน) — ปิด = `/en` เด้งกลับไทย · พรีวิวใน ERP ดูได้เสมอ
- ตัวดึงข้อมูลกลาง (`getSiteConfig` / `getStorePage(s)` / `fetchStorefrontProducts`) สลับทุกช่อง `<key>_en` ให้ทั้งก้อนด้วย `localizeContent()` → ERP ส่ง `_en` มาเพิ่มเมื่อไหร่ เว็บใช้ได้ทันทีไม่ต้องแก้เว็บ
- สินค้า: products API ส่ง `name_en` (name_en ผ่านกฎชื่อร้าน) · `description_en` (english_description / introduction_en)
- ข้อความตายตัวบนเว็บ: `t('ไทย','English')` — `useT()` (หน้าจอ) · `getT()` (เซิร์ฟเวอร์) · ลิงก์ภายในใช้ `@/components/ui/Link` (เติม `/en` ให้เอง)
- สลับภาษา = โหลดทั้งหน้า (Next ไม่วาด layout ซ้ำตอนเปลี่ยนหน้าแบบลื่น) · hreflang + sitemap มีคู่ `/en` เมื่อร้านเปิด
- ตัวจัดหน้า: สลับแผงเป็น EN → พรีวิวเปิดหน้า `/en` เอง

## ข้อมูลซ้อนหลายชั้น (ธีม · หมวด · คอลเลกชัน) — ก้อน 4

- **เก็บ:** ตัวทำความสะอาดเดิมเก็บเฉพาะช่องที่รู้จัก → ต่อท้ายด้วย `carryTranslations(raw, normalized, KEYS)` (จับคู่ชิ้นใน array ด้วย `id`/`key`) — ใช้แล้วใน `normalizeTheme` (`THEME_TEXT_KEYS`) · `normalizeFieldMap` (`CATEGORY_TEXT_KEYS` + options/options2 `label` + unit `default`) · `normalizeWebCollections` (`COLLECTION_TEXT_KEYS`)
- **แก้:** `components/translation-table.tsx` — `<TranslateButton value onChange keys crumbOf />` = ปุ่ม "🌐 EN x/y" → ป๊อปตารางคำแปล (ไทย | อังกฤษ | แปล | ตรวจแล้ว + แปลที่ยังขาดทีเดียว) แก้ลง state ของแผงนั้น แล้วบันทึกตามปกติ
  - ใช้ที่: แท็บดีไซน์ (เมนู/ท้ายเว็บ/แผงเมนูใหญ่/หัวเว็บ/หน้าสินค้า/ตะกร้า/ตัวกรอง) · แท็บหมวดหมู่ · แท็บคอลเลกชัน
- หน้าจอที่สร้าง object ใหม่จากช่องที่รู้จัก (เช่น `strip()` ของแท็บคอลเลกชัน) ต้องแนบ `...pickTranslations(obj)` ไม่งั้นคำแปลหายตอนบันทึก
- ข้อความที่ไม่มีอักษรไทย (อังกฤษอยู่แล้ว / ค่าตั้งค่าอย่าง "count") ไม่นับว่าต้องแปล (`needsTranslation`)
- **ข้อมูลร้าน** (store_settings): ฟิลด์ที่ตั้ง `i18n: true` ใน `SITE_INFO_FIELDS` มีแถว `<key>_en` + แถว `_i18n` (JSON) · แท็บข้อมูลร้านสลับ ไทย/EN ได้
- **หน่วย / ชื่อชุดตัวเลือก:** แท็บจับคู่ฟิลด์ช่อง 🌐 EN · ว่าง = `commonLabelEn` (ใบ→pc · สี→Colour) · listing ที่กรอกหน่วยทับ = ใช้คำมาตรฐาน
- **ชื่อสี:** ไม่ต้องกรอก — products API ใช้ `SwatchIndex.english()` จากทะเบียนสีกลาง (`erp_color_dictionary.en`) สีผสมแปลทีละคำ · คำที่ไม่มีในทะเบียน = ใช้ไทย (ไปเพิ่มคำในทะเบียนสี) · โทนสีของตัวกรองใช้ทางเดียวกัน (site API `colorTones[].name_en`)
  - **✏️ ตั้งเองราย SKU (2026-10-20):** แถวสีในแท็บ 🛍 เว็บไซต์ แก้ "ไทย / EN / ราคา" ได้ในแถว → เขียนลง SKU ใน ERP จริง (`skus_v2.color_th` / `color` / `list_price` · action `skuFields` ของ `/api/parent-web-listings` · กฎกลาง `lib/website-sku-fields`)
  - เว็บหน้าไทยโชว์ **สี (ไทย)** ก่อน (ว่าง = ช่อง Color) · หน้า /en ใช้ **ช่อง Color** ถ้าเป็นอังกฤษ → ไม่งั้นทะเบียนสีกลาง — ตัวเดียวทั้งระบบ `baseColor()` / `baseColorEn()` ใน `lib/website-size-options` (ตัวเลือกเว็บ · ตาราง สี×ไซส์ · ออเดอร์ · แท็บ 🛍)
  - แก้ชื่อสีหลัก → SKU ไซส์ของสีเดียวกัน ("ดำ / L") เปลี่ยนตาม · ชื่อซ้ำกับสีอื่นของรุ่น = ไม่ยอม · ชื่อในการตั้งค่าการ์ด (`web_card_colors`) ทุกร้านตาม · audit ค่าเก่า/ใหม่ทีละ SKU · เคารพสิทธิ์ฟิลด์ของ skus_v2

## 🌐 ศูนย์แปลภาษา (แท็บ "🌐 แปลภาษา" ในจัดการเว็บร้าน) — ก้อน 5

รวมทุกข้อความของร้านไว้ตารางเดียว: กรองตามแหล่ง/สถานะ · ค้นหา · "แปลที่ยังขาด" ทีเดียว · "✓ ตรวจแล้วทั้งหมดที่เห็น" · บันทึกครั้งเดียว

- **ดึงข้อมูล:** `GET /api/website/translations?shop=<slug>` (สิทธิ์ `products.view`) — หน้าแรก/หน้าเว็บ (published+draft) · ธีม · จับคู่ฟิลด์ · คอลเลกชัน (+ชื่อจาก ERP) · ข้อมูลร้าน · ชื่อ/คำอธิบายสินค้า (Parent SKU ที่ลงเว็บร้านนี้)
- **ตัวเชื่อม:** `lib/translation-center.ts` — `blocksAdapter` (Section) · `pathsAdapter` (ข้อมูลซ้อนลึก) · `productsAdapter` (สินค้า) แปลงทุกแหล่งเป็นแถวกลาง `CenterRow` + เขียนคำแปลกลับ · เพิ่มแหล่งใหม่ = เขียนตัวเชื่อม 1 ตัว
- **หน้าจอ:** `components/website-translation-center.tsx`
- **บันทึกกลับที่เดิมของแต่ละแหล่ง** (API เดิม ไม่มีทางลัด): layout/pages/theme/field-map/collections/settings + `PATCH /api/master-v2/parent-skus/<id>` (`name_en` · `introduction_en` หรือ `english_description` ตามแหล่งคำอธิบายที่ร้านตั้ง)
- **กันเผยแพร่งานค้าง:** หน้า/ธีมที่มีร่าง — ถ้าต่างจากที่เผยแพร่ "แค่คำแปล" (`onlyTranslationsDiffer`) = เผยแพร่เลย · ถ้ามีงานอื่นค้างในร่าง = เก็บเป็นร่าง + แจ้งให้ไปกดเผยแพร่ที่แท็บนั้น
- สินค้าไม่มีช่องเก็บสถานะ AI → ป้าย "AI รอตรวจ" ของสินค้าจำแค่บนหน้าจอรอบนั้น (บันทึกแล้วโหลดใหม่ = ครบแล้ว)

## ✉️ ออเดอร์จำภาษาลูกค้า + ข้อความแจ้งตามภาษา — ก้อน 6

- อีเมลสมาชิก (ยืนยัน/ตั้งรหัสใหม่) เป็นภาษาของหน้าที่กด + ลิงก์พากลับ `/en/account/...`

## ข้อจำกัดตอนนี้

- ข้อความที่ "ดับเบิลคลิกแก้ในพรีวิว" ของผืนผ้าใบอิสระแก้ได้เฉพาะไทย (อังกฤษแก้ที่แผงขวา)
- ค่าสเปกสินค้า (วัสดุ/ขนาดที่พิมพ์เป็นไทย) · ค่าตัวเลือกชุดที่ 2 · ชื่อหน้าที่สร้างเอง (ชื่อเมนูอัตโนมัติ) ยังภาษาเดียว
- หน้าบัญชีสมาชิก (login/สมัคร/บัญชี) และหน้าเก่าของ IG ยังเป็นไทย
- ของในตะกร้าจำชื่อตามภาษาตอนกดใส่
- รายการ "เข็มขัดสั่งทำ" ในออเดอร์ยังเก็บชื่อไทยอย่างเดียว · ข้อความ error ตอนสั่งซื้อจาก ERP (เช่น "สินค้าหมดแล้ว") ยังเป็นไทย
- ถ้อยคำแจ้งลูกค้าแก้ในโค้ด (`lib/customer-messages.ts`) — ยังไม่มีหน้าตั้งค่าให้แก้เอง

## หน้าดีไซน์ (ธีม) — สวิตช์ ไทย | EN ทั้งหน้า (2026-10-19)
