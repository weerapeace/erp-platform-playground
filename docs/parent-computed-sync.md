# เขียนช่องคำนวณของ Parent SKU ลงฐานข้อมูล (parent-computed-sync)

> เจ้าของสั่ง "แก้ที่ต้นทาง" 2026-11-21 · ของกลาง ใช้ได้ทุกระบบที่อ่านคอลัมน์ของ Parent SKU

## ปัญหาที่แก้

ป๊อป Parent SKU คำนวณ **Platform Description** และ **สรุปขนาด** สดทุกครั้งที่เปิด จาก บทนำ + รายละเอียด + ขนาด + Notes + บล็อก ⚙ (`lib/computed-text`) แต่ไม่เคยบันทึกผลลงฐานข้อมูล
คอลัมน์ `parent_skus_v2.platform_description` จึงยังเป็นข้อความเก่าจาก Odoo (เคสจริง: LY22 ยังมีข้อความของ Larkspur #21)
ระบบที่อ่านคอลัมน์ตรง ๆ (ลง LINE / TikTok · ตัวเตรียมร่าง · เช็กข้ามร้าน · เว็บร้าน) จึงได้ข้อความเก่า

## ทำงานยังไง

| ตอนไหน | ทำอะไร |
|---|---|
| กดบันทึกใน Parent SKU (ทีละตัว / แก้หลายรายการ ≤300 ตัว) | หลังบันทึกเสร็จ คิดค่าของรุ่นนั้นแล้วบันทึกตามหลัง (ไม่ทำให้ปุ่มช้า) |
| ทุกคืน 03:20 (`/api/cron/parent-computed-sync`) | คิดทุกรุ่น บันทึกตัวที่เปลี่ยน (เก็บตกการแก้ตารางเชื่อม / ตั้งบล็อก ⚙ / แก้ทางอื่น) |
| คนกดเอง | `GET` = ลองดูตัวเลข + ตัวอย่างก่อน/หลัง (ไม่เขียน) · `POST` = เขียนจริงทุกรุ่น หรือ `{ ids }` เฉพาะบางรุ่น · ต้องมีสิทธิ์ `products.edit` |

- ค่าที่คำนวณ = ตัวเดียวกับป๊อป Parent SKU / ส่งออกสเปก (`loadParentComputedColumns` ใน `lib/spec-export-server`)
- ส่วนคิด (เทสต์ได้): `lib/parent-computed-sync.ts` · ตัวเขียน: `lib/parent-computed-sync-server.ts`
- ช่องที่เขียน: `SYNCED_PARENT_COMPUTES` = Platform Description (ไทย) + สรุปขนาด

## กติกาความปลอดภัย

- **สูตรได้ค่าว่าง → ไม่ลบข้อความเดิม** (ไม่มีหน้าไหนรายละเอียดหาย) แค่นับไว้ในผล
  - ขนาด "0 x 0 cm." (สินค้าไม่มีกว้าง/สูง) = ว่าง — ลองดูจริง 2026-11-21: 149 รุ่น ในนั้น 111 รุ่นคอลัมน์มีขนาดจาก Odoo อยู่ ห้ามทับ
- **ตัดช่องว่างหัว-ท้าย** ก่อนเทียบ/เขียน (สูตรขึ้นต้นด้วยช่องว่างทุกรุ่น) — ผลลองดูหลังแก้: รายละเอียดเปลี่ยนจริง ~649 รุ่น (เนื้อหาต่าง 474 · ที่เหลือต่างแค่การขึ้นบรรทัด) · ขนาด 30 รุ่น
- **ย้อนได้:** ค่าเดิมของ Platform Description เก็บในประวัติเวอร์ชัน (`entity_field_history` · source `computed_sync` · ป้าย "ระบบอัปเดตตามสูตร")
- **ประวัติ:** ทุกรอบที่มีการเปลี่ยนลง audit `parent_computed:sync` (ทีละตัว = มีค่าเดิม→ใหม่ · ทั้งหมด = รายชื่อรหัสที่เปลี่ยน)
- **ลำดับ "แก้ล่าสุด" ไม่สลับ:** ทริกเกอร์ `parent_skus_v2_touch_updated_at` (migration `202612210100_parent_computed_touch`) คง `updated_at` เมื่อแก้แค่ช่องคำนวณ — แก้ช่องอื่นยังขยับเวลาเหมือนเดิม
- ไม่แตะร้านค้า

## ยังไม่ทำ (ต้องให้เจ้าของตัดสิน)

- **ชื่อบนแพลตฟอร์ม (`name_platform`) และช่อง EN** — คอลัมน์ว่างเกือบทุกตัว (ไม่มีค่าเก่าค้าง) ถ้าเขียน = ชื่อสินค้า/ข้อความ EN บนร้านและเว็บเปลี่ยน
- งานย่อยแบบ "เขียนคำอธิบาย" ยังเลือกปลายทาง `platform_description` ได้ (`lib/subtask-sync`) — ข้อความที่ส่งเข้าไปจะถูกสูตรทับรอบถัดไป (ยังไม่มีใครใช้ 0 ครั้ง)

## โค้ดใหม่ต้องทำยังไง

- อ่าน Platform Description: อ่านคอลัมน์ได้แล้ว (ตรงกับป๊อปหลังบันทึก / ทุกคืน) · ถ้าต้องตรงทันทีแม้เพิ่งแก้ตารางเชื่อม ใช้ `loadParentComputedTexts`
- **ห้าม** เขียนคอลัมน์ช่องคำนวณด้วยมือจากที่อื่น — จะถูกสูตรทับรอบถัดไป ให้แก้ช่องต้นทาง (บทนำ/รายละเอียด/ขนาด/บล็อก ⚙) แทน
