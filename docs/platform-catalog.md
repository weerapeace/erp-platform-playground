# สินค้าบนแพลตฟอร์ม + ระบบเดาคู่สินค้า

หน้า `/master/platform-catalog` — ดูว่าแต่ละร้าน (Shopee / Lazada / TikTok / LINE SHOPPING / เว็บไซต์) มีสินค้าอะไร
แล้ว **จับคู่** กับสินค้าในระบบเรา (Parent SKU) · จับคู่แล้วถึงจะเทียบสต๊อก/ส่งราคาได้ถูกตัว

## หน้าตา (แบบ A + โหมดทีละตัวแบบ B)

| ส่วน | ใช้ทำอะไร | ของกลางที่ใช้ |
|---|---|---|
| ปุ่มเลือกร้าน + จำนวนสินค้า | สลับร้าน · แสดงเฉพาะร้านขายของ (ไม่มี IG/FB/YouTube) · จำร้าน/แบรนด์ล่าสุดในเครื่อง | `lib/selling-platforms` · `PlatformIcon` |
| การ์ดตัวเลข 5 ใบ | ทั้งหมด (+ยังไม่จับคู่) / จับคู่แล้ว (+% · จำนวนรุ่นในระบบ) / รอยืนยัน (ระบบเดาให้) / ต้องหาคู่เอง / ไม่ต้องจับคู่ — **กดการ์ด = กรองตาราง** · รอยืนยัน + ต้องหาคู่เอง = ยังไม่จับคู่ · % จับคู่ไม่นับตัวที่ไม่ต้องจับคู่ · หลายประกาศชี้สินค้าตัวเดียวกันได้ (รุ่น ≤ รายการ) | `components/stat-filter-cards` |
| ตาราง | ชื่อ + SKU + รหัสบนร้าน · ช่อง "จับคู่ในระบบ" มีปุ่มยืนยัน/จับคู่ในแถว · กดแถว = ป๊อปรายละเอียด | `MiniTable` (กางแถว) · `ERPModal` |
| กล่องจับคู่ | คู่ที่ระบบเดา (คะแนน + เหตุผล) + ค้นหาเอง | `components/platform-catalog/match-candidates` + `ParentSkuPicker` |
| ⚡ จับคู่ทีละตัว | คิวซ้าย รายละเอียดขวา · คีย์ลัด 1-3 เลือก · S ข้ามไปก่อน · X ไม่ต้องจับคู่ · ← → เลื่อน | `components/platform-catalog/match-workbench` |
| 🚫 ไม่ต้องจับคู่ | ในแถวที่กาง · ป๊อปรายละเอียด · โหมดทีละตัว (X) · ติ๊กหลายตัว → แถบล่าง · เลือกเหตุผลก่อน · "เลิกข้าม" ได้ทุกเมื่อ | `components/platform-catalog/ignore-dialog` · `BulkActionBar` |
| ✓ ยืนยันทั้งหมดที่รหัสตรงกัน | ยืนยันทีเดียวเฉพาะตัวที่รหัสตรงและไม่กำกวม · ถามก่อนเสมอ · เกิน 100 รายการต้องพิมพ์ "ยืนยัน" | `ConfirmDialog` (requireTyped) |

## ระบบเดาคู่ (ของกลาง)

- กติกา: `lib/platform-match-suggest.ts` (pure, มี test) · อ่าน DB: `lib/platform-match-server.ts`
- API: `GET /api/platform-catalog/suggest?platform_id=&brand_id=` (หรือ `&listing_id=` ขอตัวเดียว) — **แค่เสนอ ไม่บันทึก**
- หน้า "จับคู่สินค้าเร็ว" (`/api/platform-match`) ใช้ตัวเดาตัวเดียวกัน แต่ส่งเฉพาะคู่ที่มั่นใจสูง (เพราะหน้านั้นมีปุ่มยืนยันทั้งหมด)

| คะแนน | เหตุผล | ตัวอย่าง |
|---|---|---|
| 100 | รหัส SKU ตรงกันเป๊ะ | RNG20 = RNG20 |
| 95 | รหัสตรงเมื่อตัดขีด/เว้นวรรค/วงเล็บ · หรือ SKU บนร้านเป็นรหัส SKU ลูกในระบบ | PIN6 = PIN-6 · IG-EQ008 = "IG-EQ008 (ที่ง้างโซ่)" · BSD12-01 → BSD12 |
| 90 | รหัสท้ายชื่อสินค้าตรง (ไฟล์ Shopee หลายตัวไม่มีช่อง SKU) | "…1 ชิ้น DH12" → DH12 |
| 75 | มีรหัสนี้อยู่ในชื่อสินค้า | "TTN สีทาขอบ…" → TTN |
| 60 | รหัสขึ้นต้นเหมือนกัน | LHP-SET → LHP |
| 34-55 | ชื่อคล้ายกัน (ตัดชื่อแบรนด์ก่อนเทียบ) | — |

- รหัสสั้น ≤2 ตัว (PT, CE, CM) หัก 20 · คำตัวเล็กล้วน (cm., ml) ไม่นับเป็นรหัส · ตัวซ้ำ `_DUP_` ไม่เสนอ
- การ์ด "ระบบเดาให้" = คะแนน ≥ 60 · "รหัสตรงกัน" (ยืนยันทีเดียวได้) = ตัวแรก ≥ 90 และไม่มีตัวที่สอง ≥ 90

## บันทึก + สิทธิ์ + ประวัติ

- `POST /api/platform-catalog/match` — `{ listing_id, parent_sku_id }` หรือ `{ items: [...] }` ≤500 · `parent_sku_id` ว่าง = ยกเลิกจับคู่
- สิทธิ์: ดู `products.platforms.view` · จับคู่/นำเข้า/ลบ `products.platforms.edit`
- audit ทุกตัว (`entity_type = platform_catalog`): `from` (คู่เดิม) → `to` (คู่ใหม่) + `source: manual | bulk`

## ไม่ต้องจับคู่ (ข้าม)

- ช่องในตาราง `platform_catalog_listings`: `match_ignored` (ค่าเริ่ม false) · `match_ignore_reason` · `match_ignored_at` (migration `202611020200_platform_catalog_match_ignore`)
- `POST /api/platform-catalog/ignore` — `{ listing_ids ≤500, ignored, reason }` · ข้ามต้องมีเหตุผล · ตัวที่จับคู่อยู่ข้ามไม่ได้ (นับเป็น skipped) · audit `match_ignored` เดิม→ใหม่ + เหตุผล
- สถานะ (`listingMatchStatus` ใน lib/platform-match-suggest): จับคู่แล้ว > ไม่ต้องจับคู่ > รอยืนยัน (ระบบเดา ≥60) > ต้องหาคู่เอง
- จับคู่ตัวที่ข้ามไว้ → `/match` ล้างสถานะข้ามให้เอง · ตัวเดาคู่/หน้าจับคู่สินค้าเร็วไม่โชว์ตัวที่ข้าม · แดชบอร์ด "ยังไม่จับคู่" ไม่นับตัวที่ข้าม
- นำเข้าไฟล์/ดึง LINE รอบหน้าไม่แตะ 3 ช่องนี้ (upsert เฉพาะช่องที่ส่ง)
- เหตุผลที่เลือกล่าสุดจำไว้ในเครื่อง (`platform-catalog:ignore-reason`) · เกิน 100 รายการต้องพิมพ์ "ยืนยัน"

## มุมมองหน้าร้าน (แบบ Seller Center) — 2026-11-08

เจ้าของอยากให้ทีมในแอป "จัดการงาน" ดูสินค้าบนร้านได้ง่ายแบบหน้าสินค้าของ Shopee/LINE → เลือก **แบบ A (แท็บสถานะ + แถวสินค้า) + การ์ดกองงานแบบ D ด้านบน**

- **ไม่ใช่หน้าใหม่** — หน้าเดิมมีปุ่มสลับ "หน้าร้าน / จับคู่ + ตั้งค่า" · `?view=shop` = เปิดมุมมองหน้าร้าน (สลับแล้วเขียน URL ให้)
- **เมนู:** แอปจัดการงาน "สินค้าบนแพลตฟอร์ม" → `/master/platform-catalog?view=shop` (migration `202611240100_tasks_platform_shop_menu`) · แถวเดิม `/master/platform-catalog` ใส่ `tasks` ใน app_keys แต่ `app_overrides.tasks.place = hidden` — เพราะเชลล์ดูว่าหน้าอยู่แอปไหนจาก path อย่างเดียว ไม่งั้นเปิดจากแอปจัดการงานแล้วหัวบนเด้งไปแอปช่องทางขาย
- **ข้อมูล:** `GET /api/platform-catalog?view=shop&platform_id=&brand_id=&with_counts=1` → `ShopViewResponse` · server = `lib/platform-shop-view-server` (select เฉพาะช่องที่ใช้จาก raw ไม่ดึงคำอธิบาย) · อ่านอย่างเดียว
- **กฎกลาง** `lib/platform-listing-health` (pure + เทสต์): สรุป raw → รูปแรก / สต๊อกรวม / เปิด-ปิดขาย / ราคา-ราคาลด / ตัวเลือก / หมวด / สถานะ (`ขายอยู่ · ใกล้หมด ≤3 · หมด · ปิดขาย · รอตรวจ · ไม่รู้สถานะ`) + แท็บ + กองงาน + ชื่อ+รหัสซ้ำ
  - LINE = ครบ · Lazada = สถานะ+สต๊อก ไม่มีรูป · **Shopee (ไฟล์ export) = ไม่รู้สถานะ** ราคา/สต๊อกขึ้น "—" แท็บขึ้น "?" รูปใช้รูปปกของตัวที่จับคู่แล้ว
  - รอตรวจ = เปิด/ปิดขายไม่รู้ (เช่น รายการที่ระบบสร้างขึ้น LINE แล้วยังไม่ได้ดึงกลับ)
  - ซ้ำ = **ชื่อ+รหัสเหมือนกันทุกตัว** (รหัสเหมือนแต่ชื่อต่าง เช่น Shopee BCN32 30/32 มม. = ลงแยกขนาด ไม่นับ)
- **แท็บ:** ทั้งหมด · ขายอยู่ (รวมใกล้หมด) · หมด · ปิดขาย · รอตรวจ · ยังไม่จับคู่ · ยังไม่ลง
  - **ยังไม่ลง** = สินค้าของแบรนด์ (Parent SKU เปิดใช้) ที่ไม่มีรายการบนร้านนี้จับคู่อยู่ → ต้องเลือกแบรนด์ · ยังไม่จับคู่เกิน 20% ขึ้นเตือนว่าเชื่อไม่ได้ (ต่างจาก "ลงแล้ว" ของหน้า 📤 ลงสินค้าบนแพลตฟอร์ม ที่ดูจากร่าง `platform_product_id`)
- **กองงาน (StatFilterCards):** หมดแต่ยังเปิดขาย · ใกล้หมด · ปิดขายอยู่ · รอตรวจ · ไม่มีรูปบนร้าน · ชื่อ+รหัสซ้ำ · ยังไม่จับคู่ · ไม่มีรูปในระบบ (Parent SKU ไม่มีปก — แยก "ไม่มีรูปเลย" กับ "มีรูป SKU/แกลเลอรีแต่ยังไม่ตั้งปก") · โชว์เฉพาะกองที่มีของ
- **งานค้าง:** งานแอปจัดการงานที่สถานะยังไม่ปิด (`erp_creative_statuses.is_terminal = false`, งาน is_active) ผูกผ่าน `erp_creative_task_parent_skus` หรือ `parent_sku_id` ของงาน
- **สร้างงาน:** ปุ่มในแถว / ติ๊กหลายแถว → `CreateTaskModal` (prop ใหม่ `presetProducts` = แบรนด์ + สินค้า + ร้าน เลือกไว้ให้ เปลี่ยนได้) → งาน 1 ใบรวมหลายสินค้า · รายการที่ยังไม่จับคู่ใส่ในงานไม่ได้ (บอกในแถบล่าง) · ต้องมีสิทธิ์ `tasks.create`
- แบ่งหน้า 25/50/100 (Pager) — รูป LINE โหลดจาก CDN ของ LINE ตรง (lazy)

## เฟส 1: เลือกแบรนด์ก่อน + ลงสินค้าขึ้นร้าน (2026-11-08)

เจ้าของขอ: "ต้องเลือกแบรนด์ก่อนเข้า จะได้แยกประเภทได้ชัดเจน" + "เพิ่มสินค้าลงร้านจากหน้านี้ และจาก Parent SKU ได้ด้วย"

- **หน้าเลือกแบรนด์** (`components/platform-catalog/brand-gate`): มุมมองหน้าร้านไม่มี "ทุกแบรนด์" · การ์ด = โลโก้ + สินค้าในระบบ + รายการบนร้านต่อแพลตฟอร์ม + ร้านที่ตั้งไว้ + หมวดกลางตั้งแล้วกี่ตัว · ข้อมูล `GET /api/platform-catalog?view=brands` (ไม่รวมแบรนด์งานลูกค้า) · จำแบรนด์ล่าสุด (localStorage เดิม) · หัวหน้ามีปุ่ม "เปลี่ยนแบรนด์" · เลือกแบรนด์แล้วร้านที่ไม่มีของ → สลับไปร้านที่มีของมากสุด
- **ชิปหมวดกลาง**: กรองการ์ดกองงาน/แท็บ/ตาราง · รายการที่ยังไม่จับคู่ = "ไม่รู้หมวด" · `ShopItem.category_id` (หมวดของสินค้าที่จับคู่) · `ShopViewResponse.categories`
- **ตัวช่วยลงสินค้า** (`components/platform-listing/add-to-platform-wizard` · กฎ `lib/platform-add-plan` pure + เทสต์): เลือกร้าน → ตรวจความครบ → แก้เลย (ProductPlatformManager) / สร้างงานเติม (CreateTaskModal) / ข้าม → ยืนยัน + ผลรายตัว
  - เข้าได้ 3 ปุ่ม: มุมมองหน้าร้าน แท็บ "ยังไม่ลง" (ปุ่ม "ลงร้าน" ในแถว + ติ๊กหลายตัว) · Parent SKU แท็บแพลตฟอร์ม "ลงร้านนี้" · หน้ารายการ Parent SKU ติ๊กหลายรุ่น → "ลงบนแพลตฟอร์ม"
  - ตรวจ = `GET /api/product-platforms/readiness?parent_sku_ids=` (≤200, ใหม่) + `on_shop` · บันทึกร่าง = `/prepare` เดิม · ลงจริง = `/api/line-shopping/create-product` (ร้านที่ `capabilities.api` + มีปลายทางใน `REAL_CREATE_ENDPOINT` — ตอนนี้ LINE) · `/api/platform-accounts` ส่ง `can_publish` เพิ่ม
  - ร้านอื่น (Shopee/Lazada/TikTok/Website) = บันทึกร่างอย่างเดียว (ไฟล์อัปโหลด Seller Center = เฟส 2)
  - สิทธิ์: บันทึกร่าง `products.platforms.edit` · ลงจริง `products.platforms.publish` · สร้างงาน `tasks.create`
- **กันลงซ้ำ** (บทเรียน JEAN08 ถูกสร้างซ้ำบน LINE 6 รายการ ก.ค. 2026):
  1. ตัวช่วยข้ามตัวที่มีบนร้านแล้ว (ร่างมีรหัส หรือมีรายการบนร้านจับคู่อยู่) · ลงจริงทีละตัว · > 20 ตัวต้องพิมพ์ "ยืนยัน"
  2. `create-product` ปฏิเสธถ้ามีรายการบน LINE จับคู่สินค้านี้อยู่แล้ว (409)
  3. `create-product` ล็อกระหว่างสร้างด้วยช่องเดิมของร่าง (`last_sync_status = creating` · ล็อกเกิน 3 นาที = หลุด) · พลาด = `failed` + `last_error` · ไม่แก้โครงตาราง
  - ถ้าร้านตอบพลาดแต่อาจสร้างไปแล้ว → ให้กด "ดึงสินค้าจากร้าน" ก่อนลองใหม่ (ข้อ 2 กันให้หลังจับคู่)
- แท็บแพลตฟอร์มใน Parent SKU: นับ "ลงขายแล้ว" รวมตัวที่มีรายการบนร้านจับคู่อยู่ด้วย (เดิมดูแค่ร่าง)
- **ราคา LINE ไม่มีราคาเต็ม → ใช้ราคาขาย** (เจ้าของตัดสิน 2026-11-08): กฎกลาง `linePrice(fake, sale)` ใน `lib/platform-listing-builder` — ตัวตรวจความครบ · `create-product` · `push-prices` ใช้ตัวเดียวกัน · มีราคาเต็ม = ราคาหลัก + ส่วนลด (เต็ม − ขาย) · ไม่มีราคาเต็ม = ราคาขาย ไม่มีส่วนลด · ไม่มีทั้งคู่ = ไม่ส่ง (เดิมต้องมีราคาเต็ม → IG ลงได้ 5/192 · LM 17/925)

## ซ้ำบนร้าน + ตัวเลือก↔SKU (2026-11-08)

ที่มา: JEAN08 บน LINE มี 6 หน้า (กดสร้างสำเร็จ 6 ครั้งตอนทดสอบ 5–6 ก.ค.) — หน้าจับคู่ทำงานทีละ "หน้าบนร้าน" จึงเห็น 6 แถว และปุ่ม "ยืนยันทั้งหมด" จะจับทั้ง 6 กับรุ่นเดียวกัน

- **ซ้ำบนร้าน** = ชื่อ+รหัสเหมือนกันทุกตัว (`duplicateCounts` ใน `lib/platform-listing-health` — กฎเดียวกับมุมมองหน้าร้าน) · ไม่นับตัวที่ตั้งไม่ต้องจับคู่แล้ว
  - แถวมีป้าย "ซ้ำ ×N" · การ์ดกรอง "ซ้ำบนร้าน" (โผล่เมื่อมี)
  - **"ยืนยันทั้งหมดที่รหัสตรงกัน" ไม่รวมตัวซ้ำ** (ป๊อปยืนยันบอกจำนวนที่ไม่รวม)
  - ป๊อปรายละเอียด: รายการชิ้นที่ซ้ำ + "เปิด" ไปตัวอื่น + **"เก็บตัวนี้ · อีก N ตัวตั้งไม่ต้องจับคู่ (ซ้ำบนร้าน)"** (ConfirmDialog → `/api/platform-catalog/ignore` เหตุผล `IGNORE_REASON_DUP` มีประวัติ) · ตัวอื่นจับคู่อยู่แต่ตัวนี้ยังไม่จับ = ให้ไปเก็บตัวที่จับคู่แทน
  - ของบนร้านจริงไม่ถูกลบ — เจ้าของต้องลบตัวเกินใน Seller Center เอง
- **ตัวเลือกบนร้าน ↔ SKU** (ป๊อปรายละเอียด · LINE/Lazada) — `components/platform-catalog/listing-variants` + `GET /api/platform-catalog?view=variants&listing_id=` + กฎ `lib/platform-variant-match` (pure + เทสต์)
  - หน้าบนร้าน 1 หน้า = Parent SKU (คนกดจับคู่) · ตัวเลือก (สี/ไซซ์) = SKU — **ระบบจับเองด้วยรหัสทุกครั้งที่ส่งราคา/สต๊อก ไม่ได้บันทึกคู่**
  - ลำดับ: รหัสตรงเป๊ะ → ตัดตัวอักษรท้ายเป็นรหัสสี (`baseOfCode` ตัวเดียวกับ push-prices) → ไม่เจอ (ส่งราคา/สต๊อกไม่ได้) · ไม่มีรหัส · เตือน "อยู่คนละรุ่น" เมื่อ SKU ที่เจอไม่ใช่ของรุ่นที่จับคู่
  - อ่านอย่างเดียว (ยังไม่ให้แก้คู่) · LINE ที่ระบบสร้างขึ้นร้านแต่ยังไม่ได้ดึงกลับ = ยังไม่มีข้อมูลตัวเลือก (กด "ดึงสินค้าจาก LINE")
## การ์ด + เรียง + สถานะบนร้าน ในแท็บจับคู่ (2026-11-09)

- **การ์ดใบเดียวสองแท็บ** `components/platform-catalog/listing-card` (`ListingCard` · `ShopStateBadge` · `SHOP_STATE_CLS`) — แท็บจับคู่ + มุมมองหน้าร้าน · สลับ ตาราง/การ์ด ด้วย `LayoutSwitch` ของ MiniTable (จำในเครื่อง) · การ์ด: รูปจากร้าน · สถานะ+สต๊อก · ซ้ำ ×N · ส่วนลด % · ราคาจ่ายจริง · ตัวเลือก · ส่วนท้าย = สถานะจับคู่ (ปุ่มจับคู่/เปลี่ยน ในการ์ดเปิดป๊อปแทนการกางแถว)
- **สรุปรูป/สต๊อก/สถานะ** `GET /api/platform-catalog?view=summary` (`loadListingSummaries` กฎเดียวกับหน้าร้าน) — โหลดตามหลังตาราง เฉพาะ LINE/Lazada · LM ~937 รายการ ≈ 2.7 วิ · ~230KB
- **ตัวเรียง** (จำในเครื่อง `platform-catalog:sort`): งานที่ต้องทำก่อน (ซ้ำ→รอยืนยัน→หาเอง→จับคู่แล้ว) · ชื่อ ก–ฮ ตัวซ้ำติดกัน · ลดราคามากสุด · ลงร้านล่าสุด (เลขสินค้า LINE เรียงตามวันลง — ร้านไม่ส่งวันที่) · ตัวเลือกเยอะสุด · + คอลัมน์ สถานะร้าน/สต๊อก/ราคาจ่ายจริง/ชื่อ (สลับทิศได้) · ยังไม่มี "ขายดี" (ยังไม่ดึงออเดอร์ LINE รายสินค้า)
- **ชิปสถานะบนร้าน** (ใช้ร่วมกับการ์ดกรองจับคู่): หมดแต่ยังเปิดขาย · ใกล้หมด ≤3 · ปิดขาย · รอตรวจ

- ไอคอนใหม่ในทะเบียนกลาง: `table-view` (▤) · `grid-view` (▦)

## ราคาผิดปกติ + ติ๊กยืนยันหลายใบ (2026-11-09)

- **ราคาผิดปกติ** (ชิปในแถว "สถานะบนร้าน" + ป้ายบนการ์ด/ช่องราคา) — กฎ `priceFlags` ใน `lib/platform-listing-health`: ลูกค้าจ่าย < 10฿ · ลดเกิน 80% · **ราคาที่ลูกค้าจ่ายไม่ตรงกับที่ระบบจะส่ง** (LINE ที่จับคู่แล้ว)
  - "ที่ระบบจะส่ง" = `expectedLinePrice` ใน `lib/platform-variant-match` — **push-prices ใช้ตัวเดียวกัน** (ราคาเต็ม/ขาย ของรหัสตัวเอง → รหัสสี → `linePrice`)
  - `linePriceDiff`: "pay" = เงินที่ลูกค้าจ่ายต่าง (นับเป็นผิดปกติ) · "full" = จ่ายตรงแต่ราคาเต็ม/ตัวขีดฆ่าต่าง (ส่วนใหญ่ในระบบไม่มีราคาเต็ม — ไม่นับ) · ข้อมูลจริง LM 2026-11-09: จับคู่ 871 → pay 284 รุ่น (2,000 ตัวเลือก) · full อย่างเดียว 494 · ตรง 93
  - ตารางตัวเลือกในป๊อปมีคอลัมน์ "ราคาที่ระบบจะส่ง" (แดง = จ่ายไม่ตรง · ส้ม = แค่ราคาเต็ม) + เตือนว่ากด "ส่งราคา" แล้วบนร้านจะเปลี่ยนเป็นตามคอลัมน์นี้
  - ⚠️ กด "ส่งราคาทั้งหมด" ตอนนี้ = ราคาลูกค้าจ่ายเปลี่ยน ~284 รุ่น + ตัวขีดฆ่าหาย ~494 รุ่น → ให้เจ้าของตรวจราคาในระบบก่อน
- **ติ๊กแล้วยืนยันคู่ที่ระบบเดา** (BulkActionBar "ยืนยันคู่ที่ระบบเดา (N)") — ใช้ฟังก์ชันเดียวกับ "ยืนยันทั้งหมดที่รหัสตรงกัน" (`confirmMany`) · ไม่รวมตัวซ้ำบนร้าน · ป๊อปบอกจำนวนที่มั่นใจ (รหัสตรง) vs เดาจากชื่อ + คะแนน % · เกิน 100 ต้องพิมพ์ "ยืนยัน"

- ตารางกลาง MiniTable: เส้นแบ่งหัวคอลัมน์เห็นตลอด · ลากด้วยนิ้วได้ · ดับเบิลคลิกเส้น = พอดีเนื้อหา (กระทบทุกตารางที่เปิด `resizable`) · ตารางหน้าร้านเปิดปรับความกว้างแล้ว

## ป้าย "ไม่อยู่บนร้านแล้ว" อัตโนมัติ (2026-11-09)

- **ใครติด:** `upsertCatalogListings({ markMissing: true })` ใน `lib/platform-catalog-sync` — ส่ง markMissing เฉพาะตอน "ดึงได้ครบทั้งร้าน"
  - LINE (`/api/line-shopping/sync-products`): เลขสินค้าไม่ซ้ำ ≥ ยอดที่ LINE รายงาน (totalRow)
  - Lazada (`/api/lazada/sync-products`): ไม่หมดเวลา/ไม่ล้มกลางทาง + ครบตามยอดที่ Lazada รายงาน (filter=all ไม่รวมตัวที่ลบ → ไม่เจอ = ร้านลบแล้ว · ตัวปิดขายยังมาครบ)
  - นำเข้าไฟล์ (Shopee) **ไม่ติด** — ไฟล์อาจ export มาไม่ครบ
- **ติดยังไง:** ช่อง `status` = `"removed"` (`LISTING_GONE_STATUS`) — ไม่เพิ่มคอลัมน์ · **ไม่ลบแถว** (คนกดล้างเอง) · ข้ามแถวที่ไม่มีเลขบนร้าน
- **กันพลาด:** จะติดเกินครึ่งร้าน (`GONE_GUARD_RATIO`) และเกิน 20 ตัว (`GONE_GUARD_MIN`) = ไม่ติด → ผลลัพธ์ `removed_skipped` + ข้อความเตือนในหน้า (สงสัยดึงมาไม่ครบ)
- **ล้างป้ายเอง:** รอบไหนเจอกลับมาบนร้าน → status กลับเป็นค่าจากร้าน (หรือว่าง) · นับใน `restored`
- **หน้าตา:** สถานะ `gone` ใน `ShopState` (ป้ายเทาเส้นประ · รูปการ์ดจางขาวดำ · สต๊อกเป็น —) · `listingMatchStatus` → `"gone"` ชนะทุกสถานะ
  - แท็บจับคู่: "ทั้งหมด" ไม่รวมตัวที่ไม่อยู่บนร้าน · การ์ด "ไม่อยู่บนร้านแล้ว" (โชว์เมื่อมี) → แถบอธิบาย + ปุ่ม **ล้างรายการที่ไม่อยู่บนร้าน (N)** · ปุ่ม "ล้างออก" ในแถว · ติ๊กหลายตัว → BulkActionBar "ล้างที่ไม่อยู่บนร้าน"
  - หน้าร้าน: แท็บ/กอง "ไม่อยู่บนร้านแล้ว" (โชว์เมื่อมี) · ไม่ปนแท็บอื่น · ไม่นับเป็นตัวซ้ำ/ยังไม่จับคู่/ยังไม่ลง
- **ล้าง:** `DELETE /api/platform-catalog` body `{ gone_ids }` (≤500) — server ลบเฉพาะแถวที่ status = removed จริง · audit ทีละแถว (`reason: gone_from_shop` + snapshot)
- **งานที่ไม่นับตัวที่ไม่อยู่บนร้าน** (ตัวกรองกลาง `.or(LIVE_LISTING_OR)` — อย่าใช้ `.neq` อย่างเดียว ตัด null ทิ้ง): ตัวเดาคู่ · ส่งราคา/รายละเอียดขึ้น LINE · กันสร้างซ้ำบน LINE (ร้านลบแล้วลงใหม่ได้) · ความพร้อมลงร้าน · ตัวเลขบนปุ่มเลือกร้าน · การ์ดแบรนด์ · แดชบอร์ดแพลตฟอร์ม
- ข้อมูลจริง ณ วันทำ: LINE ทั้งหมด status ว่าง (934 แถว) · ดึงรอบล่าสุดเจอครบ → ยังไม่มีตัวที่ติดป้าย จนกว่าร้านจะลบสินค้า

## ตัวช่วยลงสินค้า 3 ขั้น + ดูและแก้ก่อนส่งขึ้น LINE (2026-11-10)

- เจ้าของขอ: "ต้องบอกด้วยว่ารายละเอียดจะดึงอะไรไปบ้าง แก้ได้ด้วย ทำให้ดูง่ายด้วย" → `AddToPlatformWizard` เหลือ 3 ขั้น: **เลือกร้าน → ดูและแก้รายละเอียด → ยืนยัน**
  - ขั้น 1: ร้านที่ลงจริงได้ (LINE) เป็นการ์ดเด่น · ร้านอื่น (บันทึกร่าง) พับไว้ พร้อมตัวเลือก "ราคาในร่าง / ร่างเดิม" (ไม่มีผลกับ LINE — LINE ใช้ราคาในระบบเสมอ)
  - ขั้น 2: เข้าขั้นนี้ = บันทึกร่าง LINE ให้ก่อน (เติมเฉพาะช่องที่ว่าง) → `LineCreatePreviewEditor` (components/platform-listing/line-create-preview) ทีละสินค้า (มีแถบเลือกสินค้าเมื่อหลายตัว · ข้ามตัวนี้ · สร้างงานให้ทีมเติม) · ร้านอื่นยังเป็นรายการความครบ + แก้เลย/สร้างงานเติม/ข้าม
  - กด "ถัดไป: ยืนยัน" = ตรวจความครบใหม่ก่อน (ใช้ข้อมูลหลังแก้) · ตอนลงจริง บันทึกร่าง LINE แบบไม่เขียนทับ (ไม่ลบสิ่งที่แก้)
- **ดูก่อนส่ง = ส่งจริง:** ของกลาง `lib/line-create-payload` (`buildLineCreate`) ใช้ทั้ง `GET /api/line-shopping/create-product?parent_sku_id=` (preview) และ `POST` (สร้างจริง) — ห้ามประกอบ payload แยกที่อื่น
  - ทุกช่องบอก "มาจาก": ชื่อ (ร่าง → ชื่อสำหรับแพลตฟอร์ม → ชื่อสินค้า) · หมวด (หมวดกลาง → หมวด LINE / เลือกไว้) · แบรนด์ · รายละเอียด · น้ำหนัก · รูป · ราคา (SKU ไหน — สืบทอดจากตัวสีบอก "จาก X") · สต๊อก
  - ช่องที่ขาด (`missing`) + ด่าน (`blockers`: มีบน LINE แล้ว / ไม่มีแบรนด์ / ไม่มี API Key) ขึ้นแดงด้านบน · ไม่ส่งตอนลง: บาร์โค้ด, ขนาดกล่อง
- **แก้แล้วไปเก็บที่ไหน:**
  - ชื่อ / รายละเอียด / หมวด → ร่าง LINE (`PATCH /api/product-platforms`) · แบรนด์ / น้ำหนัก → ร่าง `extra.brand` / `extra.weight` — ไม่เปลี่ยนข้อมูลสินค้าในระบบ
  - รูป → ร่าง `extra.line_images` (ใหม่: มีค่า = ใช้ตามนั้นเป๊ะ ≤7 · ปุ่ม "กลับไปใช้รูปอัตโนมัติ" = ล้างกลับ) · หน้าดูก่อนส่งโชว์ **รูปทั้งหมดของสินค้า** (ปก/แกลเลอรี/สี/SKU/รูปในรายละเอียด) ให้ติ๊กเลือก + ลากเรียง
- **รายละเอียด = HTML ย่อหน้า:** ในระบบเป็นข้อความธรรมดา (1,470/1,470) แต่ LINE เก็บเป็น HTML (920/934) → เดิมส่งข้อความดิบ = ขึ้น LINE ติดกันเป็นก้อนเดียว · ตอนนี้แปลงด้วยของกลาง `noteToHtml(text, LINE_DESC_HTML)` (lib/rich-note — เพิ่มตัวเลือก keepBlankLines/keepIndent/bullets ค่าเริ่มเหมือนเดิม) เก็บบรรทัดว่าง + ย่อหน้าเยื้อง · ขีด "- " คงเป็นข้อความ · หน้าดูก่อนส่งแสดงแบบเดียวกับที่ LINE จะเห็น · ⚠️ ยังไม่ได้ลองส่ง &nbsp; ขึ้น LINE จริง
  - **ราคา → เปลี่ยนราคาในระบบ** (`POST /api/product-platforms/sku-price` · audit `sku_price` · ต้องมีสิทธิ์ products.edit) — เจ้าของเลือก 2026-11-10 ให้ราคามีที่เดียว (ไม่งั้นปุ่มส่งราคาทั้งหมดจะทับกลับ) · ราคาที่สืบทอดจากตัวสี → แก้ที่ตัวสี

## ลงร้านอื่นจากรายการนี้ — เฟส 1: ไป LINE (2026-11-10)

เจ้าของอยากเอาสินค้าที่ลงบน Lazada/Shopee แล้ว ไปลง LINE ได้เลยโดยใช้ข้อมูลบนร้านเดิม (ตัวที่ร้านไม่มี ใช้ Parent SKU → SKU) · แผนทั้งหมด 4 เฟส: 1 LINE (ทำแล้ว) · 2 ไฟล์ Excel ของ Shopee (ไม่แตะร้าน · ต้องได้แม่แบบจาก Seller Centre) · 3 สร้างสินค้าบน Lazada (ย้ายรูป + ช่องบังคับต่อหมวด) · 4 สร้าง Parent SKU จากรายการที่ยังไม่มีในระบบ

- **ทางเข้า:** ลิ้นชักสินค้าบนร้าน (Lazada/Shopee ที่จับคู่แล้ว) ปุ่ม "ลงร้านอื่นจากรายการนี้" · มุมมองหน้าร้าน ติ๊กหลายรายการ → แถบ "ลงร้านอื่น (N)" (≤ `COPY_MAX_ITEMS` 50 — Lazada ต้องดึงสดทีละตัว) · ไม่จับคู่ = ไม่โผล่ (ต้องจับคู่ก่อน)
- **ไม่ใช่ตัวช่วยใหม่:** `AddToPlatformWizard` prop `sources` (parent id → รายการต้นทาง) · ร้านต้นทางไม่ให้เลือกเป็นปลายทาง · เข้าขั้น 2 = เตรียมร่าง LINE (เดิม) → `POST /api/platform-listing/copy {action:"apply"}` ทีละตัว (ค่าเริ่ม) → `CopyMappingTable` อยู่เหนือหน้าดูก่อนส่ง (`LineCreatePreviewEditor`) · ลงจริง = `create-product` เดิม (อ่านร่าง) · ขั้นยืนยันไม่ทับร่าง LINE ที่คัดลอกมา
- **กฎ (pure + เทสต์ `lib/__tests__/listing-copy.test.ts`):** `lib/listing-copy-source` แปลงร้านต้นทางเป็นหน้าตาเดียว — LINE `raw.line` (ครบ) · Lazada ดึงสด `loadLazListingLive`+`lazadaListingView` (สำเนาย่อในระบบไม่มีรูป/รายละเอียด · ดึงไม่ได้ = ใช้สำเนาย่อ + เตือน) · Shopee ไฟล์ = ชื่อ+รายละเอียดเท่านั้น · `lib/listing-copy-map` = `planCopy` / `applyCopyChoices` / `priceFills`
  - ช่องที่เลือกแหล่งได้: ชื่อ · รายละเอียด (HTML → ข้อความ ตัดรูป · จุดเด่น Lazada อยู่บนสุด) · รูป (≤7 · ลิงก์ของร้านต้นทาง ส่งตรง) · แบรนด์ (No Brand = ไม่นับ) · น้ำหนัก
  - ค่าเริ่ม: ร่างที่คนแก้ไว้ = คงไว้ · ร้านต้นทางมี = ใช้ของร้าน · ไม่งั้นข้อมูลในระบบ · "ข้อมูลในระบบ" = ล้างช่องในร่าง ให้ตัวสร้างใช้ของ Parent SKU
  - หมวด: ไม่แปลงหมวดร้านต่อร้าน — หมวดกลางของสินค้า → หมวด LINE (`platform_category_mappings`)
  - ตัวเลือก: LINE สร้างจาก SKU ในระบบเสมอ · จับกับร้านต้นทางด้วยรหัส SKU (บอกตัวที่มีฝั่งเดียว)

## กับดักที่แก้แล้ว

- **เลือก Lazada แต่ตารางโชว์ของ Shopee** — คำตอบของร้านเดิมที่มาช้ามาทับ → ทุกการโหลดมีเลขรอบ ทิ้งคำตอบของรอบเก่า + ล้างตารางทันทีที่สลับร้าน
- **ร้านที่มีสินค้าเกิน 1,000 ตัวหายครึ่ง** — GET `/api/platform-catalog` เดิม `.limit(5000)` แต่ PostgREST ตัดที่ 1,000 → ใช้ `fetchAllPages`
- **แดชบอร์ดแพลตฟอร์มนับสินค้าบนร้านขาด** — `/api/platform-dashboard` `.limit(20000)` โดนตัดที่ 1,000 (มี ~1,200) → `fetchAllPages`
