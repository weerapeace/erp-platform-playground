# 🔔 แจ้งเตือนเว็บร้านอัตโนมัติ — LINE พนักงาน · LINE ลูกค้า · ตะกร้าค้าง · ของถูกใจลดราคา (ชุด 5)

ทุกอย่าง **ปิดไว้ก่อน** · พังแล้วเงียบ ไม่ทำให้สั่งซื้อ/บันทึกล้ม · ตั้งที่ ERP › เว็บไซต์ › ร้าน › 🏪 ข้อมูลร้าน › 🔔 แจ้งลูกค้าอัตโนมัติ

## 1) แจ้งพนักงานในกลุ่ม LINE "🛍 เว็บร้าน"
ใช้บอทบริษัทเดิม (ศูนย์ LINE) · ตั้งกลุ่มที่ ERP › ศูนย์ LINE › 🛍 กลุ่มเว็บร้าน · เปิด/ปิดรายเหตุการณ์ + แก้ข้อความได้ที่เดียวกัน
- 🛒 ออเดอร์เว็บใหม่ (`webshop_order`) — ทั้งลูกค้าทั่วไปและสมาชิก
- 💳 ลูกค้าแนบสลิปที่ต้องให้คนตรวจ (`webshop_slip`) — ตรวจผ่านอัตโนมัติแล้วไม่แจ้ง
- ↩️ ลูกค้าขอคืน/เปลี่ยน (`webshop_return`)
ยังไม่ตั้งกลุ่ม = ไม่ส่ง (ไม่ตกไปกลุ่มอื่น)

## 2) แจ้งลูกค้าทาง LINE OA ของร้าน (`line_notify_enabled`)
สถานะออเดอร์ (สั่งแล้ว · จ่ายแล้ว · ส่งแล้วพร้อมเลขพัสดุ · สำเร็จ · ยกเลิก · คืนเงิน) ถ้อยคำเดียวกับอีเมล + ผลคำขอคืน/เปลี่ยน
ส่งได้เมื่อครบ 3 ข้อ:
1. ลูกค้าเป็นสมาชิกที่ **เข้าสู่ระบบด้วย LINE** และแอดเพื่อน OA ร้านแล้ว
2. ตั้ง `LINE_OA_TOKEN_<รหัสร้านตัวใหญ่>` ใน Vercel โปรเจกต์ ERP (Channel access token ของ OA ร้าน — ความลับ) เช่น `LINE_OA_TOKEN_LOUISMONTINI`
3. LINE Login ของเว็บกับ OA อยู่ **Provider เดียวกัน** ใน LINE Developers (ไม่งั้นรหัสลูกค้าไม่ตรงกัน LINE จะปฏิเสธ)

## 3) 🛒 เตือนลืมของในตะกร้า (`cart_reminder_enabled` · `cart_reminder_hours` 2–72 ค่าเริ่ม 6)
- เปิดแล้ว เว็บร้านส่งตะกร้าของ **สมาชิกที่เข้าสู่ระบบ** ไป ERP (หน่วง 3 วิ · ของเหมือนเดิมไม่ส่งซ้ำ) → ตาราง `store_member_carts`
- ทิ้งไว้เกินชั่วโมงที่ตั้ง (แต่ไม่เกิน 7 วัน) → อีเมล + LINE **1 ครั้งต่อชุดของ** (เปลี่ยนของ/จำนวนแล้วเตือนได้อีก) · สั่งซื้อแล้ว = ล้างตะกร้าที่เก็บไว้
- ลิงก์ไปหน้า /cart · ⚠️ ตะกร้าจริงอยู่ในเครื่องลูกค้า — เปิดลิงก์จากเครื่องอื่นตะกร้าจะว่าง (ในข้อความมีชื่อสินค้าให้ค้นต่อได้)

## 4) ❤️ ของที่ถูกใจลดราคา (`wishlist_alert_enabled` · `wishlist_alert_pct` 1–90 ค่าเริ่ม 5)
- ราคาอ้างอิง = ราคาบนเว็บ **ครั้งแรกที่ระบบตรวจ** หลังกดใจ (`store_wishlists.price_at_add`)
- ราคาตอนนี้ (สูตรเดียวกับหน้าเว็บ · ราคาต่ำสุดของตัวเลือก · ไม่รวมโปรอัตโนมัติ/คูปอง) ต่ำกว่าอ้างอิง ≥ % ที่ตั้ง → แจ้ง (รวมสูงสุด 5 ชิ้นต่อข้อความ)
- แจ้งราคานี้ไปแล้วไม่แจ้งซ้ำ (`alerted_price`) · ลดลงอีกแจ้งได้อีก · ของที่ตั้ง "หมด"/ไม่เปิดขาย ไม่แจ้ง

## 5) 🔔 แจ้ง "มีของแล้ว / ชุดเปิดขาย" อัตโนมัติ (`restock_auto_enabled` · 2026-10-28)
ต่อยอดปุ่มเดิม "แจ้งฉันเมื่อมีของ" (ตาราง `store_restock_requests` · แท็บ 🏪 ข้อมูลร้าน › 🔔 รอแจ้งของเข้า) — เจ้าของเลือก: ทุกคน · ส่งอัตโนมัติ · ของหมด + ชุดรอเปิด
- ถึงเวลาแจ้ง = สินค้ากลับมา "เผยแพร่ + ไม่ได้ตั้งหมด" · ชุดมาใหม่ถึงเวลาเปิด (`restockReady`)
- ฝาก **อีเมล** → ระบบส่งอีเมลเอง (ต้องตั้งระบบอีเมลแล้ว — ยังไม่ตั้ง = คงไว้ในรายชื่อ) · **สมาชิก** (กดปุ่ม "แจ้งเข้าบัญชีของฉัน") → LINE ที่เข้าระบบไว้ ไม่ได้ = อีเมลที่ยืนยันแล้ว
- ฝาก **เบอร์โทร / LINE ID** = ร้านติดต่อเองเหมือนเดิม (ระบบส่งให้ไม่ได้)
- ไม่ต้องยินยอมรับข่าวสาร — ลูกค้าขอเองรายครั้ง · ข้อความบอกว่าส่งครั้งเดียว · ส่งแล้ว status = notified + `auto_channel` (ป้าย 🤖 ในรายชื่อ) + audit `notify`
- 🔒 จองแถวก่อนส่ง (pending → notified) · ส่งไม่ได้สักทาง = คืนเป็นรอ (รอบหน้าลองใหม่)
- เปิดแล้ว: การ์ดชุดที่ยังไม่เปิด (SoonCard) มีปุ่ม "แจ้งฉันตอนเปิดขาย" · สมาชิกที่เข้าระบบอยู่มีปุ่มกดครั้งเดียว · ปิด = แบบเดิมทุกอย่าง
- ERP รายชื่อ: แถวชุด "🆕 ชุด …" · สมาชิก "👤 ชื่อ" · ปุ่ม "⚡ ส่งที่พร้อมตอนนี้" (เรียกรอบตรวจของร้านทันที)
- ไฟล์: `lib/webshop-reminders.ts` (restockReady / restockAlertMessage) · `lib/webshop-reminders-db.ts` runRestockAlerts · `lib/website-restock-db.ts` (ตรวจเป้าหมาย) · `/api/public/storefront/restock` (+dropId) · `/api/storefront-member/restock` · migration `202611050100_store_restock_auto` (drop_id · customer_id · auto_channel · contact_type member) · เว็บร้าน `RestockNotify` + `RestockConfig` + SoonCard · `/api/member/restock`

## ใครได้รับ (ข้อ 3–4)
เฉพาะสมาชิกที่ **ยินยอมรับข่าวสาร** (`marketing_opt_in` · PDPA) และบัญชียังใช้งานได้ · อีเมลต้องยืนยันแล้ว · ทุกข้อความบอกวิธีปิดรับ · ส่งแล้วจดใน audit log (`notify`)
อีเมลต้องตั้ง `RESEND_API_KEY` + `EMAIL_FROM` ก่อน (ยังไม่ตั้ง = ส่งได้แค่ LINE)

## รอบตรวจ (ทำไมไม่ใช่ cron)
Vercel Hobby ตั้ง cron ได้ 2 ตัว (ใช้ครบแล้ว) → ระบบตรวจ "ระหว่างทาง" หลังตอบคำขอ ห่างกันอย่างน้อย **30 นาทีต่อร้าน**:
ลูกค้าเปิดเว็บ (ตัวนับสถิติ) · พนักงานเปิดแท็บออเดอร์ · หรือเรียก `/api/cron/webshop-reminders` (CRON_SECRET หรือสิทธิ์ products.edit · `?shop=<slug>`)
กันส่งซ้ำ: จองแถวด้วยเงื่อนไขในคำสั่ง update ก่อนส่ง (2 รอบชนกัน = คนเดียวได้ส่ง) · ส่งไม่สำเร็จไม่ลองใหม่ (ไม่สแปม) · เวลารอบล่าสุดเก็บที่ `store_settings.reminders_last_run`
