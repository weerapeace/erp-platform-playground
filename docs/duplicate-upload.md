ยังไม่ใส่ (ตั้งใจ):
- 📸 ลงรูปเว็บทีละมาก (`website-image-mass-upload`) — ไม่ใช้ป๊อป (อัปเบื้องหลัง) · ตรวจในหน้าตรวจก่อนลงแทน: รูปซ้ำกันเองในชุดที่ลากมา (ป้าย "ซ้ำ #n" / "= -01 #n" · ไฟล์เดียวกันเป๊ะอัปครั้งเดียว) + "ซ้ำเดิม" กับรูปบนเว็บ · เทียบกับคลัง (ป้าย ใช้รูปเดิม/อัปใหม่) รอฟังก์ชันตรวจแบบไม่เด้งป๊อป
- 📂 จัดรูปหลายโฟลเดอร์ (`product-image-router`) — อัปทีละหลายร้อยไฟล์เบื้องหลัง (ปิดหน้าต่างได้) · ป๊อปถามกลางงานใช้ไม่ได้
- รูปที่วาง/แทรกในโน้ตอ้างอิงของงาน (RichTextEditor ใน `task-detail-drawer`) — ส่วนใหญ่เป็นภาพแคปหน้าจอ (ไม่ซ้ำ) และตัวแก้ข้อความต้องได้ URL กลับทันที ไม่มีจังหวะ "ยกเลิก"

## ใช้ทำอะไร
ก่อนส่งรูปขึ้นที่เก็บไฟล์ ระบบเช็กว่า "รูปนี้มีในคลังกลางอยู่แล้วไหม" — ถ้ามี ถามผู้ใช้ว่า **ใช้รูปเดิม** หรือ **อัปโหลดใหม่**
ใช้รูปเดิม = ไม่ส่งไฟล์ซ้ำ ไม่กินพื้นที่ (เดิม `/api/admin/upload` เก็บไฟล์ลง R2 ก่อนแล้วค่อยกันซ้ำแค่แถวในคลัง → ไฟล์ซ้ำยังกินพื้นที่)

- ซ้ำ 1 รูป → ป๊อปเทียบรูปใหม่กับรูปเดิมแบบเต็ม (ชื่อ / ขนาด / อัปเมื่อ / โดย / แท็ก / ใช้อยู่ที่ไหน)
- ซ้ำหลายรูป → ป๊อปสรุปทุกรูป เลือกรายรูป หรือ "ใช้รูปเดิมทั้งหมดที่ซ้ำ" / "อัปใหม่ทั้งหมด" + บอกว่าประหยัดได้กี่ KB
- รูปที่อยู่ในช่องนี้แล้ว (`existingKeys`) → เสนอ "ข้าม"
- ไม่ซ้ำเลย → อัปทันที ไม่ถาม · ตรวจไม่สำเร็จ (เน็ต/คลังมีปัญหา) → อัปตามปกติ ไม่ขวางงาน

## วิธีใช้
```ts
import { uploadImagesWithDupCheck } from "@/components/duplicate-upload";

const r = await uploadImagesWithDupCheck(files, {
  folder: "storefront-products", max: 2000,      // เหมือน uploadResizedImage
  target: "แถวสี TTM002 · แทน",                    // บอกผู้ใช้ว่ากำลังอัปเข้าที่ไหน
  existingKeys: currentKeys,                       // r2_key ที่อยู่ในช่องนี้แล้ว
  onError: (f, e) => toast.error(`อัปโหลด ${f.name} ไม่สำเร็จ: ${e.message}`),
});
if (!r) return;               // กดยกเลิก → ไม่อัปอะไร
add(r.keys);                  // key รูปเดิม + รูปใหม่ เรียงตามไฟล์ที่เลือก · r.uploaded / r.reused / r.skipped
```
เด้งป๊อปไม่ได้ (เช่นลงรูปทีละมาก ตรวจเบื้องหลังตอนผู้ใช้ยังจัดรูป) ใช้ `findDuplicateMatches([{ file, original? }], { existingKeys })`
→ ผลต่อไฟล์เรียงตามที่ส่ง (`null` = ไม่ซ้ำ) `{ match, kind: "same" | "look", here, unsure, newSize?, decision }` · `decision` = ค่าตั้งต้นแบบเดียวกับในป๊อป
· ส่งกี่ไฟล์ก็ได้ (แบ่งคำขอทีละ 20 ไฟล์ให้เอง) · ชุดที่ตรวจไม่สำเร็จ = null ทั้งชุด

ช่องที่อัปไฟล์เองแบบอื่น (ไม่ย่อด้วย canvas) ใช้ `askDuplicateUploads([{ file, original? }], opts)` → ได้แผนต่อไฟล์ (`reuse` = รูปเดิมในคลัง · `null` = อัปใหม่ · ไฟล์ที่ข้ามไม่อยู่ในผล · `null` ทั้งก้อน = ยกเลิก)

## ตรวจซ้ำแบบไหน (2 ระดับ)
1. **ไฟล์เดียวกันทุกจุด** — ลายนิ้วมือไฟล์ (sha256) ของ **ไฟล์หลังย่อ** และ **ไฟล์ต้นฉบับ** เทียบกับ `assets.checksum` (มี index) → ป้ายเขียว "ไฟล์เดียวกันทุกจุด"
2. **หน้าตาเหมือนกันแต่คนละไฟล์** (เซฟใหม่ / ย่อคนละขนาด / บีบอัดใหม่ / รูปปก SKU จาก Odoo) — ลายนิ้วมือหน้าตารูป `lib/image-hash.ts`
   - ย่อรูปเหลือ 256px บนพื้นขาว → รูปทรง (เทียบความสว่างช่องติดกัน 128 บิต) + ภาพจิ๋วสี 16×16 ช่อง
   - **ต้องเทียบสีเสมอ**: รูปสินค้าที่ถ่ายแบบเดียวกันคนละสี (ด้ายหลอด/ซิป) รูปทรงตรงกันเป๊ะเป็นร้อยรูป → ถ้าดูแค่รูปทรงจะเสนอรูปผิดสี
   - เบราว์เซอร์ (`lookHashOfBlob`) กับเซิร์ฟเวอร์ (`lib/image-hash-server` · sharp) ให้ค่าตรงกัน (ทดสอบแล้วรูปทรงต่างกัน 0–3 บิต)
   - เก็บที่ `assets.phash` / `assets.phash_color` · RPC `find_look_alike_assets` (service role เท่านั้น) คัดรูปทรงใกล้ แล้ว API เทียบสีต่อ
   - เกณฑ์ `LOOK_MAX_BITS` / `LOOK_MAX_COARSE` / `LOOK_MAX_FINE` ใน `lib/image-hash.ts`

### ความแม่น (วัดจากคลังจริง 2026-11-01 · 10,555 รูป)
- รูปเดียวกันที่ทำเป็นคนละไฟล์ (ย่อครึ่ง / ย่อ 1600 / webp / png / ย่อเหลือ 400) → จับได้ ~96%
- รูปซ้ำจริงในคลัง (Odoo เก็บรูปเดียวกันหลาย SKU) สีต่าง ≤ 2.4 · ด้ายคนละเฉดที่ใกล้กันสุด (ส้ม #744 กับ #939) ต่าง ≥ 4 → ไม่ถูกจับ
- ห่วงคนละขนาดที่ต่างแค่ตัวเลขบนรูป → ผ่านรูปทรง+สี แต่ถูกขั้นเทียบรายละเอียดตัดทิ้ง (18–59 · รูปซ้ำจริง 2–10)
- ทดสอบจริงในเบราว์เซอร์: รูปเว็บที่เซฟใหม่ → เจอรูปเดิม · ด้าย #462 → เจอ SKU #462 ไม่ใช่เฉดข้างเคียง · ห่วง 31 มม. → เจอตัวเอง ไม่ใช่ 15 มม.
- ค้นในฐานข้อมูล: 1 ไฟล์ ~60ms (กลุ่มด้ายหลอดที่หนักสุด) · 20 ไฟล์พร้อมกัน ~1.3 วิ
- รูปที่แต่งแล้ว (ครอปขอบ / ปรับแสง) ตั้งใจให้ "ไม่จับ" — ถือเป็นคนละรูป
   - **ขั้นสุดท้ายในเบราว์เซอร์**: เทียบรายละเอียดกับรูปเดิมจริง (proxy `?w=960&q=90` · ตารางเทา 48×48 · `detailGridOfBlob`)
     เพราะรูปทรง+สีมองไม่เห็นตัวหนังสือเล็ก ๆ — รูปห่วงคนละขนาดที่ใช้รูปเดียวกัน ต่างกันแค่ตัวเลข "31 มม." / "15 มม."
     ≤ `DETAIL_SURE` = เหมือนชัด · ≤ `DETAIL_MAX` = ก้ำกึ่ง (ถาม แต่ตั้งต้น "อัปใหม่" + เตือน "ตรวจดูก่อนใช้รูปเดิม") · เกิน/เทียบไม่ได้ = ไม่ถาม
   - ป้ายส้ม "หน้าตาเหมือนกัน (คนละไฟล์)" + เครื่องหมาย ≈ · ถ้ารูปใหม่ละเอียดกว่ารูปเดิมเกิน 15% → ตั้งต้นเป็น "อัปโหลดใหม่" + เตือน "รูปใหม่ละเอียดกว่า"
   - รูปเรียบ (ขาวล้วน/สีเดียว) ไม่มีลายนิ้วมือ → ตรวจได้แค่ระดับ 1

**ห้ามกันซ้ำด้วยชื่อไฟล์** — รูปเว็บชื่อ 1.jpg … 5.jpg ซ้ำกันเป็นร้อยรูป (คนละรูป)

ลายนิ้วมือภาพมี 2 รุ่น: `lib/image-similarity` (รุ่นเบา เทียบในเบราว์เซอร์ล้วน · เครื่องมือลงรูปทีละมาก "เตือนให้ดูด้วยตา")
กับ `lib/image-hash` (รุ่นนี้ · ค้นทั้งคลังจากฐานข้อมูล · แม่นพอจะ "เสนอใช้รูปเดิม") — งานใหม่ที่ต้องเทียบกับคลังให้ใช้ `lib/image-hash`

### ลายนิ้วมือของรูปในคลังมาจากไหน
- อัปผ่าน `/api/admin/upload` → คำนวณทันทีตอนลงคลัง (พร้อมเก็บกว้าง×สูง)
- เข้าคลังทางอื่น (คลังกลาง / Google Drive / รูปแม่ / งานพิมพ์ ฯลฯ) → cron รายวัน `/api/cron/asset-look-hash` เติมให้รูป 7 วันล่าสุด
- รูปเก่าทั้งหมด → เติมครั้งเดียวด้วยสคริปต์ (2026-11-01)

## ข้อควรรู้
- "ใช้รูปเดิม" = หลายที่ใช้ไฟล์ R2 ตัวเดียวกัน (เหมือนเลือกจากคลัง) → ห้ามลบไฟล์ R2 ตอนเอารูปออกจากช่อง
- สิทธิ์ API = `files.upload` (เท่าการอัปโหลด) · อ่านอย่างเดียว ไม่เขียน audit
- ป๊อปอยู่บน root แยก (mountDialog) → ข้อความใช้ `tr()` · ไอคอน `<Icon>`
- "ใช้อยู่ที่ไหน" = `asset_usages` + รูปเว็บร้าน (store_listings: รูปบนเว็บ/รูปรายสี — ค้นเฉพาะตอนเจอรูปซ้ำจากโฟลเดอร์เว็บ)
