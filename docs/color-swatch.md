# 🎨 ทะเบียนสีกลาง (Color Swatch)

**ใช้ทำอะไร:** บอกว่า "ชื่อสี" แต่ละชื่อหน้าตาเป็นจุดสีแบบไหน — ใช้กับจุดสีบนการ์ดสินค้าและปุ่มเลือกสีในหน้าสินค้าของเว็บร้านทุกร้าน (และหน้าจอ ERP ที่อยากโชว์จุดสีในอนาคต)

## ข้อมูลอยู่ไหน
ต่อยอด **พจนานุกรมสี** `erp_color_dictionary` (ตัวเดียวกับที่ใช้แปลชื่อสีไทย↔อังกฤษ) เพิ่ม 3 ช่อง:

| ช่อง | ความหมาย |
|---|---|
| `swatch_kind` | `null` = ยังไม่ตั้ง · `solid` สีเดียว · `split` หลายสีแบ่งช่อง (2–4) · `image` รูปลาย · `none` ไซส์ / ไม่ใช่สี (2026-11-10) |
| `swatch_colors` | รหัสสี `#RRGGBB` |
| `swatch_image_key` | r2 key ของรูปลาย |

## กฎการหาจุดสี (`lib/color-swatch.ts` → `SwatchIndex.resolve`)
1. หาชื่อเต็มก่อน (ไทย → อังกฤษ → ตัดวงเล็บท้าย เช่น `Brown (08)` → `Brown`)
2. ไม่เจอ + เป็นชื่อผสม (`กรมท่า-ครีม-ขาว` แยกด้วย `- / , + &`) → ประกอบจากสีย่อย (สีแรกของแต่ละตัว) สูงสุด 4 สี
3. สีย่อยขาดตัวใดตัวหนึ่ง หรือเป็นรูปลาย → ไม่ส่งจุดสี (เว็บใช้รูปเล็กของสีนั้นแทนเหมือนเดิม)
4. ตัวเลือกที่กรอกจุดสีเองในหน้าจัดการสินค้า (web_options) ชนะเสมอ

หน้าตา (`swatchCss`): 1 สี = สีเต็ม · 2 สี = แบ่งครึ่งเฉียง · 3–4 สี = ชิ้นพาย · รูปลาย = รูปเต็มวง → ส่งเป็นค่า CSS `background` ให้เว็บใช้ตรง ๆ

## ใช้ยังไง
- หน้าจอ: `<ColorSwatchButton />` (ปุ่ม + ป๊อปอัป) หรือ `<ColorSwatchManager />` จาก `components/color-swatch-manager`
  - ตอนนี้อยู่ใน ERP → เว็บไซต์ → ดีไซน์ → แท็บการ์ดสินค้า (ข้างสวิตช์ "จุดสีตัวเลือก") และแท็บหน้าสินค้า (ชิ้น "ตัวเลือก" แบบวงกลมสี)
- API: `GET/POST /api/color-swatches` (อ่าน = `products.view` · แก้ = `products.edit`)
- ฝั่ง server: `new SwatchIndex(rows.map(rowToSwatchEntry)).resolve(label)` → `swatchCss(spec, imageUrl)`

## สิทธิ์ / Audit
- ทุกการบันทึกเขียน `audit_logs` (entity_type `color_dictionary`, metadata.field `swatch` + ก่อน/หลัง)
- บันทึกแล้วสั่งเว็บร้านทุกร้านล้างแคชทันที

## ข้อจำกัด
- ชื่อสีผสมใช้สีแรกของสีย่อยแต่ละตัว (สีย่อยที่เป็นหลายสี/รูปลาย ใส่ในชื่อผสมไม่ได้)
- ชื่อใหม่ที่ยังไม่มีในพจนานุกรม ต้องใส่ชื่ออังกฤษด้วย (พจนานุกรมใช้แปลชื่อสีด้วย)
- ห้ามใส่ "use client" ใน `lib/color-swatch.ts` (API route import ไปใช้)

## 📏 ไซส์ (ไม่มีสี) — ชนิด `none` (2026-11-10)
**ปัญหา:** ช่องสีของ SKU บางรุ่นเก็บสีกับไซส์รวมกัน เช่น LEABL001–003 `ดำ (01),M (20.5 cm.)` · PI338 `10 รู` → ทะเบียนสีขึ้น "ขาด: M (20.5 cm.)" และจุดสีไม่ขึ้นทั้งชื่อ

**ทางแก้:** ตั้งชื่อส่วนนั้นเป็น "ไซส์ (ไม่มีสี)" ในทะเบียนสี (แท็บหน้าตาจุดสี → แบบ "ไซส์" หรือปุ่มแนะนำ "ตั้งเป็นไซส์") — ไม่แตะข้อมูล SKU
- จุดสี (`resolve` / `missingParts`) ข้ามส่วนที่เป็นไซส์ → `ดำ (01),M (20.5 cm.)` = จุดสีดำ · เหลือสีเดียวเป็นรูปลายก็ใช้รูปได้
- ไซส์ล้วน (`10 รู`) = ไม่มีจุดสี แต่ไม่ขึ้น "ยังไม่ตั้ง" และไม่เตือน "สียังไม่ผูกทะเบียนสี" ในหน้ารายการ (`isSizeOnly` → `noColor`)
- แท็บ "สีหลักในตัวกรอง": ชื่อไซส์ = "ไม่ใช่สี / ไซส์" อัตโนมัติ (ป้ายเดียวกัน — ตั้ง "ไม่ใช่สี" ที่แท็บนั้นก็เขียนชนิด `none` ลงทะเบียนสี · ชื่อที่มีจุดสีอยู่แล้วเก็บในแถวพิเศษ `_not_color` แทน ไม่ลบจุดสีทิ้ง)
- หน้าเว็บ (`/api/public/storefront/products` → `splitOptionSizes`): ชื่อตัวเลือกตัดไซส์ออก (`ดำ (01)`) + บรรทัด "ไซส์: M (20.5 cm.)" (EN "Size") เป็นแถวแรกของหัวข้อ "ขนาด" — ทำเฉพาะเมื่อ ทั้งรุ่นไซส์เดียวกัน · ตัดแล้วชื่อไม่ซ้ำ · ไซส์ไม่ขึ้นต้นด้วยตัวเลข (เว็บร้านอ่านเลขในแถวขนาดไปคิดตัวกรองขนาด) ไม่ผ่าน = ชื่อเต็มเหมือนเดิม
- ออเดอร์/หลังบ้านยังใช้ชื่อสีเต็มของ SKU (ไม่เปลี่ยน)
- `looksLikeSize(name)` = แนะนำเท่านั้น (S/M/L/XL · เลข+cm/mm/นิ้ว · n รู · A4…) เจ้าของต้องกดเอง + บันทึกทีเดียวเหมือนสีอื่น
- รุ่นที่มีหลายไซส์จริง ให้ใช้ "ตัวเลือกชุดที่ 2" (`docs/website-size-options.md`) ไม่ใช่ทางนี้
- บันทึก: `lib/color-swatch-save.ts` (ใช้ร่วม 2 API) · audit metadata.source บอกว่ามาจากแท็บไหน
