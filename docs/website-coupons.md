# 🎟️ คูปองส่วนลด + 🎁 ป๊อปอัปลูกค้าใหม่ (เว็บร้าน)

## ใช้ทำอะไร
- เจ้าของร้านสร้างโค้ดส่วนลด (เช่น `WELCOME10` ลด 10%) ที่ ERP `/website/<shop>` แท็บ **🎟️ คูปอง**
- ลูกค้าใส่โค้ดที่หน้าชำระเงิน → เห็นส่วนลดทันที → ตอนกดสั่ง ERP ตรวจ + คิดส่วนลดใหม่เองเสมอ
- ป๊อปอัปลูกค้าใหม่ (ตั้งที่แท็บ **🏪 ข้อมูลร้าน** กลุ่ม 🎁) แจกโค้ด — เลือกได้ว่าต้องกรอกอีเมลก่อน (เข้ารายชื่อรับข่าวสารเดิม)

## ข้อมูล
| ตาราง | เก็บอะไร |
|---|---|
| `store_coupons` | นิยามคูปองต่อร้าน (โค้ดไม่ซ้ำในร้าน · % หรือ บาท · ขั้นต่ำ · ลดสูงสุด · ช่วงวัน · จำนวนครั้ง · เบอร์ละครั้ง · เฉพาะลูกค้าใหม่ · เปิด/ปิด) |
| `store_coupon_redemptions` | ใช้กับออเดอร์ไหน เบอร์อะไร ลดเท่าไร (1 ออเดอร์ 1 คูปอง) |

- migration `202610150300_store_coupons.sql` · RLS เปิด ไม่มี policy (เข้าผ่าน API service role เท่านั้น)
- **ไม่แก้ตาราง `store_orders`** — ยอดลดอยู่ช่อง `discount` เดิม · โค้ดอยู่ในตาราง redemptions

## กฎกลาง (ห้ามคิดส่วนลดเองที่อื่น)
- `lib/website-coupons.ts` (ฟังก์ชันล้วน มี test `lib/__tests__/website-coupons.test.ts`)
  - `evaluateCoupon(coupon, subtotal, usage)` — ตรวจ + คิดส่วนลดด้วย **lib/money** (สตางค์ · ปัด half-up)
  - ลดเฉพาะค่าสินค้า (ไม่ลดค่าส่ง · ค่าส่งคิดจากยอดก่อนลด) · ไม่เกินยอดสินค้า · แบบ % มีเพดานได้
  - เหตุผลที่ใช้ไม่ได้เป็นภาษาคน (ปิดใช้งาน / ยังไม่เริ่ม / หมดอายุ / ใช้ครบ / ยอดไม่ถึงขั้นต่ำ / เบอร์นี้ใช้แล้ว / เฉพาะลูกค้าใหม่)
  - `sanitizeCouponInput` — ตรวจข้อมูลจากหน้าจอ ERP (บอกว่าผิดตรงไหน ไม่เดาค่าให้)
- `lib/website-coupons-db.ts` (ฝั่งเซิร์ฟเวอร์) — `checkCoupon` · `couponUsage` · `couponUseCounts`
  - **ไม่นับออเดอร์ที่ยกเลิก** (status `cancelled`) → ยกเลิกออเดอร์แล้วโค้ดกลับมาใช้ได้
  - ลูกค้าใหม่ = เบอร์นี้ยังไม่มีออเดอร์ที่ไม่ใช่ยกเลิกกับร้าน

## API
| เส้นทาง | ใคร | ทำอะไร |
|---|---|---|
| `/api/website/coupons` | ERP (guardApi) | GET รายการ+จำนวนที่ใช้ · POST สร้าง · PATCH แก้/เปิด-ปิด · DELETE (เฉพาะที่ยังไม่เคยใช้ — ใช้แล้วให้ปิดแทน) · audit ทุกครั้ง |
| `/api/public/storefront/coupon` | ลูกค้า (CORS) | POST `{shop, code, subtotal, phone?}` → ดูผลล่วงหน้าเท่านั้น |
| `/api/public/storefront/orders` | ลูกค้า | รับ `couponCode` → ตรวจ/คิดใหม่ใน `createStorefrontOrder` · ใช้ไม่ได้ = ไม่รับออเดอร์ บอกเหตุผล · บันทึก redemption |
| `/api/public/storefront/site` | เว็บร้าน | แนบ `info.promo_label` · คูปองของป๊อปอัปใช้ไม่ได้ = ปิดป๊อปอัปให้เอง |

## ข้อจำกัดที่รู้
- จำนวนครั้ง (usage_limit) ไม่ได้ล็อกแบบ transaction — ถ้าลูกค้า 2 คนสั่งพร้อมกันวินาทีเดียวกันตอนเหลือ 1 สิทธิ์ อาจเกินได้ 1 ครั้ง
- ยังไม่มีคูปองส่งฟรี / ลดเฉพาะหมวด / ลดเฉพาะสินค้า
- ~~หน้าออเดอร์ใน ERP ยังไม่โชว์โค้ด~~ → ตั้งแต่ M4 ออเดอร์เก็บ `coupon_code` + ERP/หน้าตามออเดอร์โชว์แล้ว

## 👤 คูปองเฉพาะสมาชิก (M5)
- ฟอร์มคูปอง ERP: ติ๊ก "👤 เฉพาะสมาชิก" (+ เลือกระดับขั้นต่ำได้ จากแท็บ 👥 สมาชิก → ⭐ ระดับสมาชิก) · คอลัมน์ `members_only` / `min_tier` (migration 202610190100)
- กฎ (`evaluateCoupon`): ไม่ได้เข้าสู่ระบบ = "เข้าสู่ระบบก่อนใช้" · ระดับไม่ถึง = "สำหรับสมาชิกระดับ X ขึ้นไป" · ⚠️ ระดับที่ตั้งไว้ถูกลบ = ไม่มีใครใช้ได้ (ตารางคูปองเตือน ⚠️) — ปลอดภัยกว่าแจกทุกคน
- ตรวจในนามสมาชิก: เว็บร้าน `/api/member/coupon` → ERP `/api/storefront-member/coupon` (รู้รหัสสมาชิก) · ตอนสั่งจริง `createStorefrontOrder` ส่งรหัสสมาชิกให้ `checkCoupon` เอง
- สมาชิกเห็นคูปองพวกนี้: หน้าบัญชีแท็บ 🎟️ (ระดับไม่ถึง = ล็อก · ใช้แล้ว = จาง) + ปุ่มลัดในช่องโค้ดตอนชำระเงิน — `memberCouponList` · คูปองทั่วไปไม่ประกาศ (เป็นโค้ดลับ/โค้ดป๊อปอัป)
- ป๊อปอัปลูกค้าใหม่ใส่คูปองเฉพาะสมาชิกไม่ได้ (บันทึกข้อมูลร้านจะเตือน · ถ้าเปลี่ยนทีหลัง ป๊อปอัปปิดตัวเอง)
- test: `lib/__tests__/website-coupons.test.ts` (กฎ) · `website-coupons-db.test.ts` (ตัวเชื่อม DB กับฐานข้อมูลจำลอง `fake-db.ts`)
