# ดับเบิลคลิกเพื่อแก้ไข (DblClickToEdit)

ฟอร์มที่เปิดมาแบบ "ดูอย่างเดียว" (ช่องล็อกอยู่) — **ดับเบิลคลิกช่องไหนก็ได้ = เข้าโหมดแก้ไขทั้งฟอร์ม** แล้วเคอร์เซอร์ไปรอที่ช่องนั้นเลย ไม่ต้องมีปุ่ม "✏️ แก้ไข"

เจ้าของขอเมื่อ 2026-11-07: "เอาปุ่มแก้ไขออก แต่ให้ double คลิกช่องที่เป็น readonly เพื่อแก้ไขได้" — ใช้ครั้งแรกที่ป๊อปอัปใบงานออกแบบ (`components/design-sheet-detail`, แท็บข้อมูลงาน)

## ทำงานยังไง
- ดับเบิลคลิก (เมาส์) หรือแตะ 2 ครั้งเร็ว ๆ (จอทัช) ที่ช่องที่ล็อก → เรียก `onEdit()` → ช่องหายล็อก → โฟกัสช่องที่คลิก
- ช่องที่แก้ได้อยู่แล้วในโหมดดู (เช่น สถานะ, ลิงก์ไฟล์งาน) / ปุ่ม / ลิงก์ → ทำงานปกติ ไม่ถูกดัก
- ชี้ช่องที่ล็อก = เคอร์เซอร์พิมพ์ + พื้นช่องอมสีส้มอ่อน (รู้ว่ากดได้) · tooltip "ดับเบิลคลิกที่ช่องเพื่อแก้ไข"
- ไม่มีสิทธิ์แก้ (ไม่ส่ง `onEdit`) → ไม่มีอะไรเกิดขึ้น

## วิธีใช้
```tsx
import { DblClickToEdit } from "@/components/dbl-click-edit";

<DblClickToEdit className="space-y-3" locked={!fullEdit} onEdit={canEdit ? () => setEditing(true) : undefined}>
  <label className="block">
    <span>ชื่องาน</span>
    <input value={form.name} disabled={!fullEdit} ... />
  </label>
  ...
</DblClickToEdit>
```
- ช่องในฟอร์มล็อกด้วย `disabled` ตามปกติ · ห่อแต่ละช่องด้วย `<label>` (หรือใส่ `data-dbl-field` ที่กรอบ) เพื่อให้รู้ว่าคลิกช่องไหน แล้วโฟกัสถูก
- บอกวิธีใช้ให้ผู้ใช้เห็น ตรงที่ปุ่มแก้ไขเคยอยู่ (ป๊อปใบงาน: ข้อความเทา "ดับเบิลคลิกที่ช่องเพื่อแก้ไข" ในแถบล่าง · แก้อยู่ = "กำลังแก้ไข")

## เทคนิค
- ช่อง `disabled` บางเบราว์เซอร์ไม่ส่งเหตุการณ์เมาส์เลย → ระหว่างล็อกตั้ง `pointer-events:none` ให้ช่อง disabled (เหมือน `.lig-dbl` ของ LineItemsGrid / `.split-grow` ของ SplitPanes) เหตุการณ์จึงตกที่ `<label>`
- จับ "กด 2 ครั้งที่ช่องเดิมภายใน 450ms" เองด้วย (นอกจาก dblclick) เพราะมือถือบางรุ่นไม่ส่ง dblclick และกล่อง SplitPanes ที่ขยายตอนคลิกแรกทำให้ช่องขยับ เบราว์เซอร์เลยไม่นับเป็น dblclick

## ตัวที่คล้ายกัน
- แก้ทีละช่องแล้วบันทึกทันที → `InlineEdit` (components/inline-edit) หรือ quick edit ของ MasterCrud
- ตารางรายการ → `LineItemsGrid` `readonly` + `onRequestEdit` (ดับเบิลคลิกแถว)

## ข้อจำกัด
- เข้าโหมดแก้ไขแล้วไม่มีปุ่ม "ยกเลิกแก้ไข" — ออกด้วยบันทึก หรือปิดป๊อปอัป (เหมือนเดิมตอนมีปุ่ม)
- ไม่มี audit log ในตัว (แค่สลับโหมด) — การบันทึกจริงยัง audit ตามเดิม
