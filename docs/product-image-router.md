# 📂 จัดรูปหลายโฟลเดอร์ (Product Image Router)

ลากหลายโฟลเดอร์ (หรือหลายรูป) มาวางทีเดียว แล้วเลือกว่ารูปไหนลงช่องไหนของสินค้า — ตรวจก่อนอัปทุกครั้ง · อัปเบื้องหลัง · ย้อนทั้งชุดได้

## ใช้ที่ไหน

| จุด | เปิดยังไง | ขอบเขต |
|---|---|---|
| หน้ารวม Parent SKU (`/master/parent-skus`) | ปุ่ม **📂 จัดรูปหลายโฟลเดอร์** หัวหน้า | หลายรุ่นทีเดียว (หารุ่นจากชื่อโฟลเดอร์) |
| คลังไฟล์กลาง (`/master/assets`) | ปุ่ม **📂 จัดรูปสินค้าหลายโฟลเดอร์** ข้าง ⬆ อัปโหลด (ซ่อนในแท็บ Artwork/งานพิมพ์) | หลายรุ่นทีเดียว |
| ตาราง SKU ลูกในหน้า/drawer Parent SKU | ปุ่ม **📂 จัดรูปหลายโฟลเดอร์** หัวตาราง · หรือโยนโฟลเดอร์ลงช่อง "📂 โยนหลายโฟลเดอร์…" ในโหมด 🖼 รูปภาพ | รุ่นนั้น (+ รุ่นอื่นที่ชื่อโฟลเดอร์ชี้ถึง) |

สิทธิ์: `products.edit` + `files.upload` · โหมด **แทนที่ของเดิม** ต้องมี `attachments.delete` (หัวหน้า/แอดมิน)

## ตั้งชื่อยังไง

- **ชื่อโฟลเดอร์ = รหัส**: `BCG11-01/` = สีนั้น · `BCG12-01-L/` = รหัสไซส์ → เข้าสีหลัก (BCG12-01) · `BCG11/` = ทั้งรุ่น (ไม่ผูกสี) · `BCG11-07/` ถ้ารุ่นไม่มีสี 07 = ให้เลือกเอง
- ไฟล์เดี่ยวไม่มีโฟลเดอร์ใช้รหัสในชื่อไฟล์แทน (`BCG11-01_3.jpg`) — ไฟล์เดี่ยว **ไม่ตั้งปกตามตำแหน่ง** (กันเพิ่มรูปเดียวแล้วปกเปลี่ยน)
- **ชื่อไฟล์บอกช่องเองได้**: `ปก` / `cover` / `main` = ปก · `hero` = Hero คอม · `hero_m` = Hero มือถือ · `desc` = รูป Description · `png` = รูปตัด PNG · ที่เหลือใช้แม่แบบ
- เรียงตามตัวเลขในชื่อ (1, 2, 10 · IMG_4519 < IMG_4521) · ลากสลับได้

## ช่องปลายทาง (ของกลางทั้งหมด — ไม่มีตัวอัปใหม่)

| ช่อง | ทางที่ใช้ |
|---|---|
| รูปหลัก SKU ลูก (ปก) · รูป SKU ลูก · แกลเลอรี Parent | `/api/attachments` (≤ 2 MB) · ไฟล์ใหญ่/ตัวเต็ม = ส่งตรงเข้า R2 (`product-originals/`) แล้ว `/api/product-images` · ปก = `PATCH /api/attachments/[id]` |
| รูป Description | `/api/assets` (หรือส่งตรงเข้า R2) → `/api/assets/description` |
| รูปตัด PNG | `/api/website/product-png` |
| รูปบนเว็บ · สีนี้ / Hero คอม / Hero มือถือ | อัปรูป → `/api/website/listings/images` (ตัวรวมของ 📸 ลงรูปเว็บทีละมาก · เลือกร้านได้) |

เพดาน: แกลเลอรี 9 รูป/ตัว · รูปบนเว็บรายสี 8 · Hero / PNG ช่องละ 1 · ครั้งละ ≤ 300 รูป

## ตั้งค่า (จำต่อคน — `useUserPref`)

- **แม่แบบ** `product_image_router_template` — ค่าเริ่ม: รูป 1 = ปก · ที่เหลือ = รูป SKU ลูก · โฟลเดอร์ทั้งรุ่น = แกลเลอรี Parent · ปุ่ม "จำเป็นแม่แบบ" จำจากที่ตั้งตอนนี้
- **ขนาดรูป** `product_image_router_resize` — ลดอัตโนมัติตามช่อง (สินค้า 1,500 · เว็บ 2,000 · Hero คอม 2,560 · Hero มือถือ 1,440 · Description 1,200 px) / ลดเท่ากัน (1,200–3,000) / ไม่ลด (เกิน 20 MB ลดให้เสมอ) · ตั้งทับรายโฟลเดอร์ได้
- **ร้าน** `product_image_router_shops` — ยังไม่เคยติ๊ก = ทุกร้านที่ขายรุ่นนั้น

## ตั้งช่องได้ 3 ระดับ

ทีละรูป (ใต้รูป) · ทั้งคอลัมน์ ("รูปที่ n ของทุกโฟลเดอร์ →") · ทั้งโฟลเดอร์ (ตามแม่แบบ / ทุกรูป → SKU ลูก / แกลเลอรี Parent / Description / รูปบนเว็บ / ข้าม)
โฟลเดอร์ที่ใช้แม่แบบ/ตั้งทั้งโฟลเดอร์ → ลากสลับแล้วช่องตั้งใหม่ตามตำแหน่ง · แก้ทีละรูปแล้ว = "ปรับเองทีละรูป" ช่องติดไปกับรูป

## ตรวจก่อนอัป (`lib/product-image-routing` · pure + test)

`planRoute` → ไม่อัป: ยังไม่เลือกสี/รุ่น · โฟลเดอร์ทั้งรุ่นแต่เลือกช่องที่ต้องมีสี · ไม่ได้เลือกร้าน · ปกเกิน 1 · เกินเพดาน
`imageWarning` → ยังอัปได้แต่เตือน: รูปซ้ำในชุด (ลายนิ้วมือ ขนาด+SHA-256 256 KB แรก) · Hero ไม่ใช่ 16:9/เล็ก · ไม่ใช่ PNG · รูปเล็ก < 1,000 px · เกิน 20 MB จะลดให้

## หลังอัป + 🕘 ประวัติชุดอัป (รอบ 2)

- อัปเบื้องหลัง (`runBackgroundTask`) — ปิดหน้าต่างได้ · กลับมาดูผล/อัปซ้ำเฉพาะรูปที่พลาดได้ (หน้าต่างคงสถานะไว้จนกว่าจะเปลี่ยนหน้า · อัปซ้ำ = ชุดเดิม)
- **ประวัติชุดอัป** = ตาราง `erp_image_batches` (1 แถว/การกดยืนยัน) + `erp_image_batch_items` (1 แถว/รูปที่สำเร็จ) · migration `202611010400_image_batches` · เปิด RLS ไม่มี policy (เซิร์ฟเวอร์เท่านั้น)
  ของกลาง `lib/image-batches` · API `/api/product-images/batches` (GET รายการ · POST create/items/finish/seen/undo)
- **🕘 เคยอัปแล้ว**: ลายนิ้วมือไฟล์ต้นฉบับ (ขนาด + SHA-256 ของ 256 KB แรก + 64 KB ท้าย · ก่อนย่อ) → เคยอัปให้ "รุ่นเดียวกัน" แล้ว + ยังอยู่จริง + ชุดยังไม่ถูกย้อน = ข้ามให้ (เลือกช่องเอง = อัปซ้ำ แต่มีเตือน "จะซ้ำ")
  จำได้เฉพาะรูปที่อัปผ่านหน้าต่างนี้ตั้งแต่ 2026-10-26 · รูปที่แก้/export ใหม่ = รูปใหม่
- **↩ ย้อนทั้งชุด** (ทันทีหลังอัป หรือทีหลังที่ปุ่ม 🕘 ประวัติการอัปรูป ในหน้าต่าง) — ทำฝั่งเซิร์ฟเวอร์ (`undoImageBatch`):
  เอารูปใหม่ออก (audit detach + เก็บเป็นเวอร์ชันแบบเดียวกับลบทีละรูป · `lib/attachment-remove`) → โหมดแทนที่: คืนรูปเดิมจากเวอร์ชัน (`restoreVersion`) → คืนปกเดิม (RPC set_primary)
  → เอารูป Description ออก (`lib/description-images`) → คืน PNG เดิมถ้ายังเป็นรูปของชุดนี้ → รูปบนเว็บ/Hero คืนค่าเดิมเฉพาะที่ยังไม่มีใครแก้ต่อ (`lib/website-listing-undo`)
- **สิทธิ์ย้อน**: คนที่อัปชุดนั้นเอง หรือผู้มีสิทธิ์ลบรูป `attachments.delete` (หัวหน้า/แอดมิน) · ไม่จำกัดเวลา · ย้อนซ้ำไม่ได้ (409)
- audit: `product_images:upload|retry|undo` (ทั้งชุด) + audit ของแต่ละทางที่อัป/ลบ
