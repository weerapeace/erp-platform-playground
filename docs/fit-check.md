# 📐 เช็คขนาด — ใส่ตุ๊กตา/ของได้ไหม (ของกลาง)

## ใช้ทำอะไร
บอกว่ากระเป๋าแต่ละรุ่นใส่ตุ๊กตา/ของอะไรได้ กี่ชิ้น ช่องไหน — คำนวณจาก "ช่องใส่ของ" (ขนาดด้านใน) ของกระเป๋า กับขนาดมาตรฐานของตุ๊กตาในทะเบียน ไม่ต้องติ๊กเองทีละรุ่น

## ข้อมูล (migration 202610190200)
- `parent_skus_v2.compartments` = ช่องใส่ของ `[{id,name,w,h,d,window}]` (ซม. ด้านใน)
  - `null` = ยังไม่ได้วัด → ร้านที่เปิดเช็คขนาดจะขึ้นแท็บ ⚠️ ต้องแก้
  - `[]` = ไม่มีช่องใส่ของ (ไม่ใช่กระเป๋า เช่น พวงกุญแจ) → ไม่เตือน ไม่ขึ้นในหน้าเช็คขนาด
- ทะเบียน `product_fit_items` (ตัวเดิมของ "ใส่อะไรได้บ้าง") + ช่องใหม่: `kind` (item ของใช้ติ๊กเอง / doll ตุ๊กตาคำนวณเอง) · `width/height/depth_cm` · `is_soft` (นุ่ม บีบได้) · `size_estimated` (ขนาดประมาณ — ยังไม่ได้วัดของจริง)
  - แก้ที่ `/m/product_fit_items` · ตุ๊กตาเริ่มต้น 5 แบบ ขนาดประมาณจากร้านค้าออนไลน์ (ติ๊ก "ขนาดประมาณ" ไว้ — วัดของจริงแล้วแก้ + เอาติ๊กออก)
  - ตุ๊กตา (kind=doll) ถูกซ่อนจากป๊อปติ๊ก "ใส่อะไรได้บ้าง" แบบเดิม (เพราะคำนวณเอง)
- สวิตช์ต่อร้าน: SiteInfo `fit_check_enabled` (ข้อมูลร้าน → 📐 เช็คขนาด)

## กฎ (`lib/fit-check.ts` · มี test)
- หมุนของได้ทุกด้าน เลือกท่าที่ใส่ได้มากสุด · เลือกช่องที่ดีที่สุดในกระเป๋า
- ✅ ใส่สบาย = ทุกด้านเล็กกว่าช่อง เหลือ ≥ 0.5 ซม. · ⚠ พอดี (แน่น) = ชิดขอบ < 0.5 ซม. หรือของนุ่มต้องบีบ ≤ 10% · ✕ ใส่ไม่ได้
- จำนวน = วางเรียงเป็นตาราง → "ประมาณ" เสมอ (ของนุ่มที่ต้องบีบนับ 1)
- ขนาดตุ๊กตาที่ติ๊ก "ประมาณ" → หน้าจอขึ้น * บอกว่าเป็นค่าประมาณ

## หน้าจอ ERP (`components/compartments-editor.tsx`)
- ลิ้นชักตั้งค่าเว็บของสินค้า → แท็บ 🔤 ปั๊มชื่อ · แบนเนอร์ · รายละเอียด → แผง "📐 ช่องใส่ของ" (บันทึกเองที่ตัวสินค้า · ทุกร้านเห็นเหมือนกัน · ร้านที่เปิดเช็คขนาดและยังไม่วัด = กางให้เอง)
- ฟอร์ม Parent SKU ฟิลด์ "ช่องใส่ของ (ขนาดด้านใน)" (ต่อสาย 2 ที่: app/master/parent-skus/page.tsx + MasterRecordDrawer ใน components/master-crud)
  - ยังไม่ได้วัด = ย่อเหลือช่องติ๊ก "ติ๊กเพื่อใส่ขนาดช่อง" (`toggle` — เจ้าของขอ "จะได้ไม่รก") · ติ๊กออก = กลับเป็นยังไม่ได้วัด (หน้าดูต้องกดบันทึก) · ติ๊กกลับ = คืนตัวเลขเดิม
  - ลิ้นชักเว็บไม่ใช้ `toggle` เพราะแผง 📐 พับ/กางเองอยู่แล้ว
- ผลคำนวณขึ้นสดระหว่างกรอก · เตือนถ้าช่องใหญ่กว่าขนาดภายนอกของกระเป๋า · บันทึกผ่าน PATCH master-v2 (สิทธิ์ products.edit + สิทธิ์รายฟิลด์ + audit)
- ⚠️ ต้องแก้: `lib/website-listing-health` key `no_compartments` (เฉพาะร้านที่เปิดเช็คขนาด) → ปุ่ม "ไปแก้" พาไปแท็บที่มีแผงช่องใส่ของ

## หน้าเว็บ (รอบ B)
- **Section "📐 เช็คขนาด (ใส่ตุ๊กตาได้ไหม)"** (ตัวจัดหน้า กลุ่มสินค้า · `fitcheck`): ลูกค้าเลือกตุ๊กตา/ของ หรือพิมพ์ กว้าง × สูง × หนา เอง (+ ติ๊ก "นุ่ม บีบได้") → การ์ดรุ่นที่ใส่ได้ + ป้าย "ใส่สบาย/พอดี (แน่น) · ประมาณ N ตัว · ช่องไหน" เรียงใส่สบายก่อน
  - ตั้งได้: หัวข้อ · ให้พิมพ์ขนาดเอง · โชว์รุ่นแน่น · คอลัมน์ · จำนวนสูงสุด
  - ร้านไม่เปิดเช็คขนาด / ยังไม่มีรุ่นที่วัด = ไม่โชว์บนเว็บจริง (พรีวิวใน ERP บอกว่าต้องตั้งอะไร)
- **หน้าสินค้า หัวข้อขนาด + ป๊อป 📏 เทียบขนาด**: products API ต่อบรรทัด "ใส่ได้ Labubu … ประมาณ 2 ตัว" ท้ายรายการ "ใส่ได้" เดิม (`withFitLines`) · มีเกิน 2 อย่าง = แยกบรรทัดละอย่าง
- ข้อมูลที่ส่งเว็บ (เฉพาะร้านที่เปิด): site API `fitTargets` (ตุ๊กตาขึ้นก่อน) · products API `fitBoxes` (ช่องใส่ของของรุ่นที่วัดแล้ว)
- เว็บร้าน: `src/lib/fit-check.ts` = **สำเนา** ของ ERP lib/fit-check.ts (แก้กฎต้องแก้ทั้ง 2 ที่) · `src/components/fit/FitCheckBody.tsx` (วาดทั้งหน้าจริงและพรีวิวสด) + `FitCheckView.tsx`

## รอบ C
- **ตัวกรองหน้ารวมสินค้า**: กลุ่ม "ใส่อะไรได้" (ตั้งที่ ERP แท็บหน้ารายการสินค้า → ตัวกรอง) ใช้ชื่อที่คำนวณได้ **ไม่มีจำนวน** (products API `fitNames` + ที่ติ๊กเอง `fitManual`) → "Labubu …" เป็นตัวเลือกเดียว ไม่แตกเป็น "2 ตัว"/"4 ตัว" · ไม่มีของที่คำนวณได้ = ใช้ `dimensions.fits` แบบเดิม
- **รายงานรุ่นที่ยังไม่วัด**: หน้า "สินค้าบนเว็บ" ตัวกรอง "📐 ยังไม่วัดช่อง (N)" (โผล่เมื่อร้านเปิดเช็คขนาดและยังเหลือ · ลิงก์ตรง `?filter=fit`) → กดแถวเปิดลิ้นชัก → แผงช่องใส่ของ
- **รูปตุ๊กตาบนปุ่มเลือก**: `product_fit_items.image_key` (migration 202610190300 · ช่องรูปที่ /m/product_fit_items) → site API `fitTargets[].imageKey` → ปุ่มแบบการ์ดรูป (มีรูปอย่างน้อย 1 ตัว · ตัวไม่มีรูป = 🧸)
