# ระบบแพ็คสินค้า (Packing Station) — แผน (รออนุมัติ ยังไม่เขียนโค้ด)

> สถานะ: **แผนเท่านั้น** (2026-11-17) · ยังไม่แก้โค้ด/ฐานข้อมูล
> **เจ้าของตัดสินแล้ว (รอบ 1):** เก็บคลิปใน **NAS Synology 90 วัน** + ปุ่ม **เก็บถาวร** · เอาข้อเสนอ **1 (โหมดสถานี + PIN/บัตร) · 2 (เช็กสถานะสด) · 3 (เก็บถาวร + รายงานของผิด/ขาด) · 5 (ใบรวมหยิบของ)** · ขอวิธีจบออเดอร์ให้เร็ว (§10)
> รอบ 2 รอเลือกใน widget: วิธีต่อ NAS (§11) · รุ่น NAS · วิธีจบเร็ว · ข้อเสนอ 6-15 (§12)
> ตัวเลขทุกตัวในเอกสารนี้ดึงจากฐานข้อมูลจริงวันที่ 2026-11-17 (ย้อนหลัง 30 วัน)

## 1. เจ้าของต้องการอะไร (สรุปภาษาคน)

พนักงานแพ็คของ **ยิงบาร์โค้ดใบปะหน้า** → จอเปิดออเดอร์นั้นขึ้นมา + **กล้องเริ่มอัดทันที (ไม่เกิน 60 วินาที)**
→ จอบอกว่าต้องหยิบอะไร ใช้กล่องไหน มีอะไรพิเศษไหม → **ยิงบาร์โค้ดสินค้าทีละชิ้นเพื่อเช็กก่อนลงกล่อง**
→ ยิงใบปะหน้าใบต่อไป = **คลิปเดิมถูกบันทึก + เริ่มอัดคลิปใหม่ของออเดอร์ใหม่**

ได้ 2 อย่าง:
1. **หลักฐานการแพ็ค** — ลูกค้าเคลมว่า "ได้ของไม่ครบ/ผิด" → เปิดคลิปของออเดอร์นั้นส่งให้ Shopee/Lazada/TikTok ได้
2. **จับเวลาพนักงาน** — แต่ละคนแพ็คได้กี่ออเดอร์/ชั่วโมง ใช้เวลาเฉลี่ยเท่าไร หยิบผิดบ่อยไหม

ระบบนี้ = **ชั้นหลักฐาน + จับเวลา ที่วางบนศูนย์ออเดอร์เดิม** (`/master/platform-orders`)
**ไม่ตัดสต๊อก ไม่ส่งสถานะไปร้านค้า** (BigSeller ยังคุมสต๊อกอยู่) จนกว่าเจ้าของสั่ง

## 2. ข้อเท็จจริงจากข้อมูลจริง (สิ่งที่แผนนี้ยึด)

|---|---|
| ออเดอร์ทั้งหมด | **2,478** |
| เฉลี่ยต่อวัน | **80** (ค่ากลาง 68) |

แยกช่องทาง (30 วัน รวมยกเลิก): Shopee (ดึงอัตโนมัติ) 2,492 · Lazada (จากเมล) 366 · TikTok 103 · LINE SHOPPING ยังไม่มีในศูนย์ออเดอร์

### 2.2 ⚠️ เลขพัสดุ (ใบปะหน้า) — ปัญหาใหญ่สุดที่ต้องแก้ก่อน

ใบปะหน้ามีบาร์โค้ด 2 แบบ: **เลขพัสดุ** (ของขนส่ง เช่น TH… / THT…) และ **เลขออเดอร์** (ของร้าน)
ระบบต้องหาออเดอร์เจอจาก "อะไรก็ได้ที่ยิงมา"

| ช่องทาง | เลขออเดอร์ | เลขพัสดุในระบบ | หมายเหตุ |
|---|---|---|---|
| Shopee (API) | ✅ ครบ 2,721 (14 หลัก เช่น `2611…`) | ❌ **0 ใบ** | ตอนนี้ดึงมาแค่เลขแพ็กเกจ (`OFG…`) ยังไม่ได้ขอเลขพัสดุจาก Shopee |
| TikTok (API) | ✅ ครบ (18 หลัก) | ✅ 111/123 (Flash `THT…` 15 ตัว) | ใช้ได้เลย |
| Lazada (เมล) | ✅ ครบ | ❌ 0 | เมลไม่มีเลขพัสดุ · API Lazada ยังหลุด → ยิงเลขออเดอร์บนใบปะหน้าแทน |
| LINE SHOPPING | — | — | ยังไม่เข้าศูนย์ออเดอร์ |

**ทางแก้ (เฟส 0):** ตอน Shopee ดึงออเดอร์ทุก 15 นาที ให้ขอเลขพัสดุเพิ่ม (คำสั่ง "อ่าน" ของ Shopee `get_tracking_number` — อ่านอย่างเดียว ไม่ได้ส่งอะไรกลับไปที่ร้าน) แล้วเก็บลงช่อง `tracking_no` ที่มีอยู่แล้ว
ระหว่างรอ: ตัวค้นรับได้ทั้ง **เลขออเดอร์ / เลขแพ็กเกจ / เลขพัสดุ** — ใบปะหน้า Shopee มีเลขออเดอร์พิมพ์อยู่ ยิงเลขนั้นได้

### 2.3 บาร์โค้ดสินค้า — พร้อมใช้

- สินค้าที่ขายใน 30 วัน **651 SKU — มีบาร์โค้ดในระบบครบ 651 (100%)**
- บาร์โค้ด = รหัส SKU (Code128) ตามที่โมดูลพิมพ์บาร์โค้ดพิมพ์อยู่แล้ว · QR รุ่น `/s/<รหัส>` ก็อ่านได้ (ใช้ `parseScanned` ตัวกลาง)
- ⚠️ รหัสซ้ำ 2 กลุ่ม (`JEAN08-01`, `PIX34-05`) — ตอนเช็กจะเทียบกับสินค้าในออเดอร์ก่อน จึงไม่สับสน
- ❓ **ต้องถามเจ้าของ:** สินค้าจริงในคลังติดสติกเกอร์บาร์โค้ดแล้วหรือยัง? ถ้ายัง → ใช้โหมด "ติ๊กมือ + เหตุผล" ไปก่อน แล้วค่อยพิมพ์สติกเกอร์ (มีระบบพิมพ์อยู่แล้ว)
- รายการในออเดอร์ที่จับคู่ SKU ได้: 2,319 / 2,928 บรรทัด (**79%**) → อีก 21% จับคู่ไม่ได้ จอจะโชว์ชื่อ/รหัสจากร้าน + ให้ติ๊กมือ และลิงก์ไปหน้าจับคู่ SKU

### 2.4 กล่องที่ใช้ — มีเกือบครบ

- ทะเบียนกล่อง `parcel_sizes` มี **19 ขนาด** (A, AA, B, B+3, C, D, E, F, M, BAG, CLOTH BOX ฯลฯ)
- Parent SKU ผูกกล่องผ่าน `parent_skus_v2.parcel_size_id`
- SKU ที่ขายใน 30 วัน: **619/651 (95%) รู้กล่องแล้ว** · คิดเป็นจำนวนชิ้น 2,285/2,554 (**89%**)
- Parent ที่ขายจริงแต่ยังไม่มีกล่อง: **22 ตัว** (ทั้งระบบ Louis Montini ยังไม่มีกล่อง 175 ตัว แต่ส่วนใหญ่ไม่ได้ขายช่วงนี้)
- **กรณีไม่มีกล่อง:** จอขึ้น "ยังไม่ได้ตั้งกล่อง" + ให้พนักงานเลือกกล่องที่ใช้จริง → ระบบเก็บไว้ → หน้า "แนะนำกล่องจากของจริง" ให้หัวหน้ากดยืนยันตั้งเป็นค่าประจำ (ข้อมูลเติมตัวเองจากการแพ็คจริง)
- **ออเดอร์หลายชิ้น:** แนะนำกล่องใบใหญ่สุดในออเดอร์ + ให้เลือกกล่องจริง (ภายหลังทำ "สูตรกล่องรวม" ได้ถ้าเจอบ่อย)

### 2.5 หมายเหตุพิเศษ — ต้องมีช่องใหม่

- ช่อง `work_instruction_notes` ที่มีอยู่ **เป็นคำสั่งผลิต** (เช่น "เพิ่มช่องซิปใส", "ทำช่องใส่การ์ด") ไม่ใช่วิธีแพ็ค → **ห้ามเอามาใช้ปนกัน**
- เสนอช่องใหม่บน Parent SKU (ตั้งครั้งเดียว ใช้ทุกออเดอร์):
  - `pack_note` — ข้อความวิธีแพ็ค เช่น "ใส่ถุงกันฝุ่น + ยัดกระดาษทรงกระเป๋า"
  - `pack_flags` — ป้ายลัด: แตกง่าย · ห่อบับเบิ้ล · ห่อของขวัญ · ห้ามพับ · ใส่การ์ดขอบคุณ
- หมายเหตุจากลูกค้า: TikTok มี `buyer_message` อยู่แล้ว (6 ใบ) · Shopee ต้องขอ `message_to_seller` เพิ่มตอนดึงออเดอร์ (เฟส 0)
- ของแถม/เซ็ต: ใช้ระบบเซ็ตสินค้าเดิม (SKU Bundle) แตกเป็นรายการลูกให้เช็กทีละชิ้น · ของแถมต่อแบรนด์ (การ์ด/สติกเกอร์) ตั้งที่การ์ดแบรนด์ (เฟส 3)

## 3. หน้าจอและขั้นตอน (หน้าใหม่ `/packing`)

### 3.1 สถานีแพ็ค (หน้าหลัก)

```
[ยิงใบปะหน้า] → เปิดออเดอร์ + กล้องเริ่มอัด (นับถอยหลัง 60 → 0)
   ├─ หัว: เลขออเดอร์ · ร้าน (Shopee/Lazada/TikTok) · ขนส่ง · ส่งภายใน · COD
   ├─ กล่องที่ใช้: B (17×25×9) ← จาก Parent SKU · ปุ่มเปลี่ยนกล่อง
   ├─ ⚠ หมายเหตุพิเศษ: แตกง่าย · ลูกค้าเขียน "ห่อของขวัญให้ด้วย"
   ├─ รายการ: รูป · รหัส · สี · จำนวน 0/2 → ยิงบาร์โค้ดสินค้าแล้วติ๊กเขียว
   │     ยิงผิด = จอแดง + เสียงเตือน "สินค้านี้ไม่อยู่ในออเดอร์"
   │     ยิงเกิน = เตือน "เกินจำนวน"
   │     ไม่มีบาร์โค้ด = ติ๊กมือ + เลือกเหตุผล (ไม่มีสติกเกอร์ / สติกเกอร์อ่านไม่ออก / อื่น ๆ)
   └─ ครบ = "แพ็คเสร็จ" (กดเอง หรือ ยิงใบต่อไปก็ถือว่าเสร็จ)
```

กฎ:
- **ออเดอร์ถูกยกเลิก / ส่งไปแล้ว** → จอแดงเต็มจอ "ห้ามแพ็ค" (กันส่งของที่ลูกค้ายกเลิกไปแล้ว — ข้อมูล 30 วันมียกเลิก 436 ใบใน Shopee)
- ออเดอร์เดิมเคยแพ็คแล้ว → เตือน "แพ็คไปแล้วเมื่อ 10:42 โดย น้องเอ" ให้เลือกแพ็คซ้ำ (เก็บเป็นคลิปที่ 2) หรือยกเลิก
- ยิงใบต่อไปทั้งที่ยังเช็กไม่ครบ → ถาม "ออเดอร์ก่อนหน้ายังไม่ครบ 1 ชิ้น — บันทึกเป็น 'มีปัญหา' ไหม?"
- ยิงไม่เจอออเดอร์ → "ไม่พบออเดอร์นี้ (อาจยังไม่ดึงเข้าระบบ รอ 15 นาที)" + ปุ่มดึงใหม่

### 3.2 กล้องอัด 60 วินาที

- เริ่มอัด **ทันทีที่ยิงใบปะหน้า** · นับถอยหลังตัวใหญ่ · 15 วินาทีสุดท้ายเปลี่ยนสีส้ม · ครบ 60 = หยุดเอง
- ยิงใบต่อไป = หยุด + เก็บคลิปเดิม → เริ่มคลิปใหม่ทันที (ช่องว่างไม่ถึงครึ่งวินาที)
- **ตัวหนังสือฝังในวิดีโอ** (มุมจอ): เลขออเดอร์ · เลขพัสดุ · ชื่อพนักงาน · วัน-เวลาเดินจริงทุกวินาที · ชื่อสถานี
  วิธีทำ: เอาภาพกล้องวาดลงผืนภาพ (canvas) พร้อมตัวหนังสือ แล้วอัดจากผืนภาพนั้น → ตัวหนังสือติดอยู่ในคลิป ลบไม่ได้
  + เก็บข้อมูลเดียวกันในฐานข้อมูล + "ลายนิ้วมือไฟล์" (SHA-256) ไว้พิสูจน์ว่าคลิปไม่ถูกตัดต่อ
- ชนิดไฟล์: เลือกอัตโนมัติตามเบราว์เซอร์ — Chrome รุ่นใหม่/Safari = **MP4** (แพลตฟอร์มรับง่ายกว่า) · ไม่รองรับ = WebM
- ความละเอียด **720p 15-20 ภาพ/วินาที ~1 Mbps** (อ่านใบปะหน้า/ชื่อสินค้าออก ไฟล์เล็ก)
- เสียง: **ปิดเป็นค่าเริ่มต้น** (ความเป็นส่วนตัว + ไฟล์เล็ก) เปิดได้ในตั้งค่าสถานี
- อัปโหลด **เบื้องหลัง ไม่บล็อกออเดอร์ถัดไป**: คลิปเข้าคิวในเครื่อง (IndexedDB) → ส่งตรงขึ้นที่เก็บด้วยลิงก์อัปชั่วคราว → เน็ตหลุดเก็บไว้ในเครื่องแล้วลองใหม่เอง → มุมจอโชว์ "รออัป 3 คลิป" · ปิดแท็บตอนยังค้างจะเตือน
- PC + กล้อง USB + เครื่องยิง = **แนะนำ** (ยิงบาร์โค้ดด้วยเครื่องยิง กล้องอัดอย่างเดียว ไม่แย่งกัน)
  มือถือบนขาตั้ง = ใช้ได้ (กล้องตัวเดียวทั้งอัดและอ่านบาร์โค้ด) แต่จอเล็ก/แบตหมด/ร้อน — เหมาะเป็นสถานีสำรอง

### 3.3 ค้นหลักฐาน

- หน้า `/packing/evidence`: ค้นด้วยเลขออเดอร์ / เลขพัสดุ / วันที่ / พนักงาน → เปิดคลิปดูได้เลย
- ลิ้นชักออเดอร์ในศูนย์ออเดอร์ → ปุ่ม **"ดูวิดีโอแพ็ค"** (โชว์ผลเช็กของ + เวลา + คนแพ็ค)
- **ส่งให้แพลตฟอร์ม:** ปุ่ม "ดาวน์โหลด MP4" (อัปขึ้นหน้าข้อพิพาทเอง) + "คัดลอกลิงก์ 7 วัน" (ลิงก์หมดอายุเอง)
- ปุ่ม **"เก็บถาวร"** — คลิปที่มีเคลมจะไม่ถูกลบตามรอบ

### 3.4 แดชบอร์ดพนักงาน `/packing/dashboard`

- ต่อคน/ต่อวัน: ออเดอร์ที่แพ็ค · **ออเดอร์/ชั่วโมง** · เวลาเฉลี่ยต่อออเดอร์ · % ยิงผิด · % ติ๊กมือ · ออเดอร์ที่มีปัญหา
- อันดับประจำวัน + กราฟรายชั่วโมง (เห็นช่วงคอขวด)
- **วิธีนับเวลาให้ยุติธรรม:**
  - เวลาแพ็ค 1 ออเดอร์ = ยิงใบปะหน้า → กดเสร็จ (หรือยิงใบถัดไป)
  - ช่วงว่างระหว่างออเดอร์ **เกิน 3 นาที = พัก** ไม่นับเป็นชั่วโมงทำงาน
  - ออเดอร์ที่ใช้เวลา **เกิน 10 นาที** = ค่าผิดปกติ ไม่เอามาคิดค่าเฉลี่ย (โชว์แยกให้หัวหน้าดู)
  - ออเดอร์/ชั่วโมง = จำนวนออเดอร์ ÷ เวลาทำงานจริง (ไม่รวมพัก)
- ห้ามใช้ตัวเลขตัดสินคนอย่างเดียว — มีช่องหัวหน้าเขียนเหตุผล (เช่น ออเดอร์ห่อของขวัญ)

## 4. ที่เก็บวิดีโอ + ค่าใช้จ่าย (คิดจากออเดอร์จริง)

### 4.1 ขนาดไฟล์

| ความละเอียด | ต่อ 1 นาทีเต็ม | คลิปเฉลี่ย ~35 วิ |
|---|---|---|
| 480p ~0.6 Mbps | ~4.5 MB | ~2.6 MB |
| **720p ~1 Mbps (แนะนำ)** | **~7.5 MB** | **~4.5-5 MB** |
| 1080p ~2.5 Mbps | ~19 MB | ~11 MB |

(80% เป็นออเดอร์ชิ้นเดียว คาดว่าคลิปจริงสั้นกว่า 35 วิ ตัวเลขนี้เผื่อไว้แล้ว)

### 4.2 ต่อเดือน (720p · ~2,500 ออเดอร์/เดือน)

| เก็บไว้ | พื้นที่ค้างในที่เก็บ | ค่า R2 โดยประมาณ* |
|---|---|---|
| 30 วัน | ~12 GB | ~฿2/เดือน |
| **60 วัน (แนะนำ)** | ~25 GB | **~฿10/เดือน** |
| 90 วัน | ~37 GB | ~฿16/เดือน |
| 1 ปี | ~150 GB | ~฿80/เดือน |

\* R2 = $0.015/GB/เดือน · ฟรี 10 GB แรก (ใช้ร่วมกับรูปสินค้าที่มีอยู่) · **ดาวน์โหลดดูคลิปไม่เสียเงิน** · อัปโหลดไม่กี่พันครั้ง/เดือน อยู่ในโควตาฟรี

ทำไม 60 วัน: ช่วงเปิดเคลม/คืนของของแพลตฟอร์มส่วนใหญ่ราว 15-30 วันหลังลูกค้าได้รับของ (ต้องเช็กกติกาล่าสุดของแต่ละร้าน) → 60 วันเผื่อขนส่ง + ข้อพิพาทลากยาว · คลิปที่กด "เก็บถาวร" ไม่ถูกลบ

## 5. ข้อมูลที่ต้องเพิ่ม (อธิบายก่อนทำ migration)

**ตารางใหม่ 1 ตาราง — `packing_sessions`** = "บันทึกการแพ็ค 1 ครั้ง" (1 แถว = แพ็ค 1 ออเดอร์ 1 รอบ)
- ออเดอร์ไหน · ยิงรหัสอะไรมา · ใครแพ็ค · สถานีไหน
- เวลาเริ่ม / เช็กครบ / เสร็จ · สถานะ (กำลังแพ็ค / เสร็จ / มีปัญหา / ทิ้งกลางคัน)
- กล่องที่แนะนำ / กล่องที่ใช้จริง · น้ำหนัก (ถ้ามีเครื่องชั่ง)
- ผลเช็กของ (ยิงอะไร ถูก/ผิด/เกิน กี่ครั้ง · ติ๊กมือพร้อมเหตุผล) — เก็บรวมเป็นก้อนเดียวในแถว
- ปัญหา (ของขาด / ของผิด / ของเสีย / อื่น ๆ) + หมายเหตุ
- คลิป: ที่อยู่ไฟล์ · ขนาด · ความยาว · ชนิดไฟล์ · ลายนิ้วมือไฟล์ · สถานะอัป · ลบได้หลังวันที่ · เก็บถาวรไหม
- ปิดสิทธิ์อ่านตรงจากหน้าเว็บ (เหมือนตารางออเดอร์) — อ่าน/เขียนผ่าน API ที่เช็กสิทธิ์เท่านั้น

**เพิ่มช่องในตารางเดิม (ไม่แก้/ลบข้อมูลเก่า):**
- `parent_skus_v2` + `pack_note` (ข้อความ) + `pack_flags` (ป้ายลัด)
- `platform_orders` + `packed_at` / `packed_by` / `buyer_note`
  เหตุผลที่ไม่ใช้ช่อง `status = packed` เดิม: ช่องนั้น **ถูก Shopee เขียนทับทุก 15 นาที** (Shopee PROCESSED → packed) ถ้าเราเขียนลงไปจะถูกลบ/สับสนว่าใครเปลี่ยน → แยกช่องของเราเอง ไม่ยุ่งกับร้าน

**สิทธิ์ใหม่:** `packing.pack` (แพ็ค) · `packing.view_video` (ดูคลิป) · `packing.dashboard` (ดูแดชบอร์ด/อันดับ) · `packing.manage` (ตั้งค่าสถานี/กล่อง/เก็บถาวร/ลบ)
→ เพิ่มกฎใน `lib/menu-permissions` + `menuVisibleTo` ตามกฎเมนู

**ประวัติ (audit log):** แพ็คเสร็จ · แจ้งปัญหา · เปลี่ยนกล่อง · ติ๊กมือ · ดู/ดาวน์โหลด/แชร์คลิป · กดเก็บถาวร/ลบคลิป · แก้ `pack_note`

## 8. ข้อแนะนำเพิ่มเติม (ข้อดี/ข้อเสีย)

1. **ระบบเข้าใช้ของคนแพ็ค**
   - (แนะนำ) **โหมดสถานี**: หัวหน้าล็อกอินเครื่องครั้งเดียว · คนแพ็คสลับตัวด้วยการยิงบัตรพนักงาน/กด PIN 4-6 หลัก → เร็ว เปลี่ยนคนได้ในวินาทีเดียว · ข้อเสีย: ต้องทำบัตร QR พนักงาน + ตัวเช็ก PIN
   - บัญชีส่วนตัวต่อคน: ปลอดภัยสุด แต่ล็อกอิน/ออกทุกครั้งที่เปลี่ยนกะช้า และลืมออกแล้วงานไปลงชื่อคนอื่น
2. **เช็กสถานะสดตอนยิง** — ถาม Shopee (อ่านอย่างเดียว) ว่าออเดอร์ยังไม่ถูกยกเลิก ก่อนเริ่มแพ็ค · ข้อดี: ปิดช่องโหว่ 15 นาทีที่ลูกค้ายกเลิกหลังเราดึงข้อมูล · ข้อเสีย: ช้าขึ้น ~0.5 วิ ต่อออเดอร์
3. **คิวออฟไลน์** — คลิปค้างในเครื่องเมื่อเน็ตหลุด (มีแน่ในเฟส 2) · ออฟไลน์เต็ม (เปิดออเดอร์ได้ตอนไม่มีเน็ต) ต้องโหลดออเดอร์รอแพ็คไว้ล่วงหน้า → เฟส 4
4. **เครื่องชั่ง** — ต่อ USB อ่านน้ำหนักอัตโนมัติ เทียบน้ำหนักควร-จริง จับของขาดได้ · ต้องซื้อเครื่องชั่งที่ต่อคอมได้ + Chrome เท่านั้น
5. **รายงานของผิด/ของขาด** — ปุ่ม "มีปัญหา" ระหว่างแพ็ค + หัวหน้าเห็นในศูนย์แจ้งเตือน · ลูกค้าเคลมทีหลัง → ผูกกลับมาที่คลิปและคนแพ็ค (นับเป็น error rate ที่แท้จริง)
6. **ทำเครื่องหมาย "แพ็คแล้ว"** ในศูนย์ออเดอร์ (ช่อง `packed_at` ของเราเอง) — **ไม่ตัดสต๊อก ไม่ส่งสถานะไปร้าน** จนกว่าเจ้าของสั่ง
7. **พิมพ์ใบปะหน้าจากจอเดียวกัน** — สะดวก แต่ตอนนี้ BigSeller พิมพ์อยู่ ถ้าพิมพ์ 2 ที่จะสับสน → เฟส 4 หลังเลิก BigSeller
8. **ใบรวมหยิบของ (Pick list)** — รวมสินค้าทุกออเดอร์ที่ต้องส่งวันนี้ หยิบทีเดียวแล้วค่อยแพ็ค · มีหน้าพิมพ์ `kind=pick` อยู่แล้วในศูนย์ออเดอร์ → แค่เพิ่มลิงก์จากหน้าแพ็ค
9. **การวางกล้อง** — ติดเหนือโต๊ะมองลงตรง ๆ สูง ~60-80 ซม. · เห็นทั้งโต๊ะ + กล่อง · ไฟสว่างไม่ย้อนแสง · พื้นโต๊ะสีเรียบ · ยกใบปะหน้าให้กล้องเห็น 2 วิแรก · แนะนำกล้อง USB 1080p ขาหนีบ (~฿800-1,500)
10. **ความเป็นส่วนตัว** — คลิปเห็นชื่อ-ที่อยู่ลูกค้า → ถังส่วนตัว · ดูได้เฉพาะ `packing.view_video` · ทุกการดู/ดาวน์โหลด/แชร์ลงประวัติ · ลิงก์แชร์หมดอายุเอง · แจ้งพนักงานเป็นลายลักษณ์อักษรว่ามีการอัดภาพ (กล้องหันที่โต๊ะ ไม่หันหน้าคน) · ปิดเสียงเป็นค่าเริ่มต้น
11. **แท็บ "แพ็ค" ในศูนย์แจ้งเตือน** — คลิปค้างอัป · ออเดอร์มีปัญหา · ออเดอร์ใกล้หมดเวลาส่ง
12. **การ์ด Brand Hub** — "แพ็คสินค้า" ต่อแบรนด์: วันนี้แพ็คกี่ใบ · Parent ที่ยังไม่มีกล่อง/วิธีแพ็ค · ของแถมประจำแบรนด์

| **F2 การ์ดบาร์โค้ดคำสั่ง** (แนะนำ) | การ์ด A5 เคลือบติดโต๊ะ: `*PK-DONE` เสร็จ · `*PK-PROBLEM` มีปัญหา · `*PK-REDO` อัดใหม่ · `*PK-SKIP` ข้าม · การ์ดกล่อง `*PK-BOX-C` ฯลฯ (ยิง = ตั้งกล่องที่ใช้จริง) | ใช้เครื่องยิงตัวเดิม ฟรี · ตั้งกล่องได้โดยไม่จับเมาส์ | ต้องพิมพ์การ์ด 1 แผ่น |

| F4 จบอัตโนมัติ | เช็กครบ + ไม่มีการยิงอะไร 5 วิ = จบ | เร็วสุด | เสี่ยงจบก่อนปิดเทป → คลิปไม่เห็นตอนปิดกล่อง |
| **F5 ปุ่มใหญ่ + Spacebar** | ปุ่มเขียวเต็มความกว้าง · มือถือ = ปุ่มสูง 56px ล่างจอ | สำรองเสมอ | ต้องหันไปกด |

- รหัสคำสั่งขึ้นต้น `*PK-` เพราะ **ตรวจ DB แล้ว `PK-` เฉย ๆ ชนรหัส SKU จริง 4 ตัว** · `*` ไม่ชนอะไร · ต้องพิมพ์เป็น Code128 (Code39 ใช้ `*` เป็นตัวเปิด/ปิด อ่านไม่ได้)
- เพิ่มชนิด `packing-cmd` ใน `lib/scan-code.ts` ที่เดียว (ห้ามเช็กรหัสคำสั่งกระจายในหน้า)
- พิมพ์การ์ดด้วยระบบพิมพ์บาร์โค้ดเดิม (`components/barcode-print`) ไม่ทำหน้าพิมพ์ใหม่
- กดจบตอนเช็กยังไม่ครบ = ไม่จบเงียบ ๆ → บันทึกเป็น "มีปัญหา" ให้หัวหน้าเห็น

## 11. ที่เก็บคลิป = NAS Synology 90 วัน (เจ้าของเลือก)

ตัวเลขเดิมยังใช้: คลิปใหม่ ~12 GB/เดือน → ค้างใน NAS ~37 GB (เดือนแคมเปญ ~50 GB) · ค่าที่เก็บ ฿0 · ใช้เน็ตอัปโหลดออฟฟิศ ~1 Mbps ต่อโต๊ะ

### 11.1 วิธีส่งคลิปจากเว็บเข้า NAS (ให้เจ้าของเลือก)

ปัญหาที่ต้องแก้: เว็บ ERP เป็น https บน Vercel → เบราว์เซอร์ส่งไฟล์ไปเครื่องในออฟฟิศแบบ http ไม่ได้ (โดนบล็อก) และต้องเปิดดูคลิปจากนอกออฟฟิศได้ (ตอนเคลม)

| วิธี | ทำยังไง | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **A ตัวรับคลิปบน NAS + Cloudflare Tunnel (แนะนำ)** | ลงโปรแกรมเล็ก ๆ ใน Container Manager ของ NAS: รับคลิป (ตรวจลายเซ็นจาก ERP) → เก็บ `/packing/YYYY-MM/` · ลบทุกคืนเมื่อเกิน 90 วัน ยกเว้นโฟลเดอร์ `ถาวร` · เล่นคลิปด้วยลิงก์ชั่วคราว 10 นาที · ต่อเข้าเน็ตด้วย Cloudflare Tunnel (ไม่ต้องเปิดพอร์ตเราเตอร์ HTTPS ฟรี) | ควบคุมครบ สิทธิ์ละเอียด ลบอัตโนมัติแม่น · ไม่มีค่าเดือน | ต้องเป็น NAS ที่ลง Container Manager ได้ (ส่วนใหญ่รุ่น "+") · ต้องมีโดเมนใน Cloudflare |
| B WebDAV ในตัว DSM | เปิด WebDAV + Reverse Proxy ใส่หัว CORS + ใบรับรอง HTTPS (DDNS synology.me) · ลบ 90 วันด้วย Task Scheduler | ใช้กับ NAS รุ่นเล็ก (ARM / ตระกูล j) ได้ | ตั้งค่ายาก · บัญชี WebDAV เดียว สิทธิ์หยาบ · ลิงก์ดูชั่วคราวทำยาก |
| C พัก R2 แล้ว NAS ดึงกลับ | คลิปขึ้น R2 ถังส่วนตัวก่อน → Cloud Sync บน NAS ดึงลง → R2 ลบเองใน 7 วัน | ไม่ขึ้นกับ NAS/เน็ตออฟฟิศตอนอัด · เสถียรสุด | 2 ที่ · หลัง 7 วันยังต้องให้ NAS เปิดดูจากนอกได้ (ต้องทำส่วนดูแบบ A หรือ B อยู่ดี) |

### 11.2 กติกาที่เหมือนกันทุกวิธี

- ERP ไม่เก็บไฟล์ เก็บแค่ "ที่อยู่ไฟล์บน NAS" + ขนาด + ความยาว + ลายนิ้วมือไฟล์ + วันลบ (`keep_until` = วันแพ็ค + 90) + `keep_forever` ใน `packing_sessions`
- **ปุ่มเก็บถาวร** (สิทธิ์ `packing.manage`): ย้ายไฟล์ไปโฟลเดอร์ `ถาวร` บน NAS + ตั้ง `keep_forever` + ลงประวัติพร้อมเหตุผล (เช่น เลขเคลม) · เลิกเก็บถาวรได้ (กลับไปนับ 90 วันจากวันแพ็ค)
- หน้าค้นหลักฐานโชว์ "จะลบใน N วัน" · เหลือ ≤ 7 วันขึ้นสีส้ม
- แนะนำ RAID + Hyper Backup โฟลเดอร์ `ถาวร` ไปที่อื่นอีกชั้น
- เพิ่มที่เก็บชนิด "NAS" ในกฎที่เก็บไฟล์ (`lib/storage-policy.ts` + `STORAGE_WIRING`) หมวด `packing_videos`
- NAS ไม่ตอบ: โต๊ะแพ็คเก็บคลิปในเครื่อง (IndexedDB) แล้วส่งใหม่เอง + เตือนในศูนย์แจ้งเตือน (หรือพัก R2 7 วัน ถ้าเลือกข้อ 10)
- คลิปเห็นที่อยู่ลูกค้า → ลิงก์ดูทุกครั้งออกโดย ERP หลังเช็กสิทธิ์ `packing.view_video` · ลิงก์แชร์ให้ลูกค้า/แพลตฟอร์มหมดอายุใน 7 วัน

### 11.3 ต้องให้เจ้าของตอบ

1. รุ่น NAS (เช่น DS920+) — จะได้รู้ว่าลง Container Manager ได้ไหม
2. มีโดเมนของตัวเองอยู่ใน Cloudflare ไหม (ใช้ทำ Tunnel)
3. เน็ตออฟฟิศอัปโหลดได้เร็วแค่ไหน
4. NAS ทำ RAID / สำรองข้อมูลอยู่แล้วไหม
