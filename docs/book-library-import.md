# คลังหนังสือ — ลงรายการจากอีเมล (📧 จากอีเมล)

## ใช้ทำอะไร

วางเนื้อหาอีเมลสั่งซื้อ / ใบเสร็จ / ใบยืนยันคำสั่งซื้อ → ระบบแยกเป็น "รายการหนังสือ" ให้ →
ผู้ใช้ตรวจ/แก้ในตาราง → กดบันทึกเข้าคลังทีเดียวหลายเล่ม

ปุ่มอยู่บนหัวหน้า `/book-library` ทั้งมุมมองชั้นหนังสือและมุมมองตาราง (เห็นเมื่อมีสิทธิ์ `books.edit`)

## ทำไมไม่ต่อ Gmail อ่านเมลอัตโนมัติ

เจ้าของถามเรื่องดึงจาก Gmail โดยตรง (2026-08-16) — สรุปข้อจำกัดที่ทำให้เลือกวิธี "วาง" ก่อน:

- บัญชีที่ใช้เป็น **Gmail ส่วนตัว (@gmail.com)** ไม่ใช่ Google Workspace →
  Service Account ที่ระบบใช้กับ Google Drive อยู่แล้ว **อ่านกล่องเมลไม่ได้**
  (domain-wide delegation ใช้ได้เฉพาะ Workspace)
- สิทธิ์อ่านเมล (`gmail.readonly`) เป็น **restricted scope** ของ Google:
  - อยู่โหมด Testing ได้ แต่ **refresh token หมดอายุทุก 7 วัน** → ต้องกดล็อกอินใหม่เรื่อย ๆ
  - จะขึ้น Production ต้องผ่าน verification + security assessment (มีค่าใช้จ่ายสูง ไม่คุ้มกับผู้ใช้ 1-2 คน)
- ถ้าวันหนึ่งอยากได้อัตโนมัติจริง **ทางที่ไม่ติดข้อจำกัดข้างบน = Google Apps Script**
  ที่รันในบัญชีเจ้าของเอง (ติด label เมล → สคริปต์ยิงเข้า API ของ ERP ตามเวลา)
  — ยังไม่ได้ทำ ถ้าทำให้ต่อยอดจาก endpoint เดิมด้านล่างได้เลย

## ส่วนประกอบ

| ส่วน | ไฟล์ | หน้าที่ |
|---|---|---|
| ป๊อปอัป | `app/book-library/import-mail-modal.tsx` | วางข้อความ → ตารางตรวจ/แก้ → บันทึก |
| ตัวอ่าน | `app/api/book-library/parse-email/route.ts` | รับ `{text}` → คืน `{books:[…]}` |
| บันทึกจริง | `/api/master-v2/book_library/import` (ของกลาง) | insert + audit log |

## ตัวอ่าน (parse-email)

- ใช้ AI ผ่านของกลาง `chatJson()` (`lib/ai-caption.ts`, JSON mode) — โมเดลตามที่ตั้งใน
  ตั้งค่า → คำสั่ง AI (`ui_config.ai_product_model`) ค่าเริ่มต้น `gpt-4o-mini`
- **ไม่เขียนอะไรลงฐานข้อมูล** — เป็นตัวช่วยกรอกล้วน ๆ ผู้ใช้ต้องกดยืนยันเอง
- guard สิทธิ์ `books.edit`
- เพดาน: ข้อความ 20,000 ตัวอักษร · ผลลัพธ์ 60 เล่ม/ครั้ง
- ค่าที่คืนถูก normalize ฝั่ง server แล้ว: `status` ต้องอยู่ใน owned/wishlist/upcoming/skipped
  (ตรงกับ CHECK constraint ของตาราง) · วันที่ต้องเป็น `YYYY-MM-DD` จริงเท่านั้น
  (AI มักตอบ "ไม่ระบุ" ปนมา) · `price` ต้องเป็นตัวเลข > 0 · `buy_url` ต้องขึ้นต้น http(s)

## ทำไมใช้ AI แทนกฎรายร้าน

เจ้าของซื้อหลายที่ปนกัน (มาร์เก็ตเพลส / ร้านหนังสือไทย / ต่างประเทศ) รูปแบบอีเมลต่างกันหมด
และร้านเปลี่ยนเทมเพลตเมื่อไรกฎก็พัง — ตัวอ่านแบบ AI จึงคุ้มกว่า
แลกกับ "ต้องให้คนตรวจก่อนบันทึกเสมอ" ซึ่งเป็นเงื่อนไขที่ยอมรับได้สำหรับงานนี้

## กันเพิ่มซ้ำ (2 ชั้น)

1. **ชั้นฐานข้อมูล (ด่านจริง)** — unique index `book_library_active_title_uniq`
   บน `lower(btrim(title))` เฉพาะแถวที่ `is_active` → ไม่ว่าจะเพิ่มจากทางไหน
   (ฟอร์ม / เพิ่มทั้งชุด / จากอีเมล / ยิง API ตรง) ชื่อเล่มซ้ำก็เข้าไม่ได้
   · แถวที่ลบแล้ว (`is_active=false`) ไม่กันชื่อ → สร้างใหม่ชื่อเดิมได้
   · ตัวนำเข้ากลางจะ retry ทีละแถวเมื่อ batch พัง → เล่มที่ไม่ซ้ำเข้าได้ตามปกติ
     ส่วนเล่มที่ซ้ำถูกรายงานใน `failed[]` (ข้อความไทยจาก `friendlyDbError`)
2. **ชั้นหน้าจอ (ให้เห็นก่อน)** — `POST /api/book-library/check-duplicates`
   (guard `books.view`) รับ `{titles:[]}` คืนว่าชื่อไหนมีแล้ว
   · เพิ่มทั้งชุด: เล่มที่มีอยู่แล้วขึ้นเป็นปุ่มสีเทาขีดฆ่า กดไม่ได้ + ไม่ถูกสร้าง ("ข้าม N เล่ม")
   · จากอีเมล: แถวที่ซ้ำติดป้าย "ซ้ำ" และไม่ติ๊กให้ (ผู้ใช้ยังติ๊กเองได้ถ้าตั้งใจ — แต่จะโดนด่าน DB)

เทียบชื่อแบบเดียวกันทั้ง 2 ชั้น: ตัวพิมพ์เล็ก + ตัดช่องว่างหัวท้าย (ฝั่ง API ยุบช่องว่างซ้ำเพิ่มด้วย)

## หารูปปกอัตโนมัติ (Google Books)

ปุ่ม **🖼 หารูปปกให้** ในมุมมองชั้นหนังสือ (โผล่เมื่อมีเล่มที่ยังไม่มีปก) →
ยิง `POST /api/book-library/find-cover {id}` **ทีละเล่ม** (ไม่ยิงพร้อมกัน กันโดนจำกัดโควตา
และกันเซิร์ฟเวอร์ทำงานเกินเวลา) พร้อมโชว์ความคืบหน้า · เจอ error ระดับตั้งค่า/โควตา → หยุดทันที

**ต้องตั้ง env `GOOGLE_BOOKS_API_KEY`** (ที่ Vercel → Settings → Environment Variables → redeploy)
ไม่ตั้ง = ปุ่มยังกดได้แต่ขึ้นข้อความบอกให้ไปตั้งค่า (ไม่พัง)

วิธีค้น: ISBN (แม่นสุด) → ไม่มีก็ `ชุด + เล่ม` → ไม่มีอีกก็ชื่อเรื่อง ·
เอา `imageLinks.thumbnail` มาขอ `zoom=1` (ตัดเงาหน้าปก) → ตรวจชนิด/ขนาดไฟล์ →
เก็บลง R2 `book-covers/<id>/<ts>.<ext>` → อัปเดต `cover_r2_key`

**ทำไมเก็บลง R2 ไม่ใช่ลิงก์ตรง:** ลิงก์ของ Google เปลี่ยน/หมดอายุได้ และตัวแสดงรูปกลาง
(ตาราง/ชั้นหนังสือ/ฟอร์ม) ใช้ R2 key เหมือนกันหมด — เก็บลง R2 แล้วใช้ได้ทุกที่โดยไม่ต้องแก้ของกลาง

**ที่วัดไว้ก่อนเลือกทางนี้ (2026-08-16):** Google Books **ไม่มีกุญแจ = โควตา 0** ยิงไปโดน 429 ทันที ·
Open Library ฟรีไม่ต้องมีกุญแจ แต่ค้นชื่อไทย ("ดาบพิฆาตอสูร") ได้ 0 ผล ขณะที่ชื่อ EN/JP เจอพร้อมปกรายเล่ม
→ ถ้า Google Books ยังหาปกไทยไม่เจอ ทางถัดไปคือให้ AI แปลชื่อไทย→ญี่ปุ่น/อังกฤษ ก่อนค้น
(จะได้ปกฉบับต่างประเทศ ไม่ใช่ปกไทย)

## ข้อจำกัดที่รู้อยู่

- อ่านได้เฉพาะ **ข้อความ** — ยังไม่รับรูปภาพ/แคปหน้าจอ (ถ้าจะทำ ใช้โมเดล vision แบบเดียวกับ
  `app/api/china-pay/ocr-slip-extract`)
- กันซ้ำเทียบจาก **ชื่อเล่ม** เท่านั้น — ถ้าตั้งชื่อคนละแบบ (เช่น "ดาบพิฆาตอสูร 1" กับ
  "ดาบพิฆาตอสูร เล่ม 1") ระบบมองว่าคนละเล่ม
- ราคาต่อเล่มบางอีเมลบอกแค่ยอดรวม → ช่องราคาจะว่าง (ตั้งใจ ไม่เดา)
- ยังไม่ดึงรูปปกจากอีเมล
