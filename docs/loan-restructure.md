# ปรับโครงสร้างหนี้ (Loan Restructuring)

> เปลี่ยนเงื่อนไขสัญญาเงินกู้กลางทาง (ลดดอก / ยืดเวลา / พักเงินต้น / ทบดอกค้าง) โดยเงื่อนไขเก่าและงวดที่จ่ายแล้วไม่หาย

## ใช้ทำอะไร

ธนาคารตกลงเปลี่ยนเงื่อนไขเงินกู้ให้ (มักมีหนังสือแจ้ง) → ลงในระบบเป็น "ครั้งที่ปรับ" 1 ครั้ง
ระบบจะสร้างตารางผ่อนเวอร์ชันใหม่ตั้งแต่วันมีผล อัปเดตเงื่อนไขในสัญญา และเก็บของเดิมไว้ในประวัติ
กระดานเงินสดเห็นงวดใหม่ทันที (อ่านจากตารางผ่อนเวอร์ชันที่ active อยู่แล้ว)

## ที่อยู่ในหน้าจอ

- หน้า **สัญญาเงินกู้** (`/loan-contracts`) → เปิดสัญญา → แผง **🔧 ปรับโครงสร้างหนี้** ท้ายหน้า
  - ปุ่ม 🔧 เปิดป๊อป 4 ขั้น (เฉพาะสิทธิ์ `loan_contracts.restructure` — ตอนนี้ admin เท่านั้น)
  - เส้นเวลาประวัติทุกครั้ง + ปุ่ม ↩ ย้อนกลับ (เฉพาะครั้งล่าสุด)
- ตารางสัญญา: คอลัมน์ `restructure_count` (ป้ายส้ม "ปรับแล้ว n ครั้ง · วันที่") และ `last_restructure_date`

## ป๊อป 4 ขั้น

| ขั้น | กรอกอะไร | หมายเหตุ |
|---|---|---|
| 1 เรื่องอะไร | ธนาคารให้อะไร (หลายอย่างได้) · วันมีผล · เลขหนังสือ · เหตุผล | ลงย้อนหลังได้ |
| 2 เงื่อนไขใหม่ | เงินต้น ณ วันมีผล (ค่าเริ่มต้น = เงินต้นคงเหลือ) · ดอกค้างทบเข้าต้น · ดอกเบี้ย · วิธีผ่อน · พักเงินต้น N งวด · งวดที่เหลือ · วันตัดงวด · ค่างวด (ว่าง = ระบบคิด) · ค่าธรรมเนียม (เก็บแยก) | ตารางเทียบ "เดิม / ใหม่" ข้าง ๆ กัน |
| 3 ตารางผ่อนใหม่ | งวดหลังวันมีผล — แก้รายงวด / ➕ / 🗑 / วางจาก Excel ของธนาคาร / ↺ ให้ระบบคิดใหม่ | เงินต้นรวมต้องเท่ากับเงินต้นตั้งต้น (คลาด ≤ 1 บาท) |
| 4 ยืนยัน | สรุปว่าจะเกิดอะไรบ้าง | |

## เกิดอะไรขึ้นตอนกด "ยืนยัน" (ฟังก์ชัน `loan_restructure_apply` ทำใน transaction เดียว)

1. บันทึกแถวใน `loan_restructurings` (snapshot เงื่อนไขเดิม `old_terms` + ใหม่ `new_terms`)
2. ตารางผ่อนเวอร์ชันเดิม → `superseded` · สร้างเวอร์ชันใหม่ (`source = 'restructure'`)
3. เวอร์ชันใหม่ = **คัดลอกงวดเดิมที่ครบกำหนดก่อนวันมีผล** + งวดใหม่
   - ต้องคัดลอก เพราะ `loan_contract_reallocate` ตัดยอด "ใบจ่ายทุกใบ" ลงเวอร์ชันที่ active เท่านั้น
   - งวดใหม่งวดแรกใส่ `principal_adjustment` = เงินต้นตั้งต้นใหม่ − ยอดที่ไล่ต่อจากงวดเดิม
     (`loan_schedule_chain_recompute` บวกค่านี้ก่อนไล่ยอด — เป็นทางเดียวที่เงินต้นกลางตารางกระโดดได้)
4. ดอกค้างทบเข้าต้น > 0 → ใบเบิก `loan_drawdowns` 1 ใบ (เงินต้นคงเหลือของสัญญา = เบิกสะสม − จ่ายแล้ว จึงขยับตาม)
5. ค่าธรรมเนียม > 0 → `loan_contract_fees` 1 แถว (จ่ายแยก ไม่อยู่ในตารางผ่อน)
6. อัปเดตสัญญา: ดอกเบี้ย/ชนิด/อ้างอิง/วิธีผ่อน/วันตัดงวด/วันสิ้นสุด/`restructure_count`/`last_restructure_date`
7. `loan_contract_reallocate` → ตัดยอดใบจ่ายใหม่ทั้งหมด + recompute

ย้อนกลับ (`loan_restructure_revert`): คืน `old_terms`, เวอร์ชันเก่ากลับ active, ปิดใบเบิก/ค่าธรรมเนียมของครั้งนั้น
ถ้ามีใบจ่ายยืนยันแล้วหลังวันมีผล → ตอบ `PAYMENTS_AFTER:n` → หน้าจอให้พิมพ์ CONFIRM แล้วส่ง `force=true`

## ข้อจำกัด / ควรรู้

- ใบจ่ายที่จ่ายตาม "ตารางเดิม" หลังวันมีผล จะถูกตัดยอดใหม่ตามตารางใหม่ (ตั้งใจ — กรณีลงย้อนหลัง)
- ถ้าไป "วางจาก Excel ทั้งใบ" ในป๊อปงวดผ่อนภายหลัง `principal_adjustment` ของงวดแรกใหม่จะหาย (ยอดคงเหลือกลางตารางเพี้ยน) — ให้แก้รายงวดแทน
- ยังไม่มี approval flow (admin กดแล้วมีผลทันที) · เอกสารหนังสือธนาคารแนบที่แกลเลอรี "เอกสารสัญญา" ของสัญญา
