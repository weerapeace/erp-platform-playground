# คนรับงาน (หลายคน) + วันที่จ่าย — ของกลางป๊อปจ่ายงาน

ไฟล์: `app/master/work-board/crew-pick.tsx`, `app/master/work-board/dispatch-date-pick.tsx`

## ใช้ทำอะไร

- **CrewPick** = เลือก "คนรับงาน" ในโต๊ะได้หลายคน (กดชื่อเป็นปุ่ม) เพื่อจำว่าใบนี้ให้ใครไป
  - ไม่เลือกใคร = **🏢 ทั้งโต๊ะ (ไม่ระบุคน)** — ใช้ตอนจำไม่ได้ว่าให้ใคร
  - **↺ ชุดล่าสุดของโต๊ะนี้** = กดครั้งเดียว ได้ชุดคนเดียวกับใบล่าสุดที่โต๊ะนี้ระบุคนไว้
  - ⚠️ ที่ชื่อ = คนนั้นเคยทำรุ่นนี้เสีย (ป๊อปจ่ายงานปกติส่ง `flag` มา)
  - คนเกิน 12 คน (เช่น โต๊ะเหมา ที่เลือกได้ทุกคน) มีช่องค้นหาชื่อ/รหัส · งานเหมา (`required`) ต้องเลือกอย่างน้อย 1 คน
- **DispatchDatePick** = ช่องวันที่จ่าย ตั้งต้นเป็นวันนี้ ย้อนวันได้ · ค่า `null` = ไม่ระบุวัน (จำไม่ได้)

## ใช้ที่ไหน

| จุด | ทำอะไร |
|---|---|
| ป๊อปจ่ายงานปกติ (ลากการ์ดเข้าโต๊ะ) | เลือกคน + วันที่จ่าย |
| ป๊อปจ่ายงานหลายใบ (มุมมองตาราง) | เลือกคนเดียวกันทุกใบ + วันที่จ่าย |
| รายละเอียดใบงาน (กดการ์ดในโต๊ะ) | **✏️ แก้** คนรับ / วันที่จ่าย ของใบที่จ่ายไปแล้ว |
| การ์ดงานบนบอร์ด | ป้ายมุมซ้ายบน 👥 = หลายคน · 👤 = คนเดียว · 🏢 = ทั้งโต๊ะ |

ป๊อป 👤 ของบอร์ดแผน (`dispatch-plan-board.tsx`) เลือกหลายคนได้อยู่แล้วตั้งแต่ก่อนหน้านี้ — เก็บข้อมูลรูปแบบเดียวกัน

## เก็บข้อมูลยังไง (ใบงาน `mo_work_orders`)

| ช่อง | หลายคน | ทั้งโต๊ะ |
|---|---|---|
| `assignees` (jsonb) | `[{id, name}, …]` | `[]` |
| `assignee_name` | ชื่อต่อกันด้วย ", " | ชื่อโต๊ะ |
| `assignee_id` | คนแรก | null |
| `assignee_type` | craftsman | department |

ใช้ `crewFields(crewList(ids, people), deskName)` สร้างช่องเหล่านี้เสมอ อย่าประกอบเอง

- `crewIdsOf(wo)` อ่านคนรับของใบเดิมได้ รวมใบเก่าที่เป็นช่างเดี่ยว (ไม่มี `assignees`)
- ตอนบันทึก ระบบตัดคนที่ไม่อยู่ในโต๊ะแล้วทิ้ง (เปลี่ยนโต๊ะในป๊อป/ย้ายคน)
- POST/PATCH `/api/mo/work-orders` รับ `assignees` (ตัดชื่อว่าง/ซ้ำ สูงสุด 50) · จ่ายงานแล้ว DM แจ้ง**ทุกคน**ที่รับงาน
- ค่าแรง: เลือกคนเดียวที่มีเรตเฉพาะใน BOM → ใช้เรตคนนั้น · หลายคน/ทั้งโต๊ะ → ราคากลาง
- **ไม่กระทบเงินเดือน** — สรุปค่าแรงรายเดือนคิดจากงานเหมารายชิ้น ไม่ได้อ่านช่องผู้รับของใบงาน

## สิทธิ์ / ประวัติ

- เลือก/แก้คนรับ และวันที่จ่าย = สิทธิ์ `work_board.dispatch` (เหมือนจ่ายงาน)
- ทุกการแก้บันทึก audit log (`mo_work_order` update) อยู่แล้วจาก PATCH เดิม

## ✅ "จำไม่ได้ว่าจ่ายวันไหน" (บันทึกวันว่าง) — เปิดแล้ว 2026-10-28

- ใต้ช่องวันที่มีลิงก์ **🤷 จำไม่ได้ว่าวันไหน** → ช่องกลายเป็น "🤷 ไม่ระบุวัน" (กดอีกทีเพื่อกลับมาใส่วัน = วันนี้)
- ไม่กดอะไร = วันนี้ เหมือนเดิม · แก้ทีหลังได้ที่รายละเอียดใบงาน "วันที่จ่าย ✏️ แก้"
- DB: ปลด "ห้ามว่าง" ของ `mo_work_orders.dispatch_date` แล้ว (เจ้าของอนุมัติ) — ค่าเริ่มต้นยังเป็นวันนี้ · ข้อมูลเดิมไม่ถูกแตะ
  ```sql
  alter table public.mo_work_orders alter column dispatch_date drop not null;
  ```
  (`supabase/migrations/202611030200_mo_work_orders_dispatch_date_nullable.sql`)
- ปิดปุ่มชั่วคราวได้ด้วย `ALLOW_UNKNOWN_DATE = false` ใน `dispatch-date-pick.tsx`
- API: POST `dispatch_date: null` = ไม่ระบุ · ไม่ส่ง/ผิดรูปแบบ = วันนี้ · PATCH รับ `null` ได้
- หน้าที่แสดงวันจ่าย (ประวัติจ่าย, สถานะใบสั่งผลิต, งานค้าง, รายละเอียดใบงาน) แสดงค่าว่างเป็น "—" / "🤷 ไม่ระบุ" · ตัวนับ "จ่ายมาแล้วกี่วัน" ข้ามใบที่ไม่มีวัน

## ข้อจำกัด

- หน้าสรุปที่นับตาม "ชื่อผู้รับ" (เช่น งานเสียต่อช่าง, แดชบอร์ดผลิต) เห็นใบหลายคนเป็นชื่อรวม "ลม, แพง" — เหมือนที่บอร์ดแผนเก็บมาตั้งแต่ก่อน
- จ่ายด่วน (แตะการ์ด→แตะโต๊ะ) ยังเป็นทั้งโต๊ะ ไม่ถามคน — แก้คนทีหลังได้ที่รายละเอียดใบงาน
