# ภาพรวมการตลาด (`/marketing/dashboard`)

หน้าแรกของแอปการตลาด เปิดใช้เมื่อ 2026-11-23 (แผนการตลาดรอบ 1 · เจ้าของเลือกแบบ A)

## ใช้ทำอะไร

ใช้ตัดสินใจเรื่องการตลาดจาก **ออเดอร์จริงทุกช่องทาง** (Shopee · Lazada · TikTok · LINE · เว็บ) ทุกตัวเลขกดเจาะลึกต่อได้

| แท็บ | ดูอะไร |
|---|---|
| ภาพรวม | ยอดขายเทียบเป้า · ต้องขายวันละเท่าไหร่ · ยอดสะสมเทียบเส้นเป้า · คาดการณ์สิ้นเดือน · กล่อง "ต้องจัดการ" · เทียบช่วงก่อน / เดือนก่อน / ปีก่อน |
| ยอดขาย & ช่องทาง | ยอดรายวัน · ตารางแยกช่องทาง (กดแถว = กรองช่องทางนั้น) · แผนที่ความร้อน วัน×ชั่วโมง |
| สินค้า | 80/20 (กลุ่ม A/B/C) · ดาวรุ่ง/กำลังตก (14 วันล่าสุด เทียบ 14 วันก่อนหน้า) · ตาราง (กดแถว = ดูออเดอร์ → เปิดหน้าออเดอร์) |
| ยกเลิก | จัดกลุ่มเหตุผล (ฝั่งร้าน / ลูกค้าขอแก้ / ไม่จ่าย / เปลี่ยนใจ / ถูกกว่า / ขนส่ง) · แยกช่องทาง |
| แคมเปญวันพิเศษ | วันเลขเบิ้ล 15 และ 25 ของเดือน: ยอดวันงานกี่เท่าของวันปกติ · 3 วันก่อนและหลังงาน |
| ไฟล์ Shopee | หน้า Dashboard เดิม (สถิติร้านจากไฟล์ shop-stats ที่อัปโหลด) ไม่ได้แก้ |

## ตัวเลขมาจากไหน

- **ยอดขาย** คือมูลค่าสินค้า (จำนวน × ราคาหลังส่วนลดร้าน) เป็นชุดเดียวกับแดชบอร์ดช่องทางขาย และตรงกับตัวเลขของ Shopee
  - สูตรอยู่ที่ `lib/platform-dashboard-calc`
  - ใบที่นับเป็นยอดขายใช้กติกา `countsAsSale` ซึ่งไม่นับใบยกเลิกและใบที่ยังไม่จ่าย
- **วันปกติ** (ใช้ในแท็บวันพิเศษ) คือยอดเฉลี่ยของวันที่ 8–14 ก่อนวันงาน
- **ดาวรุ่ง/ตก:** ยอดต้องเปลี่ยนอย่างน้อย 30% และต้องมียอดพอ (กันสินค้าที่ขายชิ้นเดียวแล้วแกว่ง)
- **แจ้งเตือนสินค้ากำลังตก:** นับเฉพาะสินค้ากลุ่ม A ที่ยอด 14 วันหายไปอย่างน้อย ฿2,000 หรือ 0.5% ของยอดรวม (`significantFalls`)

## เป้า

- เก็บที่ `ui_config.platform_sales_targets` ที่เดียวกับแดชบอร์ดช่องทางขาย
- ช่องเก็บเป้ามี 2 แบบ:
  - เป้ารวม: `YYYY-MM|แบรนด์หรือ*`
  - เป้าแยกช่องทาง: `YYYY-MM|แบรนด์หรือ*|รหัสช่องทาง` (เพิ่มเมื่อ 2026-11-23 เป้าเดิมไม่หาย)
- ตั้ง แก้ หรือลบเป้าได้จากปุ่ม "ตั้งเป้า" (ต้องมีสิทธิ์ `products.platforms.edit`)
  - หลังบันทึกจะมีปุ่มย้อนกลับในแจ้งเตือนมุมจอ
  - ทุกการแก้ลงประวัติ (audit)

## แจ้งเตือนทุกเช้า

- ส่งที่ `/api/cron/marketing-alert` เวลา 09:20 (เวลาไทย) ทุกวัน เข้ากระดิ่งในชื่อเรื่อง `marketing.alert`
- ส่งเฉพาะวันที่มีเรื่องระดับเตือนหรือด่วน วันละครั้ง:
  - ยอดเดือนนี้ช้ากว่าเป้าเกิน 10%
  - ยอดเมื่อวานต่ำกว่าเฉลี่ย 28 วันเกิน 40%
  - มีออเดอร์ยกเลิกเพราะฝั่งร้านใน 7 วัน
- เรื่อง "สินค้ากำลังตก" แนบไปด้วย แต่ไม่ทำให้ระบบส่ง
- เลือกคนรับได้ที่กฎแจ้งเตือน (แผนผัง → แท็บแจ้งเตือน) ถ้าไม่ตั้งกฎ ระบบส่งหาแอดมิน
- ไม่ส่ง LINE เพราะในข้อความมียอดขาย

## ข้อจำกัดที่รู้แล้ว

- ออเดอร์ Lazada ที่มาทางอีเมลไม่มียอดเงิน หน้าเว็บนับจำนวนใบได้ แต่ยังไม่รวมยอดเงิน และมีป้ายบอก
- รายการสินค้าที่ยังไม่จับคู่ SKU แสดงแยกเป็น "รหัสบนร้าน" ในตารางสินค้า
- เหตุผลยกเลิกมีเฉพาะ Shopee และ TikTok (Lazada ไม่ส่งเหตุผลมา)
- ยังไม่มี: โฆษณา (รอบ 3) · กรวยการซื้อ (รอบ 4) · ลูกค้า (รอบ 5) — ดูแผนใน memory `marketing_analytics_roadmap`

## รอบ 2 — ค่าธรรมเนียม + กำไร (2026-11-24)

เจ้าของเลือก: แบบ A (2 แท็บแยก) + ข้อเสนอ 1 ดึงค่าธรรมเนียมย้อนหลังอัตโนมัติ · 2 ขายดีแต่ยังไม่มีต้นทุน + ปุ่มไปกรอก · 4 เตือนค่าธรรมเนียมพุ่ง

| ส่วน | ไฟล์ |
|---|---|
| แท็บ ค่าธรรมเนียม / กำไร | `app/marketing/dashboard/profit-tabs.tsx` (`?tab=fees` · `?tab=profit`) |
| API | `GET /api/marketing/profit?from&to&platform_id&brand_id` — กำไรส่งเฉพาะคนมีสิทธิ์ `products.cost.view` |
| ตัวดึงค่าธรรมเนียม | `/api/cron/platform-fees` ทุก 30 นาที (11,41) · เรียกเองโดยไม่ใช่ cron = ดูว่าค้างกี่ใบ |
| สูตร (pure + เทสต์) | `lib/marketing-profit-calc.ts` — จัดหมวดค่าธรรมเนียม · สรุปแยกช่องทาง · กำไรต่อสินค้า · ขายดีแต่ไม่มีต้นทุน |
| โหลดข้อมูล (server) | `lib/marketing-fees-server.ts` — `loadFeeContext` · `recentFeeSpikes` |

- ค่าธรรมเนียมจริงต่อออเดอร์ = `raw.shopee_income` / `raw.lazada_income` (ตัวเดียวกับหน้ารายละเอียดออเดอร์ `/api/platform-orders/income`) · อ่านจากร้านอย่างเดียว
- ค่าธรรมเนียม = คอมมิชชั่น · ค่าบริการ/โปรแกรม · ค่าธุรกรรม · ค่าส่งสุทธิที่ร้านออก · ค่าโฆษณา/แอฟฟิลิเอต · อื่น ๆ — **ไม่นับ** ส่วนลดของร้านเอง/คืนเงิน
- % ค่าธรรมเนียม คิดจากใบที่ดึงแล้ว · "ประมาณทั้งช่วง" ขึ้นเมื่อดึงได้ ≥ 20 ใบต่อช่องทาง
- ต้นทุนต่อชิ้น = ราคาซื้อของ SKU (`skus_v2.standard_price`) → ไม่มี = ต้นทุนรุ่น (`parent_skus_v2.product_cost`) → ไม่มี = ไม่คิดกำไร (ไม่เดา)
- เตือนทุกเช้า: ค่าธรรมเนียม 7 วันของช่องทางใด สูงกว่า "ปกติ" (30 วันก่อนหน้า) เกิน 3 จุด % (ต้องมี ≥ 20 ใบทั้งสองช่วง) → `fee_spike` · ไม่ใช้เกณฑ์ตายตัวเพราะ Shopee % สูงอยู่แล้ว (~36% ของมูลค่าสินค้า เพราะคิดรวมส่วนลดที่ Shopee ออกให้)
- ใบที่ไม่มียอดเงิน (Lazada จากเมล) ไม่นับใน %
- TikTok ยังดึงค่าธรรมเนียมไม่ได้ (ต้องเปิดสิทธิ์การเงินในแอป TikTok)
- ข้อมูล ณ 2026-11-24: มีต้นทุนแค่ ~2% ของยอด 30 วัน · กรอก 20 รุ่นขายดีแรก ≈ ครอบคลุมเพิ่ม ~50%

## รอบ 3 — โฆษณา (2026-11-24)

เจ้าของเลือก: แบบ A (แท็บ "โฆษณา" `?tab=ads`) + ข้อ 1 Shopee Ads อัตโนมัติ · 2 ROAS จุดคุ้มทุนต่อแบรนด์ · 3 เตือนแคมเปญขาดทุน 3 วันติด · 4 ค่าแอฟฟิลิเอต/Boost · 5 รวมไฟล์ที่อัปโหลด · 6 เชื่อม Meta Ads

| ส่วน | ไฟล์ |
|---|---|
| แท็บโฆษณา | `app/marketing/dashboard/ads-tab.tsx` |
| API | `GET/PATCH /api/marketing/ads-overview` (PATCH = จุดคุ้มทุน · products.platforms.edit · audit) · `PATCH /api/marketing/ads/accounts` (ปิด/เปิดดึง · ตัดการเชื่อม Meta) |
| ตัวดึง | `/api/cron/marketing-ads` วันละ 2 รอบ 08:40/20:40 (`40 1,13 * * *`) · POST = ปุ่ม "ดึงตอนนี้" |
| Shopee Ads | `lib/shopee-ads.ts` — get_all_cpc_ads_daily_performance · get_product_level_campaign_id_list · get_product_campaign_daily_performance (ชื่อช่องจากเอกสาร Shopee 2026-11-24 · ย้อนได้ 6 เดือน) |
| Meta Ads | `lib/meta-ads.ts` + `lib/meta-ads-connect.ts` · เริ่มที่ `/api/marketing/ads/meta/start` (สิทธิ์ ads_read) · ใช้ callback เดิม `/api/meta/oauth/callback` (state ขึ้นต้น `ads:`) |
| ดึง/เก็บ | `lib/marketing-ads-server.ts` — ครั้งแรกย้อน 90 วัน · ต่อไปดึงทับ 7 วันล่าสุด · `recentLosingCampaigns` |
| สูตร (pure + เทสต์) | `lib/marketing-ads-calc.ts` |
| ตาราง | `marketing_ads_daily` (ยอดรายวัน ร้าน/แคมเปญ) · `marketing_ads_accounts` (บัญชี + สถานะดึง + token Meta เข้ารหัส) — server เท่านั้น |

- ROAS = ยอดจากโฆษณา ÷ ค่าโฆษณา (ยอดซื้อภายใน 7 วันหลังคลิก ตามแพลตฟอร์ม) · ค่าการตลาด ÷ ยอดขายรวม = (ค่าโฆษณา + ค่าแอฟฟิลิเอต/Boost) ÷ ยอดขายทุกช่องทาง
- จุดคุ้มทุน: ui_config `marketing_ads_breakeven` = { "*" | brand_id: ROAS } · สถานะ ทำกำไร (≥ ×1.2) / เฉียดทุน / ขาดทุน · ยังไม่ตั้ง = ไม่เตือน
- เตือนเช้า `ads_loss`: แคมเปญที่ ROAS ต่ำกว่าจุดคุ้มทุนติดกัน ≥ 3 วัน (7 วันล่าสุดถึงเมื่อวาน)
- ยังไม่ดึง: แคมเปญ Shopee GMV Max (อีกชุด API) · Lazada/TikTok Ads (ใช้ไฟล์ที่อัปโหลด)
- Meta: token อยู่ได้ ~60 วัน หมดแล้วกด "เชื่อม Meta Ads ใหม่" · แอป Meta โหมดพัฒนาใช้ได้กับคนที่เป็นแอดมินแอป · คนอื่นต้องผ่าน App Review

## รอบ 4 — คนเข้าร้าน (2026-11-25)

เจ้าของเลือก: แบบ A (แท็บ "คนเข้าร้าน" `?tab=traffic`) + ข้อ 1 เก็บยอดเข้าชมทุกวัน · 2 คนดูเยอะขายน้อย / ขายดีคนดูน้อย · 3 เตือนดาวตก · 4 เตือนคนดูพุ่ง

| ส่วน | ไฟล์ |
|---|---|
| แท็บ | `app/marketing/dashboard/traffic-tab.tsx` |
| API | `GET /api/marketing/traffic?from&to&brand_id` |
| ตัวเก็บ | `/api/cron/marketing-traffic` ทุกคืน 00:05 (`5 17 * * *`) จดเป็นยอดสิ้นวันเมื่อวาน · POST = ปุ่ม "เก็บตอนนี้" (จดเป็นวันนี้) |
| ดึง/โหลด | `lib/marketing-traffic-server.ts` — Shopee `get_item_extra_info` (≤ 50 ต่อครั้ง) · สินค้า = platform_catalog_listings สถานะ normal/ยังไม่รู้ |
| สูตร (pure + เทสต์) | `lib/marketing-traffic-calc.ts` |
| ตาราง | `marketing_item_stats` (ยอดสะสมต่อสินค้าต่อวัน) — server เท่านั้น |

- Shopee ให้แค่ยอดสะสม → ยอดรายวัน = สะสมวันนี้ − เมื่อวาน · **ย้อนหลังไม่ได้** · ยอดรายวันขึ้นหลังเก็บครบ 2 วันติด
- อัตราซื้อ = ชิ้นที่ขาย (ออเดอร์ Shopee ที่นับเป็นยอดขาย ผ่าน `platform_order_items.raw.item_id`) ÷ คนดู · นับเฉพาะวันที่มีข้อมูลคนดู
- ป้าย: คนดูติด 25% บน + อัตราซื้อต่ำกว่าครึ่งค่ากลาง = "คนดูเยอะ ขายน้อย" · ขายติด 25% บน + คนดูต่ำกว่าค่ากลาง = "ขายดี คนดูน้อย" (ต้องมีสินค้าที่มีคนดู ≥ 8 ตัว)
- เตือนเช้า: `rating_drop` (ดาวลด ≥ 0.05 จากวันก่อน · รีวิว ≥ 5) · `view_spike` (คนดูวันล่าสุด ≥ 3 เท่าของเฉลี่ย และ ≥ 50 · ข้อมูลระดับ info)
- Lazada / TikTok ไม่มีช่องทางให้ดึงยอดคนดู
