# 📤 ลงสินค้าบนแพลตฟอร์ม (ของกลาง)

หน้า: `/master/platform-listing` (แอป "ช่องทางขาย" → งานขายออนไลน์ → 📤 ลงสินค้าบนแพลตฟอร์ม)
คนละทิศกับ **🛒 สินค้าบนแพลตฟอร์ม** (`/master/platform-catalog` = ดูของที่อยู่บนร้าน / ดึงเข้ามา)

## ใช้ทำอะไร
เอาสินค้าใน ERP ขึ้นร้าน (เริ่มที่ Lazada) แบบทีละหลายตัว:
1. เลือกร้าน + แบรนด์ → ตารางกลางแสดงสินค้าทั้งแบรนด์ พร้อมสถานะ
2. เลือกหลายตัว → **📤 เตรียมลงสินค้า**: ระบบเติมชื่อ รายละเอียด หมวด รูป แบรนด์ + กฎราคา แล้วบันทึกเป็นร่าง พร้อมผลตรวจ
3. เลือกหลายตัว → **🗂️ ตั้งหมวดกลาง** (หมวดของร้านมาจากการจับคู่หมวดกลาง → ร้าน)
4. รายแถว → **🏬 เปิดตัวจัดการ** (ProductPlatformManager ตัวเดิม ตรงแท็บร้านนั้น) แก้ทีละตัว
5. **ลงสินค้าจริง**: เฉพาะร้านที่มีตัวเชื่อม (`erp_platforms.capabilities.api = true`) — **Lazada ยังไม่เปิด** ปุ่มขึ้น "ยังไม่เปิดลงสินค้าจริง"

## สถานะ
| สถานะ | ความหมาย |
|---|---|
| ยังไม่เตรียม | ยังไม่มีร่างของร้านนี้ · คอลัมน์ "ความพร้อม" = ถ้ากดเตรียมตอนนี้จะพร้อมไหม |
| เตรียมแล้ว · ขาดข้อมูล | มีร่างแล้ว แต่ยังขาดข้อบังคับ (ดูคอลัมน์ "ยังขาด") |
| พร้อมลง | มีร่างและผ่านข้อบังคับครบ |
| ลงแล้ว | ร่างมีรหัสสินค้าบนร้านแล้ว (การเตรียมจะข้ามตัวนี้) |

## กฎของแต่ละร้าน — `lib/platform-required-fields.ts`
- **Lazada** (เกณฑ์ทั่วไป ยืนยันกับระบบจริงตอนเชื่อมร้าน): ชื่อ ≤ 255 · หมวดต้องมีรหัสหมวด Lazada · รูป 1–8 · ตัวเลือก ≥ 1 และ**ชื่อห้ามซ้ำ** · ทุกตัวเลือกมีราคา · น้ำหนักพัสดุ · ขนาดกล่อง (บังคับ) · แบรนด์ · รายละเอียด · รูปทุกตัวเลือก · รหัสไม่มีเครื่องหมาย `* / #` (แนะนำ)
- **LINE SHOPPING**: 7 ข้อเดิม (ราคาใช้ราคาเต็ม fake_price)
- ร้านอื่น: ชุดทั่วไป
- ข้อที่ไม่บังคับแต่ไม่ผ่าน = ⚠ ควรดู · ทุกข้อมี `note` ภาษาคน

## ตรรกะกลาง
- `lib/product-listing-context.ts` — ประกอบข้อมูลสินค้าต่อร้าน (ตัวสี/ตัวขาย 3 ชั้น · รวมรูป · น้ำหนัก/กล่อง · หมวดกลาง→ร้าน) · `loadListingContext` (สินค้าเดียว = GET /api/product-platforms เดิม ผลเหมือนเดิมทุกช่อง + `sale_ok`) · `loadListingContexts` (หลายสินค้า query เป็นชุด)
- `lib/platform-listing-builder.ts` — `prepareDraft` (ร่าง + ผลตรวจ) · `listingCtx` (ค่าที่ตัวตรวจใช้ — ตัวจัดการรายสินค้าใช้ตัวเดียวกัน) · กฎราคา `same` / `pct` (ปัดขึ้นเป็นบาทเต็ม) · ตัวเลือกที่ลงขาย = ใช้งานอยู่ + เปิดขาย
- ร่างเดิม: ค่าเริ่มต้น **เติมเฉพาะช่องที่ว่าง** · ติ๊ก "ทับข้อมูลร่างเดิม" = ใช้ค่าจาก ERP · ราคาไม่ถูกเก็บในร่าง (คิดสดจาก SKU + `extra.price_rule`)
- เก็บใน `platform_listing_drafts`: title · description · category_path · image_keys (≤ เพดานรูปของร้าน) · status · `extra` {brand, price_rule, prepared{at,by}} · `validation` {platform, checked_at, ready, blockers, checks}

## API
| เส้น | ทำอะไร | สิทธิ์ |
|---|---|---|
| `GET /api/product-platforms/readiness?platform_code=&brand_id=` | สินค้าทั้งแบรนด์ + สถานะ + สรุป (ป้อนตารางกลาง) | `products.platforms.view` |
| `POST /api/product-platforms/prepare` {platform_code, parent_sku_ids ≤200, price_rule, overwrite} | เตรียม/บันทึกร่างหลายตัว + audit ต่อสินค้า (`prepare_listing`) · **ไม่เรียก API ของร้าน** | `products.platforms.edit` |
| `PATCH /api/product-platforms` {set_platform_category, parent_sku_ids ≤500} | ตั้งหมวดกลางหลายสินค้า (ของเดิมรับตัวเดียว ยังใช้ได้) | `products.platforms.edit` |
| `POST /api/product-platforms/publish` | ลงขาย (จำลอง) — **ปฏิเสธ**ร้านที่ไม่มีตัวเชื่อมจริง | `products.platforms.publish` |

## ห้าม / ข้อควรระวัง
- ห้ามเปิดลงขายจำลองกับร้านที่ไม่มีตัวเชื่อม — เดิมทำให้ร่างขึ้น "ลงขายแล้ว" พร้อมรหัสปลอม `MOCK-…`
- รายการร้านในหน้านี้กรองเฉพาะร้านขายของ (lazada, shopee, tiktok, line_shopping, website) — `erp_platforms` ยังไม่มีธงแยกประเภท
- สินค้า IG ยังไม่มีหมวดกลาง → ทุกตัวขึ้น "ขาดหมวด Lazada" จนกว่าจะตั้งหมวดกลาง + จับคู่กับ Lazada

## ต่อไป
- ตัวเชื่อม Lazada จริง (`/product/create` + รูป) → เปิด `capabilities.api` ของ Lazada
- เดาหมวดจากหมวดของ Shopee (ไฟล์ BigSeller Online Products มีหมวด 37 หมวดของ IG)
