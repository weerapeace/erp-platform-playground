# เปลี่ยนปกโปรทุกร้าน (`/master/promo-covers`)

เจ้าของขอ 2026-11-20: "อยากทำระบบเปลี่ยนรูปปกทีเดียวทุก Platforms — ทำ Promotion แล้วต้องแก้รูปปก"
เลือกจาก widget: แบบตัวอย่าง (PC+มือถือ) + กรอบโปรอัตโนมัติ + TikTok/Lazada ส่งล่วงหน้า + แจ้งเตือนเมื่อล้มเหลว

## ใช้ทำอะไร
ชุดโปร 1 ชุด = หลายรุ่น × หลายร้าน · ตั้งเวลาเริ่ม-จบ · ระบบเปลี่ยน **รูปแรก (ปก)** ของสินค้าบนร้านให้เอง แล้วจบโปรก็ **ย้อนเป็นปกเดิมอัตโนมัติ**

1. เลือกรุ่น (ป๊อปการ์ดรูปกลาง `MarketingSkuPickerModal` — ติ๊กได้หลายรุ่น)
2. ปกโปร 3 วิธี: อัปเองรายรุ่น (วางหลายไฟล์ได้ ชื่อไฟล์ = รหัสรุ่น) · เลือกจากคลังรูป (`AssetPicker`) · กรอบโปรอัตโนมัติ (อัป PNG พื้นใส 1 ไฟล์ → ระบบแปะทับปกในระบบของทุกรุ่นด้วย sharp → JPG จัตุรัส 1500px)
3. เลือกร้าน: Shopee · Lazada · TikTok · LINE SHOPPING · เว็บเรา (FB/IG Shop ตามเว็บผ่าน feed — ส่งตรงไม่ได้)
4. ตั้งเวลา + ย้อนอัตโนมัติ + ส่งล่วงหน้า (TikTok/Lazada ค่าเริ่ม 24 ชม.)
5. "ตรวจก่อน/หลัง แล้วยืนยัน" → ป๊อปยืนยัน (ปกก่อน→หลัง · จำนวนต่อร้าน · ติ๊กเข้าใจ · เกิน 100 รายการพิมพ์ "ยืนยัน")

ยืนยัน ≠ ส่งทันที — ส่งจริงตอนถึงเวลา (ตัวตั้งเวลาทุก 15 นาที) หรือกด "ทำเดี๋ยวนี้" / "เริ่มเดี๋ยวนี้"

## สินค้าบนร้านที่โดนเปลี่ยน
- ร้านตลาด = `platform_catalog_listings` ที่ **จับคู่กับรุ่นแล้ว** + **เปิดขายอยู่** (Shopee normal · Lazada active · TikTok activate · LINE ทุกตัวที่ไม่หลุดร้าน) + ร้านมีกุญแจเชื่อมต่อ
- เว็บเรา = `store_listings` ที่ขึ้นเว็บอยู่ (ทุกร้านเว็บที่มีรุ่นนั้น)
- รุ่นที่ยังไม่จับคู่ / ปิดขาย / ร้านยังไม่เชื่อม = ไม่ส่ง (บอกเหตุผลในหน้า)

## วิธีส่ง/ย้อนต่อร้าน (lib/promo-cover-server.ts — ใช้ตัวช่วยเดิมของลิ้นชักสินค้าบนร้าน)
| ร้าน | ส่งปกโปร | ย้อน | หมายเหตุ |
|---|---|---|---|
| Shopee | ฝากรูป `media_space.upload_image` → `update_item` image_id_list (แทนตัวแรก) | ใส่ image_id เดิมกลับ (สำรอง: ฝากสำเนาปกเดิม) | เปลี่ยนทันที |
| Lazada | `/image/migrate` → `/product/update` Images | ใส่ลิงก์รูปเดิมกลับ | Lazada ตรวจ QC ≤ 24 ชม. → สถานะ "รอร้านตรวจ" |
| TikTok | Upload Product Image → Partial Edit `main_images` | ใส่ uri เดิมกลับ (สำรอง: ฝากสำเนา) | ต้องรอ TikTok ตรวจ ระหว่างตรวจร้านยังโชว์ของเดิม — ย้อนก็ต้องรอตรวจ |
| LINE | `PATCH /products/{id}` imageUrls (ลิงก์สาธารณะของเรา) | ใส่ลิงก์รูปเดิมของ LINE กลับ | ดึงสดก่อนแก้ทุกครั้ง |
| เว็บเรา | `store_listings.web_images` = [ปกโปร, …รูปเดิม] (ว่าง = คิดรูปอัตโนมัติก่อน) | คืนค่าเดิมทั้งช่อง (ไม่มีใครแตะรูปอื่น) / เปลี่ยนเฉพาะรูปแรก | ล้างแคชเว็บร้าน + อัปเดต "ใช้อยู่ที่ไหน" |

**เก็บปกเดิม:** ตอนส่งจดชุดรูปเดิมบนร้าน (`before_refs`) + สำเนาปกเดิมเป็น JPG ในคลังรูปเรา `promo-covers/<ชุด>/backup/<รายการ>.jpg` (`backup_key`)

**กันทับงานคน:** ย้อนเฉพาะเมื่อรูปแรกบนร้านยังเป็นปกโปรของเรา (`applied_ref`) — มีคนเปลี่ยนเองระหว่างโปร = สถานะ "มีคนเปลี่ยนปกเอง" ไม่ทับ + แจ้งเตือน · กด "ย้อนทับเลย" ได้รายรายการ

**ย้อนตอนร้านยังตรวจปกโปรไม่เสร็จ (TikTok/Lazada):** บนร้านยังเห็นปกเดิม → ไม่นับว่าย้อนแล้ว (`stillInReview`) คงสถานะ "รอร้านตรวจ" แล้วลองใหม่ทุก 15 นาที · "ย้อนทับเลย" = ส่งชุดรูปเดิมซ้ำทันที

**เช็กซ้ำหลังย้อน (`verifyReverts` ในตัวตั้งเวลา · คอลัมน์ `revert_checked_at`):** ย้อนแล้ว TikTok รอ 1 ชม. / Lazada รอ 24 ชม. แล้วดูบนร้านจริง (อ่านอย่างเดียว) — ปกเดิมขึ้นแล้ว = จด "ร้านตรวจแล้ว" · ร้านยังตรวจ = ดูรอบหน้า (เกิน 3 วัน = แจ้งเตือน) · ร้านไม่ผ่านรูปเดิม/ปกโปรยังค้าง = "ย้อนไม่ผ่าน" + แจ้งเตือน → กด "ลองใหม่" · มีคนเปลี่ยนรูปแรกเอง = จบ ไม่ทับ · Lazada เทียบรูปตามชื่อไฟล์ (ชื่อเซิร์ฟเวอร์เปลี่ยนหลังตรวจ)

## สถานะ
- ชุด: ร่าง → รอเริ่ม (ยืนยันแล้ว) → กำลังใช้ → จบแล้ว · ลบ = ถังขยะ (กู้คืนได้ · ต้องย้อนปกเดิมครบก่อน)
- รายร้าน: รอส่ง · ขึ้นปกโปรแล้ว · รอร้านตรวจ · ส่งไม่ผ่าน · ข้าม · ย้อนปกเดิมแล้ว · ย้อนไม่ผ่าน · มีคนเปลี่ยนปกเอง
- แก้ชุดที่ "รอเริ่ม" (รุ่น/รูป/ร้าน/เวลาเริ่ม) = กลับเป็นร่าง ต้องยืนยันใหม่ · ชุด "กำลังใช้" แก้ได้แค่ชื่อ/เวลาจบ

## ตาราง (migration 202612200800)
`promo_cover_campaigns` · `promo_cover_items` (รุ่น + ปกโปร) · `promo_cover_targets` (รายการรายร้าน + ปกเดิม + ผล) — RLS เปิด ไม่มี policy ใช้ผ่าน API service role

## API (products.platforms.view = ดู · products.platforms.publish = แก้/ส่ง)
- `GET/POST /api/promo-covers` · `GET/PATCH/DELETE /api/promo-covers/[id]`
- `GET /api/promo-covers/[id]/preview` (อ่านอย่างเดียว) · `POST …/frame` (แปะกรอบ ทีละ 8 รุ่น)
- `POST …/confirm` {ack} / {undo} · `POST …/run` {mode: run | start_now | revert | retry | force_revert}
- ตัวตั้งเวลา `GET /api/cron/promo-covers` (vercel.json ทุก 15 นาที · ออฟฟิศทีม AI "ผู้เปลี่ยนปกโปรทุกร้าน")

## แจ้งเตือน
กฎ `promo_cover.failed` (ไม่มีกฎ = แอดมิน) + คนสร้าง/ยืนยันชุด · แจ้งครั้งเดียวต่อรายการ · ลิงก์เปิดชุดนั้น

## ประวัติ (audit)
- ชุด: `promo_cover_campaign` (สร้าง/แก้ auditDiff/ยืนยัน/ลบ/กู้คืน/ย้อน/ลองใหม่)
- สินค้าบนร้าน: `platform_catalog` / `store_listing` source `promo_cover` (ปกก่อน → หลัง) — ขึ้นในประวัติของลิ้นชักสินค้าบนร้านด้วย

## ข้อจำกัดที่รู้
- TikTok/Lazada ต้องรอร้านตรวจ — ปกโปรอาจขึ้นก่อนเวลาเริ่ม (ส่งล่วงหน้า) และปกเดิมกลับมาหลังเวลาจบ (รอตรวจตอนย้อน)
- Shopee ร้าน 3:4 — ปกโปรถูกเติมขอบขาวเป็น 3:4 อัตโนมัติ (กรอบจัตุรัสจะมีขอบบน/ล่าง)
- FB/IG Shop ตามเว็บผ่าน feed เท่านั้น (ร้าน FB/IG ยังไม่เปิด)
- ร้านที่ยังไม่เชื่อม (Shopee IG · TikTok IG) ส่งไม่ได้จนกว่าจะต่อร้าน · Lazada IG ต้องต่อใหม่ก่อน 10 ธ.ค.
- ยังไม่มีปุ่ม "ทำซ้ำชุดเดิม" (สร้างชุดใหม่จากชุดเก่า)
