# 🔄 โหมด "อัปเดตงาน" — บอร์ดจ่ายงาน

ใช้เมื่อสถานะใบงานในระบบไม่ตรงกับของจริง เช่น ระบบบอกว่า "รอจ่าย" แต่ของจริงจ่ายไปแล้ว หรือถึง QC แล้ว
ทางลัดนี้บอกระบบว่า "ใบนี้ไปถึงขั้นนี้แล้ว" โดยไม่ต้องไล่กดทีละขั้น

## วิธีใช้

1. บอร์ดจ่ายงาน → ปุ่ม **⋯** → **🔄 อัปเดตงาน** (เห็นเฉพาะคนที่มีสิทธิ์จ่ายงาน) → หน้าสลับเป็นมุมมองตาราง และมีแถบสีเหลืองบอกว่าอยู่ในโหมดอัปเดต
2. ทุกแถว (ทั้งแท็บ รอจ่าย / กำลังผลิต / รอ QC รับเข้า) มีปุ่ม **🔄 อัปเดต** ท้ายชื่อสินค้า
3. ป๊อปขั้น 1: ดู "ระบบบันทึกไว้ตอนนี้" → เลือก "ตอนนี้ของจริงอยู่ขั้นไหน" จาก **เส้นขั้นตอน 5 หมวด**
   (1 วัตถุดิบ · 2 เตรียมผลิต · 3 อยู่กับช่าง · 4 QC · 5 จบใบ — กดขั้นเดียว ขั้นก่อนหน้าเป็นสีม่วง · ป้ายเขียว "ระบบบันทึกถึงตรงนี้" · ยกเลิกใบแยกไว้ล่างสุด)
   → ระบบติ๊กขั้นก่อนหน้าให้ · **ของครบ / เตรียม / ตัด เอาติ๊กออกได้** (บางทีจ่ายไปก่อนตัดครบ)
   · ขั้นที่ระบบมีอยู่แล้วขึ้น "มีในระบบแล้ว" และไม่ทำซ้ำ
   · **⚠️ ยังขาดของอยู่** (ใต้แถวของครบ) → เลือกวัตถุดิบที่ขาด (ระบบเลือกตัวที่ยังต้องซื้อ/รออนุมัติ/รอของให้ก่อน)
     ตัวที่ขาด = ไม่ถูกติ๊กเตรียม/ตัด และไม่ติดป้ายของครบ → ยังขึ้นในหน้าขอซื้อให้ฝ่ายจัดซื้อเห็น (`mark-ready` ส่ง `except`)
4. ป๊อปขั้น 2: เติมเฉพาะข้อมูลที่ยังไม่มี + ดู "ระบบจะบันทึก" ก่อนกดบันทึก
   - **จ่ายงานแยกแถวได้** (＋ เพิ่มแถวจ่าย) — จ่ายหลายช่าง/หลายโต๊ะ/หลายวัน = หลายใบจ่ายงาน · แต่ละแถวมี โต๊ะ · จำนวน · วันที่ · คนรับ · "จัดคนในโต๊ะ" (ของกลาง `DeskStaffPanel` ตัวเดียวกับป๊อปจ่ายงาน)
   - **ส่งคืนแยกรอบได้** (＋ เพิ่มรอบส่งคืน) — ส่งไม่พร้อมกัน แต่ละรอบมี จำนวน · วันที่ · "ส่งจากใบไหน" (อัตโนมัติ = ใบเก่าก่อน / ใบจ่ายเดิม / แถวจ่ายใหม่)
   - **ทุกขั้นมีช่องวันที่ แต่ข้ามได้** (ว่าง = จำไม่ได้): ของครบเมื่อ · เตรียม/ตัดเสร็จเมื่อ · วันที่จ่าย · วันที่ส่งคืน · QC รับเข้าเมื่อ · ส่งออกเมื่อ · ปิดใบเมื่อ · ยกเลิกเมื่อ
5. ป๊อปขั้น 3: ผลทีละขั้น ✅/❌ — ถ้าพังกลางทาง ขั้นที่ ✅ เก็บไว้แล้ว เปิดป๊อปใหม่ทำต่อได้

## สถานะที่เลือกได้ → สิ่งที่ระบบบันทึก

| เลือก | ติ๊กให้อัตโนมัติ | ถามเพิ่ม | บันทึกผ่าน (ระบบเดิม) |
|---|---|---|---|
| 📦 ของครบแล้ว | — | — | ป้าย "ของครบ (อัปเดตย้อนหลัง)" ที่ขั้นซื้อของ (`skip-stage` · เอาคืนได้) |
| 🧺 เตรียมของแล้ว | ของครบ | — | `mark-ready` parts=prep |
| ✂️ ตัดแล้ว | ของครบ, เตรียม | — | `mark-ready` prep+cut |
| 🚚 จ่ายงานแล้ว | + ตัด | โต๊ะ · คนรับ (หลายคน/ทั้งโต๊ะ) · วันที่ (จำไม่ได้ได้) · จำนวน | `POST /api/mo/work-orders` |
| ↩️ ช่างส่งคืนบางส่วน | + จ่ายงาน | จำนวนที่คืน (ที่เหลือค้างช่าง) | `POST /api/mo/submissions` |
| 📥 ส่งคืนครบ (รอ QC) | + จ่ายงาน | จำนวน (ค่าตั้งต้น = ทั้งหมด) | `POST /api/mo/submissions` |
| 🗄️ QC รับเข้าชั้นแล้ว | + ส่งคืน | ของดี · ชั้น · ของเสีย (+สาเหตุ) | `qc-warehouse/items` receive |
| 📤 ส่งออกจาก QC แล้ว | + QC รับเข้า | — | receive แล้ว ship ของดีที่เพิ่งรับเข้า |
| 🏁 ปิดใบแล้ว | ทุกขั้น (QC/ส่งออก เอาออกได้) | — | `POST /api/mo/bulk-status` close (กฎ `lib/mo-workflow`) |
| ✖️ ยกเลิกใบ | — | เหตุผล (บังคับ) | bulk-status cancel · เฉพาะใบที่ยังไม่จ่าย |

สถานะที่ "ระบบคิดเอง" (ยังไม่มีสูตร, ขอซื้อรออนุมัติ, สั่งแล้วรอของ, วางแผนจ่ายไว้) ตั้งในโหมดนี้ไม่ได้ — มาจากเอกสารจริง

## เตือนเวลาใส่ไม่ครบ (กฎเดียวกับป๊อปลงงานปกติ)

- **แถบสรุปบนสุด** (ขั้น 2): ❌ ต้องแก้ N จุด · ⚠️ เตือน N · ไม่ใส่วันที่ N ช่อง (ข้ามได้) + ปุ่ม "ไปที่ช่องแรก"
- **ช่องที่ผิดเป็นกรอบแดง** (ต้องแก้) / **เหลือง** (เตือน) + ข้อความใต้ช่อง · หัวแต่ละส่วนมีป้ายนับ
- **ปุ่มบันทึก**: มีจุดต้องแก้ = "ยังขาด N จุด — ไปแก้" (กดแล้วพาไปช่องนั้น) · มีแต่คำเตือน = "บันทึก (มีคำเตือน N)"
- **ยอดตามกันอัตโนมัติ** จนกว่าจะพิมพ์แก้เอง: ส่งคืน ← ยอดจ่าย · ของดี QC ← ยอดส่งคืน − ของเสีย

กฎรายช่องมาจาก **ของกลาง `lib/work-entry-rules.ts`** (ป๊อปจ่ายงานบนบอร์ดใช้ตัวเดียวกันแล้ว):

| ขั้น | ต้องแก้ (แดง) | เตือน (เหลือง · บันทึกได้) |
|---|---|---|
| จ่ายงาน | ไม่เลือกโต๊ะ · จำนวน ≤ 0 / เกินที่เหลือ · โต๊ะเหมาไม่เลือกช่าง · จ่ายรวมเกิน | เตรียม/ตัดยังไม่ครบ ("ยังไม่พร้อมจ่าย") · จ่ายไม่ครบทั้งใบ · ช่างเคยทำรุ่นนี้เสีย · ค่าแรง/ชิ้นเกิน 2 เท่าราคากลาง · วันที่ในอนาคต |
| ส่งคืน | จำนวน ≤ 0 / เกินที่ค้างช่าง · เกินยอดของใบที่ระบุ | ยังค้างช่างบางส่วน · ค่าแรงผิดปกติ · วันส่งคืนก่อนวันจ่าย / ในอนาคต |
| QC | ของดี+เสีย ไม่อยู่ในช่วง · ไม่เลือกชั้น · ของเสียไม่เลือกสาเหตุ (รายการเดียวกับหน้าโกดัง QC · เพิ่มใหม่ได้) | วันที่ก่อนวันส่งคืน / ในอนาคต |

ค่าแรง: จ่ายงาน = ช่อง ค่าแรง/ชิ้น ตั้งต้นจากราคากลางในสูตร (เลือกช่างคนเดียวที่มีเรตเฉพาะ = เรตนั้น) → ส่ง `labor_cost` = ต่อชิ้น × จำนวน ·
ส่งคืน = ช่อง ค่าแรง/ชิ้น ว่าง = ยังไม่ลงค่าแรง · ใส่ = ส่ง `wage` ยอดรวม · ค่าแรงว่างหรือวันที่ว่าง = ติดป้าย "ยังไม่ลงวันที่/ค่าแรง"

## ข้อมูลเพิ่มเติม · ไล่ใบต่อเนื่อง (รอบ 6)

- **📝 ข้อมูลเพิ่มเติม** (ไม่บังคับ ล่างสุดขั้น 2) — บันทึก "หลัง" ขั้นสถานะเสมอ (พังทีหลังก็ไม่กระทบสถานะ)
  - **ปัญหาที่เจอ** (หลายรายการ: ข้อความ · เล็กน้อย/ปานกลาง/รุนแรง · กี่ชิ้น) → `/api/mo/issues` = กล่อง "⚠️ ปัญหา" ของใบงานบนบอร์ด
  - ☐ **จำเป็นปัญหาของรุ่นนี้ (ทุกสี)** → `/api/parent-sku-issues` (กันซ้ำในตัว) — สิทธิ์ `qc.defect`
  - **หมายเหตุถึงช่าง** (ต่อแถวจ่าย) → `mo_work_orders.note`
  - **บันทึกถึงทีม** → ต่อท้าย `manufacturing_orders.note` เป็นบรรทัด "[อัปเดตงาน วันที่] ข้อความ" (PATCH `/api/mo/[id]`)
- **💰 ค่าแรงกลับเข้าสูตร (BOM)** — พิมพ์ค่าแรง/ชิ้นที่ต่างจากราคากลาง (แถวจ่าย หรือรอบส่งคืน) → ขึ้นช่อง ☑ "บันทึกค่าแรง ฿X/ชิ้น กลับเข้าสูตร" (ติ๊กไว้ให้แล้ว · เอาออกได้) → `/api/bom/labor-rates` ราคากลาง (ประวัติเดิมเก็บไว้ · สิทธิ์ `products.edit`)
- **⚠️ ปัญหาที่เคยแจ้ง** — ขั้น 1 โชว์ปัญหาของใบนี้ + ของรุ่นนี้ (กดดู) กันแจ้งซ้ำ
- **⚠️ QC รับไม่หมด** — ของดี+เสีย < ที่รอรับ = เตือน "ยังเหลือรอ QC N ชิ้น"
- **ใบถัดไป →** (หน้าผลลัพธ์) / **ข้ามใบนี้ →** (ขั้น 1) — ไล่ตามลำดับแถวของแท็บที่เปิดอยู่ (ตามคำค้น) ไม่ต้องปิดป๊อป
- **จำค่าล่าสุด** (ต่อเครื่อง `localStorage wb-catchup-last`): โต๊ะ · คนรับ · ชั้น QC — ไม่จำวันที่ (กันวันผิดติดไปเงียบ ๆ)
- **ปุ่มเลือกคน (CrewPick กลาง) โชว์แค่ชื่อเล่น** — ไม่มีชื่อเล่น = ชื่อเต็ม · ชื่อเล่นซ้ำในรายชื่อ = ต่อรหัส · ชี้ค้าง = รหัส+ชื่อเต็ม (มีผลทุกป๊อปที่ใช้ CrewPick)

## ก่อน → หลัง · ใบขาย · ปลายทางส่งออก · ย้อนกลับ (รอบ 7)

- **จะอัปเดตอะไร เป็นอะไร** (ขั้น 1 ใต้รายการติ๊ก): ตาราง ซื้อของ/เตรียม/ตัด/จ่ายงาน/ช่างคืน/QC/สถานะใบ = `ตอนนี้ → หลังบันทึก` (ไม่เปลี่ยน = เทา) + "บนบอร์ด: ย้ายจากแท็บ X → Y"
- **ส่งคืนจากใคร**: ค่าเริ่มต้น = ช่างที่จ่าย (1 รอบต่อ 1 คน ยอดเท่าที่ค้าง · ตามอัตโนมัติจนแก้เอง) · เรียกด้วยชื่อเล่น "แมว · โต๊ะโด่ง" · มีที่มาเดียว = ไม่มีช่องเลือก · หลายที่มา = เลือกได้ + "แบ่งให้อัตโนมัติ" อยู่ท้ายสุด
- **เช็กใบขาย** (จับคู่ด้วยรหัสสินค้า — ใบสั่งผลิตยังไม่ผูกใบขายตรง ๆ): โชว์ใบขาย (`erp_playground_sales_orders` ไม่นับยกเลิก) + ใบส่งของ · ส่งออก/ปิดใบ แต่ไม่พบใบขาย หรือยังไม่มีใบส่งของที่ส่งแล้ว = เตือนเหลือง (บันทึกได้)
- **ส่งออกจาก QC ไปไหน**: เข้าคลังขาย (เลือกคลัง) / ขายออก — รายชื่อคลังเป็นของกลาง `lib/qc-ship.ts` (หน้าโกดัง QC ใช้ตัวเดียวกัน)
- **ยังต้องตามต่อ** (หน้าผลลัพธ์): ส่งคืนที่ยังไม่ลงค่าแรง/วันที่ (ลิงก์ตารางส่งงาน) · จ่ายเป็นทั้งโต๊ะ · วันที่ว่าง · ของที่ยังขาด · QC ค้าง · ใบขาย
- **↶ ย้อนการอัปเดตนี้** (หน้าผลลัพธ์ · ถามยืนยันก่อน): ย้อนจากหลังไปหน้า — QC คืนคิว (`return_queue`) → ลบส่งคืน (`DELETE /api/mo/submissions`) → ยกเลิกใบจ่าย (`DELETE /api/mo/work-orders/[id]`) → คืนติ๊กเฉพาะตัวที่เพิ่งติ๊ก (`mark-ready` `only`) → เอาป้ายของครบออก (เฉพาะป้ายที่โหมดนี้ติด) → ลบปัญหา (ไม่ลบปัญหาของรุ่นที่มีอยู่ก่อน) → คืนหมายเหตุเดิม → คืนค่าแรง BOM เดิม
  - **ย้อนไม่ได้**: ส่งออกจากชั้น / ปิดใบ / ยกเลิกใบ สำเร็จแล้ว (ปุ่มไม่ให้กด บอกเหตุผล) · ตัดไว้บางส่วนก่อนหน้า (บอกให้ย้อนเองที่หน้าใบสั่งผลิต) · วัตถุดิบที่ย้ายเข้า WIP ตอนจ่ายใบแรก
  - API ที่เพิ่ม: submissions POST คืน `id` · mark-ready รับ `only` · skip-stage เอาป้าย buy ออกได้ด้วยสิทธิ์จ่ายงานเมื่อเป็นป้ายจากโหมดนี้

## วันที่ไปเก็บที่ไหน

| ขั้น | ที่เก็บ |
|---|---|
| ของครบ | ข้อความในป้าย (เหตุผล "ของครบเมื่อ …") |
| เตรียม/ตัด | `manufacturing_orders.prep_done_at/cut_done_at` + `mo_materials.cut_done_at` (`mark-ready` `done_date`) |
| จ่ายงาน | `mo_work_orders.dispatch_date` |
| ส่งคืน | `wo_submissions.submitted_at` — ช่องนี้ DB บังคับห้ามว่าง (ค่าเริ่มต้น = วันนี้) → ไม่ใส่วัน = ลงเป็นวันที่อัปเดต + ติดป้าย "ยังไม่ลงวันที่/ค่าแรง" (info_pending) ไปแก้วันทีหลังได้ที่ตารางส่งงาน |
| QC รับเข้า | `qc_warehouse_items.created_at` (receive `date` · ไม่ใส่ = เวลาที่อัปเดต) |
| ส่งออก / ปิดใบ / ยกเลิก | ไม่มีช่องในตาราง → เก็บใน audit (`date`, `source: catch_up`) |

วันที่ทุกช่องเก็บเป็นเที่ยงวันเวลาไทย (กันวันเพี้ยนข้ามโซนเวลา)

## กติกาสำคัญ (เจ้าของอนุมัติ 2026-10-28)

- **ไม่ส่งแจ้งเตือน**: ทุกคำขอส่ง `quiet: true` → ไม่ส่ง LINE กลุ่ม / ไม่ DM ช่าง / ไม่เด้งกระดิ่ง เรื่องงานเก่า (ประวัติ audit ยังลงครบ + ติด `catch_up: true`)
- **ค่าแรง**: ส่งงานย้อนหลัง = "ยังไม่ลงค่าแรง" (`info_pending`) เสมอ → เงินเดือนยังไม่นับจนกว่าจะไปใส่ที่ตารางส่งงาน
- **ป้ายของครบ**: ปกติข้ามขั้นได้เฉพาะแอดมิน — ยกเว้นในโหมดนี้ คนมีสิทธิ์ `work_board.dispatch` ติดป้าย "ซื้อของ" ได้ (`via: "catch_up"`) · เอาป้ายออกยังต้องแอดมิน
- **"ถึง QC"** = เข้าคิว "รอ QC รับเข้า" (ยังไม่ขึ้นชั้น) · ถ้าเลือก "QC รับเข้าชั้นแล้ว" ถึงจะวางขึ้นชั้น
- **สิทธิ์แต่ละขั้น = สิทธิ์ของ API เดิม** (เตรียม/ตัด/ส่งงาน = products.edit · จ่ายงาน/ปิด = work_board.dispatch · QC = qc.receive/qc.ship) — ไม่มีสิทธิ์ขั้นไหน ป๊อปบอก "คุณไม่มีสิทธิ์ทำขั้นนี้" และหยุดตรงนั้น

## พนักงานอัปเดต → หัวหน้ายืนยัน (รอบ 8)

เจ้าของ: "บางทีพนักงานเป็นคนอัปเดต อยากให้เรากดยืนยันด้วย (ตั้งค่าคน/ตำแหน่งได้) และไปแก้ได้ด้วย — เฉพาะโหมดนี้"

**สิทธิ์ 3 ตัว** (หมวดผลิต · ตั้งตามตำแหน่งที่ /admin/roles-permissions + รายคนที่หน้าผู้ใช้) — คีย์อยู่ที่ `CU_PERM` ใน catch-up.ts
| สิทธิ์ | ความหมาย | ค่าเริ่ม |
|---|---|---|
| `work_board.catch_up` | ใช้โหมดอัปเดตงานได้ (ส่งให้หัวหน้ายืนยัน) — คนที่มี `work_board.dispatch` ใช้ได้อยู่แล้ว | admin, manager |
| `work_board.catch_up_direct` | บันทึกได้เลย ไม่ต้องรอ | admin, manager |
| `work_board.catch_up_approve` | ยืนยัน / แก้ / ตีกลับ คำขอของคนอื่น + ได้แจ้งเตือน | admin, manager |

**ทางเดิน**
1. พนักงาน (ไม่มี direct) กรอกป๊อปเหมือนเดิม → ปุ่มล่างเป็น **"ส่งให้หัวหน้ายืนยัน"** → `POST /api/mo/catch-up/requests {action:"submit"}` เก็บ `CuDraft` (ทุกช่องที่กรอก + `facts` ตอนส่ง) ลง `work_catch_up_requests` · **ยังไม่แตะใบงาน** · กระดิ่งเด้งหาหัวหน้า (ลิงก์ `/master/work-board?cu=requests` เปิดคิวให้เลย)
2. บนตาราง: แถวขึ้นป้าย "รอยืนยัน · ชื่อ" · หัวหน้าเห็นปุ่ม **"ตรวจ"** แทน "อัปเดต" · แถบเหลืองมีปุ่ม **"รอยืนยัน (N)"** (หัวหน้า) / **"คำขอของฉัน (N)"** (พนักงาน) → คิว `catch-up-queue.tsx`
3. หัวหน้าเปิด = ป๊อปตัวเดิม ใส่ข้อมูลที่พนักงานกรอกให้ (`hydrate`) · แก้ได้ทุกช่อง · ใบเปลี่ยนหลังส่งคำขอ = เตือน (`cuFactsDiff`) · **"ยืนยันและบันทึก"** = `claim` (pending→processing กันสองคนยืนยันซ้อน · ค้างเกิน 10 นาทีให้คนอื่นต่อได้) → รันขั้นต่าง ๆ ด้วย**สิทธิ์ของหัวหน้า** (`cuRun` เดิม) → `finish` เก็บผลทีละขั้น + แจ้งเตือนคนส่ง · ย้อนการอัปเดตได้เหมือนเดิม
4. **"ตีกลับ"** ต้องใส่เหตุผล → แจ้งเตือนคนส่ง · พนักงานเปิดใบนั้นอีกครั้งเห็นเหตุผล + ปุ่ม "ใช้ข้อมูลเดิมแก้ต่อ"
5. คำขอที่ยังรอ: คนส่งแก้แล้ว "ส่งคำขอที่แก้" / "ยกเลิกคำขอ" ได้ · คนอื่นที่ไม่ใช่หัวหน้าเปิดใบนั้น = เห็นว่ามีคำขอค้าง (ไม่เห็นรายละเอียด) และกดต่อไม่ได้ · 1 ใบงาน มีคำขอค้างได้ทีละ 1 (unique index)

- ยืนยันคำขอของตัวเองไม่ได้ (ยกเว้นมีสิทธิ์บันทึกได้เลยอยู่แล้ว) · ทุกขั้นเขียน audit (`catch_up.request / request_edit / request_cancel / approve / reject`)
- ตาราง `work_catch_up_requests` RLS เปิด ไม่มี policy + revoke anon/authenticated — อ่าน/เขียนผ่าน API เท่านั้น (migration `202611070100_work_catch_up_requests.sql`)
- เป็นด่านของ "โหมดนี้" เท่านั้น — ป๊อปจ่ายงาน/ส่งงานปกติไม่เปลี่ยน (คนที่จ่ายงานได้ ก็ยังจ่ายงานแบบปกติได้เหมือนเดิม)

## ค่าแรงตามใบจ่าย · แท็บ "ทั้งหมด" · ของอยู่ไหน (รอบ 9)

เจ้าของ: "ค่าแรงไม่ต้องใส่ก็ได้เพราะมีข้อมูลข้างบนอยู่แล้ว" · "ต้องมีดูทั้งหมดด้วย บางทีอัปเดตไปแล้วหาไม่เจอ รับเข้า QC แล้วของอยู่ไหน"

- **บั๊กที่แก้ (ต้นเหตุหาไม่เจอ):** คิวแท็บ "รอ QC รับเข้า" โหลดแยกครั้งเดียวตอนเปิดหน้า → หลังอัปเดต ใบที่ช่างเพิ่งส่งคืนหายจากทุกแท็บจนกด F5 (เจอจริง: PIX12-01) · ตอนนี้ป๊อปบันทึกแล้วโหลด `loadQcQueue` + แท็บทั้งหมดใหม่ทุกครั้ง

- **ค่าแรงรวมของใบส่งคืนหลายรอบ** (ของกลาง `lib/wo-labor.ts` `woLaborTotal`/`syncWoLabor` · ใช้ใน /api/mo/submissions POST/PATCH/DELETE): เดิมเขียนทับด้วยค่าแรงรอบล่าสุด → ตอนนี้ = ค่าแรงทุกรอบที่ลงแล้ว + ส่วนที่เหลือคิดราคาต่อชิ้นของรอบล่าสุด (ส่งครบรอบเดียว = เหมือนเดิม) · วันทำยังไม่มีใบไหนส่งหลายรอบ (0 ใบ)
- **แท็บ "ทั้งหมด"** (โผล่เฉพาะโหมดอัปเดตงาน · `GET /api/mo/catch-up/all`): ทุกใบที่ยังเปิด + ที่ปิด/ยกเลิกใน 30 วัน · คอลัมน์ "ตอนนี้ของอยู่ไหน" จากกติกากลาง `cuLocate` (catch-up.ts: รอจ่าย / อยู่กับช่าง / รอ QC รับเข้า / โกดัง QC · ชั้น / ของเสีย / รอปิดใบ / ปิดแล้ว / ยกเลิก — ใบเดียวหลายขั้นได้) · ปุ่ม "ไปแท็บ…" หรือ "โกดัง QC ↗" · เพิ่งอัปเดตขึ้นก่อน
- **หลังบันทึก:** ป๊อปโหลดข้อมูลใบใหม่แล้วบอก "ตอนนี้ของอยู่: …" + "ไปดูใบนี้ในตาราง" (สลับไปแท็บทั้งหมด + ค้นใบนี้) · แถบเหลืองมี "เพิ่งอัปเดต: …" กดหาใบได้

### รอบ 10 — ป๊อปรับงานคืนแบบเดิม คิดค่าแรงต่อชิ้น (2026-10-29)
