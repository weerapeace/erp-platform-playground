# ข้ามขั้นตอนใบสั่งผลิต (เฉพาะแอดมิน)

ใช้ทำอะไร: จัดการใบงานค้าง — ดันใบที่ติดขั้น (เช่น ไม่มีใครติ๊ก "มีของแล้ว") ไปขั้นถัดไป โดยไม่ต้องแก้ข้อมูลจริง

## ใช้ยังไง
บอร์ดจ่ายงาน → มุมมองตาราง → กดช่อง "ขั้นตอน" ของแถว → แผง 🚦 ความคืบหน้า
- แอดมินเห็นปุ่ม **⏭ ข้าม** ใต้ขั้นที่ยังไม่ครบ → กล่องยืนยันบอกผลกระทบ + ติ๊ก "ข้ามขั้นก่อนหน้าด้วย"
- ขั้นที่ข้ามแล้วเป็นแถบลายเทา + ปุ่ม **↩ เอาคืน**
- ครบ/ข้ามทุกขั้น → ปุ่ม **🏁 ปิดใบนี้** (ผ่านกฎ lib/mo-workflow — ยังมีใบจ่ายงานค้าง = ปิดไม่ได้)

## เก็บที่ไหน
`manufacturing_orders.skipped_stages` (jsonb) = `{ buy|prep|cut|dispatch|receive: { by, by_name, at, reason } }`
เป็น "ป้าย" อย่างเดียว — ไม่แก้ติ๊กเตรียม/ตัด ไม่ยกเลิกใบขอซื้อ ไม่สร้างใบจ่ายงาน → เอาคืน = ลบป้าย

## ผลกระทบแต่ละขั้น (กติกาที่ `lib/mo-skip.ts` — MO_SKIP_META)
| ขั้น | ผลกระทบ | เหตุผล |
|---|---|---|
| ซื้อของ | ไม่นับใน หน้าขอซื้อ / purchase-needs / material-demand / material-readiness · material-progress นับเป็นของครบ · ใบขอซื้อ/PO เดิมไม่ถูกยกเลิก | ไม่บังคับ |
| เตรียม / ตัด | work-board API นับครบ (ไฟพร้อมจ่าย) | ไม่บังคับ |
| จ่ายงาน | นับว่าจ่ายแล้ว แต่ไม่มีใบจ่ายงาน = ไม่มีค่าแรงช่าง · ใบยังอยู่แท็บรอจ่าย (ขั้น = รอรับคืน/ปิดใบ) | **บังคับ** |
| รับคืน | ปิดใบได้โดยไม่ต้องรับคืนครบ · ไม่มีของเข้าคิว QC = สต๊อกสินค้าสำเร็จรูปไม่เพิ่ม | **บังคับ** |

## API / สิทธิ์ / audit
- `PATCH /api/mo/[id]/skip-stage` `{ stages, skip, reason }` — สิทธิ์ `admin.users`
- audit_logs: entity_type `mo`, action `skip_stage` / `unskip_stage`, metadata `{ mo_no, stage, reason }` (ดูได้ในแผง 🕘 ประวัติ)

## ห้ามใช้เมื่อ
- ใบที่ยังผลิตจริงในระบบ — ข้ามจ่ายงาน/รับคืน ทำให้ค่าแรงช่างและสต๊อกไม่ถูกบันทึก
- อยากยกเลิกใบ → ใช้ 🧹 จัดการใบค้าง (ยกเลิก + เหตุผล) แทน
