# แผนผังการทำงาน (`/master/flow-map`)

> เจ้าของขอ 2026-11-02: "แผนผังที่โชว์การทำงานจริงในระบบ … ซื้อ, ผลิต, จ่ายงาน, ขาย ว่าอะไรเชื่อมอะไร update อันนี้แล้วไปไหน"

## ใช้ทำอะไร

หน้าเดียวดูว่าเอกสาร/หน้าจอในงาน ซื้อ · ผลิต · จ่ายงาน · ขาย ส่งต่อกันยังไง
- **กล่อง** = เอกสาร / หน้าจอ — กดดู: เปิดหน้าไหน · เก็บตารางไหน · สถานะมีอะไร · ตัวเลขตอนนี้ · ช่องโหว่
- **เส้น** = การส่งต่อ แยก 4 แบบ (สี + ลายเส้น): ระบบทำให้เอง · คิดสดตอนเปิดดู · คนต้องไปกด · ยังไม่เชื่อม
- 5 มุมมอง: ภาพรวม / ซื้อ / ผลิต / จ่ายงาน / ขาย · ซ่อน/แสดงเส้นแต่ละแบบได้
- ทางเข้า: เมนู Master Data → "แผนผังการทำงาน" · ปุ่มในหน้า "คู่มือ Flow งาน" (`/master/work-flows`)

ไม่ใช่ "คู่มือ Flow งาน" (`/master/work-flows`) — หน้านั้นบอกว่าแต่ละขั้นเก็บไฟล์ไว้ที่ไหน (เนื้อหาแก้ได้ในเว็บ) ส่วนหน้านี้บอกว่าระบบส่งต่อข้อมูลกันจริงยังไง (อ่านจากโค้ด)

## ชิ้นส่วน

| ชิ้น | ไฟล์ | หน้าที่ |
|---|---|---|
| ทะเบียนแผนผัง | `lib/flow-map.ts` | กล่อง (`FLOW_NODES`) · เส้น (`FLOW_EDGES` + ไฟล์ที่ทำจริง) · ตำแหน่งในแต่ละผัง (`FLOW_VIEWS`) · นิยามตัวเลขสด (`FLOW_METRICS`) — pure ไม่ import อะไร |
| เรขาคณิต | `lib/flow-map-layout.ts` | ตำแหน่งเส้น/เลข + SVG เป็นข้อความ (หน้าพิมพ์) + `flowGeometryProblems` (เทสต์) + `isRecentEdge` (ป้ายเพิ่งแก้) |
| ตัวเลขสด | `app/api/flow-map/metrics.ts` → `health` (นับ) + `list` (รายการ) | นิยาม/เงื่อนไขกรองที่เดียว ตัวเลขกับรายการตรงกันเสมอ (สิทธิ์ `products.view`) ตัวไหนพังคืน `null` |
| prompt บอก AI | `lib/flow-map-prompt.ts` | รวมสิ่งที่อยากแก้ + ข้อมูลส่วนนั้น (หน้า/ตาราง/สถานะ/ตัวเลข/เส้น/ไฟล์) + ข้อกำหนด (where-used, เสนอแผนก่อน, อัปเดตแผนผัง) |
| หน้าจอ | `components/flow-map/` (`index` ผัง · `request` ช่องอยากแก้ + ตะกร้า + ส่งรายงานปัญหา · `metric-list` ป๊อปรายการ · `journey` ออเดอร์ 1 ใบ) + `app/master/flow-map/page.tsx` | |
| พิมพ์ / PDF | `app/print/flow-map/page.tsx` (`?view=` ผังเดียว) | A4 แนวนอน 1 หน้าต่อผัง + ตารางเส้น + หน้าออเดอร์ 1 ใบ (ระบบพิมพ์กลาง) |
| เทสต์ | `lib/__tests__/flow-map.test.ts` | ไฟล์ที่เส้นอ้างต้องมีจริง · กล่อง/เส้น/ผังชี้กันถูก · **เส้นห้ามทับกล่อง/เลขห้ามซ้อน** · ออเดอร์ 1 ใบชี้เส้นที่มีจริง · prompt มีข้อมูลครบ |

## ของเสริมในหน้า

- **อยากแก้อะไรในส่วนนี้** (แผงรายละเอียดทุกกล่อง/เส้น): ติ๊กช่องโหว่ที่รู้แล้ว หรือพิมพ์เองหลายข้อ → **สร้าง prompt + คัดลอก** (วางในแชท Claude/Codex) · **ใส่ตะกร้า** · **ส่งเข้ารายงานปัญหา**
- **ตะกร้ารายการแก้**: เก็บคำขอจากหลายส่วน (จำในเครื่อง `localStorage` `erp.flowMap.basket`) แล้วสร้าง prompt เดียว / ส่งรายงานปัญหาทีเดียว
- **ส่งเข้ารายงานปัญหา**: POST `/api/issue-reports` (ของกลาง "แจ้งปัญหาการใช้งาน" /issue-report · สิทธิ์ `report.create`) แอปปลายทางตามส่วน (`FLOW_ISSUE_APP`) · รายละเอียด = prompt เต็ม
- **กดตัวเลขแล้วเห็นรายการ**: ป๊อปกลาง + ตารางกลาง สูงสุด 200 แถว · ปุ่ม "เปิด" ไปหน้าเอกสาร (`?open=` เฉพาะหน้าที่รองรับ)
- **แท็บ "ออเดอร์ 1 ใบ เดินทางยังไง"**: `FLOW_JOURNEY` อ้าง id เส้น → ข้อความ/แบบตามเส้นจริงเอง
- **ป้าย "เพิ่งแก้"**: เส้นที่มี `changed: { date, note }` ภายใน `FLOW_RECENT_DAYS` (30) วัน ขึ้นจุดม่วงบนผัง + ป้ายในรายการ
- **พิมพ์ / PDF**: ปุ่มบนหน้า → `/print/flow-map` (ผังที่ดูอยู่) หรือทุกผัง
- **คำแนะนำต่อเส้น** (`lib/flow-map-advice.ts` · pure): "ควรทำอัตโนมัติไหม?" = ควรทำอัตโนมัติ / กึ่งอัตโนมัติ (ระบบร่าง คนยืนยัน) / คงให้คนกด / ยังไม่ต้องทำ + ข้อดี · ข้อเสีย · จุดเสี่ยงตอนนี้ · flow แบบอื่น
  - **ทุกเส้นที่ "คนต้องกด" / "ยังไม่เชื่อม" ต้องมีคำแนะนำ** (เทสต์บังคับ) · ปิดช่องโหว่แล้วแก้/ลบคำแนะนำของเส้นนั้น · แนบไปกับ prompt ด้วย
- **โน้ตแปะ (post-it)** (`lib/flow-map-notes.ts` + `components/flow-map/notes.tsx`): ปุ่ม "แปะโน้ต" → แตะบนผัง (แตะกล่อง/เส้น = ติดส่วนนั้น) หรือ "＋ แปะโน้ต" ในแผงรายละเอียด
  - 4 สี · ลากแถบบนเพื่อย้าย · Enter บันทึก · ลบข้อความหมด = ลบโน้ต · ซ่อน/แสดงโน้ตได้ · โน้ตที่ติดส่วนนั้นขึ้นในแผงรายละเอียด + แนบไปกับ prompt
  - **ส่วนตัว** = `user_ui_prefs` key `flow_map_notes` (useUserPref · ต่อคน ไม่ต้องมีตารางใหม่ · สูงสุด 300 โน้ต) — แก้สองเครื่องพร้อมกันเครื่องหลังทับ
  - **ทั้งทีม** = ตารางความคิดเห็นกลาง `erp_record_comments` (`module_key` flow_map · `comment_type` note — ตารางรับแค่ comment/note/system) ผ่าน `/api/flow-map/notes` — ทุกคนเห็น แก้/ลบได้เฉพาะเจ้าของ (แอดมินลบได้) · สร้าง/ลบลง audit log

## ผังการเงิน — เห็นเฉพาะแอดมิน (เพิ่ม 2026-11-03)

> เจ้าของขอ: "เพิ่มหน้า flow ของระบบ บัญชี (หมุนเงินหน่อย) ขาย, ซื้อ, เครดิต และที่เหลือ … เห็นแค่ admin"

- 5 แท็บต่อท้ายกลุ่ม 🔒 "การเงิน · เฉพาะแอดมิน": **หมุนเงิน** (ภาพรวม เงินเข้า → กระเป๋าเงิน ← เงินออก / หนี้ธนาคาร) · **เงินเข้า** · **เงินออก** · **เครดิต & หนี้** · **บัญชี & ภาษี**
- ผังการเงิน = `FlowView.finance: true` · กล่อง/เส้นการเงิน id `F1…F26` + กล่อง `cf bank gl tb tax ptax cust sup credit board china payrun fixed loan inst lpay od odint card`
- **ใครเห็น:** สิทธิ์ `flow_map.finance.view` (`FLOW_FINANCE_PERM`) — แอดมินผ่านเสมอ (erp_can / can() ของแอดมิน = true) · ให้คนอื่นดู = เพิ่มสิทธิ์นี้ใน `erp_permissions` แล้วติ๊กให้ตำแหน่ง/รายคน
- **ซ่อนครบทุกชั้น ไม่ใช่แค่แท็บ:**
  - แท็บ: `flowViewsFor(can(...))` (หน้าจอ + หน้าพิมพ์)
  - ตัวเลข: `FLOW_METRICS[k].finance` → `/api/flow-map/health` ไม่ส่ง key ให้คนไม่มีสิทธิ์ · `/api/flow-map/list` ตอบ 403
  - โน้ตทั้งทีม: `/api/flow-map/notes` ไม่ส่ง/ไม่รับโน้ตบนผังการเงิน หรือที่ติดกล่อง/เส้นในชุด `FLOW_FINANCE_ONLY`
  - เทสต์บังคับ: ตัวเลขการเงินติดได้แค่กล่อง/เส้นที่มีแค่ในผังการเงิน (กันตัวเลขหลุดไปผังทั่วไป)
  - ⚠️ ข้อความในทะเบียน (`lib/flow-map.ts`) อยู่ใน JS ของหน้าเว็บทุกคน → **ห้ามใส่ยอดเงิน/จำนวนจริง** ให้ใช้ตัวเลขสด (metrics) แทน
- ของใหม่ในเรขาคณิต: **กล่องสูงหลายแถว** (`FlowPos` ตัวที่ 3 เช่น `bank: [1, 1, 3]`) · **เส้นรวมสาย** (`feed` — เงินกู้ + OD + บัตร รวมเป็นเส้นเดียวเข้าเงินในบัญชี) · **หัวคอลัมน์** (`heads`) · **จุดเขียว = นับในกระแสเงินสด** (`FlowNode.cashflow`)
- ข้อค้นพบหลักตอนทำ: ระบบรู้ว่าต้องรับ/จ่ายเท่าไร แต่**ไม่รู้ว่าเงินในบัญชีเหลือเท่าไร** — ไม่มีสมุดบัญชีธนาคาร (เส้นแดงเข้า "เงินในบัญชี") · ลงบัญชีอัตโนมัติ = "ยังไม่ต้องทำ" จนกว่ารับชำระ/ใบจ่ายเงิน/สมุดธนาคารใช้จริง

## ทำให้ไม่ตกยุค (สำคัญ)

- **แก้ workflow / การส่งต่อเมื่อไร ให้แก้ `lib/flow-map.ts` ด้วย** — คู่กับทะเบียน `lib/workflow-registry.ts` และขั้นตอน `npm run where-used` (CLAUDE.md §46 Step 3)
  - เส้นเปลี่ยนแบบ (เช่น ช่องโหว่ถูกปิด `missing` → `auto`) · ข้อความ `detail` / `warn` · ช่องโหว่ของกล่อง `gaps` · **`changed` = วันที่แก้ + เปลี่ยนอะไร** (ขึ้นป้ายเพิ่งแก้)
- ย้าย/ลบไฟล์ที่เส้นอ้าง → เทสต์ล้ม ต้องมาแก้ทะเบียน
- ตัวเลขสด (เช่น ใบขายเก่าที่ยังจองของ, ใบขอซื้อไม่มีรหัส) คิดใหม่ทุกครั้งที่เปิดหน้า — ช่องโหว่ที่ข้อมูลจริงยังค้างจะขึ้นจุดแดงเอง

## เพิ่มกล่อง / เส้น / มุมมอง

1. กล่อง: เพิ่มใน `FLOW_NODES` (id สั้น) · `area` = buy/make/dispatch/sell/stock/hr/fin · `href` = หน้าที่เปิด
2. เส้น: เพิ่มใน `FLOW_EDGES` · `files` = ไฟล์ที่ทำการส่งต่อนี้จริง · `workflow` = key ในทะเบียน workflow (ถ้ามี)
3. วางในผัง: `FLOW_VIEWS[].pos` = `[คอลัมน์ 0–3, แถว, สูงกี่แถว?]` (แถว `"s"` = แถวคลังของภาพรวม) · `edges` = `[id, ด้านออก, เลื่อน, ด้านเข้า, เลื่อน, { c, bf, a, b, feed }]`
   - ด้าน `l r t b` · `c` = แนวเลี้ยวของเส้นหักมุม · `bf` = ตำแหน่งเลขบนเส้น (0–1) · `a`/`b` = ใช้กล่องอื่นเป็นต้น/ปลายในผังนี้ · `feed` = `[กล่อง, ด้าน, เลื่อน][]` เส้นสั้นมารวมสายที่แนว `c`
   - ผังเฉพาะผู้มีสิทธิ์การเงิน: ใส่ `finance: true` (+ `heads` ชื่อ 4 คอลัมน์)
4. ตัวเลขสดใหม่: เพิ่ม key ใน `FlowMetricKey` + `FLOW_METRICS` แล้วเขียนวิธีนับใน `/api/flow-map/health`
5. รัน `npx vitest run lib/__tests__/flow-map.test.ts` แล้วเปิดหน้าดูว่าเส้นไม่ทับกล่อง

## ข้อจำกัด

- ผังวาดด้วยตำแหน่งที่กำหนดเอง (ไม่จัดอัตโนมัติ) — เพิ่มกล่องต้องหาช่องว่างและเส้นทางเอง
- เนื้อหาเป็นภาษาไทย (ป้ายบนหน้าจอแปลได้ผ่าน `t()`)
- ตัวเลขสดเป็นยอดรวม ไม่ได้กดลงไปดูรายการได้ (ใช้ปุ่ม "เปิดหน้า" ไปหน้าเอกสารนั้นแทน)
