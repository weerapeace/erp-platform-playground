# กฎ "เพิ่มได้ ต้องแก้ + ลบได้" และของกลางที่ใช้

เจ้าของกำหนด (2026-09-29): **หน้าไหนเพิ่มข้อมูลได้ ต้องมีที่แก้ไขและที่ลบ (หรือยกเลิก/ปิดใช้งาน) มาด้วยเสมอ**

## เลือกแบบไหน: ลบ / ยกเลิก / ปิดใช้งาน

| ข้อมูลแบบไหน | ใช้ | เหตุผล |
|---|---|---|
| ใบร่าง ที่ยังไม่มีผลกับใคร | **ลบ** (เก็บสำเนาลง audit log ก่อน) | ยังไม่มีเอกสารอื่นอ้างถึง |
| เอกสารที่ยืนยัน/ส่ง/ออกไปแล้ว | **ยกเลิก** | ต้องเหลือร่องรอย + มีเอกสารอื่นอ้างถึง |
| ข้อมูลหลักที่เอกสารเก่าอ้างถึง (ร้าน, บริษัท, ธนาคาร, พนักงาน) | **ปิดใช้งาน** | ลบแล้วเอกสารเก่าจะชี้ไปหาของที่ไม่มี |
| รายการที่กระทบยอด (สต๊อก, เงิน) | **กลับรายการ / แก้ผ่านตัวคิดส่วนต่าง** | ต้องคืนยอดให้ครบทุกที่ที่เคยเขียน |

ทุกแบบต้อง: ถามยืนยันก่อน (ConfirmDialog / ERPModal) · เช็กสิทธิ์ที่เซิร์ฟเวอร์ · เขียน audit log

## ของกลาง

### `components/delete-draft-doc` — ปุ่ม "🗑 ลบใบร่าง"
```tsx
{detail.status === "draft" && (
  <DeleteDraftButton apiPath="/api/quotations" id={detail.id} docLabel="ใบเสนอราคา"
    number={detail.quote_number} onDeleted={(msg) => { flash(msg); setDetailOpen(false); fetchList(); }} />
)}
```
- ปุ่มโผล่เฉพาะคนมีสิทธิ์ `so.delete` (แอดมิน + ผู้จัดการ · ปรับที่ /admin/role-board)
- ลบไม่ได้ → โชว์เหตุผลในหน้าต่างยืนยัน (เช่น มีใบรับชำระอ้างถึง)
- ใช้แล้วที่: ใบเสนอราคา · ใบขาย · ใบวางบิล

### `lib/sales-doc-delete.ts` — ตรรกะลบใบร่างฝั่งเซิร์ฟเวอร์
`deleteDraftSalesDoc(admin, kind, id, actor)` — ลบได้เฉพาะ `status = draft` และไม่มีเอกสารอื่นอ้างถึง
ตรวจ: ใบรับชำระ · ใบวางบิล · ใบลดหนี้ · ใบส่งสินค้า · ใบสั่งขาย · ออเดอร์เว็บ · การจองสต๊อก
เลขของใบที่ลบจะว่าง → ชุดเลขที่เปิด "นำเลขที่ว่างกลับมาใช้" จะให้ใบถัดไปใช้เอง

### `components/gr-detail-modal` — ใบรับสินค้า (ดู / แก้ / ลบ)
แก้จำนวนหรือลบใบรับ = ระบบคืนยอดใบสั่งซื้อ + สต๊อก + ใบสำคัญร่าง ให้ครบ · เปลี่ยนไฟล์แนบได้ (เอาออกให้ว่างไม่ได้ เพราะเป็นเอกสารบังคับ)
ใช้แล้วที่: หน้ารับของ (แถบสำเร็จ + ประวัติการรับ) · หน้าประวัติการรับ (กดแถว) · หน้าใบสำคัญรับ
**ห้ามแก้ใบรับผ่านหน้า `/m/goods-receipts-v2`** — หน้านั้นแก้แถวตรง ๆ ไม่คืนยอดใบสั่งซื้อ/สต๊อก

### `components/po-detail-modal` — ยกเลิกใบสั่งซื้อทั้งใบ
ปุ่ม "❌ ยกเลิกใบสั่งซื้อ" (หรือ "ปิดยอดที่ค้าง" ถ้ารับมาแล้วบางส่วน) → `/api/purchasing/cancel-line` ทุกรายการที่ยังค้าง
เปิดกลับได้ที่หน้ารับของ → แท็บ "รับครบแล้ว" → ↩ เปิดกลับมารอรับ

## หน้าที่เพิ่มปุ่มแก้/ลบแล้ว (รอบ 3 — เงิน / สต๊อก / บัญชี)

ของพวกนี้เป็น "สมุดบัญชี" — ห้ามแก้/ลบประวัติ จึงใช้วิธี **กลับรายการ** (ลงรายการตรงข้าม อ้างถึงรายการเดิม) หรือ **ยกเลิก** แทน

| หน้า | ที่เพิ่ม | ข้อจำกัด |
|---|---|---|
| รอบจ่ายเงินเดือน `/payroll/payments` | 🗑 เอาพนักงานออกจากรอบ · ✏️ แก้วันที่จ่าย/หมายเหตุ | เฉพาะรอบร่าง · ต้องเหลืออย่างน้อย 1 คน |
| โกดัง QC | ✏️ แก้จำนวน/รหัสสินค้า/แหล่งที่มา | เฉพาะของที่ "ใส่เข้าชั้นเอง" · ของจากใบจ่ายงานให้ย้ายกลับงานรอ QC |
| ตารางส่งงาน | ✏️ แก้วันที่ส่ง/ค่าแรงของรายการที่ลงครบแล้ว | จำนวนที่ส่งแก้ไม่ได้ — ใช้ ↩️ ย้อนกลับ แล้วส่งใหม่ |
| ยอดเงินที่จีน (แอปโอนเงินจีน) | ↩ กลับรายการที่บันทึกผิด · ✏️ แก้หมายเหตุ | เฉพาะแอดมิน/ผู้จัดการ · กลับซ้ำไม่ได้ |
| สต๊อก `/inventory` → ความเคลื่อนไหว | ↩ กลับรายการ (เมนูท้ายแถว / ในป๊อปรายละเอียด) | เฉพาะ รับเข้า/เบิกออก/โอน ที่ลงมือเอง · "ปรับยอด" ให้ปรับใหม่ · รายการจากใบรับของ/ใบสั่งผลิต/ใบนับ แก้ที่เอกสารต้นทาง · ของต้องเหลือพอให้กลับ |
| ใบสำคัญรับ `/purchasing/vouchers/<id>` | ❌ ยกเลิกใบนี้ (ใบที่ยืนยันแล้ว) — ย้อนราคากลับ + ปล่อยใบรับกลับคิว | ต้องใส่เหตุผล · ถ้ามาร์คจ่ายค่าส่งแล้วต้องยกเลิกจ่ายก่อน · ราคาที่ถูกแก้ทีหลังจะไม่ถูกทับ |
| สมุดรายวัน `/accounting` | ใบร่าง: ✏️ แก้ไข · 🗑 ยกเลิกใบร่าง — ใบที่ผ่านแล้ว: ↩ กลับรายการ | ใบที่ผ่านรายการแล้วแก้/ลบไม่ได้ · กลับซ้ำไม่ได้ |
| นำเข้า Statement OD | 🕘 ประวัติการนำเข้า + ↩ ยกเลิกการนำเข้ารอบนั้น (คิดยอดใหม่ให้) | รายการถูกปิด ไม่ได้ลบ · นำเข้าไฟล์เดิมใหม่ได้ |

### ของกลางที่เพิ่ม: ย้อนราคา (`lib/po-line-price.ts`)
- `snapshotLinePrice()` — จด "ราคาก่อนเขียนทับ" ของบรรทัด PO / ราคาต่อร้าน / ราคาบน SKU (เรียกก่อนเขียนราคา)
- `restoreLinePrices()` — คืนราคาเดิมเฉพาะจุดที่ **ยังเป็นราคาที่เราเขียน** (มีคนแก้ทีหลัง = ไม่แตะ) แล้วคิดยอดรวมใบ PO ใหม่
- ข้อมูลราคาเดิมเก็บใน `audit_logs.metadata.price_before` ของรายการ `confirm` — ไม่ต้องเพิ่มตาราง

### หลักการ "กลับรายการ" (ใช้ซ้ำได้กับสมุดบัญชีอื่น)
1. รายการใหม่อ้างถึงรายการเดิม (`reference_type = "reversal"` + `reference_id` หรือ `[ref:<id>]` / `กลับรายการ <เลขที่>`)
2. เช็กก่อนเสมอว่ารายการเดิม "ยังไม่เคยถูกกลับ" และ "ไม่ใช่รายการกลับเอง"
3. เช็กว่ายอดพอให้กลับ (สต๊อก/เงินต้องไม่ติดลบ)
4. เขียน audit log ทุกครั้ง

### รูปแบบ "ถามยืนยันในแถว"
ป๊อปที่ซ้อนกันหลายชั้น (เช่น แผงปัญหาสินค้า, ป๊อปเลือกช่าง) ใช้ปุ่ม **ยืนยันลบ / ไม่ลบ** โผล่ในแถวเดียวกัน แทน ConfirmDialog
เพราะ ConfirmDialog (ชั้น z-50) จะถูกป๊อปที่ชั้นสูงกว่าบัง — หน้าเต็มปกติยังใช้ ConfirmDialog ตามเดิม

## ข้อจำกัด
- รอบนับสต๊อกที่ "ปรับแล้ว" ยกเลิกไม่ได้ (สต๊อกถูกปรับไปแล้ว) — ยอดผิดให้เปิดรอบใหม่แล้วปรับอีกครั้ง
- ใบรับที่ออกใบสำคัญและ "ยืนยันแล้ว" แก้/ลบไม่ได้ (ราคาถูกเขียนกลับระบบแล้ว) — ต้องยกเลิกใบสำคัญก่อน ใบรับจะกลับมาแก้ได้
- ใบสำคัญรับที่ยืนยัน "ก่อน" มีระบบจดราคาเดิม ยกเลิกได้ แต่ราคาในระบบจะคงไว้ (ไม่มีข้อมูลให้ย้อน)
- ไฟล์แนบของเอกสารที่ถูกลบ ยังค้างอยู่ในที่เก็บไฟล์ (ไม่ลบตาม)
