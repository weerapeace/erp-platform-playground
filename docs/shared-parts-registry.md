# ทะเบียนของกลาง (Plugin Registry)

หน้า `/admin/plugins` — "ของกลางในระบบ" บอกว่ามีชิ้นส่วนกลางอะไรบ้าง ใช้ทำอะไร ใช้ที่ไหน ตัวไหนซ้ำ ตัวไหนเลิกแล้ว

## ทำไมต้องมี

ทะเบียนเดิม (ตาราง `erp_plugins`) กรอกมือ 19 ตัวตั้งแต่ 30 พ.ค. 69 ไม่เคยอัปเดต ตัวเลข "ใช้ใน N ที่" พิมพ์เอง สวิตช์เปิด/ปิดไม่มีผลกับระบบ
ขณะที่โค้ดจริงมีชิ้นส่วนกลางกว่า 300 ตัว หลายตัวทำงานซ้ำกัน บางตัวไม่มีใครใช้ (สำรวจ 6 พ.ย. 69)

## ประกอบด้วย

| ส่วน | ไฟล์ | หน้าที่ |
|---|---|---|
| ทะเบียน | `lib/shared-parts-registry.ts` | ชื่อ · หมวด · ใช้ทำอะไร · ใช้/ห้ามใช้เมื่อไหร่ · กลุ่มงานเดียวกัน (`sameJob`) · ตัวหลัก (`primary`) · ตัวเก่า (`replacedBy`) · คู่มือ |
| ตัวนับ | `scripts/shared-parts-scan.mjs` | ไล่ import จากโค้ดจริง → ใช้กี่ไฟล์ กี่จุด ที่ไหน · ชิ้นส่วนที่ยังไม่ลงทะเบียน |
| ผลนับ | `lib/shared-parts-usage.json` | สร้างใหม่อัตโนมัติก่อน build ทุกครั้ง (`prebuild`) = ตัวเลขบนเว็บตรงกับโค้ดที่ขึ้นเว็บเสมอ |
| API | `app/api/admin/shared-parts/route.ts` | รวมทะเบียน + ผลนับ + ติดป้าย · สิทธิ์ `plugins.view` · อ่านอย่างเดียว |
| หน้าจอ | `app/admin/plugins/` | แท็บ ของกลางในระบบ · ยังไม่ลงทะเบียน · ทะเบียนเดิม |

## ป้ายที่ระบบติดให้เอง

| ป้าย | เงื่อนไข |
|---|---|
| ไม่มีใครใช้ | ไม่มีไฟล์ไหน import (หน้าทดลองใน `app/_demos` ไม่นับ เพราะไม่ได้ขึ้นเว็บจริง) |
| ตัวเก่า ควรเลิก | มี `replacedBy` |
| ทำงานซ้ำ | อยู่ใน `sameJob` เดียวกับตัวอื่น และกลุ่มนั้นมีตัวหลักแล้ว |
| ยังไม่เลือกตัวหลัก | อยู่ใน `sameJob` ที่ยังไม่มีตัวไหนเป็น `primary` |
| ใช้ที่เดียว | ใช้แค่ 1 จุด |
| ไม่มีคู่มือ | ใช้ตั้งแต่ 3 จุดแต่ไม่มี `doc` |

"จุด" = หน้า (โฟลเดอร์ใน app/) หรือชิ้นส่วน (components/x) หรือ lib หรือ API ที่ import · "ไฟล์" = จำนวนไฟล์ที่ import

## ใช้เมื่อไหร่

- ก่อนสร้างของกลางใหม่: ค้นในหน้านี้ก่อนว่ามีตัวที่ทำงานเดียวกันไหม
- ก่อนแก้ของกลาง: ดูแท็บ "ใช้อยู่ที่" ว่ากระทบหน้าไหน (ละเอียดกว่านี้ใช้ `npm run where-used -- <ไฟล์>`)
- ก่อนลบชิ้นส่วน: ดูป้าย "ไม่มีใครใช้" — **ลบต้องขออนุญาตเจ้าของทุกครั้ง**

## เพิ่ม / แก้ทะเบียน

1. เพิ่มก้อนใหม่ใน `SHARED_PARTS` (ไฟล์ `lib/shared-parts-registry.ts`)
2. เขียน `source` **บรรทัดเดียว** แบบ `source: { path: "components/x" }` หรือ `source: { path: "components/pickers", names: ["SkuPicker"] }` — ตัวนับตอน build อ่านด้วย regex
3. เขียน `what` / `when` / `notWhen` เป็นภาษาคน
4. ถ้าทำงานเดียวกับตัวอื่น ใส่ `sameJob` ชื่อเดียวกัน (และเพิ่มชื่อกลุ่มใน `SAME_JOB_LABEL`) · ตัวหลักใส่ `primary: true`
5. รัน `npm run parts:scan` แล้ว `npx vitest run lib/__tests__/shared-parts-registry.test.ts`

## ห้าม

- ห้ามจด "ใช้กี่ที่" เอง — ตัวนับทำให้
- ห้ามให้ตัวนับทำ build ล้ม — ถ้านับพลาดสคริปต์จะเก็บผลเดิมแล้วจบปกติ

## ข้อจำกัด

- นับเฉพาะ import ตรง (ไม่ไล่ต่อทอดว่าไปโผล่หน้าไหนบ้าง) — ของกลางที่ห่ออยู่ใน MasterCRUD จะเห็นแค่ "master-crud"
- แท็บ "ยังไม่ลงทะเบียน" นับเฉพาะ `components/` (lib/ มีกว่า 600 ไฟล์ ส่วนใหญ่เป็นกติกาเฉพาะโมดูล — ลงทะเบียนเฉพาะ lib ที่เป็นของกลางจริง)
- ตัวชี้วัด "หน้าที่เขียน กำลังโหลด เอง" เป็นตัวเลขคร่าว ๆ (หน้า page.tsx ที่มีคำนี้แต่ไม่ได้ import LoadingState/Spinner)
- แท็บ "ทะเบียนเดิม" ยังอ่านตาราง `erp_plugins` และสวิตช์เดิมยังกดได้แต่ไม่มีผล — รอเจ้าของตัดสินใจ (เอาออก / ทำให้มีผลจริง)
