# ส่งงานจัดเรียงเข้าคลังงานพิมพ์ → โฟลเดอร์ส่งร้านพิมพ์

เจ้าของสั่ง 2026-11-16 แล้วเลือกข้อ 1, 3, 4, 6 จาก widget

## ปลายทาง
`[โฟลเดอร์ส่งร้านพิมพ์] / YYYY-MM-DD / <ประเภท> - <ชื่องาน>`

| ส่วน | มาจากไหน |
|---|---|
| โฟลเดอร์ส่งร้านพิมพ์ | ค่าตั้งต้น `ui_config.nesting_drive_root` → ถ้าไม่มี ใช้ `print_drive_root` (= `G:\Shared drives\Louis Montini\[4] Assets\Printed\ไฟล์ส่งร้านพิมพ์ (Printed Files)`) |
| วันที่ | วันที่ในเครื่องผู้ส่ง (`todayFolder`) · เซิร์ฟเวอร์ตรวจรูปแบบอีกชั้น ผิดรูปแบบ = วันนี้ตามเวลาไทย |
| ชื่อโฟลเดอร์งาน | ประเภท (DTF/UV) + ชื่อ · ชื่อตั้งจากชื่องาน แก้ได้ในหน้าต่าง · ไฟล์ข้างในตั้งชื่อตามชื่อ (ไม่มีประเภทนำหน้า) |

- แบบเดิม (`Printed/<ประเภท>/<โฟลเดอร์ย่อย>/<ชื่องาน>`) และช่อง "โฟลเดอร์ย่อย" เลิกใช้ในหน้าต่างนี้แล้ว
  - route `/api/nesting-jobs/drive-groups` ยังอยู่ แต่ไม่มีหน้าไหนเรียก
- "เพิ่มงานพิมพ์" ในคลังไฟล์ ยังใช้ `print_drive_root` + ซับของประเภทเหมือนเดิม (ไม่กระทบ)

## เปลี่ยนปลายทาง
- ปุ่ม "เปลี่ยน" → วางลิงก์โฟลเดอร์ Drive (หรือ id)
  - `GET /api/nesting-jobs/drive-root?folder=` ตรวจว่ามีจริงและแชร์ให้ระบบแล้ว
  - จำไว้ในเครื่องนี้ (localStorage `nesting-send-root`)
- หาโฟลเดอร์ไม่เจอ ทั้งตั้งต้นหรือที่จำไว้ = กล่องแดง + ช่องวางลิงก์ และปุ่มส่งใช้ไม่ได้
  - ถ้าตอนส่ง เซิร์ฟเวอร์ตอบ 409 `root_missing` จะเปิดช่องเลือกใหม่ให้เอง
- ผู้ดูแล (`assets.manage`) กด "ตั้งเป็นค่าเริ่มของทุกคน" → `PUT /api/nesting-jobs/drive-root` (มี audit)
  - path ในเครื่องรู้เฉพาะเมื่อเป็นโฟลเดอร์เดียวกับ `print_drive_root`

## ลิงก์แชร์
- ส่งเสร็จ → `driveShareAnyone` (lib/google-drive) เปิด "ทุกคนที่มีลิงก์ดูได้" ที่โฟลเดอร์งาน (ร้านเห็นเฉพาะงานนั้น)
- หน้าต่างไม่ปิดเอง → โชว์ลิงก์ + คัดลอกให้อัตโนมัติ + ปุ่มคัดลอก/เปิด
- Shared drive ห้ามแชร์นอกองค์กร = แจ้งเตือนสีเหลือง (`share_error`) ไฟล์ยังขึ้น Drive ครบ
- audit ของการส่งบันทึก `shared_anyone` / `share_error`

## ข้อจำกัด
- ส่งใหม่ข้ามวัน = ได้โฟลเดอร์วันที่ใหม่ → "ทับของเดิม" ทับเฉพาะไฟล์ชื่อซ้ำในโฟลเดอร์ของวันนั้น
- ยังไม่มีหน้าต่างเดินดูโฟลเดอร์ (ข้อ 2 ไม่ได้เลือก) — เปลี่ยนด้วยการวางลิงก์เท่านั้น

## ระบบไม่มีสิทธิ์เขียน (เจอจริง 2026-11-16)
- โฟลเดอร์ที่แชร์ให้บัญชีระบบแค่ "ดู" = เห็นชื่อได้ แต่สร้างโฟลเดอร์วันที่ไม่ได้ (Drive: Insufficient permissions for the specified parent)
- หน้าต่างตรวจก่อนส่ง (`driveFolderAccess` → capabilities.canAddChildren) → กล่องแดง + อีเมลบัญชีระบบให้คัดลอก + "ตรวจอีกครั้ง" · ปุ่มส่งใช้ไม่ได้
- วิธีแก้: ใน Drive แชร์โฟลเดอร์ปลายทางให้อีเมลนั้นเป็น "ผู้จัดการเนื้อหา" (Content manager)
- เซิร์ฟเวอร์ตอบ 409 `no_write` ถ้าสิทธิ์เปลี่ยนหลังตรวจ
