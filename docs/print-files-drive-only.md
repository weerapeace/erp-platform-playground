# ไฟล์งานพิมพ์ = Google Drive เท่านั้น

> กฎจากเจ้าของ (2026-10-27): **ไฟล์ PDF ที่ทำเสร็จ ห้ามเก็บใน R2 — ต้องเก็บใน Google Drive เท่านั้น**
> โค้ดกฎกลาง: `lib/print-file-policy.ts` — ทุกทางที่ไฟล์งานพิมพ์อาจลง R2 ต้องเรียกตัวนี้ ห้ามเขียนตรวจเองแยก

## ใช้ทำอะไร

กันไฟล์สั่งพิมพ์ (PDF / EPS / AI / PostScript) หลุดไปเก็บใน R2 — ทั้งกดผิดช่อง ลากผิดที่ และเปลี่ยนนามสกุลหลบ
(เช็กทั้งชื่อไฟล์และเนื้อไฟล์ เช่น PDF ที่ตั้งชื่อเป็น `.png` ก็ถูกจับ)

## ไฟล์ไหนอยู่ที่ไหน

| ไฟล์ | เก็บที่ |
|---|---|
| PDF / EPS / PNG แผ่นพิมพ์ที่จัดเสร็จ (หน้าจัดเรียง → ส่งเข้าคลังงานพิมพ์) | **Google Drive** — ตัวช่วยในเครื่องส่งตรง `[แม่งานพิมพ์]/Printed/<ประเภท>/…` |
| ไฟล์ .ai / .pdf ที่แนบตอน "เพิ่มงานพิมพ์" ในคลังไฟล์ (ช่อง "ไฟล์พิมพ์") | **Google Drive** (โฟลเดอร์ของงานนั้น) |
| รูปตัวอย่างบนการ์ดงานพิมพ์ (PNG / JPG / WebP) | R2 ได้ — เป็นรูปไว้ดู ไม่ใช่ไฟล์พิมพ์ |
| PNG ลายต้นฉบับของงานจัดเรียง (`nesting-prints/<sha>.png`) | R2 ได้ — เป็นไฟล์ต้นทาง ต้องเป็น PNG จริงเท่านั้น |

### ไฟล์พิมพ์ PNG ของลาย — ที่เดียว ใช้ร่วมกัน (2026-10-27)

- ที่เก็บกลาง = `lib/print-store.ts` (R2 `nesting-prints/<sha>.png` + ผูกกับลายที่ `assets.nest_print_file` · ไฟล์ใหม่แทนที่ของเดิม)
- ใส่ไฟล์ได้ 3 ทาง ได้ไฟล์เดียวกัน:
  1. หน้าจัดเรียง: ลาก PNG ใส่การ์ดลาย → ตัวช่วยในเครื่อง (v1.5+) ส่งเข้าคลังเอง (`/api/nesting-jobs/print-files`)
  2. การ์ดลายในคลังไฟล์ → ช่อง "🖨 ไฟล์พิมพ์ (PNG ตัวจริง)" (`components/asset-library/print-file-slot.tsx` · `/api/assets/[id]/print-file`)
     — ไฟล์ ≤ 4 MB อัปผ่านเว็บ · ใหญ่กว่านั้นเบราว์เซอร์ส่งตรงเข้า R2 (ลิงก์ชั่วคราว · ต้องเปิด CORS ของ bucket เหมือนทางวิดีโอ)
  3. ปุ่ม "📁 ใช้ไฟล์จาก Drive" (บนการ์ดลาย และบนการ์ดที่ไฟล์หายในหน้าจัดเรียง) → เลือก PNG ในโฟลเดอร์ Drive ของการ์ด
     → เซิร์ฟเวอร์คัดลอกเข้าคลัง (ไม่ต้องอัปซ้ำ · เทียบ `sha256Checksum` ของ Drive บอกว่าไฟล์ไหนเหมือนในคลัง/ซ้ำกันเอง)
- หน้าจัดเรียง: ไฟล์ไม่อยู่ในเครื่อง → ดึงจากคลังเอง (ตัวช่วย 1.5+) · ลายมีไฟล์พิมพ์ใหม่กว่าในการ์ด = ใช้ไฟล์นั้นแทน (ชิ้นที่แยก = แยกใหม่ตามค่าเดิม)
  · ข้อความตามสาเหตุ: มีในคลังแต่ตัวช่วยเก่า (บอกวิธีอัปเดต) / ยังไม่มีในคลัง (ใส่ครั้งเดียว + ปุ่ม Drive) / โหลดจากคลังไม่สำเร็จ

## จุดที่กันไว้

| ทาง | กันที่ | ผล |
|---|---|---|
| คลังไฟล์ → เพิ่มงานพิมพ์ (ทีละรูป / หลายรูป) | หน้าเว็บ `components/asset-library/print-modals.tsx` + API `POST /api/assets` (เฉพาะ `source='print'`) | ไม่รับ — ขึ้นข้อความให้ใส่ช่อง "ไฟล์พิมพ์" (ขึ้น Drive) แทน |
| การ์ดงานพิมพ์ → แทนที่ไฟล์ | หน้าเว็บ `detail-modal.tsx` + API `POST /api/assets/[id]/replace` | ไม่รับ PDF/EPS/AI · รับเฉพาะรูป PNG/JPG/WebP |
| หน้าจัดเรียง → ส่งเข้าคลังงานพิมพ์ (รูปการ์ด) | API `POST /api/nesting-jobs/[id]/publish` | ต้องเป็นรูปจริง (ดูจากเนื้อไฟล์) |
| คลัง PNG ลายต้นฉบับ | ตัวช่วย `web/cloud_files.py` (v1.5.1+ ไม่ส่ง/ไม่รับไฟล์ที่ไม่ใช่ PNG) + API `PUT /api/nesting-jobs/print-files` (ไม่ใช่ PNG = ลบทิ้ง ไม่ผูกกับลาย) | เก็บได้เฉพาะ PNG |

## ห้ามใช้กับอะไร

- **ไม่ใช่กฎ PDF ทั้งระบบ** — ใบเสนอราคา / ใบแจ้งหนี้ / ไฟล์แนบ / คลังไฟล์หมวดอื่น ยังเก็บ PDF ใน R2 ได้ตามเดิม
- ใช้เฉพาะ "หมวดงานพิมพ์" (`assets.source='print'`) และงานจัดเรียง (`/api/nesting-jobs/*`)

## ถ้าจะเพิ่มทางอัปไฟล์ใหม่ในหมวดงานพิมพ์

1. ฝั่งหน้าเว็บ: `printPreviewProblem(file.name, file.type)` → ได้ข้อความ = แจ้งผู้ใช้ (`t(msg.th, msg.en)`) แล้วไม่อัป
2. ฝั่ง API: `printPreviewProblem(name, type, ไบต์แรก ~16 ตัว)` ทุกครั้ง (อย่าเชื่อหน้าเว็บอย่างเดียว) → 400 พร้อม `msg.th`
3. ไฟล์พิมพ์จริงส่งเข้า Drive (ดู `uploadArtworkToDrive` ในคลังไฟล์ หรือ `drive_push` ของตัวช่วย)

## ข้อจำกัดที่รู้แล้ว

- ไม่ได้ไล่ลบไฟล์เก่า — ตรวจแล้ว ณ 2026-10-27 ไม่มี PDF/EPS/AI อยู่ใน R2 เลย
- ตัวช่วยรุ่นก่อน 1.5.1 ไม่ตรวจเองตอนส่ง แต่ฝั่ง ERP ยังตรวจตอนยืนยัน (ไม่ใช่ PNG = ลบทิ้ง) จึงไม่มีไฟล์หลุดไปผูกกับลาย
