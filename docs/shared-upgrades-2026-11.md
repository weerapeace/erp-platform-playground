## รอบสุดท้าย (L) — ย้ายหน้าที่เขียน "กำลังโหลด…" เอง มาใช้ของกลาง LoadingState

- ย้ายแล้ว 165 หน้า (9 ชุด ชุดละ ≤20) — กล่องข้อความ "กำลังโหลด…" ธรรมดา → โครงสีเทา (skeleton)
- หน้าที่มีข้อความรอเฉพาะ (เช่น "กำลังโหลดหนี้ทุกก้อน…") = คงข้อความ + หน้าตากล่องเดิม (`boxClassName`) แต่ใช้ของกลางแล้ว
- แถวตารางรอโหลด (`<td colSpan>`) → `<LoadingState rows={3} />` ในแถว
- ไม่ย้าย (ไม่ใช่กล่องรอโหลด): ข้อความบนปุ่ม "กำลังโหลด…/โหลดใหม่", หัวข้อหน้า, หน้าสาธารณะ /offer, ข้อความแบบมีเงื่อนไขซ้อน — 6 จุด
- เครื่องมือย้าย: codemod (แปลงเฉพาะรูปแบบ `<div className="…">กำลังโหลด…</div>` ในหน้า "use client")

## ส่ง PDF ไป LINE / อีเมล จากแถบพิมพ์ (เจ้าของเลือกแบบ A + ข้อ 1, 2, 3 · 2026-11-18)

- ปุ่ม "📤 ส่ง PDF" อยู่ในแถบพิมพ์ (`PrintToolbar`) ทุกหน้าพิมพ์เอกสารที่ตั้งชื่อไฟล์ (23 หน้า เช่น ใบสั่งขาย ใบวางบิล ใบลดหนี้ ใบส่งของ)
- ทางเดิน: ทำ PDF ในเครื่องจากพรีวิว (jsPDF + html2canvas ใน `public/vendor`, โหลดเฉพาะตอนกดส่ง) → `POST /api/print-send` → เก็บ Google Drive "ERP เอกสารที่ส่ง/YYYY-MM" (ไม่ใช่ R2) → เปิดลิงก์ให้คนมีลิงก์ดูได้ → LINE ได้ข้อความ + ลิงก์ (ผ่าน `lib/line-send` · LINE ส่งไฟล์ PDF ตรง ๆ ไม่ได้) · อีเมลได้ไฟล์แนบ + ลิงก์ (ตอบกลับไปหาคนส่ง)
- กลุ่ม LINE ที่เลือกได้ = กลุ่มที่ตั้งไว้ในศูนย์ LINE (ไม่รวมกลุ่มรับเข้า เช่น ส่งรูปคำสั่งซื้อ/ส่งงานออกแบบ)
- ข้อ 1: จำผู้รับ + ช่องทางล่าสุดต่อชนิดเอกสาร (ในเครื่อง) · ข้อ 2: บันทึกประวัติ audit `document.sent` (ใคร ส่งไฟล์ไหน ถึงใคร สำเร็จไหม ลิงก์) · ข้อ 3: แก้ข้อความก่อนส่ง และจำข้อความไว้ใช้กับเอกสารชนิดนี้ครั้งหน้า
- ส่งเมื่อกด "ส่งตอนนี้" เท่านั้น · สิทธิ์ `reports.view` (ทุกตำแหน่งมีอยู่แล้ว) · ไฟล์เกิน 4 MB ลดคุณภาพรูปอัตโนมัติ
- ข้อจำกัด: PDF เป็นภาพของพรีวิว (ข้อความในไฟล์เลือก/ค้นไม่ได้) · ตัดหน้าตามความสูง A4 — เอกสารยาวอาจตัดกลางแถว

เทสต์: `lib/__tests__/print-send.test.ts`
