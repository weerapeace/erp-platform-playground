# บิลจากร้านจีน → จับคู่ใบสั่งซื้อ (ในใบสำคัญรับ)

> ของกลาง: `lib/seller-bill-match.ts` (กติกาจับคู่ · pure) · `lib/seller-bill.ts` (อ่านบิลด้วย AI + ใส่ลงใบ · server)
> หน้าจอ: `components/seller-bill-panel` บนหน้า `/purchasing/vouchers/<id>` · API `/api/purchasing/vouchers/<id>/seller-bills`

## ใช้ทำอะไร

ร้านในจีนส่ง "บิล / ใบส่งของ" (送货单 · 发货单) เป็นภาษาจีนมากับของ จัดซื้อเอาบิลมาใส่ในใบสำคัญรับได้เลย ไม่ต้องพิมพ์เอง

1. อัปโหลดรูปหรือ PDF บิล (หรือกดอ่านจากบิลที่แนบไว้ตอนรับของ)
2. AI อ่านชื่อจีน แปลไทย อ่านจำนวน ราคา ¥ และยอด แล้วตรวจว่า จำนวน × ราคา = ยอดรวมบิล
3. ระบบจับคู่แต่ละแถวกับ **บรรทัดใบสั่งซื้อที่ยังค้างของร้านเดียวกับใบนี้เท่านั้น** แล้วติดป้าย
   - **มั่นใจ** (≥ 80%) — คะแนนสูง และราคาตรงกับ PO หรือเคยจับคู่แล้ว
   - **ให้เช็ก** — เจอตัวที่น่าจะใช่ แต่มีจุดต่าง (ราคา จำนวน ขนาด หรือสี)
   - **ไม่เจอใน PO ร้านนี้** — ให้กด "เลือกจับคู่เอง" (ค้นได้เฉพาะ PO ของร้านนี้) หรือ "ข้าม"
   - **ไม่ใช่สินค้า** — ค่าส่งในจีน ค่ากล่อง ภาษี → "ข้าม" หรือ "เพิ่มเป็นค่าใช้จ่าย"
4. คนต้องตัดสินทุกแถว (ใช่ / เลือกเอง / ข้าม) ก่อนกด "ใส่ลงใบสำคัญรับ"
5. ใส่ลงใบแล้ว ราคา ¥ จากบิลจะอยู่ในรายการ (ป้าย "จากบิลร้าน") และตอนกดยืนยันใบ ราคาจะเขียนกลับ PO กับราคาต่อร้านตามระบบเดิม

## ห้ามใช้เมื่อไหร่ / ข้อจำกัด

- **จับคู่อัตโนมัติ** = เฉพาะใบสั่งซื้อของร้านนี้ (ตั้งใจ — เปิดกว้างแล้วจับผิดง่าย) · **เลือกเอง** ได้กว้างกว่า (ดูหัวข้อ "เลือกจับคู่เอง 3 แท็บ") · สร้างสินค้าใหม่จากแผงนี้ไม่ได้ (ใช้ "＋ เพิ่มรายการ" พิมพ์ชื่อเองในใบ)

## เลือกจับคู่เอง 3 แท็บ (เจ้าของขอ 2026-11-04 "เลือกอะไรก็ได้ ไม่ใช่แค่สินค้าของคนนั้น")

| แท็บ | ผูกกับ | ตอนใส่ลงใบ / ยืนยันใบ |
|---|---|---|
| ① PO ร้านนี้ | กลุ่ม PO ร้านนี้ (`match_key`) | เหมือนเดิม |
| ② PO ร้านอื่น (`?other=1` → `loadOtherShopGroups`) | "ย้าย PO มาเป็นร้านนี้" (`move_po`) → หน้าเว็บเรียก API กลาง `PATCH /api/purchasing/po-edit { header: seller_name/seller_partner_id }` **ก่อน** ใส่ลงใบ (ป๊อปยืนยัน) แล้วถือเป็น PO ร้านนี้ · หรือ "ใช้แค่รหัสสินค้า" (= แท็บ ③) | ย้ายไม่ได้ถ้า PO นั้น จ่ายเงินแล้ว / ผูกบิลโอนเงินจีน / รับของไปบางส่วน (`po_locked`) |
| ③ สินค้าทั้งหมด (SkuPicker) | รหัสสินค้าอย่างเดียว (`sku_pick`, `match_key` = null) | ติ๊ก "เปิดใบสั่งซื้อย้อนหลังให้ร้านนี้" (ค่าเริ่มเปิด) → `createManualPo` (lib/po-manual · วันที่บิล) แล้วแปลงเป็นแถว PO (กดใส่ซ้ำไม่เปิดใหม่) · ไม่ติ๊ก = รายการผูกรหัสอย่างเดียว → ยืนยันใบ = ราคาต่อร้านนี้ + ราคาบนสินค้า (รับของ/จ่ายตาม PO ไม่ได้ ใบสั่งผลิตยังขึ้นต้องซื้อ) |

- คำใบ้ "เจอใน PO ร้านอื่น" (`otherShopHint`) ให้แถวที่ไม่เจอ — ไม่ผูกเอง กด "ดู" = เปิดแท็บ ② พร้อมคำค้น
- จำคู่ + เติมชื่อจีน ใช้กับแถวนอกใบสั่งซื้อด้วย (ผูกรหัสสินค้า)
- ไม่ใช่ใบส่งของบริษัทขนส่ง (EK-…, กก./คิว) — อันนั้นใช้แผง "ใบส่งของจากขนส่ง" (`components/delivery-bill-panel`)
- ถ้าใบนี้มาจากใบรับของ บรรทัดนั้นจะ **ได้ราคาอย่างเดียว** (จำนวนยึดตามใบรับ) · ถ้าเป็นใบเปล่า ระบบเพิ่มรายการผูก PO แต่ **ของยังไม่เข้าสต๊อก** จนกว่าจะรับของที่หน้ารับของ (ป้าย "ยังไม่รับของ")
- ลายมือหวัด/รูปเอียงมาก AI อ่านตัวเลขผิดได้ — แก้จำนวน/ราคาในแถวได้ก่อนกดใช่

## การจับคู่ทำยังไง (lib/seller-bill-match.ts)

เป้าหมาย = "กลุ่ม" คือสินค้า 1 ตัวใน PO 1 ใบ (PO ของเราแตกบรรทัดตามใบสั่งผลิต เช่น 13 บรรทัดของเดียวกัน)

| สัญญาณ | คะแนน |
|---|---|
| เคยจับคู่แล้ว (จำคู่ ต่อร้าน) | +4 |
| AI เลือกตัวนี้ (ส่งรายการ PO ของร้านให้ AI เลือก) | +3 × ความมั่นใจ AI |
| AI เลือกของเดียวกันแต่คนละ PO | +2.6 × ความมั่นใจ |
| ราคา ¥ ตรง PO (±2%) | +1.2 |
| เบอร์/รหัสตรง (G322, #402) | +1 |
| ชื่อแปลไทยคล้าย (bigram) | +1.5 × ความคล้าย |
| จำนวนตรงกับที่ค้าง/ที่สั่ง | +0.6 |
| ขนาดตรง / สีตรง | +0.6 / +0.5 |
| ขนาดไม่ตรง / สีไม่ตรง | −1.5 / −1.2 |

ต่ำกว่า 1.2 = ไม่เจอ · ของเดียวกันอยู่หลาย PO → เลือกใบที่ราคาตรง แล้วเตือน "มีใน N PO"

"ค้าง" = จำนวนสั่ง − จำนวนที่ออกใบสำคัญใบอื่นไปแล้ว (ใบที่ยกเลิกไม่นับ) · บรรทัดที่รับครบ/ปิดยอดไม่นับ

แบ่งจำนวนลงบรรทัด PO: เรียงตามลำดับบรรทัด (ใบสั่งผลิตเก่าก่อน) เติมทีละบรรทัดเท่าที่ค้าง ส่วนเกินลงบรรทัดสุดท้าย (`distributeQty`)

## โยนรูปบิล → ออกใบสำคัญ (ป๊อป ＋ ออกใบสำคัญรับ แท็บ "จากบิลร้าน (AI อ่านให้)")

ของกลาง: `components/seller-bill-intake` (หน้าจอ) · `lib/seller-bill-intake.ts` (server) · `lib/seller-bill-shop.ts` (pure: หาร้าน) · API `POST /api/purchasing/seller-bills/intake` (อ่าน) + `/create` (สร้าง)

1. วาง / ลาก / Ctrl+V / ถ่ายรูป — หลายไฟล์ = หลายหน้าของบิลเดียวกัน (ไม่เกิน 6) · PDF ได้ · อัปตามกฎที่เก็บไฟล์ หมวด supplier_bills
2. AI อ่านรอบเดียว (ส่งรายชื่อร้านจีนในทะเบียนไปด้วย) → `bills[]` แยกตามร้าน (รูปเดียวหลายร้าน = หลายบิล) + ชื่อร้าน/เบอร์/เลขบัญชีในบิล + เลขที่/วันที่/สกุล/รายการ
3. หาร้านในทะเบียน (`rankShops`): เลขบัญชีตรง (+6 · ปิดบางส่วน 4 หน้า+4 ท้าย +3.5) · เบอร์ตรง 8 หลักท้าย (+4.5) · ชื่อจีนตรงกับ company_name/name_en (+4 × ความคล้าย) · AI เลือก (+3 × มั่นใจ) · ของในบิลตรง PO ค้างของร้านนั้น (+3 × สัดส่วน) → เสนอ 3 ร้าน
   - **เลือกให้ล่วงหน้า** เฉพาะมั่นใจ ≥ 60% และทิ้งห่างร้านที่ 2 ≥ 15 จุด (`autoPick`) · ไม่งั้นคนเลือกเอง (ป้าย "อาจใช่" + เตือนร้านซ้ำ) · คนยืนยันร้านเสมอ (กดสร้าง = ยืนยัน)
   - ไม่เจอ → เลือกจาก SupplierPicker หรือ "＋ เพิ่มร้านใหม่" (SupplierWizard `prefill`: ชื่อจีน/เบอร์/บัญชี/ประเทศจีน/¥)
4. สกุลจากบิล (ร้านจีนในทะเบียนตั้ง default THB ทุกร้าน — ไม่ใช้) · เรท = daily_rates ของวันที่บิล · เตือนบิลซ้ำ (bill_no เดียวกัน + ร้านเดียวกัน ที่ใบยังไม่ยกเลิก) ต้องติ๊ก "ออกใหม่อยู่ดี"
5. กดสร้าง → `createVoucherFromSellerBill`: ใบร่าง (`createManualVoucher` วันที่ = วันที่บิล) + บิล kind=seller (r2_key = หน้าแรก · `raw.files` ทุกหน้า) → AI เลือกบรรทัด PO **จากข้อความ** (`aiPickCandidates` ไม่ส่งรูปซ้ำ) → `matchBillLines` → 1 ใบ = เปิดหน้าใบ (แผงบิลร้านเดิมรอเช็ก) · หลายใบ = รีเฟรชรายการ
6. จำร้าน (ติ๊กค่าเริ่มเปิด): เติม `company_name` = ชื่อจีน · `phone` · `account_number` **เฉพาะช่องที่ว่าง** (บัญชีในทะเบียนไม่ตรงบิล = ไม่ทับ) + audit partners_v2
- อ่านไม่ได้ / ไม่ใช่บิล → เหตุผลภาษาคน + อ่านอีกครั้ง / เริ่มใหม่ / "สร้างเปล่า (แนบรูปนี้ไว้)" (ใบ + บิล 0 แถว)
- ค่าใช้จ่าย AI: อ่านรูป 1 ครั้ง + จับคู่ข้อความ 1 ครั้งต่อบิล ≈ < 0.3 บาท · audit `ai_seller_bill_intake`
- ข้อมูลจริง 4 พ.ย. 2026: ร้านจีน 58 ร้าน · มีตัวจีนในชื่อ 11 · เลขบัญชี 31 · เบอร์ 32 · WeChat 0 · company_name 0

## ร้านส่งไม่ครบ (ขั้น 3 flow จัดซื้อ — ร้านไม่มีของตอนนั้น)

- ออกใบสำคัญ **ก่อนของมาถึง** ได้: หน้ารายการ → ＋ ออกใบสำคัญรับ → "จากบิลร้าน / สร้างเปล่า" (เลือกร้านจากทะเบียน) → อัปบิลในฟอร์ม
- **บิลลงน้อยกว่าที่ค้าง** (แถวนั้นขึ้น "ขาด N"): เลือก "คงไว้รอส่วนที่เหลือ" (ค่าเริ่ม — PO ไม่เปลี่ยน ยังค้างรับ) หรือ "ลด PO ตามบิล" → ตอนใส่ลงใบเรียก API กลาง `PATCH /api/purchasing/po-edit { line_qty }` (แบ่งจำนวนบิลลงบรรทัด ใบสั่งผลิตเก่าก่อน · บรรทัดที่ได้ 0 → ปิดยอด เพราะตั้งจำนวน 0 ไม่ได้ · ไม่ต่ำกว่าที่รับแล้ว) — `reducePlan()`
- **ส่วน "ไม่อยู่ในบิล"**: ของที่สั่งรอบเดียวกับบิล = PO เดียวกัน + PO ของร้านนี้ที่สั่งวันเดียวกัน (PO จีน 68% มีสินค้าตัวเดียว เปิดแยกใบตามใบสั่งผลิต) หรือกด "แสดงทั้งร้าน" ที่ยังค้างรับแต่บิลไม่มี — เลือกต่อรายการ "รอรอบหน้า" (ค่าเริ่ม) / "ปิดยอด" → ตอนใส่ลงใบเรียก API กลาง `POST /api/purchasing/cancel-line` (line_status = short_closed · ของที่ปิดยอด หน้าขอซื้อ/ใบสั่งผลิตกลับเป็น "ต้องซื้อ" ตามกติกา lib/mo-material-status) — `missingGroups()`
- มีงานแก้ PO = ป๊อปยืนยันสรุปรายการก่อนเสมอ · แก้ PO ทำหลังใส่ลงใบสำเร็จ (ล้มบางส่วน = แจ้งชื่อ PO ที่ล้ม กดใส่ลงใบอีกครั้งได้) · สิทธิ์/ประวัติ/สถานะใบ PO ตามกติกาของ API กลางนั้น ๆ (ไม่คิดเอง)
- ไม่แตะสถานะจ่ายเงิน (ป้ายสี lib/po-pay-state เป็นของกลางแยก)

## ชื่อจีนของสินค้า (skus_v2.name_cn) — `lib/sku-cn-name.ts`
