# กระแสเงินสด (Cashflow)

หน้าเดียวที่ตอบคำถามว่า **"เดือนหน้าเงินจะพอจ่ายไหม"**
โดยรวมเงินเข้า-เงินออกจากทุกโมดูลที่มีอยู่แล้วมาต่อกันเป็นเส้นเวลา

- หน้าเว็บ: `/cashflow` (เมนู 💧 กระแสเงินสด อยู่ในแอป **การเงิน (เงินกู้/OD)**)
- หน้าประกอบ: `/cashflow/board` (กระดานลากเลื่อนวัน) · `/receipts` (รับชำระเงิน · ดู [receipts.md](./receipts.md)) · `/cashflow/credit-terms` (ตั้งเครดิตหลายรายพร้อมกัน)
- ของกลาง: [`lib/cashflow.ts`](../lib/cashflow.ts)
- API: [`app/api/cashflow/route.ts`](../app/api/cashflow/route.ts) · [`app/api/cashflow/opening-balances/route.ts`](../app/api/cashflow/opening-balances/route.ts)
- เทสต์: [`lib/__tests__/cashflow.test.ts`](../lib/__tests__/cashflow.test.ts)

---

## ใช้ทำอะไร

| อยากรู้ | หน้านี้ตอบให้ |
|---|---|
| เดือนหน้าต้องจ่ายเท่าไหร่ | รวมใบซื้อ + เงินเดือน + งวดผ่อน + ดอกเบี้ย OD + เงินจีน |
| เงินจะเข้าเมื่อไหร่ | ใบวางบิล (วันครบกำหนดจริง) + ใบขายยืนยันแล้ว (คาดจากเครดิตลูกค้า) |
| เงินจะขาดวันไหน | แถบแดง 🚨 บอกวันแรกที่เงินคงเหลือติดลบ |
| ค้างรับ/ค้างจ่ายสะสมเท่าไหร่ | แถบ "ของค้างจากก่อนวันนี้" |

## ไม่ควรใช้ทำอะไร

- **ไม่ใช่งบการเงิน** — ไม่ได้ทำตามมาตรฐานบัญชี ใช้บริหารเงินสดเท่านั้น
- **ไม่ใช่ยอดเงินจริงในธนาคาร** — ระบบยังไม่ได้ต่อ API ธนาคาร ยอดตั้งต้นมาจากที่คนกรอกเอง
- **ไม่ใช้ตัดสินใจกู้เงิน/ลงทุนก้อนใหญ่โดยไม่ตรวจซ้ำ** — ตราบใดที่ยังมีป้ายเตือน ⚠️ ค้างอยู่บนหน้า

## แนวคิดหลัก — ทุกอย่างเป็น "รายการเงิน 1 บรรทัด"

ไม่ว่าจะมาจากโมดูลไหน ทุกอย่างถูกแปลงเป็น `CashflowEvent` หน้าตาเดียวกัน:

```ts
{
  date: "2026-09-15",          // วันที่เงินเข้า/ออก
  direction: "out",            // in = เข้า, out = ออก
  source: "purchase_order",    // มาจากไหน
  certainty: "expected",       // มั่นใจแค่ไหน
  ref: "PO-2026-0123",         // เลขเอกสาร
  party: "ร้านวัสดุ ABC",       // คู่ค้า
  amount: 12500,               // บาท (บวกเสมอ)
  dateConfident: false,        // วันนี้รู้จริง หรือระบบเดาให้
  dateNote: "ร้านนี้ยังไม่ได้ตั้งเครดิต — ใช้ค่าเริ่มต้น 30 วัน",
}
```

จากนั้น `buildDailySeries()` เอามาต่อกันเป็นเงินคงเหลือรายวัน

**กติกาสำคัญ:** รายการที่วันที่ตกก่อนวันเริ่มดู จะถูก *ทบเข้ายอดตั้งต้น* (ไม่ทิ้ง) เพราะของค้างเก่ายังต้องรับ/ต้องจ่ายอยู่ดี

## ระดับความมั่นใจ

| ระดับ | หมายความว่า | ตัวอย่าง |
|---|---|---|
| `actual` แน่นอน | ยืนยันวันและยอดแล้ว | งวดผ่อนตามตารางผ่อน · รอบเงินเดือนที่อนุมัติแล้ว |
| `expected` คาดว่าจะ | มีเอกสารจริงรออยู่ แต่วันอาจเลื่อน | ใบวางบิล · ใบซื้อค้างจ่าย · บิลจีนรอโอน |
| `estimate` ประมาณการ | ระบบเดาให้ ยังไม่มีเอกสาร | เงินเดือนเดือนหน้าที่ยังไม่ได้ทำรอบ · ดอกเบี้ย OD |

## แหล่งข้อมูล (อ่านอย่างเดียว — ไม่แก้ของเดิม)

| แหล่ง | ตาราง | วันที่เอามาจาก | ยอดเอามาจาก |
|---|---|---|---|
| 🧾 คำสั่งขาย | `erp_playground_sales_orders` | วันที่ขาย + เครดิตลูกค้า (`partners_v2.payment_terms_days`) | `amount_due` (ตัดใบรับชำระแล้ว) |
| 📑 ใบวางบิล | `erp_playground_billing_notes` | `due_date` | `amount_due` (ตัดใบรับชำระแล้ว) |
| 🛒 จัดซื้อ | `purchase_orders_v2` | `payment_due_date` → เครดิตร้าน → ค่าเริ่มต้น | `grand_total` (แปลงหยวนแล้ว) − `paid_amount_thb` |
| 👥 เงินเดือน | `payment_batches` + `payment_batch_lines` | `payment_date` | รวม `paid_amount` ของรอบนั้น |
| 🏦 เงินกู้ | `loan_installments` (เฉพาะ schedule version ที่ `active`) | `due_date` | `total_due − total_paid` |
| 📈 ดอกเบี้ย OD | `od_facilities` | สิ้นเดือนทุกเดือน | `estimated_interest_this_month` |
| 🇨🇳 เงินจีน | `china_bills` (ยังไม่ "โอนแล้ว") | `transfer_date` → `bill_date` | `amount_thb` หรือ (`amount_rmb` + `fee_rmb`) × เรต |
| 📌 รายการประจำ | `cashflow_manual_items` | ทุกเดือนวันที่ N / สิ้นเดือน / ครั้งเดียว | `amount` (เข้าหรือออกก็ได้) |

### กันนับซ้ำ

ใบขายที่ถูกดึงไปอยู่ในใบวางบิลแล้ว (`erp_playground_billing_note_lines.so_id`) จะ**ไม่**ถูกนับซ้ำ — นับที่ใบวางบิลอย่างเดียว

## ⚠️ กับดักจากข้อมูลจริง (ตรวจเมื่อ 2026-08-20)

สิ่งเหล่านี้เป็นเหตุผลว่าทำไมโค้ดถึงเขียนแบบนี้ — **อย่าลบทิ้งโดยไม่ตรวจข้อมูลก่อน**

1. **ใบซื้อเป็นเงินหยวน 77 จาก 143 ใบ และสะกด 2 แบบ (`RMB` กับ `YUAN`)**
   `purchase_orders_v2` ไม่มีช่องอัตราแลกเปลี่ยน → ต้องคูณเรตเองในโค้ด (`RMB_CODES`)
   ถ้าไม่คูณ ยอดค้างจ่ายจะหายไปกว่าครึ่ง (306,000 บาท เหลือแค่ 62,000)
   เรตดึงจาก `china_bills.rate` ใบล่าสุด · ผู้ใช้กรอกทับได้ในหน้า ⚙️ ตั้งค่า

2. **แทบไม่มีใครตั้งเครดิต** — ลูกค้า 1/125 ราย · ร้านค้า 2/80 ราย · `payment_due_date` ว่าง 143/143 ใบ
   → ระบบต้องเดาวันด้วยค่าเริ่มต้น และต้องบอกผู้ใช้ว่าเดา (เครื่องหมาย `~` หลังวันที่)

3. ~~ยังไม่มีที่บันทึก "ลูกค้าจ่ายเงินมาแล้ว"~~ **แก้แล้วในเฟส 2** — ใช้หน้า `/receipts`
   `amount_due` ของใบขาย/ใบวางบิลถูกคำนวณใหม่จากใบรับชำระทุกครั้ง
   ⚠️ ยังต้องมีคนไปบันทึกย้อนหลังก่อน ตัวเลขถึงจะตรง (ระบบเตือนให้ถ้ายังไม่มีใบรับชำระเลย)

4. **งวดผ่อนเงินกู้ค้างสถานะ** — `loan_payment_allocations` ว่าง 0 แถว ทั้งที่มี `loan_payments` 38 รายการ
   สาเหตุ: การจ่ายพวกนี้เข้าฐานข้อมูลมาโดยไม่ผ่าน `/api/loan-payment/record` (ตัวที่เรียกตัดยอดให้อัตโนมัติ)
   → เฟส 2 เพิ่มปุ่ม **"ตัดยอดให้ตรง"** บนหน้า /cashflow ที่เรียก `loan_contract_reallocate`
   ฟังก์ชันนี้ล้างแล้วสร้างใหม่จากต้นทาง → กดกี่รอบผลเท่าเดิม ไม่ตัดซ้ำ

5. **รอบเงินเดือนอนุมัติแล้วแต่ไม่ได้กด "จ่ายแล้ว"** — ย้อนไปถึง มิ.ย. 2026
   → นับเป็นเงินที่ยังต้องจ่าย ทำให้ยอดออกสูงเกินจริง

ทุกข้อข้างบนจะขึ้นเป็นป้ายเตือนสีเหลืองบนหน้าเว็บพร้อมลิงก์ "ไปแก้"
**อย่าซ่อนป้ายเตือน** — มันคือสิ่งที่กันไม่ให้คนเอาตัวเลขผิดไปตัดสินใจ

## 📌 รายจ่าย/รายรับประจำ — ตาราง `cashflow_manual_items`

ค่าใช้จ่ายที่ไม่มีใบเอกสารในระบบ: ค่าเช่า · ค่าน้ำค่าไฟ · อินเทอร์เน็ต · ภาษี · ประกันสังคม · ค่าบริการรายเดือน

ถ้าไม่ใส่ **ยอด "เงินออก" จะต่ำกว่าความจริงทุกเดือน** — หน้าเว็บจะขึ้นป้ายเตือนถ้ายังไม่มีรายการเลย

| ช่อง | ความหมาย |
|---|---|
| `repeat_kind` | `monthly` = ทุกเดือน · `once` = ครั้งเดียว |
| `day_of_month` | วันที่ของเดือน 1–31 · **`0` = สิ้นเดือน** · เดือนที่สั้นกว่าเลื่อนมาวันสุดท้ายให้เอง (ตั้ง 31 ใน ก.พ. ได้ 28/29) |
| `once_date` | วันที่ของรายการครั้งเดียว |
| `start_date` / `end_date` | ช่วงอายุของรายการรายเดือน (ว่าง = ไม่จำกัด) เช่น สัญญาเช่าหมดปีหน้า |

จัดการที่ `/cashflow` → ⚙️ ตั้งค่า (อยู่ที่เดียวกับยอดเงินตั้งต้น)

**ล็อกไม่ให้ลากบนกระดาน** เพราะการลากจะกลายเป็นแก้ "รอบ" ทั้งชุดโดยไม่ตั้งใจ — ต้องไปแก้ที่ตั้งค่า

## 🧲 กระดานเงินสด — `/cashflow/board`

มุมมองที่สองของข้อมูลชุดเดียวกัน (ใช้ `/api/cashflow` ตัวเดิม ไม่มีสูตรซ้ำ)
ตอบคำถามที่ตารางตอบไม่ได้: **"ถ้าเลื่อนจ่ายใบนี้ไปอีกอาทิตย์ เงินจะรอดไหม"**

| ส่วนประกอบ | ทำอะไร |
|---|---|
| คอลัมน์ = 1 วัน | วันที่มีรายการกว้าง 210px · วันว่างหุบเหลือ 26px (ดู 6 เดือนได้ในจอเดียว) · ตอนลากการ์ด วันว่างขยายเป็น 76px ให้วางง่าย |
| การ์ด = 1 เอกสาร | ลากไปวันอื่น = ลองเลื่อน · ยังไม่บันทึกจนกว่าจะกดยืนยัน |
| เส้นน้ำเงิน | เงินคงเหลือ — วาดจากความกว้างคอลัมน์จริงหลัง layout (คอลัมน์กว้างไม่เท่ากัน วัดเอาอย่างเดียว) |
| ช่องแดง | วันที่เงินติดลบ |
| เลือกหลายใบ | คลิกการ์ดเพื่อเลือก · ปุ่ม "เลือกทั้งวัน" ที่หัวคอลัมน์ · ลากใบไหนก็ได้ ทั้งชุดย้ายตาม |
| 🗂 รวมตามร้าน | ปุ่มสลับ — รวมการ์ดของร้านเดียวกันในวันเดียวกันเป็นกองเดียว ลากทั้งกองได้ กดกางดูรายใบได้ |
| 📝 โน้ตแปะวัน | `cashflow_board_notes` 4 สี — จดเรื่องที่ไม่ใช่ตัวเลข เช่น "คุยกับร้านแล้ว เลื่อนได้อีก 2 อาทิตย์" · กด ＋ ที่หัวคอลัมน์ |

### ตัวชี้วัดที่ใช้วัดผลการเลื่อน

ใช้ **"จำนวนวันที่เงินติดลบ"** เป็นตัวหลัก ไม่ใช่ "ยอดต่ำสุด"
เพราะยอดต่ำสุดมักตกที่ปลายช่วง การเลื่อนใบเดียวจึงไม่ทำให้ตัวเลขขยับ ดูเหมือนไม่มีผลทั้งที่ช่วยจริง
(ทดสอบกับข้อมูลจริง: เลื่อนใบซื้อ ฿84,000 จาก 12 → 22 ก.ย. ทำให้วันติดลบลดจาก 42 เหลือ 37 วัน แต่ยอดต่ำสุดเท่าเดิม)
