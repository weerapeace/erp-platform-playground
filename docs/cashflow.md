### ทุกแถวในแท็บต้องจ่าย "มีข้อมูล + อัปเดตได้ในที่" (2026-11-04 · ไม่แตะโครงฐานข้อมูล · ทยอยส่งทีละชนิด)

เจ้าของ: "รายการตรงนี้ต้อง update ได้ทั้งหมด และมีข้อมูลด้วย"

- **ของกลาง:** `CashflowEvent` มีช่องใหม่ `details` (รายละเอียดโชว์ใต้แถว label/value/kind คิดที่เซิร์ฟเวอร์) · `updatedAt` (ต้นทางแก้ล่าสุด) · `raw` (ตัวเลขที่ปุ่มต้องใช้) · `staleReason()` ใน lib/cashflow = ป้าย **"ข้อมูลเก่า"** เมื่อเลยกำหนดเกิน 30 วัน หรือไม่ได้แก้เกิน 45 วัน (ประมาณการไม่ขึ้น) — ขึ้นทุกแถวรวม PO
- ปุ่มแก้ทะเบียนหนี้ใช้สิทธิ์ `loan_contracts.edit` (ชุดเดียวกับแท็บหนี้ & วงเงิน) · "แก้ข้อมูล" = เปิด `MasterRecordDrawer` ของโมดูลนั้นในหน้าเลย

| ชนิด | โชว์อะไร | ปุ่ม |
|---|---|---|
| **บัตร / หนี้อื่น** (debt_cards) | วงเงิน · ยอดตามใบแจ้งยอด · ขั้นต่ำ · วันที่ใบแจ้งยอด · ครบกำหนด · จ่ายแล้ว · จ่ายล่าสุด · อัปเดตล่าสุด | **จ่ายแล้ว** (เต็มยอด / ขั้นต่ำ / ระบุเอง + วันที่ + สลิปไฟล์แนบกลาง entity `debt_cards`) → `POST /api/debt-cards/[id]/pay` บวกจ่ายสะสม สถานะ partial/paid · **ใบแจ้งยอดใหม่** → `POST /api/debt-cards/[id]/statement` เขียนใบใหม่ จ่ายเริ่ม 0 ใบเดิม + ติ๊ก "ใบเดิมจ่ายครบแล้ว" เก็บใน audit `metadata.previous` · **แก้ข้อมูลบัตร** = drawer debt-cards · กติกาตัวเลข `lib/debt-cards` (มีเทสต์) · กันกดซ้อนด้วยเช็กยอดจ่ายเดิมตอนเขียน (409) |

- ข้อมูลจริง 11-04: บัตร 4 ใบ ใบแจ้งยอด เม.ย.–พ.ค. 2026 จ่าย 0 ทุกใบ → ขึ้น "เลยกำหนด 150+ วัน" + ข้อมูลเก่า = ข้อมูลไม่ได้อัปเดต ไม่ใช่บั๊ก
- แก้กับดัก `.neq("status","paid")` ของบัตร (ตัดแถว status ว่างทิ้ง) → `.or("status.is.null,status.neq.paid")`

- **ยังไม่ทำ (เฟส 3 ต้องสร้างตาราง — ขออนุญาตก่อน):** สมุดบัญชีธนาคาร + ใบจ่ายเงินกลาง → "จ่ายแล้ว" / "รับเงินแล้ว" จะปรับยอดเงินในบัญชีจริง

## ใช้ทำอะไร

| อยากรู้ | หน้านี้ตอบให้ |
|---|---|
| เดือนหน้าต้องจ่ายเท่าไหร่ | รวมใบซื้อ + เงินเดือน + งวดผ่อน + ดอกเบี้ย OD + เงินจีน |
| เงินจะเข้าเมื่อไหร่ | ใบวางบิล (วันครบกำหนดจริง) + ใบขายยืนยันแล้ว (คาดจากเครดิตลูกค้า) |
| เงินจะขาดวันไหน | แถบแดง 🚨 บอกวันแรกที่เงินคงเหลือติดลบ |
| ค้างรับ/ค้างจ่ายสะสมเท่าไหร่ | แถบ "ของค้างจากก่อนวันนี้" |

## ไม่ควรใช้ทำอะไร

- **ไม่ใช่งบการเงิน** — ไม่ได้ทำตามมาตรฐานบัญชี ใช้บริหารเงินสดเท่านั้น
- **ไม่ใช่ยอดเงินจริงในธนาคาร** — ระบบยังไม่ได้ต่อ API ธนาคาร ยอดตั้งต้นมาจากที่คนกรอกเอง
- **ไม่ใช้ตัดสินใจกู้เงิน/ลงทุนก้อนใหญ่โดยไม่ตรวจซ้ำ** — ตราบใดที่ยังมีป้ายเตือน ⚠️ ค้างอยู่บนหน้า

ไม่ว่าจะมาจากโมดูลไหน ทุกอย่างถูกแปลงเป็น `CashflowEvent` หน้าตาเดียวกัน:

```ts
{
  date: "2026-09-15",          // วันที่เงินเข้า/ออก
  direction: "out",            // in = เข้า, out = ออก
  source: "purchase_order",    // มาจากไหน
  certainty: "expected",       // มั่นใจแค่ไหน
  ref: "PO-2026-0123",         // เลขเอกสาร
  party: "ร้านวัสดุ ABC",       // คู่ค้า
  amount: 12500,               // บาท (บวกเสมอ)
  dateConfident: false,        // วันนี้รู้จริง หรือระบบเดาให้
  dateNote: "ร้านนี้ยังไม่ได้ตั้งเครดิต — ใช้ค่าเริ่มต้น 30 วัน",
}
```

จากนั้น `buildDailySeries()` เอามาต่อกันเป็นเงินคงเหลือรายวัน

**กติกาสำคัญ:** รายการที่วันที่ตกก่อนวันเริ่มดู จะถูก *ทบเข้ายอดตั้งต้น* (ไม่ทิ้ง) เพราะของค้างเก่ายังต้องรับ/ต้องจ่ายอยู่ดี

## ระดับความมั่นใจ

| ระดับ | หมายความว่า | ตัวอย่าง |
|---|---|---|
| `actual` ยืนยันแล้ว (เดิม "แน่นอน") | ยืนยันวันและยอดแล้ว | งวดผ่อนตามตารางผ่อน · รอบเงินเดือนที่อนุมัติแล้ว |
| `expected` วันอาจเลื่อน (เดิม "คาดว่าจะ") | มีเอกสารจริงรออยู่ แต่วันอาจเลื่อน | ใบวางบิล · ใบซื้อค้างจ่าย · บิลจีนรอโอน |
| `estimate` ประมาณการ | ระบบเดาให้ ยังไม่มีเอกสาร | เงินเดือนเดือนหน้าที่ยังไม่ได้ทำรอบ · ดอกเบี้ย OD |

## 📌 รายจ่าย/รายรับประจำ — ตาราง `cashflow_manual_items`

ค่าใช้จ่ายที่ไม่มีใบเอกสารในระบบ: ค่าเช่า · ค่าน้ำค่าไฟ · อินเทอร์เน็ต · ภาษี · ประกันสังคม · ค่าบริการรายเดือน

ถ้าไม่ใส่ **ยอด "เงินออก" จะต่ำกว่าความจริงทุกเดือน** — หน้าเว็บจะขึ้นป้ายเตือนถ้ายังไม่มีรายการเลย

| ช่อง | ความหมาย |
|---|---|
| `repeat_kind` | `monthly` = ทุกเดือน · `once` = ครั้งเดียว |
| `day_of_month` | วันที่ของเดือน 1–31 · **`0` = สิ้นเดือน** · เดือนที่สั้นกว่าเลื่อนมาวันสุดท้ายให้เอง (ตั้ง 31 ใน ก.พ. ได้ 28/29) |
| `once_date` | วันที่ของรายการครั้งเดียว |
| `start_date` / `end_date` | ช่วงอายุของรายการรายเดือน (ว่าง = ไม่จำกัด) เช่น สัญญาเช่าหมดปีหน้า |

จัดการที่ `/cashflow` → ⚙️ ตั้งค่า (อยู่ที่เดียวกับยอดเงินตั้งต้น)

**ล็อกไม่ให้ลากบนกระดาน** เพราะการลากจะกลายเป็นแก้ "รอบ" ทั้งชุดโดยไม่ตั้งใจ — ต้องไปแก้ที่ตั้งค่า

### เปลี่ยนบริษัทของรายการ (เฟส 2)

- ตาราง `/cashflow` → ติ๊กหลายรายการ → **"แก้หลายรายการ"** → ช่องบริษัท (ตารางกลาง มีหน้าดูก่อนบันทึกให้)
- กระดาน → กดการ์ด → ช่อง "บริษัท" ในป๊อป (บันทึกทันที ไม่ทิ้งการ์ดที่ลองลากไว้)
- ใบสั่งซื้อ → ป๊อปใบสั่งซื้อ ✎ แก้ไข / ฟอร์มสร้างใบสั่งซื้อเอง มีช่อง "ใบซื้อของบริษัท"
- API `POST /api/cashflow/assign-company` (สิทธิ์ `cashflow.manage`) · ทะเบียน `COMPANY_ASSIGNABLE` ใน lib/cashflow:
  ใบซื้อ · บิลจีน · เงินกู้ (งวดผ่อน → เปลี่ยนทั้งสัญญา) · OD · บัตร — audit ทุกใบ (บริษัทเดิม → ใหม่)
- **เปลี่ยนจากหน้านี้ไม่ได้:** ใบขาย (บริษัท = หัวบิล/เลขใบกำกับ ต้องแก้ที่หน้าใบขาย) · ใบวางบิล (ตามใบขาย) · เงินเดือน (ตามงวด) · รายการประจำ (⚙️ ตั้งค่า)
- migration: `supabase/migrations/202610212000_company_on_purchase_docs.sql`

### กติกาที่ห้ามเปลี่ยน

- **ไม่รู้บริษัท = "ยังไม่ระบุ" ห้ามเดาเป็นบริษัทตั้งต้น** — ไม่งั้นยอดของ ISG เกินจริงแบบไม่มีใครรู้ตัว
- ดูทีละบริษัทแล้วมีของ "ยังไม่ระบุ" → **ต้องขึ้นแถบเตือนเสมอ** พร้อมบอกว่าแต่ละแบบไปตั้งได้ที่ไหน
- บัญชีที่ไม่ระบุบริษัท นับเฉพาะตอนดูทั้งกลุ่ม / ยังไม่ระบุ
- บริษัทที่ถูกปิดใช้งานแต่ยังมีเงินค้าง ยังโผล่เป็นปุ่ม (ไม่งั้นรายการหายจากทุกมุมมอง)
