# คิดผ้าก่อนซื้อ (หน้า คำนวณผ้า › แท็บแรก) — เฟส 1 + 2

หน้า `/fabric-calc` (แอป "งานอื่นๆ") · เจ้าของสั่ง 2026-11-13 ("คำนวณผ้าก่อนซื้อว่าใช้เท่าไหร่ แนะนำที่จำเป็นให้เลือกแบบละเอียด") · เลือกแบบจาก widget ทั้ง 2 เฟส · บันทึกผลได้ (เฟส 2)

## ใช้ทำอะไร / ต่างจากหน้าอื่นยังไง
| หน้า | ใช้ตอนไหน | วิธีคิด |
|---|---|---|
| `/fabric-calc` แท็บ **คิดผ้าก่อนซื้อ** (ใหม่) | ยังไม่มีใบสั่งผลิต · จะสั่งซื้อผ้า | วางชิ้นบนผ้าจริง + หักริม/เผื่อ/ปัดม้วน/ราคา/สต็อก |
| `/fabric-calc` แท็บ **สูตร BOM (แบบเดิม)** | คิดเร็ววัตถุดิบทุกชนิด | สูตร BOM (พื้นที่ ÷ หน้ากว้าง ฯลฯ — `lib/bom-calc`) |
| `/master/fabric-plan` | มีใบสั่งผลิตแล้ว (ตัดรวมหลายใบ) | วางชิ้นจริงจาก `lay_layout` ของใบ — `docs/fabric-plan.md` |

## ตัวเลือก (ค่าเริ่ม)
- **ชิ้นตัด** (จำเป็น): พิมพ์เอง หรือ "ดึงจากสูตร BOM" = เลือก SKU (SkuPicker) → สูตรของ SKU นั้น (`/api/bom?search=` แล้วกรอง product_sku ตรงเป๊ะ · หลายสูตรให้เลือก) → เลือกผ้าในสูตร → ได้ชิ้นตัด (cut_width × cut_length × pieces · ห้ามหมุนตามบรรทัด) + เลือกผ้าให้อัตโนมัติ · บรรทัดแยกไซส์ใช้ขนาดตั้งต้น
- **จำนวนผลิต** (100) · **ผ้า** (ComponentPicker — ได้หน้ากว้าง/ขนาดผืน/ราคาต้นทุน standard_price/หน่วย/สต็อก · ไม่เลือกก็ได้) · ⚠️ หน่วย SKU เทียบไม่ได้ (cm² 96 ตัว · kg) = ไม่หักสต็อก ไม่เติมราคา (unitComparable)
- หน้ากว้างเต็ม (150) · **หักริม รวม 2 ข้าง (3 ซม.)** · ม้วน/ผืน (ผืน = ใส่ผืนยาว · เลือกผ้าแบบผืนแล้วหักริมเป็น 0) · ทางผ้า หมุนได้/ห้ามหมุน (+ห้ามหมุนรายชิ้น) · หดตัว % (0 — ขยายชิ้นทั้งกว้าง/ยาว)
- เว้นระหว่างชิ้น (0 = ตรงกับใบสั่งผลิต) · **เผื่อเสีย 3%** (ไม่ใช่ 15% เดิม — เจ้าของเคยบอกว่าผ้าเหลือเยอะ) · ซื้อเป็น หลา/เมตร (เปลี่ยนหน่วยแล้วแปลงราคา/ความยาวม้วนให้) · ปัดขึ้น หน่วยเต็ม/ม้วนเต็ม/ไม่ปัด · 1 ม้วนยาว (50 หลา) · ราคา/หน่วย
- **เทียบหน้ากว้าง**: ปุ่มลัด 110/137/147/150/160 + ใส่เอง (หน้า + ราคา) → ตัวถูกสุด (มีราคาครบ) หรือใช้น้อยสุด

## ผล
ต้องใช้ (รวมเผื่อเสีย) · ควรซื้อ (ปัดแล้ว + กี่ม้วน) · ต้องซื้อเพิ่ม (หักสต็อก — สต็อกหลา↔เมตรแปลงให้) · งบซื้อเพิ่ม + ค่าผ้าต่อใบ · ใช้ผ้าคุ้ม % · เทียบวิธีเดิม (พื้นที่ ÷ หน้ากว้าง) · "ทำไมเหลือเศษ" (fitHints — แนะนำหน้ากว้างที่ลงตัว บวกริมแล้ว) · ผังการวาง (FabricLayoutPreview)

- **สรุปเห็นตลอด**: จอกว้าง/iPad แนวนอน = กล่องขวา (ควรซื้อ · ต้องซื้อเพิ่ม · งบ · ใช้ผ้าคุ้ม % · สถานะวัดจริง) · จอแคบ/iPad แนวตั้ง/มือถือ = แถบล่างจอ (`usePageOwnsBottomBar`)
- **ขั้น ② แบ่ง 3 ระดับ** กันตาลาย: กล่องหลักกรอบม่วง (จำนวนผลิต · ผ้า · ม้วน/ผืน · หน้ากว้าง) → กลุ่มพื้นเทา "การตัด" / "การซื้อ" (ยุบได้ ยุบแล้วโชว์ชิปสรุป) → "ขั้นสูง" เส้นประ ยุบไว้ (เผื่อเสีย · หด · ลายซ้ำ · เว้น — เปิดเองถ้าค่าไม่ใช่ค่าเริ่ม) · ตัวเลือก 2-3 ทางเป็นปุ่ม (`Seg`) แทน select · ช่องตัวเลขขึ้นแป้นตัวเลข (`inputMode="decimal"`)
- **ผังวางแนวตั้ง** (`FabricLayoutPreview` ของกลาง — ใช้ทุกที่): ผ้าทั้งม้วนเป็นแถบยาวเดียวในกล่องสูง 520px · นิ้วปัด/เมาส์กดลาก/ล้อเมาส์ · แถบเล็กขวา = ตำแหน่ง แตะเพื่อกระโดด · "ช่วง a–b ซม. จาก N" · เลิกแบ่งหน้า ‹ › · แก้บั๊กป้ายชื่อ: regex `SIZE_ONLY` เดิมหลุด backslash → ชื่อชิ้นทุกชื่อถูกมองเป็น "ขนาดล้วน" ไม่ได้ (ตอนนี้ "ชิ้นหน้า" + "40×55" ขึ้นครบ)
- **ชื่อชิ้นมีรายการประจำ**: ใช้ของกลางเดิม `FreeTextPicker` (kind=`cut_piece` · ตาราง `free_text_names`) — ไม่สร้างตารางใหม่ (ค้นทะเบียนแล้วเจอตัวที่ทำงานนี้อยู่) · ใส่ตั้งต้น 8 ชื่อ: ชิ้นหน้า ชิ้นหลัง ชิ้นตัว ก้น ผนังข้าง ซับใน ซิปปาก สาย · ใช้ที่ตารางชิ้น (หน้านี้) + สูตร BOM (คอลัมน์ + แผงรายละเอียด) · เพิ่มได้ทุกคน · แก้ชื่อ/เอาออก = สิทธิ์ products.edit · ชื่อเก็บเป็นข้อความในแถว (แก้รายการไม่กระทบสูตรเดิม) · ใช้บ่อยลอยขึ้นบน
  - อัปเกรด `FreeTextPicker`: รายการลอยผ่าน `FloatingDropdown` (ไม่โดนตารางตัดขอบ) · `inputClassName` · `title` · เปิดมาเห็นทุกชื่อ (กรองเมื่อพิมพ์) · ไอคอนเส้นแทนอีโมจิ · ลบถามด้วย `ConfirmDialog` · ลงทะเบียน `free-text-picker` แล้ว
- ยังไม่ทำ: โหมดทั้งตระกูลยังเป็นหน้าเดียวยาว (ไม่แบ่งขั้น)
