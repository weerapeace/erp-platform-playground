# 🏷 โปรโมชันอัตโนมัติ + ⚡ Flash sale + 🛍 ซื้อคู่กันบ่อย (เว็บร้าน · ชุด 3)

ตั้งที่ ERP › เว็บไซต์ › แท็บ **🏷 โปรโมชัน** — ลูกค้าไม่ต้องใส่โค้ด ตะกร้าลดให้เอง

## ชนิดโปร

| ชนิด | ตัวอย่าง | วิธีคิด |
|---|---|---|
| ⚡ Flash sale | 11.11 ลด 20% (ต้องมีเวลาจบ) | ลด % ต่อชิ้นของรุ่น/หมวดที่ร่วม · เว็บโชว์ราคาลด + ราคาเดิมขีดฆ่า + นับถอยหลัง ทั้งการ์ดและหน้าสินค้า |
| ซื้อครบ N ชิ้น ลด % | ซื้อ 2 ชิ้นขึ้นไป ลด 10% | นับรวมทุกรุ่นที่ร่วม |
| ซื้อ X แถม Y | ซื้อ 2 แถม 1 | เรียงชิ้นแพง→ถูก ทุก X+Y ชิ้น ชิ้นที่ถูกสุด Y ชิ้นลด (100% = ฟรี) |
| ยอดครบขั้นบันได | ครบ ฿1,500 ลด ฿100 · ครบ ฿3,000 ลด 10% | ใช้ขั้นสูงสุดที่ถึง |
| ซื้อเป็นเซ็ต | กระเป๋า X + เข็มขัด Y ลด ฿200 | ต้องมีครบทุกรุ่น · ลดต่อเซ็ต |

**วิธีรวม:** ⚡ ลดต่อชิ้นก่อน (ซ้อนได้) → โปรตะกร้า 4 ชนิดที่เหลือใช้ **ตัวที่ลดได้มากสุด 1 ตัว** → คูปองคิดต่อจากยอดหลังโปร (โปรที่ติ๊ก "ใช้คู่โค้ดไม่ได้" = ไม่รับโค้ด)

**ขอบเขต:** ทุกสินค้า / เลือกรุ่น (รหัสสีแดง = ไม่พบบนเว็บร้านนี้) / ตามหมวดเว็บ (รวมหมวดแม่ + กฎแท็ก แบบเดียวกับหน้าเว็บ)

**ช่วงเวลา:** เริ่ม–จบ เวลาไทย 24 ชม. · ยังไม่เริ่ม = เว็บยังไม่โชว์ · หมดเวลา = หายเอง

## ลูกค้าเห็นอะไร

- การ์ด/หน้าสินค้า: ⚡ ราคาลด + นับถอยหลัง · ป้ายโปร (เช่น "ซื้อ 2 ชิ้น ลด 10%")
- ตะกร้า/หน้าชำระเงิน: บรรทัดโปรแต่ละตัว + ยอดหลังลด · ชวนซื้อเพิ่ม ("เพิ่มอีก 1 ชิ้น — ซื้อ 2 ชิ้น ลด 10%" · "ซื้อเพิ่มอีก ฿310 ลด ฿100")
- หน้าขอบคุณ/ตามออเดอร์/อีเมล: แยกบรรทัดโปรกับคูปอง

## ออเดอร์ (ERP)

- ส่วนลดคิดใหม่ที่ ERP ตอนรับออเดอร์เสมอ (`createStorefrontOrder` · ไม่เชื่อยอดจากหน้าเว็บ)
- `store_orders.discount` = โปร + คูปอง (รายงานยอดขาย/แต้มอ่านช่องเดิม) · `store_orders.promos` = รายการโปร [{id,name,kind,amount}]
- แท็บ 🧾 ออเดอร์ โชว์บรรทัด 🏷 แยก · แท็บ 🏷 โชว์ว่าแต่ละโปรใช้ไปกี่ออเดอร์/ลดไปเท่าไร (90 วัน)
- เข็มขัดสั่งทำ (Belt Builder) ไม่ร่วมโปร

## 🛍 ซื้อคู่กันบ่อย (หน้าสินค้า)

- ERP คิดจากออเดอร์จริง 2,000 ใบล่าสุด: รุ่นที่อยู่ในออเดอร์เดียวกันบ่อยสุด 3 อันดับ (products API `boughtWith`)
- ติ๊กเลือก → "ใส่ตะกร้าทั้ง N ชิ้น" · ถ้ามีโปรที่เข้าเงื่อนไข โชว์ยอดหลังลด/ประหยัด
- รุ่นที่ต้องเลือกไซส์ก่อน ไม่อยู่ในกล่องนี้ · ยังไม่มีออเดอร์คู่กัน = ไม่โชว์

## 📦 สั่งจอง (พรีออเดอร์) + มัดจำ (ชุด 3b)

ตั้งที่ ERP › ข้อมูลร้าน › กลุ่ม **📦 สั่งจอง + มัดจำ** (ค่าเริ่ม ปิด) — ใช้กับสินค้าที่ตั้งสถานะสต็อก "พรีออเดอร์" ในแท็บสินค้าบนเว็บ

- ออเดอร์ที่มีของพรีออเดอร์ → มัดจำ = % ของยอดรวม (10–90 · อย่างน้อย ฿1) · **ต้องโอนพร้อมเพย์** (เก็บปลายทางถูกซ่อน · ERP ไม่รับถ้าส่งมา)
- สถานะชำระ: ยังไม่ชำระ → (สลิปมัดจำผ่าน) **มัดจำแล้ว · รอยอดที่เหลือ** → (สลิปยอดที่เหลือผ่าน) ชำระแล้ว
- QR พร้อมเพย์/ระบบตรวจสลิปใช้ "ยอดที่ต้องโอนรอบนี้" (`amountDue`) · หน้าตามออเดอร์โชว์ QR ยอดที่เหลือเมื่อมัดจำแล้ว
- ออเดอร์มัดจำแล้วยังไม่นับว่า "พร้อมแพ็ก" จนกว่าจะชำระครบ · อีเมลยืนยันบอกยอดมัดจำ + ยอดที่เหลือ
- `store_orders.deposit_amount` (migration 202610291500) · กฎ `depositFor / amountDue / paidNext` ใน lib/website-orders.ts (มีเทสต์)
