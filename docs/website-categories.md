# 📂 หมวดหมู่สินค้าบนเว็บ (ต่อร้าน)

## ใช้ทำอะไร
- จัดหมวดของเว็บร้าน (แยกจากหมวดใน ERP) — ชื่อ · คำอธิบาย · **รูปหมวด** · **แบนเนอร์หน้าหมวด** · ลำดับ
- จัดสินค้าลงหมวด — **1 รุ่นอยู่ได้หลายหมวด** (หมวดแรก = หมวดหลัก ใช้เป็นป้ายบนการ์ด)
- หน้าแรกโชว์หมวดได้ 4 แบบ (Section "หมวดสินค้า")

## ใช้ที่ไหน (ERP)
- `/website/<ร้าน>` → แท็บ **📂 หมวดหมู่** (`components/website-categories-panel.tsx`)
  - ซ้าย: รายการหมวด (ลากเรียง · ➕ เพิ่มหมวด) · ขวา: แก้หมวด + สินค้าในหมวด (➕ เพิ่มทีละหลายรุ่น · ✕ เอาออก)
  - รายการหมวดบันทึกเองหลังหยุดแก้ 0.7 วิ · สินค้า↔หมวด บันทึกทันที
  - รหัสหมวด (ใช้ในลิงก์ `/shop?cat=`) ตั้งตอนสร้างแล้วเปลี่ยนไม่ได้ — กันลิงก์/เมนูเดิมเสีย
  - ลบหมวด = ConfirmDialog → เอาหมวดนี้ออกจากสินค้าทุกตัว (สินค้ายังอยู่บนเว็บ)
- แท็บ "สินค้าบนเว็บ": ช่อง "หมวดบนเว็บ" เป็นชิปเลือกหลายหมวด (★ = หมวดหลัก)
- แท็บ "⚙️ จับคู่ฟิลด์" ยังแก้รายการหมวด/กฎจับหมวดจากหมวด ERP ได้เหมือนเดิม (กฎใช้กับสินค้าที่ยังไม่เคยจัดเอง)

## ข้อมูล
| ที่เก็บ | ช่อง | ความหมาย |
|---|---|---|
| `shops.field_map.categories[]` | `key label icon blurb imageKey bannerKey` | รายการหมวดของร้าน (เรียงตามนี้) |
| `store_listings.web_categories` (text[]) | | **null** = ยังไม่เคยจัด → หมวดเดียวแบบเดิม (`web_category` กรอกทับ / กฎจับหมวด ERP / หมวดตั้งต้น) · **array** (รวมว่าง) = จัดเองแล้ว ใช้ตามนี้ · ตัวแรก = หมวดหลัก |

- คำนวณที่ `resolveCategories()` (`lib/website-field-map.ts`) — รหัสที่ไม่มีในรายการหมวดแล้วถูกข้าม
- API: `POST /api/website/listings` `{ action: "setCategories", shopId, category, items: [{ parentId, categories }] }` (guardApi `products.edit` + audit 1 แถวต่อครั้ง)
- API สาธารณะ products ส่ง `category` (หลัก) + `categories` (ทั้งหมด) · site ส่ง `categories` (รวม imageKey/bannerKey)
- migration: `supabase/migrations/202610150100_store_listings_web_categories.sql`

## Section "หมวดสินค้า" (`type: categories`)
| ช่อง | ค่า |
|---|---|
| `layout` | `icon` การ์ดไอคอน (แบบเดิม — บล็อกเก่าไม่เปลี่ยน) · `tile` รูปใหญ่ ชื่อทับรูป · `row` รูปเล็ก+ชื่อ เรียงแถวมีเส้นคั่น · `text` ตัวอักษร |
| `cats` | หมวดที่โชว์ เรียงตามที่เลือก (ช่องชนิด `categories` ใน schema) — ว่าง = ทุกหมวด |
| `columns` `ratio` `textPos` `cta` `tileText` `textStyle` `upper` `showAll` `allText` | ปรับตามแบบ (ดู `SECTION_SCHEMAS.categories`) |

- เว็บร้าน: ตัวแสดงผลกลาง `src/components/home/CategoriesView.tsx` ใช้ทั้งเว็บจริง (`MaterialCategories` ดึงหมวด) และพรีวิวสด (`LiveBlocks` ได้รายการหมวดจากเซิร์ฟเวอร์) → แก้แบบแสดงแล้วเห็นทันที
- ไม่มีรูปหมวด = ใช้ไอคอน · รูปใช้ LoadImg + กรอบรอรูป (sf-ph)
- หน้าร้าน (`ShopClient`): เลือกหมวด → หัวหน้าหมวด (แบนเนอร์ + ชื่อ + คำอธิบาย) + ลิงก์ในแถบที่อยู่เปลี่ยนเป็น `?cat=` · กรองหมวดด้วย `categories` (หลายหมวด)

## ลำดับสินค้าในหมวด
- แท็บหมวดหมู่ → สินค้าในหมวด → ลาก ⠿ เรียง → เก็บที่ `field_map.categories[].order` (รหัสรุ่น) — ตัวที่ไม่อยู่ในรายการต่อท้ายตามลำดับรวม
- หน้าร้าน: เลือกหมวด + เรียง "แนะนำ" + ไม่ได้ค้นหา = เรียงตามนี้ (`sortByCategoryOrder` ใน src/lib/products.ts) · Section ตารางสินค้า (ทั้งหมวด) ก็เรียงตามนี้

## เมนูหมวด
- ชนิดเมนูใหม่ `categories` "📂 หมวดทั้งหมด (อัตโนมัติ)" — ลิงก์ /shop + เมนูย่อย = ทุกหมวด (Navbar เติมเอง · เปิด Mega = โชว์รูปหมวด)
- ร้านที่ยังไม่จัดเมนูเอง (ไม่ใช่ร้าน IG เดิม) + มีหมวด: "สินค้าทั้งหมด" มีเมนูย่อยหมวดให้อัตโนมัติ

## Section หมวดสินค้า: ขนาดรูป
- `imgFit` (รูปใหญ่: เต็มการ์ด/เห็นทั้งรูป) · `imgSize` 40–200 % (การ์ดไอคอน/รูปใหญ่/รูปเล็ก)

## ข้อจำกัดที่รู้แล้ว
- ร้าน IG เดิม: สินค้าที่ไม่มีหมวดตกไป "อะไหล่" เหมือนเดิม · ร้านอื่น = ไม่มีป้ายหมวด
