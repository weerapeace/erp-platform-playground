# ศูนย์ออเดอร์ออนไลน์ (เฟส A) — `/master/platform-orders`

เจ้าของเลือกหน้าตาจาก widget และอนุมัติแผน 2026-11-10 ("Approve, start") — เตรียมระบบแบบ Zort/BigSeller ไว้ก่อน Shopee อนุมัติ
**ยังไม่แตะร้านจริง** — ตัวเชื่อม Shopee (ดึงออเดอร์ / นัดขนส่ง / ใบปะหน้าจริง) อยู่เฟส B

## ใช้ทำอะไร
- ดูออเดอร์จากทุกร้านในที่เดียว: การ์ดกดกรอง **ต้องจัดส่ง · เลยกำหนดส่ง · ต้องส่งวันนี้ · ขอใบกำกับภาษี · ส่งแล้ว · ทั้งหมด**
- ติ๊กหลายใบ → **ใบหยิบรวม · ใบแพ็ก · ใบปะหน้า · แพ็กแล้ว** (แถบคำสั่งหลายรายการ)
- กดแถว → แผงรายละเอียด: เปลี่ยนสถานะตามกติกา · เลขพัสดุ · ออกใบกำกับภาษี
- **โหมดทดลอง** (ปุ่มมุมขวาบน / `?demo=1`): ออเดอร์ตัวอย่างหน้าตาแบบ Shopee ลองได้ทุกปุ่ม **ไม่บันทึกอะไร**

## สองแท็บ
| แท็บ | ออเดอร์ | ทำอะไรได้ |
|---|---|---|
| ต้องจัดการ | ออเดอร์ที่ต้องจัดส่ง (จากตัวเชื่อม API / อัปไฟล์) · ออเดอร์ TikTok / Shopee จาก API = สถานะตามร้าน | ทุกปุ่ม (API: ดูอย่างเดียว + ออกใบกำกับภาษีได้) |
| ยอดขายจากเมล | ออเดอร์ที่ระบบ 📧 อ่านจากอีเมลแจ้งยอดขาย = ร้านส่งของไปแล้วผ่าน Seller Centre · ⚠️ Shopee ของแบรนด์ที่เชื่อม Shopee API แล้ว (Louis Montini · 2026-11-14) ไม่เข้าแท็บนี้อีก — ใบเดิมที่อยู่ในช่วงที่ดึงย้ายไป "ต้องจัดการ" พร้อมสถานะจริง | ดูอย่างเดียว + ออกใบกำกับภาษีได้ |

## กติกา (ของกลาง `lib/platform-order-status.ts` · ทะเบียน workflow key `platform-order`)
- สถานะในระบบ: ต้องจัดส่ง → ยืนยัน (ตัดสต๊อกจาก WH-ONLINE) → แพ็กแล้ว → ส่งแล้ว · ยกเลิกได้ก่อนส่ง (คืนสต๊อกถ้าเคยตัด)
- สถานะบนร้านเก็บแยกที่ `platform_status` (เช่น Shopee READY_TO_SHIP) — แปลงด้วย `shopeeToInternal`
- **ออเดอร์จากเมลเปลี่ยนสถานะ/ตัดสต๊อกไม่ได้** (API ปฏิเสธ) — เดิมกดยืนยันแล้วตัดสต๊อกคลังออนไลน์ติดลบได้
- "ต้องจัดส่ง" ไม่นับออเดอร์ที่ผู้ซื้อยังไม่จ่าย (UNPAID) และ TikTok ON_HOLD (ผู้ซื้อยังยกเลิกได้) · กำหนดส่งนับวันตามเวลาไทย
- **ออเดอร์ TikTok (`source = "tiktok_api"` · ปุ่ม "ดึงออเดอร์ TikTok")** = สถานะตามร้าน (`tiktokToInternal` · `isShopManaged`) — นับงานต้องจัดส่ง แต่เปลี่ยนสถานะ/ตัดสต๊อก/จองขนส่งที่นี่ไม่ได้ · รายละเอียด `docs/tiktok-shop-connector.md`
- **ออเดอร์ Shopee (`source = "shopee_api"` · ดึงเองทุก 15 นาที + ปุ่ม "ดึงออเดอร์ Shopee")** = สถานะตามร้านแบบเดียวกับ TikTok (`shopeeToInternal` · UNPAID ไม่นับต้องจัดส่ง) · เจ้าของเลือก 2026-11-14 "ไม่ต้องดึงจากเมลแล้ว": ใบจากเมลเลขเดียวกันถูกอัปเดตเป็นแหล่งนี้ (รายการสินค้าเดิมคงไว้) และเมลออเดอร์ Shopee ของแบรนด์ที่เชื่อมแล้วถูกข้าม · รายละเอียด `docs/shopee-connector.md`

## งานพิมพ์ (`/print/platform-orders?kind=pick|pack|label&ids=` · ตัวสร้าง `lib/platform-order-print.ts`)
- **ใบหยิบรวม**: รวมรหัสทุกออเดอร์ (ตัวเลือกต่างกัน = คนละบรรทัด) · ตั้งค่าหน้าพิมพ์ด้วยของกลาง ListPrintPanel (แบบสำเร็จรูป "ตัวใหญ่ อ่านง่ายหน้าชั้นวาง")
- **ใบแพ็ก**: ออเดอร์ละใบ 2 ใบ/แผ่น A4 · บาร์โค้ดเลขออเดอร์ · ช่องติ๊กต่อรายการ
- **ใบปะหน้า**: ออเดอร์ช่องทางของร้านเองที่จองขนส่งแล้ว → ใบปะหน้าจากระบบขนส่ง (ขั้น 1 = ใบจำลอง 100×150 มม. ลายน้ำ "จำลอง" ตัวสร้าง `shippingSimLabelsHtml`) · ออเดอร์ Shopee/Lazada/TikTok ต้องใช้ไฟล์ของแพลตฟอร์ม → เฟส B · ออเดอร์ที่ยังไม่จองจะขึ้นกล่องบอกในหน้าพิมพ์

## ใบกำกับภาษี (`/api/platform-orders/invoice`)
- ออก **ผ่านใบขาย** (เลขชุดเดียวกับใบกำกับที่ออกอยู่ เช่น ISG2569-…) → เข้า `/sales/tax-report` เอง · พิมพ์ด้วย `/print/sales-order/<id>`
- ใบขายไม่ใส่คลัง = ไม่จอง/ไม่ตัดสต๊อก (กันตัดซ้ำ) → **ค้างสถานะ "ร่าง" ที่มีเลขแล้ว** (ใบขายที่ไม่มีคลังกดยืนยันไม่ได้ เพราะกติกาใบขายจะจองของ) · รายงานภาษีนับรวมและติดป้าย "ร่าง"
- ต้องตั้ง **บริษัทที่ออกใบกำกับ** ต่อร้านก่อน: 🏪 บัญชีแพลตฟอร์ม › ร้าน › ใบกำกับภาษี (`platform_accounts.tax_invoice_company_id`) — ระบบไม่เดาบริษัท
- ลูกค้า: หาในรายชื่อลูกค้า (`partners_v2`) ด้วยเลขผู้เสียภาษี (+สาขา) ไม่เจอ = สร้างใหม่ (หมายเหตุ "สร้างอัตโนมัติจากคำขอใบกำกับ…")
- ข้อมูลผู้ขอ: ป๊อปเติมจาก `platform_orders.tax_invoice_request` (เฟส B ดึงจาก Shopee `v2.order.get_buyer_invoice_info` — รองรับไทย) · พิมพ์เองได้
- ยอดรายการ ≠ ยอดออเดอร์ (ค่าส่ง/ส่วนลดของร้าน) → เตือน + ช่อง "ค่าส่งที่ผู้ซื้อจ่าย" · ราคาถือว่ารวม VAT 7% แล้ว
- ใบขายที่ผูกไว้ถูกยกเลิก = ออกใหม่ได้
- สิทธิ์: `platform_orders.manage` + สิทธิ์สร้างใบขาย `so.create` (ฐานข้อมูลเช็กเอง)

## จัดส่ง (ขั้น 1 — โหมดจำลอง) · อนุมัติ 2026-11-10 ("Approve phase 1")
แบบ Zort: เทียบราคาขนส่ง → จอง → ใบปะหน้า → สถานะ — ผ่าน SHIPPOP (`lib/shippop.ts` ตัวเดียวกับเว็บร้าน) · กติกาอยู่ `lib/order-shipping.ts`
- **โหมด (เฟส 1 · 2026-11-19 · เดิมล็อกจำลองด้วยค่าคงที่)** = `orderCenterShippingForce()`: ไม่มีกุญแจ = จำลอง · กุญแจทดลอง = ระบบทดลอง SHIPPOP (ไม่เสียเงิน) · กุญแจจริง = จำลองต่อจนตั้ง `SHIPPOP_ORDER_CENTER_LIVE=1` · รายละเอียด/ช่องโหว่ที่แก้แล้ว: `docs/shippop.md`
- **ใครส่งผ่านศูนย์นี้ได้**: เฉพาะออเดอร์ช่องทางของร้านเอง (LINE OA · Facebook · IG · LINE Shopping · เว็บ · โทร = `source: "manual"`) — ออเดอร์ Shopee/Lazada/TikTok ต้องใช้ขนส่งที่แพลตฟอร์มกำหนด, ออเดอร์จากเมลส่งไปแล้ว → ปุ่มบอกเหตุผล (`canShipViaShippop`)
- ช่องทาง "โทร / หน้าร้าน" = ไม่ผูกแพลตฟอร์ม (`platform_id` ว่าง) — เดิม NOT NULL ทำให้บันทึกไม่ผ่าน (เจอตอนตรวจหลัง deploy) · เจ้าของอนุมัติผ่อนเงื่อนไข 2026-11-10 (migration `202612020200` + unique เลขออเดอร์เฉพาะใบที่ไม่มีแพลตฟอร์ม) · ปิด/เปิดช่องทางได้ที่ `open` ใน `MANUAL_CHANNELS`
- **สร้างออเดอร์เอง** (ปุ่ม "สร้างออเดอร์"): ช่องทาง · แบรนด์ · ผู้รับ (ค้นที่อยู่ด้วยของกลาง `/api/public/address/search`) · รายการ (SkuPicker) · เก็บเงินปลายทาง → เลข `M{ปปดดวว}-{4 หลัก}` ตามเวลาไทย
- **ตั้งค่าการส่ง** ต่อแบรนด์ (`shipping_profiles`): ผู้ส่ง/ที่อยู่รับของ · กล่องมาตรฐาน · น้ำหนักต่อชิ้น (ใช้เมื่อรุ่นไม่มี `weight_g` — IG ขาด 118/262 รุ่น, LM 157/961) · ขนส่งที่ใช้ประจำ
- **จอง** (แถบติ๊กหลายใบ › "จัดส่ง" หรือในแผงรายละเอียด): ≤50 ใบ/ครั้ง · ได้เลขพัสดุ → สถานะ "แพ็กแล้ว" (ผ่าน `checkTransition`) · **ไม่ตัดสต๊อก** (ตัดตอน "ยืนยัน" เหมือนเดิม) · ยกเลิกการจองได้ตอนสถานะขนส่งยัง booking
- ขั้น 1 มีปุ่ม "จำลองสถานะถัดไป" (booking → shipping → complete) ให้ลองดูว่าสถานะออเดอร์เปลี่ยนตาม · ผู้รับ/COD แก้ได้เฉพาะออเดอร์ร้านเองที่ยังไม่จอง
- API: `/api/platform-orders/ship` POST `action=quote|book|cancel|simulate` · GET `?ids=` = ข้อมูลใบปะหน้า · `/api/shipping-profiles` GET/PATCH · audit `ship_book` / `shipping_profile`
- ขั้น 2 (ยังไม่ทำ): เจ้าของสมัคร SHIPPOP + ใส่กุญแจเอง → ปลดล็อกโหมดจริง · ขั้น 3: เรียกรถเข้ารับ/ติดตามอัตโนมัติ

## API `/api/platform-orders`
- GET รายการ: `view=todo|history|all` · `active=1` (ต้องจัดส่ง) · `due=late|today` · `invoice=requested|issued` · `status` · `q` · `page`/`page_size` (≤200) → `{ orders, total, summary }` · นับด้วย count ของฐานข้อมูล (เดิม `.limit(1000)` ตัดเหลือ 1,000 จาก 5,667)
- GET `?id=` (ใบเดียว + รายการ) · `?ids=a,b` (หลายใบ ให้หน้าพิมพ์) · `?demo=1` (ตัวอย่าง)
- PATCH `{ id | ids[] (≤200), status?, tracking_no?, carrier?, ship_to?, cod_amount? }` → ตรวจกติกา → audit ค่าเดิม→ใหม่ (`platform_order`)
- POST สร้างออเดอร์เอง `{ channel, brand_id, ship_to, items[], cod_amount?, note? }` → `source: "manual"`
- id ขึ้นต้น `demo-` = ตอบผลจำลอง ไม่บันทึก

## ข้อจำกัด / ต่อไป
- เฟส B: ตัวเชื่อม Shopee (กุญแจ + ต่ออายุ · ดึงสินค้า · ดึงออเดอร์อัตโนมัติ · นัดขนส่ง · ดึงไฟล์ใบปะหน้า · ข้อมูลผู้ขอใบกำกับ) — ปุ่ม "นัดขนส่ง" ตอนนี้บอกให้ใช้ Seller Centre ก่อน

- Lazada ดึงออเดอร์ยังแปลงสถานะเอง (ควรย้ายมาใช้ตัวแปลงกลาง) · แผนที่การไหลของงานยังไม่มีกล่องออเดอร์ออนไลน์
- ใบกำกับของเว็บร้าน (store_orders ชุด TI) ยังไม่อยู่ในรายงานภาษีขาย (ยังไม่เคยออกสักใบ ณ 2026-11-10)
