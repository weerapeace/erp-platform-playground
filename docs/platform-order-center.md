# ศูนย์ออเดอร์ออนไลน์ (เฟส A) — `/master/platform-orders`

เจ้าของเลือกหน้าตาจาก widget และอนุมัติแผน 2026-11-10 ("Approve, start") — เตรียมระบบแบบ Zort/BigSeller ไว้ก่อน Shopee อนุมัติ
**ยังไม่แตะร้านจริง** — ตัวเชื่อม Shopee (ดึงออเดอร์ / นัดขนส่ง / ใบปะหน้าจริง) อยู่เฟส B

## ใช้ทำอะไร
- ดูออเดอร์จากทุกร้านในที่เดียว: การ์ดกดกรอง **ต้องจัดส่ง · เลยกำหนดส่ง · ต้องส่งวันนี้ · ขอใบกำกับภาษี · ส่งแล้ว · ทั้งหมด**
- ติ๊กหลายใบ → **ใบหยิบรวม · ใบแพ็ก · ใบปะหน้า · แพ็กแล้ว** (แถบคำสั่งหลายรายการ)
- กดแถว → แผงรายละเอียด: เปลี่ยนสถานะตามกติกา · เลขพัสดุ · ออกใบกำกับภาษี
- **โหมดทดลอง** (ปุ่มมุมขวาบน / `?demo=1`): ออเดอร์ตัวอย่างหน้าตาแบบ Shopee ลองได้ทุกปุ่ม **ไม่บันทึกอะไร**

## สองแท็บ
| แท็บ | ออเดอร์ | ทำอะไรได้ |
|---|---|---|
| ต้องจัดการ | ออเดอร์ที่ต้องจัดส่ง (จากตัวเชื่อม API / อัปไฟล์) | ทุกปุ่ม |
| ยอดขายจากเมล | ออเดอร์ที่ระบบ 📧 อ่านจากอีเมลแจ้งยอดขาย = ร้านส่งของไปแล้วผ่าน Seller Centre | ดูอย่างเดียว + ออกใบกำกับภาษีได้ |

## กติกา (ของกลาง `lib/platform-order-status.ts` · ทะเบียน workflow key `platform-order`)
- สถานะในระบบ: ต้องจัดส่ง → ยืนยัน (ตัดสต๊อกจาก WH-ONLINE) → แพ็กแล้ว → ส่งแล้ว · ยกเลิกได้ก่อนส่ง (คืนสต๊อกถ้าเคยตัด)
- สถานะบนร้านเก็บแยกที่ `platform_status` (เช่น Shopee READY_TO_SHIP) — แปลงด้วย `shopeeToInternal`
- **ออเดอร์จากเมลเปลี่ยนสถานะ/ตัดสต๊อกไม่ได้** (API ปฏิเสธ) — เดิมกดยืนยันแล้วตัดสต๊อกคลังออนไลน์ติดลบได้
- "ต้องจัดส่ง" ไม่นับออเดอร์ที่ผู้ซื้อยังไม่จ่าย (UNPAID) · กำหนดส่งนับวันตามเวลาไทย

## งานพิมพ์ (`/print/platform-orders?kind=pick|pack|label&ids=` · ตัวสร้าง `lib/platform-order-print.ts`)
- **ใบหยิบรวม**: รวมรหัสทุกออเดอร์ (ตัวเลือกต่างกัน = คนละบรรทัด) · ตั้งค่าหน้าพิมพ์ด้วยของกลาง ListPrintPanel (แบบสำเร็จรูป "ตัวใหญ่ อ่านง่ายหน้าชั้นวาง")
- **ใบแพ็ก**: ออเดอร์ละใบ 2 ใบ/แผ่น A4 · บาร์โค้ดเลขออเดอร์ · ช่องติ๊กต่อรายการ
- **ใบปะหน้า**: ของจริงต้องใช้ไฟล์ของ Shopee (เลขพัสดุ/บาร์โค้ดขนส่ง) → เฟส B · ตอนนี้มีแค่ใบตัวอย่าง 100×150 มม. ลายน้ำ "จำลอง ห้ามใช้ส่งจริง" ในโหมดทดลอง

## ใบกำกับภาษี (`/api/platform-orders/invoice`)
- ออก **ผ่านใบขาย** (เลขชุดเดียวกับใบกำกับที่ออกอยู่ เช่น ISG2569-…) → เข้า `/sales/tax-report` เอง · พิมพ์ด้วย `/print/sales-order/<id>`
- ใบขายไม่ใส่คลัง = ไม่จอง/ไม่ตัดสต๊อก (กันตัดซ้ำ) → **ค้างสถานะ "ร่าง" ที่มีเลขแล้ว** (ใบขายที่ไม่มีคลังกดยืนยันไม่ได้ เพราะกติกาใบขายจะจองของ) · รายงานภาษีนับรวมและติดป้าย "ร่าง"
- ต้องตั้ง **บริษัทที่ออกใบกำกับ** ต่อร้านก่อน: 🏪 บัญชีแพลตฟอร์ม › ร้าน › ใบกำกับภาษี (`platform_accounts.tax_invoice_company_id`) — ระบบไม่เดาบริษัท
- ลูกค้า: หาในรายชื่อลูกค้า (`partners_v2`) ด้วยเลขผู้เสียภาษี (+สาขา) ไม่เจอ = สร้างใหม่ (หมายเหตุ "สร้างอัตโนมัติจากคำขอใบกำกับ…")
- ข้อมูลผู้ขอ: ป๊อปเติมจาก `platform_orders.tax_invoice_request` (เฟส B ดึงจาก Shopee `v2.order.get_buyer_invoice_info` — รองรับไทย) · พิมพ์เองได้
- ยอดรายการ ≠ ยอดออเดอร์ (ค่าส่ง/ส่วนลดของร้าน) → เตือน + ช่อง "ค่าส่งที่ผู้ซื้อจ่าย" · ราคาถือว่ารวม VAT 7% แล้ว
- ใบขายที่ผูกไว้ถูกยกเลิก = ออกใหม่ได้
- สิทธิ์: `platform_orders.manage` + สิทธิ์สร้างใบขาย `so.create` (ฐานข้อมูลเช็กเอง)

## ข้อมูล (migration `202612010100_platform_orders_center.sql` — เพิ่มช่องเท่านั้น)
`platform_orders` + `platform_status` · `ship_by_at` · `package_no` · `invoice_so_id` · `tax_invoice_request` · `platform_accounts` + `tax_invoice_company_id`

## API `/api/platform-orders`
- GET รายการ: `view=todo|history|all` · `active=1` (ต้องจัดส่ง) · `due=late|today` · `invoice=requested|issued` · `status` · `q` · `page`/`page_size` (≤200) → `{ orders, total, summary }` · นับด้วย count ของฐานข้อมูล (เดิม `.limit(1000)` ตัดเหลือ 1,000 จาก 5,667)
- GET `?id=` (ใบเดียว + รายการ) · `?ids=a,b` (หลายใบ ให้หน้าพิมพ์) · `?demo=1` (ตัวอย่าง)
- PATCH `{ id | ids[] (≤200), status?, tracking_no?, carrier? }` → ตรวจกติกา → audit ค่าเดิม→ใหม่ (`platform_order`)
- id ขึ้นต้น `demo-` = ตอบผลจำลอง ไม่บันทึก
