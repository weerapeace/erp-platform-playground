# 📡 สถานะการดึงออเดอร์ทุกร้าน

หน้า: `/master/platform-orders/pull-status` (ปุ่ม "สถานะดึงออเดอร์" ในศูนย์ออเดอร์) · เจ้าของเลือกจาก widget 2026-11-20 (แบบ A + ข้อเสนอ 1-5)

## ใช้ทำอะไร
ดูทีเดียวว่าแต่ละร้านดึงออเดอร์เข้า ERP อัตโนมัติปกติไหม — การ์ดละร้าน มีภาพเคลื่อนไหว:

| ภาพ | ความหมาย |
|---|---|
| จุดวิ่งจากร้าน → ระบบ | ออเดอร์ไหลเข้าปกติ |
| จุดวิ่งช้า | เข้าทางสำรอง/ข้อมูลไม่ครบ (เช่น มีแต่เมล) |
| แถบสั่น + การ์ดขอบแดง | ดึงไม่สำเร็จ / ตัวดึงเงียบเกิน 45 นาที |
| นาฬิกาทรายพลิก | กุญแจร้านเหลือ ≤ 7 วัน ต้องกดต่อร้านใหม่ |

ผู้ใช้ที่ตั้ง "ลดการเคลื่อนไหว" ในเครื่อง = ภาพนิ่ง

## ทางเข้าออเดอร์ (ตัวดึงทุก 15 นาที = pg_cron `tiktok-orders-every-15min` → `/api/cron/tiktok-orders`)
| ร้าน | ตัวดึง | ที่มา (source) |
|---|---|---|
| TikTok | `app/api/tiktok-shop/orders-sync.ts` (ย้อน 1 ชม.) | `tiktok_api` |
| Shopee | `app/api/shopee/orders-sync.ts` (ย้อน 3 ชม.) | `shopee_api` |
| Lazada | `app/api/lazada/orders-sync.ts` (ย้อน 3 ชม. · 2026-11-20) | `lazada_api` — ทับใบจากเมลเลขเดียวกัน · รายการจากเมลถูกแทนเมื่อรายการ Lazada จับคู่ SKU ได้ครบ และยังไม่ตัดสต๊อก/ยังไม่แพ็ก |
| LINE SHOPPING | `app/api/line-shopping/orders-sync.ts` (2026-11-20) | `line_shopping_api` — ⚠️ ยังไม่เคยเจอข้อมูลจริง รอบแรกที่มีออเดอร์จดรูปข้อมูลใน audit (metadata.shape) |
| เว็บไซต์ | `lib/webshop-order-mirror.ts` ส่งต่อจาก `store_orders` (ย้อน 60 วัน · 2026-11-20) | `webshop` — จัดการที่หน้าเว็บไซต์ › ออเดอร์ ศูนย์ออเดอร์ดูอย่างเดียว |
| Lazada/Shopee ผ่านเมล | สคริปต์ Gmail → `/api/platform-email/inbound` | `email` — ทางสำรอง (Shopee แบรนด์ที่เชื่อม API แล้วไม่บันทึกจากเมล) |

ตัวกลางทีละร้าน: `app/api/platform-orders/pull-runner.ts` `pullShop()` — ใช้ทั้งตัวดึงอัตโนมัติ (Lazada/LINE/เว็บ) และปุ่ม "ดึงตอนนี้" (`POST /api/platform-orders/pull` · ย้อน 3 ชม. · สิทธิ์ `platform_orders.manage` · จด audit ทุกครั้ง)

ทุกแหล่ง API = "สถานะตามร้าน" (`isShopManaged`) เปลี่ยนสถานะ/ตัดสต๊อกในศูนย์ออเดอร์ไม่ได้ · ⚠️ อ่านจากร้านอย่างเดียว ไม่แก้อะไรบนร้าน

## กติกาสถานะ (`lib/order-pull-health.ts` · มีเทสต์ `lib/__tests__/order-pull.test.ts`)
ok ปกติ · slow ต้องดู (มีแต่เมล) · stale หยุดดึง (เงียบ > 45 นาที) · error มีปัญหา (รอบล่าสุดล้ม / กุญแจหมดแล้ว) · token กุญแจเหลือ ≤ 7 วัน · off ยังไม่ต่อ

วันที่ต้องต่อร้านใหม่: Lazada = `refresh_expires_at` (ต่ออายุแล้วไม่ยืด ต้องกดต่อทุก ~30 วัน) · Shopee = `auth_expires_at` (อนุญาต 1 ปี) · TikTok = `refresh_expires_at`

ผลรอบเก็บใน `ui_config` key `order_pull:<platform>:<brand_id|all>` (แถวเดียวต่อร้าน · นับรอบล้มติดกัน) — `recordShopPull` (`lib/order-pull-server.ts`)

## กระดิ่งเตือน (`orders.pull_problem` · ตั้งคนรับที่แผนผังการทำงาน › แจ้งเตือน · ไม่มีกฎ = แอดมิน)
- ร้านดึงไม่สำเร็จ 3 รอบติด · ตัวดึงร้านเงียบเกิน 45 นาที · กุญแจร้านเหลือ ≤ 7 วัน/หมดแล้ว — ตรวจท้ายรอบทุก 15 นาที
- ตัวดึงทั้งระบบหยุด (ไม่มีรอบเกิน 60 นาที) — ตรวจข้ามระบบจาก Vercel cron `/api/cron/lazada-token` ทุกเช้า 07:30 (`checkPullerAlive`)
- เรื่องเดิมส่งวันละครั้ง (`ui_config` `order_pull_alerts`)

## ข้อจำกัด
- FB/IG ไม่มี API ออเดอร์ → สร้างออเดอร์เองในศูนย์ (การ์ดบอกไว้)
- LINE SHOPPING: ถ้าเคยสร้างออเดอร์ LINE เองในศูนย์ (manual) แล้วระบบดึงใบเดียวกันมาอีก จะเห็น 2 ใบ (เลขต่างกัน)
- เมลเป็นสถานะรวมระบบ (ไม่แยกร้าน)
